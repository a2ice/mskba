# Отчёт MSKBA-553 — единые контракты спортивных секций

## Область выполнения

Эта поставка завершает совместимость **спортивных секций** с общей контрактной системой и фиксирует безопасный следующий этап для **мероприятий и игр**. Права бэк-офиса остаются отдельными глобальными permissions.

## Изменения

1. `CreateSportsSectionHandler`: контракт владельца создаётся через `EntityContractManager::grantOwner`, бессрочный и сразу подтверждённый; спортивная роль тренера сохраняется отдельно.
2. `ManageSectionCoachHandler`: приглашение тренера через `EntityContractManager::invite`; можно задать название, комментарий, дату окончания и индивидуальные разрешения.
3. `SportsSectionAccess`: pending/declined/revoked договоры не дают прав; доступ требует действующего принятого договора и подтверждённого незаблокированного пользователя.
4. `AccountSportsSectionController`: непринимающие приглашения не появляются в управлении секциями.
5. Обновление полномочий тренера: расширение требует повторного принятия; отзыв не позволяет удалить текущего главного тренера.
6. `SportsSection` / `TrainingSession`: выборы тренеров для занятия и публичный список используют только действующие контракты.
7. Редактор секции: статусы, понятные действия, название договора, дата окончания, комментарий и ссылка на управление.
8. В административном редакторе сохраняется возможность исправлять условия контрактов тренеров с обязательной причиной, но защищена роль текущего главного тренера.
9. Универсальная передача владельца секции временно закрыта до отдельного сценария, согласующего head coach и владельца. Главным тренером временно назначается только тренер с бессрочным подтверждённым договором.
10. Разделы Event/Game не изменены: документация отдельно фиксирует матрицу миграции и тестовые риски без параллельного ACL.

## Безопасность и обратная совместимость

- Существующие принятые section contracts остаются действующими — исторические назначения не удаляются и не мигрируют заново.
- Персональный список занимающихся (`SectionTraineeMembership`) и снимки занятий (`TrainingSession`) сохраняют свои модели.
- Временное отсутствие `invitation_status=accepted` больше не даёт прав на управление или участие как тренера.
- Отдельные коммерческие права площадки и глобальные `backoffice.*` не изменяются.

## Тестовые сценарии

Обязательны: владелец и его полные права, pending coach, принятие, отклонение, отзыв, истечение срока, невозможность получить чужие права, повторный акцепт после расширения, защита главного тренера, спортивные секции/заявки/связанные команды/публичный каталог/занятия. Для Event/Game — контроль отсутствия регрессий существующих тестов.

Автоматизированные тесты:

Полный CI проверяет `php artisan test` и `npm run build`. Результаты CI и деплоя следует смотреть по PR/merge commit; успешная автоматическая проверка не равна визуальной приёмке.

## Инструкции для ручной проверки

Основная пошаговая инструкция — `docs/project/contract-management.md`, раздел «Приёмка на dev». Для проверки использовать две подтверждённые учётные записи с ролью тренера (владелец и получатель), обычного участника без прав и суперадминистратора. Не использовать реальные личные данные, платежи и настоящие договоры.

Ключевой маршрут: создание секции в личном кабинете → вкладка «Тренеры» → приглашение → у получателя «Мои контракты» → согласие → управление → изменение/отзыв → проверка истории через `/backoffice/contracts`.

## Что не сделано в этой поставке

- Отдельная подтверждаемая передача владения секцией вместе с назначением главного тренера.
- Единый публичный контрактный ACL Event/Game, включая миграцию прежних ответственностей.
- Relation contracts для бронирований, аренды, партнёрств.

Эти вопросы описаны в `docs/specification/event-contract-migration.md` и `docs/project/contract-management.md`. Реализация без предметных тестов опасна для существующего жизненного цикла игр.
