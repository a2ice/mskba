# Отчёт по исправлению мобильных таблиц бэк-офиса — задача 557

## Диагноз

На iPhone после задачи 556 некоторые значения карточки контракта выводились в столбик, по несколько символов на строке. Источник — десктопные селекторы `td:nth-child` с `width:19%`/`20%`/`14%`, оставшиеся активными при мобильном `display:grid`; из-за приоритетов CSS мобильное `width:auto` их не отменяло.

## Изменения кода

1. `public/css/backoffice-contracts.css`: desktop-width selectors перенесены под `@media(min-width:1051px)`; смартфоны — 1 колонка с шириной 100%, средние экраны — 2 колонки только при достаточной ширине. В `contract-history` и `contract-verification` используется тот же исправленный набор правил.
2. `public/css/backoffice-tables.css`: изолированный единый стиль кастомных таблиц (не общая замена стилей Filament).
3. Пользователь — системные роли, площадки, роли участия, аудит: мобильные карточки с понятными подписями.
4. Кошелёк и редактор конкретной роли (команды, мероприятия и статистика): минимальные читабельные ширины и внутренний горизонтальный скролл на мобильном.
5. `BackofficePanelProvider`: подключение CSS и cache-busting по версии.
6. `ResponsiveTablesAuditTest`: статическая регрессия по всем Blade-фрагментам таблиц в бэк-офисе, наличие подписей карточек, контроль мобильных ширин.

## Проверено локально

Проверочная модель новой сетки открыта в headless Chromium на ширинах 320, 375, 390, 430, 540, 699, 700, 760, 820, 1024, 1050, 1051 и 1280 px.

В этой модели на 390 px поля занимают полную ширину мобильной карточки (около 294 px при заданных отступах), а горизонтальная ширина документа остаётся равной ширине viewport. На 700+ px включается двухколоночный вариант; десктопные ширины не должны действовать на мобильную сетку.

**Важно:** это автономный тест сетки, не снимок реального Filament с авторизацией. Требуется ручной осмотр реального dev-сайта.

## Не затронуто

Данные, права, статусы, даты, создание/принятие/отзыв контрактов, глобальные разрешения админки, штатные Filament Resource Tables и бизнес-логика остаются неизменными.

Пошаговый сценарий — `docs/mskba_app/tasks/557/description.md`. Проверить Safari iPhone на карточках команды, пользователя, других сущностей, а также историю контрактов, роли, кошелёк и игровую статистику. Результат CI и фактического dev-деплоя зафиксировать отдельно.
