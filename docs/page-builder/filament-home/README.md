# Переход главной MSKBA на Filament-owned HTML / CSS / JS

**Статус:** подготовка миграции на ветке `dev`; `main` и production не менять.

## Что изменено в коде

- Удалена staging-only ветка в `resources/views/page-builder/show.blade.php`, которая
  автоматически вставляла `venues-scene` и подложку под Hero.
- Удалены `resources/views/page-builder/components/venues-scene*.blade.php`,
  их CSS/JS и Vite-подключения. Эти файлы НЕ управляются в Filament.
- Удалены глобальные `resources/css/page-builder-rolling-ball.css` и
  `resources/js/page-builder-rolling-ball.js`: **их содержимое сохранено здесь:**
  - [ball.css](ball.css): переносится в CSS главной страницы;
  - [ball.js](ball.js): переносится в JS главной страницы.
- Системные `hero-slider` Blade/CSS/JS, его слайды и серверный рендерер не меняются.
  PNG/WebP ассеты в `public/images/` тоже не удаляются.
- **Никакой автоматической записи HTML, CSS или JS в БД из Git.** Публикация
  и история редакций полностью под контролем оператора Filament.

## Безопасный порядок без промежутка с большим неоформленным изображением

**Рекомендуется выполнять шаги 1–3 *до* merge/deploy удаления Vite-кода.**
Существующий системный JS использует `data-rolling-ball-ready` как
защиту от повторной инициализации, поэтому временное соседство старого
Vite JS и нового опубликованного JS не запустит два независимых контроллера.

1. DEV Filament → **Контент → Страницы → Главная** (URL `/`).
   Не менять пока существующую HTML-разметку Hero Slider или мяч.
2. В действиях редактора нажать **CSS**. **Не стирать существующий CSS**:
   если он есть, дописать содержимое `ball.css` в конец. Нажать
   «Сохранить и опубликовать». Стили появляются сразу без Vite.
3. В действиях нажать **JS**. **Не стирать существующий JS**: добавить
   содержимое `ball.js` в конец. Нажать «Сохранить и опубликовать»
   (при наличии прав публикация также включает JS). Не вставлять
   `<script>`-теги. На DEV проверить, что скрипт присутствует по
   `/page-builder/scripts/page/...`. Не полагаться на HTML-preview,
   потому что редактор намеренно не выполняет page JS в preview.
4. Проверить в опубликованной главной анимацию мяча при скролле
   и её поведение на desktop/mobile; при необходимости отключить JS
   отдельно через Filament. Избегать двух копий исходника JS
   в редакторе (проверь `rollingBallProfiles`).
5. **После подтверждения шагов 2–4** объединить PR удаления ресурсов в
   `dev`, дождаться CI/`deploy_dev`, обновить страницу без кэша и
   проверить, что CSS/JS продолжает работать исключительно через Filament.

Если удалить Vite CSS прежде чем опубликовать страницу CSS,
исходный `<img class="mskba-rolling-ball__sprite">` станет видимым как
полный спрайт 1024x1024, поскольку за его скрытие отвечает именно
`ball.css`. Это **предотвращаемая регрессия**; потому рекомендуем
сначала публикацию CSS, затем JS и только потом merge.

## HTML мяча: уже присутствует на DEV

В HTML главной внутри `.container > .mskba-hero-scene` уже существует
фрагмент ниже. **Не вставляй второй мяч.**

```html
<div class="mskba-rolling-ball">
  <img class="mskba-rolling-ball__sprite"
       src="/images/ball-16.webp"
       alt="">
</div>
```

Его нужно оставить *рядом* с плейсхолдером
`<mskba-component name="hero-slider"></mskba-component>`.
Компонент рендерит собственные `data-mskba-hero-slider` атрибуты;
не копировать HTML слайдов вручную.

## Когда будем переносить «Площадки»

В HTML страницы отдельно добавить полноэкранный `.mskba-home-story`,
внутри него Hero, слой неба/города + забора/щита, затем статичную
секцию `#venues-intro` с единственным общим `.container`.
Player, заголовки, CTA и highlights — внутри `.container`.
CSS всех элементов держать в **CSS этой же страницы**, а не в
`resources`. Можно откатывать исключительно CSS публикацию.

**Ограничения HTML санитайзера:** разрешены `class`, `id`,
`img`, `a`, `section`, `div` и стандартные текстовые элементы;
произвольные `data-*`, `<svg>`, inline `style`, `<script>`, Blade
запрещены и очищаются/отклоняются. Для иконок — `<img>` или CSS,
для анимаций — отдельный Filament JS. Сохранённый `ball.js` уже
ищет вторую сцену по `.mskba-home-story`, `#venues-intro`,
`.mskba-venues-scene__visual-space`,
`.mskba-venues-scene__ball-target`, не по запрещённым data-атрибутам.
Пока Venues отсутствует, анимируется **только Hero**.

## Откат

- HTML/CSS/JS Filament имеют независимые сохранение/публикацию.
- CSS: действие «Откатить CSS».
- JS: «Отключить JS» или «Откатить JS» (для новых ответов сайта).
- Git: revert PR только для восстановления прошлой Vite-интеграции.
- HTML главной страницы не перезаписывается миграцией и остаётся
  в прежней опубликованной версии, пока пользователь не опубликует новую.

## Дополнительная проверка

- `resources/css/page-builder.css` не импортирует Ball/Venues CSS.
- `resources/js/page-builder.js` импортирует `page-builder-hero-slider.js`
  и штатные источники данных, но **не** Rolling Ball/Venues JS.
- CSS/JS мяча копируются из этих двух файлов без ссылок на GitHub Raw
  через `@import` или `<script>`: редактор требует исходный код.
- Ограничение 100 KB валидации Page Builder CSS: файл мяча ~3.5 KB.
- Проверить desktop, tablet, mobile, прокрутку вниз/вверх и `prefers-reduced-motion`.
