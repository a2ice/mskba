# Task 206 — Собственный профиль в каталоге участников

## Причина

После запуска Task 205 в `/participants` отображаются только пользователи, прошедшие публичную projection. Для текущего пользователя полезно сделать его профиль заметнее и дать быстрый переход из public profile в настройки аккаунта.

## Реализация

- Если авторизованный canonical user входит в текущую выборку `/participants`, `/players` или `/coaches`, его карточка сортируется первой до пагинации.
- После собственного профиля сохраняется алфавитная сортировка остальных участников.
- На собственной карточке отображается компактный badge «Мой профиль».
- На собственной публичной странице пользователя в sidebar добавлена кнопка «Перейти в аккаунт» → `/account`.
- Owner определяется только сервером через canonical identity.

## Почему каталог может быть коротким

Participant catalog намеренно не является списком всех `users`. Пользователь должен:
- быть canonical и confirmed;
- не быть blocked/soft-deleted;
- иметь активную роль, соответствующую выборке;
- быть доступным текущему viewer по `DISCOVERABILITY`;
- иметь доступный `PROFILE` и соответствующий `ROLE_*`, кроме существующего public-coach exception.

Поэтому технические Telegram/VK аккаунты без подтверждения либо профили с закрытой ролью/поиском в каталог не попадают.

## Проверки

- собственная карточка первая даже при имени, которое алфавитно было бы последним;
- badge «Мой профиль» выводится ровно на собственной карточке;
- CTA «Перейти в аккаунт» есть только на собственной public-profile странице.
