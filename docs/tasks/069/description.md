# Задача 069 — команды, игровые составы, мини-игры и статистика

## Цель

Реализовать B0260, B026 и B0261 как один связанный игровой контекст:

- постоянные и временные команды;
- самостоятельные игры двух постоянных команд;
- мини-игры внутри тренировки или игровой тренировки;
- единый снимок фактических составов на конкретную игру;
- итоговый счёт и персональная статистика игроков;
- объективные характеристики игрока, рассчитанные только по подтверждённой статистике.

## Принятые решения

### Команда

Команда является самостоятельной сущностью. Временность определяется наличием
`temporary_for_event_id`: отдельный дублирующий boolean не используется.

Постоянное членство и операционные роли команды хранятся через `ContractMembership`
со scope `team`. Уровни доступа: владелец, ответственный, капитан, тренер, игрок.
Активная постоянная команда обязана иметь владельца, капитана или ответственного.
Для временной команды это условие не требуется.

### Игра

Игра остаётся мероприятием типа `game`. Мини-игра отличается наличием
`parent_event_id` и не создаёт самостоятельную бронь площадки. Её время обязано
попадать внутрь родительского мероприятия.

Мини-игра является частью родительского агрегата, а не отдельным мероприятием:

- она отображается на публичной странице родительского мероприятия;
- у неё есть собственная публичная страница игры со счётом, снимком составов и
  персональной статистикой;
- её публичная видимость наследуется от родительского мероприятия, поэтому прямой
  URL не позволяет обойти ограничения родителя;
- она не попадает в общий журнал мероприятий и не увеличивает счётчик игр за день;
- создание, изменение состава, статистики или результата инициирует обновление
  Telegram-публикации родительского мероприятия;
- Telegram-сниппет родителя показывает принявших назначение ответственных, названия
  мини-игр, названия сторон и текущий счёт.

Организатор и принявшие назначение ответственные задаются на родительском
мероприятии и управляют всем игровым агрегатом: самим мероприятием и его
мини-играми. У дочерней мини-игры нет отдельного набора ответственных.

Публичная страница игры работает только на чтение. Из неё организатор,
принявший назначение ответственный или superadmin может перейти в отдельный
интерфейс управления составами и статистикой. Самостоятельная игра и мини-игра
используют одну публичную игровую проекцию; различаются лишь источники прав,
видимости и состава.

Для мини-игры без собственного расписания в базе хранится технический интервал
родительского мероприятия, необходимый для сортировки и проверки границ. Источником
истины для интерфейса служит `is_time_scheduled`: если он равен `false`, поля времени
не показываются и не отправляются обратно при редактировании. Явно заданные
одинаковые начало и окончание запрещены.

Формат хранит размер обеих сторон отдельно, поэтому поддерживает 5×5, 3×3, 1×1 и
асимметричные варианты. Для каждой игры существуют ровно две стороны A и B.

Для мини-игры интерфейс предлагает один формат, рассчитанный из общего количества
доступных участников: 1×1, 2×1, 2×2, 3×2 и далее до 6×5. Сервер повторно проверяет,
что формат сбалансирован, не превышает доступный состав и пределы 6 игроков на
стороне A и 5 игроков на стороне B.

### Снимок состава

`game_roster_entries` фиксирует фактический состав именно этой игры:

- для самостоятельной игры кандидаты берутся из постоянных команд;
- для мини-игры кандидаты берутся из подтверждённых участников родительского
  мероприятия;
- изменение постоянной команды после игры не меняет исторический состав;
- ретроспективное добавление участника в завершившееся мероприятие не меняет снимки
  ранее созданных мини-игр, а только делает игрока доступным для новых;
- один пользователь может находиться только на одной стороне конкретной игры.

### Статистика

Счёт сторон и сумма очков игроков хранятся раздельно. Несовпадение показывается как
предупреждение и не блокирует сохранение: протокол может быть неполным.

Персональная статистика агрегированная, без play-by-play: минуты, броски по зонам,
штрафные, подборы, передачи, перехваты, блоки, потери и фолы.

Сокращения в таблице статистики сопровождаются текстовыми подсказками. В частности,
`Мин` означает количество сыгранных минут, `+` — попадания, `всего` — попытки.

Только статистика со статусом `confirmed` участвует в пересчёте объективного профиля.
Субъективная самооценка игрока остаётся отдельной моделью и не перезаписывается.

## Права

Игрой управляют:

- организатор;
- участник, принявший назначение ответственного;
- подтверждённый superadmin.

Командой управляют владелец и ответственный, а superadmin имеет аварийный доступ.

## Конкурентный доступ

При операциях с несколькими объектами блокировки берутся в стабильном порядке:
площадка → родительское мероприятие → команды по возрастанию ID → игра → состав.
Это снижает вероятность deadlock при параллельном переносе игры и редактировании
состава. Уникальные ограничения БД дополнительно защищают стороны и участников.

## Ограничения первой версии

- ровно две стороны в игре;
- нет деления одной площадки на несколько одновременно доступных кортов;
- нет событийной ленты каждого игрового действия;
- объективная оценка имеет версию формулы и уровень достоверности, поэтому может
  безопасно эволюционировать позднее.
