# 321 — Единое уведомление о пополнении бонусного баланса

## Причина и запрос

После развёртывания 320 супер-администратор перечислил пользователю `apelsin1` 100 ₽ через Filament. Баланс увеличился, но toast не появился. Обычный перевод и административное пополнение должны порождать одинаковое уведомление получателю.

## Реализация

- Уведомление `finance.wallet.transfer.received` создаёт общий `TransferUserWalletBalanceHandler` через `NotifyWalletTransferRecipient`, независимо от вызывающего интерфейса.
- `type=finance`, `delivery_category=system`, `wallet_operation_id`, `transfer_origin=user|backoffice`; текст различает отправителя и администрацию.
- Проверка существующего уведомления под блокировкой записи операции защищает от дублей при replay. Если уведомление не было создано, повтор по тому же idempotency key восстанавливает его без списаний.
- Ошибка уведомления фиксируется и сообщается инициатору без отмены зачисления.
- Realtime-событие по этому сценарию отправляется после фиксации транзакции; подтверждённые внешние каналы работают существующим пайплайном.
- Регрессионные тесты пользователя и Filament.

## Приёмка

PR → зелёный CI → merge в `dev` → автодеплой. Проверить оба вида перевода под двумя аккаунтами, toast и подтверждённую почту.
