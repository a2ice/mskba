# 027 - Запретить ручное управление условиями оплаты и подтверждения площадки

## Оригинальное описание

При добавлении площадки пользователь не должен сам выбирать признаки оплаты и подтверждения бронирования. Они устанавливаются по умолчанию и в дальнейшем изменяются связанной бизнес-логикой.

## Подробное описание

`requires_payment` и `requires_booking_approval` являются денормализованными проекциями будущих условий оплаты и правил подтверждения бронирования. Их нельзя задавать вручную при создании или редактировании площадки ни в обычной web-форме, ни в Telegram Mini App, ни через подменённый HTTP-запрос.

Новая площадка получает оба значения `false` из дефолтов схемы. Существующие значения не меняются при редактировании паспортных полей. Поиск и отображение могут продолжать читать эти признаки. В будущем изменять их должны только application handlers, синхронизирующие связанные условия площадки.

## Проверка

- поля отсутствуют в web- и Telegram-формах создания и редактирования;
- переданные вручную параметры игнорируются при создании;
- переданные вручную параметры игнорируются при пользовательском и административном редактировании;
- новая площадка получает оба значения `false`;
- поиск по фактическим признакам продолжает работать.

## Результат

- элементы ручного выбора удалены из общей web-формы и формы Telegram Mini App;
- create/update FormRequest исключают признаки из validated payload;
- create handler полагается на дефолты схемы и модели;
- общий updater паспортных данных не изменяет условия доступа;
- административная форма также не позволяет вручную менять эти проекции;
- тесты подтверждают, что подменённые HTTP-параметры игнорируются при создании и редактировании.
