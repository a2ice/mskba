# 230 — Проверка новых фото лица внутри генерации

## Цель

Не заставлять пользователя отдельно подтверждать face references до нажатия «Сгенерировать».
Новые выбранные фото остаются локальным preview и отправляются вместе с generation request.

## UX

- выбор фото сразу показывает локальный preview;
- до нажатия «Сгенерировать» внешний AI не вызывается;
- если обязательный набор лица ещё не подтверждён или пользователь выбрал новое фото,
  над кнопкой показывается мелкая подпись:
  «Генерация пройдёт в два этапа: сначала проверим фото лица, затем создадим персонажа.
  Проверка лица не входит в стоимость генерации.»;
- во время generation request pending-фото получают loading overlay;
- после успешной проверки и генерации pending preview переключается на private saved reference;
- при ошибке локальный preview остаётся в форме, а ранее подтверждённый reference в storage не удаляется.

## Backend flow

Один запрос UI к MSKBA может включать новые `generation_face_references[front|left|right]`.

Порядок:

1. Pricing разрешает актуальную цену `avatar_generation`;
2. проверяется, что эффективный набор состоит из сохранённых + pending фото и содержит
   анфас и минимум одну сторону;
3. проверяется доступный баланс пользователя;
4. если есть pending-фото — они нормализуются в памяти;
5. все pending-фото проверяются одним вызовом `validateFaceReferences()`;
6. только если весь batch валиден, новые references атомарно сохраняются и заменяют старые
   соответствующих slot;
7. итоговые сохранённые references читаются из private storage;
8. выполняется второй provider call — `generatePlayerCharacter()`.

Если pending-фото нет и обязательный набор уже ранее подтверждён, шаги 4–6 полностью
пропускаются: сохранённые references сразу переиспользуются для генерации.

## Финансы

Task 230 по-прежнему не списывает деньги. Проверка generation balance выполняется до
платного face-validation call, чтобы не расходовать внешний AI при заведомо невозможной
генерации.

Кто оплачивает face-validation и будет ли у неё отдельная цена — отдельное продуктовое
решение. UI уже явно отделяет её стоимость от стоимости самой генерации.

## Инварианты

- невалидный batch не сохраняет ни один новый reference;
- ошибка AI validation не удаляет старые подтверждённые references;
- сохранённые подтверждённые references не валидируются повторно на каждой генерации;
- повторная генерация с тем же лицом не требует повторной загрузки фото;
- provider получает face validation batch одним запросом, затем generation отдельным запросом.
