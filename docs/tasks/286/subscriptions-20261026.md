# 286 — Игровые подписки (согласование 26.10.2026)

**Статус:** реализация в отдельной ветке, CI перед слиянием в dev. Этот сценарий отменяет предыдущую гипотезу автоматического сохранения сразу после авторизации.

## Пользовательский сценарий

- Термин пользователя — «подписка»; `PlayIntent`, `play_intents` и существующие маршруты остаются внутренними именами ради обратной совместимости. Другой агрегат `VenueRentalCoordination` не переименовывается.
- Форма «Хочу здесь играть» — wizard: параметры → авторизация/регистрация (если гость) → настройки → подписаться → готово. После login нет автоматического сохранения. «Назад» сохраняет состояние; отмена закрывает wizard.
- Первое поле — «Название подписки»: автозаполнение по текущей площадке, «{площадка} и похожие» либо «Игры по моим условиям» без площадки; ручное редактирование блокирует автозамену; до 80 символов.
- Второе поле — предикативный выбор площадки (название, адрес, метро) из подтверждённых площадок, при входе со страницы Venue выбран её id. Без конкретной площадки чекбокс похожих неактивен.
- Далее «Подбирать похожие площадки», радиус 1–30 км и `excluded_venue_ids` — multi-select с удаляемыми тегами. Исключения нельзя выбирать за пределами радиуса или равными основной площадке. Сервер валидирует и исключает их из рекомендаций.
- Сохранение/изменение подписки только по действию «Подписаться» / «Сохранить подписку», с идемпотентным `client_request_id`.

## Настройки и публичность

- На отдельном шаге расположены одинаковые чекбоксы: уведомления об играх, спецпредложения, избранная площадка, согласие на показ профиля.
- Для новых подписок все доступные чекбоксы включены изначально, включая публичность. При снятии публичности оформление не блокируется.
- Текст: «Согласен показывать другим посетителям мой никнейм, аватар и игровые характеристики в рамках этого поиска.»
- Личную публичность можно изменить при редактировании «Моих подписок». Исторические значения `show_on_venue=false` сохраняются.
- Отключившие публикацию всегда учитываются в численности и отображаются обезличенно (без никнейма, аватара, характеристик).

## Аудитория площадки

Показатель «Площадкой интересуются» состоит из двух непересекающихся групп:

1. **Подписаны напрямую**: действующая подписка с `venue_id = текущая площадка`, независимо от флага «похожие».
2. **Подходят по условиям**: действующая подписка без привязки к Venue либо с другой основной площадкой и включёнными похожими, если текущая площадка соответствует жёстким требованиям, радиусу и не исключена.

`total = direct_count + matched_count` после дедупликации канонического пользователя. При пересечении человек относится к прямой группе. При нескольких подходящих подписках более строгая настройка публичности имеет приоритет. Показ совпадения означает потенциальную совместимость, не реальную доступность или гарантию участия.

`VenueSubscriptionAudience` формирует список и агрегаты по одним правилам. `RecommendVenuesForIntent::matchesVenue` — общий предикат обязательных условий для альтернатив. Рендер карточки и попапа использует эти группировки. Публичные контакты и личные расписания не выдаются.

## Обязательные проверки

- Создание и редактирование с `show_on_venue=false`, включая восстановление после auth.
- Прямая подписка + подписка по условиям одного пользователя считаются однажды и только в группе прямых.
- Подписка с excluded venue не становится кандидатом и не входит в matched group; primary Venue нельзя исключить.
- При изменении параметров, радиуса, выбранной площадки не появляются нерелевантные исключения; проверка радиуса выполняется на сервере.
- Рекомендации сохраняют прежние hard filters, а выключенный флаг публикации не нарушает выбор игр.
- Адаптивность desktop/mobile/Telegram Mini App; фиксированный footer, клавиатурная навигация combobox, сохранение настроек.

## Граница

Эта игровая подписка не Event, Booking, платеж и не аренда; автоматические маркетинговые отправки / организация групп по-прежнему отдельные этапы 287–288.
