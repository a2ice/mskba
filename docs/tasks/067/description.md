# 067 - Пересобрать публичную страницу мероприятия по mobile-first референсу

## Оригинальное описание

Пересобрать страницу мероприятия согласно предоставленному мобильному референсу, предварительно подробно изучив его композицию и сопоставив интерфейс с реальными данными проекта.

## Подробное описание

Страница мероприятия должна перейти с общего sidebar-layout на самостоятельную mobile-first композицию, одинаково работающую в обычном мобильном браузере и Telegram Mini App. Нативная верхняя панель Telegram не является частью сайта и не воспроизводится приложением; внутренняя шапка MSKBA и нижний mobile primary bar остаются общими компонентами темы.

Основные блоки:

1. Hero-карточка с фотографиями площадки, счётчиком, навигацией, названием мероприятия, локальным временем, площадкой, адресом и вычисляемым состоянием набора.
2. Реальные действия участия «Пойду», «Не пойду» и «Под вопросом». Текущее участие пользователя должно визуально выделяться; действия недоступны после начала, отмены или закрытия набора.
3. Сводка количества подтверждённых участников, оставшихся мест, типа активности и состояния бронирования.
4. Таблица подробностей с временем, площадкой, адресом, покрытием при наличии данных, условиями оплаты и бронированием; переход к карте использует координаты локации.
5. Карточка описания мероприятия с компактным мобильным раскрытием длинного текста.
6. Карточка организатора с реальным именем, аватаром и Telegram-действием только при наличии подходящего контакта.
7. Горизонтальный список подтверждённых участников с аватарами, ролью организатора и остатком свободных мест.
8. Действие «Поделиться» через Telegram share-link в Mini App и Web Share API/копирование ссылки в обычном браузере.
9. Отдельный компактный блок управления для организатора или superadmin без возврата к старому sidebar.
10. Сохранение существующих сценариев отмены, редактирования, подведения итогов и управления итоговыми фотографиями.

### Источники данных и честные fallback

- hero использует опубликованную галерею площадки; при отсутствии фотографий показывается существующая тематическая заглушка;
- свободные места вычисляются только из `max_participants` и подтверждённых участников, при отсутствии лимита показывается «Без лимита»;
- стоимость выводится как «Бесплатно» при `requires_payment = false`, иначе как «По условиям площадки», поскольку точной цены в модели пока нет;
- покрытие берётся только из существующей характеристики площадки, если её можно однозначно определить, иначе отображается «Не указано»;
- кнопка связи с организатором появляется только при доступном Telegram username/контакте;
- вымышленные фотографии, имена, цены и характеристики из референса не подставляются.

### Изменение модели участия

`EventParticipantStatusEnum` расширяется состоянием `tentative` («Под вопросом»). Для web-интерфейса вводится единый сценарий смены собственного ответа, повторно использующий блокировку строки мероприятия и проверку лимита мест. `confirmed` занимает место, `tentative` и `left` место не занимают. Организатор остаётся подтверждённым и не может сменить собственный статус через публичные действия.

Изменение схемы выполняется отдельной миграцией, потому что production уже содержит таблицу участников; редактирования только исходной миграции недостаточно.

### Адаптивность

На мобильном экране блоки идут одной колонкой, интерактивные зоны рассчитаны на управление пальцем, контент учитывает fixed bottom bar и Telegram safe-area. На desktop сохраняется та же информационная иерархия, но карточки используют более широкую сетку без искусственного растягивания строк и кнопок.

## Результат

Публичная страница мероприятия переведена на самостоятельную mobile-first композицию по референсу: hero с галереей площадки, состояние набора, три ответа участника, сводка мест и бронирования, подробности, карта, описание, организатор, горизонтальный состав, sharing и компактное управление. Экран адаптирован для desktop, мобильного браузера и Telegram Mini App.

Модель участия расширена состоянием `tentative`. Единый web-сценарий смены ответа выполняется в транзакции с блокировкой мероприятия; только `confirmed` расходует лимит. Добавлена production-миграция PostgreSQL/MySQL, при этом fresh SQLite schema для тестов получает актуальный enum из исходной миграции.

Существующие сценарии редактирования, отмены, позднего подведения итогов и итоговой фотогалереи сохранены. Источником hero-фотографий является галерея площадки; отсутствующие цена, покрытие, контакт или лимит отображаются без вымышленных значений.
