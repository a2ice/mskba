# 028 - Запретить редактирование площадки во время модерации

## Оригинальное описание

Если площадка отправлена на модерацию (`pending`), её нельзя редактировать никому, кроме superadmin. При попытке сохранить ранее открытую форму нужно вернуть ошибку, иначе данные могут измениться одновременно с подтверждением модератором.

## Подробное описание

Обычный пользовательский сценарий просмотра и сохранения формы должен считать наличие pending-заявки запретом на изменение паспортных данных. Проверка при открытии формы улучшает UX, но обязательная проверка выполняется повторно внутри транзакции обновления после блокировки строки площадки.

Для устранения race condition обновление площадки и рассмотрение заявки используют единый порядок блокировок: сначала `venues`, затем `moderation_requests`. Подтверждение заявки и перевод площадки в `confirmed` выполняются атомарно в одной транзакции. Superadmin использует отдельный административный use case и сохраняет возможность исправления площадки.

## Проверка

- владелец не может открыть редактирование площадки с pending-заявкой;
- сохранение формы, открытой до отправки на модерацию, возвращает ошибку;
- после отклонения заявки редактирование снова доступно;
- superadmin может редактировать площадку с pending-заявкой;
- подтверждение заявки и площадки выполняется атомарно;
- порядок блокировок не создаёт встречный deadlock между update и moderation review.

## Результат

- добавлено доменное исключение `VenuePendingModerationException` с HTTP-кодом 409;
- обычные edit и update use cases запрещают работу при pending-заявке;
- проверка update выполняется после блокировки площадки внутри транзакции;
- moderation review блокирует площадку перед заявкой и атомарно подтверждает обе записи;
- listener подтверждения стал идемпотентным и не создаёт повторное обновление;
- superadmin продолжает редактировать pending-площадку через отдельный административный сценарий;
- тесты покрывают запрет открытия, запрет stale-save, восстановление доступа после rejection и superadmin-исключение.
