# 003 - Стабилизация текущего игрового runtime

## Цель

Получить проверенную исходную точку из накопленных изменений 083–085 до структурного рефакторинга.

## Статус

Выполнено для локального Event/Game-контура. Глобальный regression baseline зафиксирован отдельно.

## Работы

- инвентаризировать незакоммиченные изменения;
- отделить venue fixes, lifecycle, live, game_actions и seeders;
- проверить миграции, HTTP flow и JS build;
- закрыть обнаруженные регрессии без введения Tournament;
- определить, какие изменения переносятся в 086 без переписывания.

## Приёмка

- standalone game проходит create/start/live/end/confirm;
- состав с запасными подтверждается;
- live HTTP отображает текущие значения;
- область изменений зафиксирована отдельно от следующих этапов.

## Результат

- выполнены `migrate:fresh --seed`, `GameCreationSetupSeeder` и `GameLifecycleDemoSeeder`;
- миграция `game_actions` и оба демонстрационных набора данных проходят на чистой локальной БД;
- исправлено разрешение числового идентификатора Event в route binding;
- восстановлен доступ подтверждённого superadmin к управлению Event;
- актуализированы проверки после разделения публичного и управляющего UI;
- Event/Database-профиль: 49 тестов, 487 assertions — успешно;
- production frontend build — успешно;
- Reverb и VDS не использовались: live остаётся HTTP-first.

Полный набор на текущем накопленном baseline: 398 из 410 тестов проходят. Оставшиеся сбои не
относятся к Event/Game-срезу: пять `SiteSummaryTest` требуют отсутствующее в локальном PHP расширение
Redis, остальные находятся в ранее существующих Admin/Team/Coordination сценариях. Они не
маскируются и должны быть разобраны до Gate G; переход к нормализации Event/Game не зависит от них.
