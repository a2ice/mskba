# 341 - Единое правило добавления в избранное после авторизации

## Оригинальное описание

Единое правило добавления в избранное после авторизации. Требования владельца от 20.11.2026.

## Подробное описание

**Новое глобальное продуктовое правило (20.11.2026, целевое поведение):** в любом месте портала и для любого поддерживаемого типа сущности гость при попытке добавить в избранное сначала видит информационный попап «Избранное» с текстом «Для того чтобы добавить {сущность} в избранное, необходимо авторизоваться» и единственной кнопкой «Войти». Правильное склонение сущности. Строго существующий popup UI: без eyebrow, штатные крестик и иконка перемещения. Кнопка открывает штатную авторизацию. После успешного входа выполнить исходное добавление exactly once и показать штатный информационный попап успешного добавления (эталон — страница площадки). Отмена/ошибка входа не добавляет ничего. Авторизованный добавляет сразу; не менять согласованный сценарий удаления. Использовать общий action/intent, безопасный тип и ID, серверную авторизацию и идемпотентное add (не toggle). Проверить соцлогин/редирект и возврат, не сохранять секреты. Новое требование заменяет создание новых гостевых favorites из Task 294/337; не терять ранее сохранённые гостевые записи, сохранить корректный claim и автоматический PlayIntent площадки, счётчик, не создавать дублей и не менять ручные подписки. Сверить активные PR #854/#853. Обновить продуктовую и техническую документацию, закрепить глобальное правило по итогу. Проверить все точки входа и типы, Desktop/mobile/Telegram.

## Частичная реализация

Сервер запрещает новое гостевое добавление/восстановление, сохраняет удаление старых гостевых записей и claim. Добавлены idempotent add/remove и блокировка канонической записи пользователя при создании. UI и проверки пока в работе.

## UI и регрессии

Общий модальный сценарий гостевого добавления для поддерживаемых типов с возвратом после авторизации. Старый тест ожидал прежний toggle и открытие визарда подписки вместо информационного окна; обновлён под новый контракт и дополнен исполняемыми тестами отмены, входа и однократного replay. Нужен зелёный CI, production smoke и приёмка владельцем.
