# 184 - Мастер добавления площадки и пресеты логотипа команды

## Оригинальное описание

B0441: мастер добавления площадки по аналогии с мероприятием. Начальные сценарии — представитель площадки с последующим подтверждением полномочий документом либо добавление площадки в каталог.

B042: выбор логотипа из пресетов при создании команды.

## Подробное описание

Ветка `feature/184`, исходная `main` обновлена до `4423422d`. Номер 183 зарезервирован параллельной работой над Content/FAQ. Пользователь поручил реализацию и аккуратное слияние в `main`.

План:

1. Добавить выбор сценария перед существующей компактной формой площадки, переиспользовать компоненты мастера мероприятий и адресные подсказки. После создания оставить полное редактирование и показать представителю переход в существующий процесс подтверждения управления. Выбор сценария не выдает права и не заменяет проверку документов.
2. Добавить выбор из 15 существующих эмблем турниров в форму команды; валидировать идентификатор сервером и сохранять отдельный экземпляр через TeamLogoManager. Создание команды, owner-контракта и записи логотипа должно быть атомарным.
3. Проверить профильные сценарии создания и сохранения, сборку и адаптивный интерфейс. Обновить документацию и внешний backlog.
4. Перед merge повторно получить актуальную `origin/main`, сохранить параллельные изменения Content/FAQ, проверить объединенный результат.

## Статус

Выполнено. По прямому поручению пользователя реализация закоммичена в `feature/184` (`faff80a3`) и влита в актуальную `main` без конфликтов. Задача отмечена выполненной после merge. Визуальная проверка остается ограничением, указанным ниже.

## Результат

- Каноническая форма площадки стала двухшаговым мастером: сценарий и основные данные. Возврат назад не сбрасывает ответы; ошибки возвращают на нужный шаг; без JS остается обычная форма.
- Представитель после создания получает переход в существующий процесс подтверждения управления. Скан прикрепляется в переписке по заявке; выбор сценария не подтверждает права и не создает заявку автоматически.
- При создании команды доступны 15 существующих эмблем и вариант без логотипа. Пресет валидируется allowlist, сохраняется отдельным Media/WebP и может быть удален или заменен существующим способом.
- Команда, owner-контракт и запись логотипа создаются атомарно; ошибка файлового хранилища откатывает создание. Файлы при сбое очищаются компенсирующим действием, так как SQL rollback не откатывает хранилище.
- Документация обновлена через тематические раскрытия и ссылки из релевантных разделов; Content/FAQ и общая карточка справки переиспользуются без изменения их контура.

## Проверки

- 37 профильных тестов, 299 assertions: TeamLogoPresetTest, PublicVenueCreateEntryTest, TeamDraftAndCreationLimitTest, TeamMultipleSportRolesTest, CreationPageAccessTest, VenueOwnershipClaimWorkflowTest.
- Production build, Pint, `git diff --check` прошли. Сборка сохраняется в tracked `public/build` согласно текущей стратегии репозитория. Известные предупреждения сборки об отсутствующем home-court.png и крупных chunks не относятся к этой задаче.
- Проверены 263 локальные ссылки и якоря в измененных документах, 22 ссылки на ассеты из manifest.
- Визуальная desktop/mobile-проверка и проверка интерактивного мастера в браузере не выполнены: Browser runtime не обнаружил подключенных браузеров. Серверный рендер проверен профильными тестами.

## Координация

Перед подготовкой merge выполнен повторный fetch: `origin/main` оставалась на `4423422d`; параллельная `feature/183-content-faq-search` не слита. Изменения этой задачи не редактируют Content-модуль, FAQ-шаблоны, creation-guides config или общую карточку справки.
