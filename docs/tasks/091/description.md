# 091 - Показывать количество зрителей live-трансляции игры

## Оригинальное описание

На странице трансляции отображать, сколько сейчас её смотрит, и отдельно показывать количество авторизованных зрителей, например `10/25`, где 10 — авторизованные, 25 — все активные зрители.

## Подробное описание

Добавить независимый от счёта и статистики игры per-game presence. Один зритель определяется браузерной сессией, поэтому несколько вкладок одного браузера учитываются один раз. Heartbeat live-страницы продлевает присутствие в коротком временном окне и возвращает два значения: количество авторизованных зрителей и общее количество зрителей.

Presence хранится в Redis Sorted Set с cache fallback, не является доменной истиной и не должен делать live-страницу недоступной при отказе хранилища. UI показывает компактную подпись `N/M зрителей` с пояснением порядка значений. Клиент прекращает heartbeat в скрытой вкладке и обновляет данные после возвращения.

## Результат

Для каждой игры добавлен отдельный heartbeat аудитории. Браузерный fingerprint выступает идентификатором зрителя, поэтому повторный запрос и несколько вкладок одного браузера не увеличивают счётчик. Ответ содержит только агрегаты `authenticated` и `total`, без раскрытия состава аудитории.

Live-шапка после первого успешного ответа показывает `N/M смотрят` с tooltip «Авторизованные зрители / все зрители». Heartbeat выполняется раз в 45 секунд, останавливается для скрытой вкладки и возобновляется при возвращении. Redis Sorted Sets используются для атомарного production presence, cache store с lock — как совместимый fallback; ошибки presence не затрагивают игровой snapshot.

Дополнительно создан отдельный Analytics-контекст истории просмотров. Каждый непрерывный интервал просмотра хранит игру, nullable пользователя, обезличенный browser fingerprint, начало, последнюю активность и накопленное время. Возвращение после окна неактивности создаёт новую сессию. Журнал не включён в публичный API; будущий административный экран сможет агрегировать эти записи с отдельной проверкой прав.

После браузерной проверки окно продолжения исторической сессии увеличено до 180 секунд: оно намеренно чуть шире строгого online TTL, поскольку браузеры могут задерживать интервальные запросы. Уже записанные последовательные локальные сессии с разрывом до трёх минут безопасно объединены с восстановлением длительности между heartbeat.

В управление матчем добавлен сворачиваемый блок «Аудитория трансляции»: общие показатели, количество авторизованных зрителей и гостей, суммарное время, а также агрегированные сеансы вошедших пользователей. Гости остаются обезличенными. Блок доступен организатору, superadmin, ответственному с отдельным правом «Просматривать аудиторию трансляции» и ответственному турнира с правом управления играми.

После завершения или отмены игры клиент выполняет финальную синхронизацию и переводит live-экран в terminal state: отписывается от Reverb, останавливает fallback polling, heartbeat аудитории и reconnect-обработчики. Серверный audience endpoint не создаёт presence и историю для terminal Game, защищая систему от старых вкладок и клиентов.
