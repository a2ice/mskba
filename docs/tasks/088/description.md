# 088 - Добавить realtime toast-уведомления с контекстными действиями

## Оригинальное описание

Добавить адаптивные toast-уведомления, доставляемые через Reverb. Уведомление отображается в правом верхнем углу, содержит кликабельный текст для перехода к контексту, крестик для отметки как прочитанного и, когда применимо, кнопки доменного действия — например «Принять» и «Отклонить» приглашение в команду.

## Подробное описание

Нужно расширить существующий bounded context `Notification`, не создавая параллельную модель уведомлений. Сохранённый `UserNotification` остаётся источником истины и доступен в центре уведомлений, а toast становится ещё одним представлением нового in-app уведомления.

После сохранения уведомления сервер публикует безопасный presentation payload в приватный канал пользователя `users.{id}`. Клиент подписывается через общий Reverb/Echo adapter и показывает уведомление без перезагрузки страницы. При недоступном WebSocket сохранённое уведомление не теряется и остаётся доступным в центре уведомлений.

Текст toast, если у уведомления есть `action_url`, является ссылкой на связанный контекст. Отдельная кнопка «Просмотреть» в toast не выводится. Крестик вызывает существующий авторизованный use case отметки уведомления прочитанным, удаляет toast и обновляет счётчик новых уведомлений.

Контекстные кнопки не содержат произвольных URL и HTTP-методов в payload. Они формируются сервером из известного типа уведомления и вызывают специализированные авторизованные endpoints. Первая интерактивная реализация покрывает приглашение пользователя в команду: «Принять» и «Отклонить». Backend повторно проверяет получателя, актуальный статус приглашения и доменные инварианты; повторное или устаревшее действие возвращает безопасный результат.

Центр уведомлений использует тот же presentation-контракт: ссылка переносится на текст уведомления, а применимые действия отображаются кнопками. После принятия решения связанное уведомление помечается прочитанным, чтобы toast, центр и счётчик не расходились.

Toast-контейнер располагается поверх страниц справа сверху, учитывает safe area и ширину мобильного экрана, имеет ограниченное число одновременно показанных элементов и доступную семантику `aria-live`. Новые toast не должны перекрывать критичную навигацию и должны корректно работать в основной теме и Telegram Mini App.

## Результат

Добавлен единый presentation-контракт `UserNotification`, приватный канал `users.{id}` и realtime
событие `notification.created`. Основная тема и Telegram layout показывают адаптивные toast,
синхронизируют счётчик, открывают связанный контекст по заголовку, позволяют отметить уведомление прочитанным и выполнить безопасные действия
«Принять»/«Отклонить» для приглашения в команду. Центр уведомлений использует тот же каталог действий.

Недоступность Reverb не отменяет сохранение уведомления. Целевые PHP-тесты и production frontend
build проходят; остаётся ручная браузерная проверка доставки между двумя пользовательскими сессиями.
