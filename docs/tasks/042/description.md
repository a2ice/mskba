# 042 - Учитывать EXIF-ориентацию при загрузке аватара

## Оригинальное описание

Фотография с селфи-камеры после загрузки аватара отображается повёрнутой боком.

## Подробное описание

JPEG с мобильной камеры может хранить исходные пиксели без физического поворота, а правильное отображение задавать EXIF-тегом `Orientation`. До преобразования в WebP нормализатор должен применить к пикселям все восемь вариантов EXIF-ориентации, включая повороты и зеркальные отражения, и только затем вычислить итоговые размеры и выполнить уменьшение.

Production PHP-образ должен содержать расширение `exif`. После нормализации метаданные намеренно не переносятся: итоговый WebP уже физически ориентирован правильно.

## Проверка

- unit-тест JPEG с EXIF Orientation 6;
- feature-тесты загрузки аватаров;
- полный backend test suite;
- сборка Docker-образа и проверка расширений GD/WebP/EXIF;
- `git diff --check`.

## Результат

`WebpImageNormalizer` перед уменьшением читает JPEG EXIF Orientation и применяет соответствующий поворот/отражение к пикселям. После преобразования итоговый WebP уже имеет правильную физическую ориентацию и не зависит от EXIF. Docker-образ дополнен расширением `exif`.

Проверки пройдены:

- unit-тест EXIF Orientation 6 внутри production-подобного PHP-контейнера: 1 тест, 6 assertions;
- полный backend test suite: 195 тестов, 1124 assertions;
- frontend production build;
- пересборка Docker-образа и runtime-проверка: GD, WebP и EXIF доступны;
- `git diff --check`.
