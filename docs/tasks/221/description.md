# 221 — Предикативный выбор получателя перевода с учётом приватности

## Оригинальное описание

На форме перевода бонусов заменить свободный ввод получателя на стандартный
предикативный поиск пользователей, уже используемый в других частях проекта.

Видимость кандидатов должна определяться существующей настройкой приватности
«Видимость в поиске».

## Реализация

- переиспользуется `theme::partials.forms.entity-predictive-search`;
- endpoint `GET /account/wallet/transfer-recipients?q=...`;
- поиск по имени, логину и никнейму;
- минимум 2 символа, максимум 10 результатов;
- sender и alias его canonical identity исключаются;
- показываются только подтверждённые пользователи;
- Identity `DISCOVERABILITY` остаётся source of truth:
  - `Всем` — пользователь доступен;
  - `Определённым пользователям` — доступен только указанным viewer;
  - `Никому` — отсутствует в выдаче;
- POST перевода принимает выбранный `recipient_user_id`;
- backend повторно проверяет discoverability выбранного id, поэтому privacy
  нельзя обойти ручной подстановкой id;
- поиск по nickname добавлен в общий `SearchDiscoverableUsers`, поэтому
  поведение становится единообразнее и для других predictive user pickers.

## Не меняется

- переводятся только bonus-средства;
- получатель должен быть подтверждённым и не заблокированным;
- self-transfer запрещён;
- notification/toast получает только принимающая сторона;
- ledger/idempotency Task 218 не меняются.

## Проверка

- поиск находит пользователя по nickname;
- `DISCOVERABILITY=NOBODY` скрывает пользователя;
- `SELECTED_USERS` показывает кандидата только разрешённому viewer;
- crafted POST со скрытым recipient id не выполняет перевод;
- UI использует общий predictive component;
- полный CI + frontend build.
