# 331 — Расписание по залам, корректные попапы и возврат после авторизации

**Среда:** production (`main`) после успешного CI и подтверждённого deploy.

## Изменения

- На общей странице площадки блок «Расписание» содержит отдельные группы для каждого зала/корта: название, дни, собственные часы работы и собственные проценты занятости. На странице зала только его расписание.
- Нажатие даты из группы открывает существующий диалог бронирования уже с `venue_court_id` выбранного зала. Отображаемые в диалоге остальные даты и занятость соответствуют этому залу. При смене зала сбрасывается прежний ответ и выбор, а сервер по-прежнему определяет реальные слоты/цены.
- Обновление показателя занятости после получения внешнего расписания меняет только соответствующий зал, не соседние группы.
- Раскрывающийся диалог выбора действия и диалог избранного открываются по центру viewport. Верхняя панель и кнопки действий видны даже на коротких экранах; длинный контент прокручивается внутри.
- Из диалога избранного можно вернуться к первому выбору кнопкой «Назад».
- Гость сначала проходит штатный вход/регистрацию. Состояние намерения сохраняется на короткий срок, после inline-авторизации или перехода обратно на эту страницу показывается именно **подтверждение** избранного, без автоматического сохранения.

## Проверки

- Два зала с различными рабочими часами и занятостью; один зал на отдельной странице.
- Внешняя интеграция, открытие дней и отсутствие «перетекания» данных между залами.
- Раскрытие «Аренда» на компактной высоте, центрирование, возврат из избранного.
- Гость → вход inline / регистрация с возвратом → подтверждение избранного. Отмена входа не сохраняет избранное.
- Релевантные Feature/JS-тесты, сборка фронтенда, GitHub Actions, production deploy.

**Статус:** реализация в PR; после зелёного CI и merge требуется контроль production deploy и ручная визуальная приёмка.
