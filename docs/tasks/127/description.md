# 127 - Номер игрока в составе команды

## Оригинальное описание

Добавить игрокам в рамках конкретной команды nullable integer-поле номера игрока в диапазоне `0–999`. Номер должен принадлежать именно связи пользователя с командой, потому что один игрок может выступать под разными номерами в разных командах.

Отображение выполняется минимум в двухзначном формате: `0` → `00`, `1` → `01`, `9` → `09`, `77` → `77`; трёхзначные номера отображаются без дополнения, например `777` → `777`.

Дополнение после проверки на production: у активных участников одной команды не могут быть одинаковые non-null номера. Это относится и к `0` (`00`). Один и тот же номер по-прежнему может использоваться в разных командах.

## Подробное описание

Номер хранится в `contract_memberships.jersey_number`, то есть в существующей сущности командного membership, а не в профиле пользователя. Поле nullable, целочисленное; HTTP-валидация разрешает только значения от `0` до `999`.

Редактирование встроено в существующий flow управления спортивными данными участника команды. Публичные и управленческие карточки игрового состава используют единое форматирование номера через `ContractMembership::formattedJerseyNumber()`.

Уникальность проверяется внутри транзакции обновления спортивных данных после блокировки строки команды. Конфликт ищется среди других принятых membership этой команды с активным контрактом. Поэтому номер освобождается после прекращения активного участия, а параллельные обновления одной команды через этот flow не могут одновременно занять один номер.

## Результат

- добавлена nullable-колонка `jersey_number` в `contract_memberships`;
- добавлена валидация диапазона `0–999`;
- номер сохраняется вместе со спортивными данными membership;
- в интерфейсе управления участником добавлено поле номера;
- в игровых составах номер показывается рядом с ролью/капитанством;
- значения `0–9` отображаются с ведущим нулём, трехзначные остаются без изменений;
- одинаковый non-null номер, включая `0`, нельзя сохранить двум активным принятым участникам одной команды;
- одинаковые номера в разных командах разрешены;
- при конфликте пользователь получает понятное сообщение, например `Номер №00 уже занят другим участником команды.`;
- добавлены feature-тесты на разные номера одного пользователя в разных командах, повторное использование номера между командами, форматирование, nullable, границы диапазона и конфликт `00` внутри одной команды;
- актуализирована техническая документация по спортивным данным membership.
