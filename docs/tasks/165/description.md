# Task 165 — Полировка выбора зала и фотографии залов

## Контекст

Task 164 сделал `VenueCourt` публичным контекстом страницы площадки, но первая production-проверка выявила два UX-недочёта: название текущего зала в обычном `<select>` занимает слишком много места в heading, а карточка «Количество залов» повторяет тот же громоздкий control. После появления нескольких физических залов также стало необходимо хранить отдельные фотографии каждого зала.

## Цель

Сделать выбор зала компактным и единообразным, освободить heading от длинного названия зала и добавить отдельную галерею `VenueCourt` с безопасным fallback на фотографии родительского `Venue`.

## Публичный UI выбора зала

- убрать длинный `<select>` из heading;
- компактный badge с количеством залов разместить поверх hero-фотографии сразу после badge типа площадки;
- при нескольких залах badge открывает общий modal «Выбор зала»;
- полные названия залов отображаются внутри modal, текущий зал выделен, основной отмечен badge `Основной`;
- primary court ведёт на canonical `/venues/{venue}`, остальные — на `/venues/{venue}/courts/{court}`;
- карточка «Количество залов» в блоке характеристик остаётся первой, показывает число и компактный trigger `Выбрать зал`, открывающий тот же modal;
- использовать гарантированно существующую иконку `ti-layout-grid` вместо отсутствующей в текущем icon set `ti-building-arena`.

## Статус работы площадки

В overlay hero оставить только цветной bullet статуса `Открыта/Закрыта`. Текст визуально скрыть, а значение показать через обычный title-style floating tooltip проекта:

- без знака вопроса;
- без подчёркивания;
- состояние остаётся доступным для клавиатуры и screen reader через `aria-label`.

## Фотографии конкретного зала

`VenueCourt` получает polymorphic relation к существующему `Media` через morph alias `venue_court`.

Для каждого зала на `/account/venues/{venue}/courts`:

- можно загрузить до трёх JPEG/PNG/WebP до 5 МБ;
- изображение нормализуется в WebP с максимальной стороной 500 px, аналогично галерее площадки;
- можно выбрать основное фото и удалить фото;
- mutations доступны только пользователю с правом управления площадкой и имеют throttle, аналогичный venue gallery;
- файлы хранятся в `venues/{venue_id}/courts/{court_id}/...`.

### Public fallback

При рендере публичной страницы:

1. если у выбранного `VenueCourt` есть хотя бы одна фотография collection `gallery`, hero/gallery используют только фотографии этого зала;
2. если у выбранного зала своих фотографий нет, используется существующая gallery родительского `Venue` без изменений;
3. правило одинаково для primary и non-primary court.

## Совместимость

- не менять court-aware occupancy, activities, booking и Event Wizard из Tasks 163/164;
- не ослаблять privacy rules Event;
- сохранить warning достоверности Task 161;
- не создавать отдельную медиасистему: переиспользовать `Media`, `WebpImageNormalizer` и существующий image-upload UI pattern;
- существующие площадки и залы без отдельных фото продолжают показывать старые фотографии Venue.

## Acceptance criteria

- в heading больше нет длинного select с названием зала;
- поверх фото после типа площадки отображается компактный badge `N зал/зала/залов`;
- статус работы визуально представлен только цветным bullet с title-style tooltip;
- оба public trigger выбора зала открывают один modal и сохраняют корректный routing;
- карточка «Количество залов» имеет рабочую иконку `ti-layout-grid`;
- владелец может добавить/выбрать основным/удалить фото конкретного зала;
- максимум три фото и нормализация изображения покрыты regression test;
- hall gallery переопределяет Venue gallery, а пустая hall gallery корректно наследует Venue gallery;
- чужой пользователь не может управлять фотографиями зала;
- PHP tests, frontend build, CI и production deploy зелёные.
