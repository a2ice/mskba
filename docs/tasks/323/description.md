# 323 — Самостоятельная предзаявка на аренду

## Оригинальное описание

Восстановить согласованный standalone VENUE RENTAL PRE-REQUEST / PREBOOKING flow
на отдельной ветке от dev с PR #735 и #736: без обязательного Event, с постоянной
перепиской, предложением обычной брони от представителя и согласием клиента.
Production запрещён. По последнему указанию пользователя commit/push/PR/merge
выполняет supervisor после review.

## Подробное описание

- Предзаявка хранит клиента, площадку, зал, время, область, комментарий,
  idempotency key и статус active/resolved/withdrawn. Ничего не резервирует.
- Отдельная запись интереса выбрана вместо фиктивного Event и вместо нового
  типа бронирования. Предложение создаёт обычный rental VenueBooking для клиента
  с pre_request_id и created_by_representative_id (Actor).
- Один разговор сохраняется после отказа, нового предложения и переходов брони.
  Сообщения и приватные вложения используют существующие таблицы переписки.
- Просмотр, переписка и предложение используют отдельные Contract ACL. Простое
  назначение выбранным агентом прав не даёт. Согласие клиента обязательно до hold.
- Quote создаётся заново при предложении для клиента; после согласия работают
  существующие hold, payment, confirmation, cancellation, outbox и conflict engine.
- UI использует действующие компоненты обеих тем; Filament сохраняет группу
  «Заявки» и прежние панели, добавляя самостоятельные предзаявки.

Контракт: [спецификация](../../specification/venue-rental-pre-requests.md).
UI: [компоненты и ручная приёмка](../../mskba_app/tasks/venue-rental-pre-request/description.md).

## Статус и проверка

Реализация находится в рабочем дереве ветки
`feat/standalone-venue-prebooking-20261116`; задача не отмечена завершённой.
База: f27ad7e6 (#736), предшествующий 8fa65c15 (#735). Внешние ../AGENTS.md
и ../backlog/todo.md в предоставленном workspace отсутствуют.

Добавлен VenueRentalPreRequestTest: отсутствие Event/hold/payment, идемпотентность,
повторное предложение, consent и отказ, истечение срока и запоздалая задача,
конкурирующие клиенты одного слота, права чтения/переписки/предложения,
superadmin, зал другой площадки, приватные файлы, актуальная клиентская цена и
неизменяемый snapshot в обычном платёжном окне.

Локально проходят PHP syntax lint (31 файл), git diff --check, проверка новых
документационных ссылок, literal route names и пар директив новых Blade-страниц.
Composer install не смог
записать скачанные архивы зависимостей (Permission denied), npm ci завершился
ошибкой `Exit handler never called`. Зависимости изначально отсутствовали;
PHPUnit, Pint, Vite build и визуальная проверка приложения не выполнены.
Прямой `npm run build` подтверждает отсутствие vite. Профильные Node-тесты
venue-rental-review / venue-day-booking проходят: 10/10. Для запуска в sandbox
Windows использованы `--preserve-symlinks --preserve-symlinks-main`, чтобы Node
не обращался к метаданным недоступного родительского пользовательского каталога.
Ни .env, ни секреты не читались. CI, commit, push и deploy не запускались.
Удаление собственных временных файлов проверки отклонено автоматической
политикой (`blocked by policy`), включая повтор с проверенным literal path.
Остались `.validation/` и временные php*.tmp / sf_proc_00.* от Composer в корне;
это не файлы feature, их не следует включать в commit. Частичные каталоги
зависимостей не означают успешную установку.

До release обязательны профильные PHP-тесты (включая существующие event-first,
special terms и Filament), сборка и desktop/mobile UI review. Проверка двух
клиентов в тесте последовательная; настоящие параллельные транзакции на целевой
СУБД остаются отдельным обязательным integration gate, результат не заявляется.
