# 299 — Промокоды и специальные предложения для группы: выпуск, управление, доставка

## Цель
Владелец или уполномоченный администратор площадки может создать и передать **в конкретную группу интересов** промокод на скидку при будущей брони этой площадки. Поддержать ограниченные сроком и **бессрочные** коды. Группа видит предложение, но сам факт публикации ещё не изменяет quote или цену бронирования (Task 300).

## Правила выпуска
- Scoped авторизация по конкретной площадке и праву управления коммерческими предложениями. Не любой «организатор игры» может назначить цену зала.
- Структура: `venue_id`, `interest_group_id`, автор, уникальный нормализованный код (хранить безопасно), название/описание и условия, `status = draft/active/paused/revoked`, валюта, тип скидки (проценты либо фиксированная сумма в minor units), величина, `valid_from`, nullable `valid_until` («бессрочно»), scope зала/части, допустимые даты/окна бронирования, ограничения минимальной суммы, число использований в целом/на аккаунт (если включено).
- Нулевые/отрицательные скидки, процент вне диапазона, mismatched currency/venue, дата окончания раньше начала и небезопасный объём использования недопустимы. Бессрочный код не означает неизменяемый: владелец может паузить/отзывать.
- Справочник статусов и прозрачная история изменений, версионность условий, UTC для технических сроков + timezone площадки для показанных дат.
- В MVP **только одна скидка на одну бронь**; отсутствие стэкинга с другими промо, бонусами и ручными скидками до отдельной согласованной ценовой политики.
- Отдельные валидации code uniqueness и прав при создании/редактировании/публикации/отзыве; нельзя менять размер уже применённой скидки задним числом.

## Публикация в группу
- Страница Task 297 содержит видимый участникам разрешённый раздел «Предложения», управляющим — «Создать промокод» и историю.
- Отправка группе не является SMS/email/Telegram-маркетингом по умолчанию. Внешняя доставка — **только с отдельным согласием** на коммерческие сообщения и частотными ограничениями из Task 288.
- Для неавторизованных и приватных подписчиков не раскрывать персональные данные, target IDs и статистику чужих применений; пользователь может увидеть доступное предложение без автоматического оформления брони.
- При отписке/удалении подписки возможность последующего использования решается серверной политикой: предлагаемое правило первой версии — проверять **активное членство в группе на момент применения**, а не считать публикацию бессрочным правом. Обязательная фиксация этого правила в UI.
- Промокод действует **только** для выделенной группы/площадки; отправка другой аудитории не делает его общедоступным.

## Приёмка
Срок/бессрочность, пауза/отзыв, ограничения по venue/court/date/user, приватность, role-based authorization, аудит и антиспам, честная маркировка условий. Test fixtures для скидок; без внедрения расчёта в frontend. **Цена/бронирование — Task 300.**

**Связано:** 288 (спецпредложения), 297 (страница группы), 298 (рабочие процессы). **Статус:** запланировано.

## Уточнение архитектуры: административная и публичная страницы

Управление промокодами вынесено в отдельный раздел аккаунта площадки:
`/account/venues/{venueId}/group-offers`. Создание, публикация, пауза, отзыв и история условий доступны владельцу либо администратору данной площадки (активное membership владельца/админа), или пользователю с **явно делегированным правом** `venue.group-offers.manage`. Права другого зала/площадки не распространяются на этот раздел, а снятие membership закрывает доступ.

Страница `/venues/{venueId}/interest-group` только показывает опубликованные актуальные предложения участнику группы, не показывает панели редактирования, статусы черновиков и чужие коды. Плашка предложений скрывается при отсутствии доступных активных предложений. Для каждого кода предоставляется копирование в буфер обмена; реальное применение скидки при бронировании остаётся №300.

Не смешивать отдельное разрешение управления промокодами с правом менять ценовую политику аренды.
