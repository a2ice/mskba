# 002-03 — Видимая область диалога, компактные карточки и логотип

2026-09-06 · **0.1-draft, ревизия 3** · `feature/139`, без commit.
URL: http://127.0.0.1:8013/. Chrome 152.0.7977.82, Playwright.
Рабочая тема/маршруты/PHP не менялись; добавлена уменьшенная копия брендового asset.

## Почему повторная проверка

Пользователь повторно показал обрезание диалога из «Хочу играть», лишнюю высоту
media-card и тонкий шов фото; предоставил `public/images/logo-image.png`.
Предыдущие результаты resize-тестов не гарантировали работу в его окружении.

Воспроизведён аналогичный дефект при увеличении **visualViewport**: layout
390×620, visible viewport при scale 2 — 195×310, а старый диалог оставался
337.5×529 и уходил за видимую область. Отдельно CSS zoom 2 давал ширину диалога
1120 px при окне 768 px. Точный масштаб/режим браузера пользователя неизвестен;
не утверждается, что его среда идентична эмуляции.

## Исправления

1. Диалог позиционируется по visualViewport (центр, размеры и offset), учитывает
   эффективный CSS zoom. Пересчёт при открытии/resize/scroll через animation frame.
   Лимиты 95% высоты и 90% ширины относятся к **видимой области**. При очень малой
   области compact padding сохраняет действия и close; body прокручивается отдельно.
2. Media-card: 16:9 вместо 16:10, общий overlap body 56 px, интервалы 8/8/16 px,
   без растяжения до соседней промокарточки. Badge перенесён наверх, чтобы не
   пересекался с поднятым текстом. Градиент закреплён `bottom:0` внутри фото,
   последние 2 px фото маскируются до фона. ResizeObserver меняет только высоту
   градиента (25% → 35% карточки), не координату его нижнего края и не layout.
3. Пользовательский исходник 1536×1024 не изменён. Уменьшенная копия
   `public/images/logo-mark-100.png`: **98×100 px**, PNG с прозрачностью,
   21 278 bytes; отображается высотой 40 px в header/footer. UI-иконки Tabler
   не менялись. Исходник и производный asset относятся к запросу пользователя;
   автоматически не коммитились.
4. CSS/JS URL содержат ревизию `002-03`, футер явно помечен ревизией 3.

## Проверки диалога

Открытие — **именно кнопкой «Хочу играть» после прокрутки**, не только аватаром.

| Layout / режим | Видимая область | Диалог | Отклонение центра X/Y |
| --- | --- | --- | --- |
| 390×620, обычный | 390×620 | 351×509 | 0 / 0 |
| 390×620, visual scale 2 | 195×310 | 175.5×294.5 | 0 / 0 |
| 768×1100, CSS zoom 2 | 768×1100 | 691.20×1045 | 0 / 0 |
| 390×620, CSS zoom 1.25 | 390×620 | 351×575 | 0 / 0 |
| 320×568, обычный | 320×568 | 288×461 | 0 / 0 |
| 844×390, landscape | 844×390 | 560×370.5 | 0 / 0 |
| 1440×900, обычный | 1440×900 | 560×461 | 0 / 0 |

Во всех строках все три кнопки внутри видимой области; ширина ≤90%, высота ≤95%.
При длинном DOM stress-контенте footer не сдвигается при scroll body.
Tab: body → cancel → confirm → close → body, Esc возвращает focus на «Хочу играть».
Stress-контент и zoom добавлялись только для проверки, после проверки сброшены.

## Карточки и ресурсы

- Ширины 320/360/390/639/640/768/1023/1024/1440: root overflow и выходы
  элементов main за viewport не обнаружены.
- При 390 px высота карточки **409.13 → 315.81 px** (−93.32 px).
  При 1440 px после отключения растяжения соседним promo — **364.88 px**.
- Hover и reduced motion проверены; layout не меняется при усилении градиента.
- Пиксельные пробы около стыка фото на масштабах 100/125/200%: по двум боковым
  колонкам внутри рамки, четыре строки вокруг стыка — только **RGB(20,22,24)**,
  точный `--surface`. Это проверка выбранных точек, не заявление о всех пикселях
  при произвольном browser/device scale. Снимки также просмотрены визуально.
- Логотип: natural size 98×100, displayed 39.20×40, прозрачность сохранена.
- Console/page errors, failed requests, HTTP ≥400 в наблюдаемом прогоне отсутствуют.
- JS syntax, диагностика редактора, локальные ссылки и PNG проверяются перед показом.
  PHPUnit/Vite не требуются для статического стенда и не запускались.

## Границы проверки и приёмка

CDP visual scale (аналог pinch) и CSS zoom — разные проверки, ни одна не выдаётся
за настоящий Cmd+ браузерный zoom или запуск в пользовательском VS Code WebView.
Safari/Firefox, iOS/Android, экранная клавиатура, Telegram и системный select
остаются непроверенными в реальных средах. Размеры адаптируются при visualViewport
events, но это ещё не проверка всех особенностей WebView.

На момент технического прогона требовалась повторная приёмка; её результат ниже.
Ранее сохранённые [002-01](002-01.md) и [002-02](002-02.md) остаются историей,
не подтверждают текущую ревизию автоматически.

## Приёмка 2026-09-06

Пользователь проверил ревизию 3 в Chrome device emulation с **Fit to window**:
iPad Air 820×1180 / 1180×820 и iPhone 12 Pro 390×844 / 844×390.
На предоставленных снимках диалог целиком помещается в виртуальном экране,
центрирован; в landscape footer остаётся видимым при прокрутке body.
Подтверждение пользователя: **«получилось»**. Остальное оформление ранее оценено
положительно. Шаг 002 принят, версия гайдлайна — **1.0**.

Последнее наблюдаемое обрезание при device emulation 100% объяснялось тем, что
виртуальный экран не помещался в физическую область DevTools. Fit to window
показал весь viewport без изменения кода. Это отличается от отдельно воспроизведённых
выше CSS/visual zoom случаев. Гипотеза об ошибочной высоте VS Code не подтверждена.
Для дальнейших проверок эмуляции сначала убедиться, что виден весь экран устройства.

Это пользовательская проверка эмуляции, не реальных iPad/iPhone или Telegram.
Перечисленные ограничения сохраняются. По согласованному процессу выполняется
отдельный commit 002 без push; общая задача 139 остаётся открытой до merge.
