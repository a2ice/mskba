# 003 — Архитектура Vue и стратегия перехода

## Цель
Согласовать SPA-подобное поведение без поломки существующего Laravel-приложения.

## Описание
- Сравнить Vue + Inertia, Vue islands в Blade и отдельный SPA + API; оформить ADR.
- Утвердить alias, директории, изоляцию CSS/JS, маршрутизацию, preview и rollback.
- Определить переходы на legacy-экраны: существующий resolver не даёт наследования.
- Описать page props/DTO, перенос запросов из Blade в подготовку данных,
  session auth, CSRF, validation/redirects, flash, permissions и безопасную сериализацию.
- Определить SEO/первоначальный HTML, lazy-loading, lifecycle подписок, аналитику,
  Telegram, browser history, scroll и сохранение формы. Не создавать вторую доменную логику.
- Для отложенного Mini App проверить legacy-тему по Telegram-контексту, auth/deep
    links и переходы; предусмотреть safe-area, dynamic viewport и адаптер SDK/BackButton.
    Если отложенный перенос создаёт существенную переделку, согласовать изменение плана.
- Зафиксировать измеримые бюджеты загрузки/переходов и способ их проверки.

## Статус
На согласовании. Пользователь разрешил начать 003 после приёмки 001 и 002;
2026-09-06 подготовлен архитектурный черновик. Приложение не изменено,
зависимости не устанавливались, сборки и runtime-проверки не запускались.

## Критерии приёмки
Архитектура и переходный режим согласованы; определены контракты, риски, проверки
и безопасный способ разработки без глобального включения неполной темы.

## Результат выполнения
Подготовлено [архитектурное предложение / ADR-139-003](../architecture.md):
сравнение вариантов, request-scoped переходный режим, preview/rollback,
page props, auth/validation, SSR, lifecycle, Telegram и измеримые бюджеты.
Проверены исходники ключевых точек интеграции и официальные контракты Inertia.
Рекомендация Vue + Inertia + SSR, alias и TypeScript ещё не приняты.
Отдельные gate: интеграция актуального main по разрешению пользователя,
проверка совместимости пакетов и Node 22+ для Inertia 3 SSR; foundation spike
предлагается в начале 004. Совместимость Mini App на устройствах не доказана.
После приёмки устойчивые решения переносятся в техническое раскрытие со ссылкой
из `docs/specification.md`. Коммит — после явной приёмки, без push/merge.
