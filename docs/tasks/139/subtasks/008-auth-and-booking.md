# 008 — Формы, авторизация и бронирование

## Цель
Применить единый дизайн к полноценному пользовательскому действию с серверной валидацией.

## Описание
Перенести необходимые для выбранного flow вход/регистрацию и возврат после входа,
выбор времени/зоны, расчёт, отправку заявки, подтверждения и статус бронирования.
Использовать текущие auth/booking use cases и условия оплаты. Состав экранов
коммерческой стороны уточнить по матрице 001, без молчаливого исключения из доступа.
Проверить CSRF, истёкшую сессию, двойную отправку, занятый слот, устаревший расчёт,
pending/error/success, доступные способы входа и согласия пользователя.

## Статус
Запланирована. Зависимость: 007.

## Критерии приёмки
Сквозной сценарий проходит на тестовых данных без реальных платежей и рассылок.
Каждая форма и состояние приняты визуально; ошибки расположены по гайдлайну.
Контрактные проверки защищают авторизацию, цену и целостность бронирования,
не дублируя существующее покрытие. Несохранённые данные не теряются молча.

## Результат выполнения
Не выполнено. Перед реализацией уточнить отдельный список форм и состояний.
