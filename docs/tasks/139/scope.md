## Фактическая инвентаризация

2026-09-06 выполнен `php artisan route:list --json` внутри `phpfpm`.
Найдено 136 GET-маршрутов. Это не 136 экранов: присутствуют JSON, download,
auth callbacks, служебные URL и legacy redirects. Сверены группы шаблонов в
`resources/themes/mskba_dark/views/pages`. POST/PUT/DELETE-контракты и поведение
каждого маршрута предстоит проверить в 003 и соответствующем предметном этапе.

## Приоритетные пользовательские сценарии

1. Гость открывает главную → находит площадку → просматривает сведения.
2. Выбирает условия аренды → входит при необходимости → возвращается к действию →
   отправляет заявку → видит статус; управляющий обрабатывает её разрешённым способом.
3. Находит мероприятие/команду/турнир → знакомится с условиями → подаёт заявку.
4. Организатор управляет составом и ходом игры, зритель получает live-обновления.
5. Пользователь открывает уведомление/deep link и попадает в нужное состояние экрана.

## Принятые решения и оставшиеся вопросы

1. Публичную часть и аккаунт переносим, админку оставляем на старой теме.
2. Новый UI Mini App можно отложить, если это не создаёт проблем позднее.
   В 003 проверить сохранение Telegram-контекста, текущих deep links и авторизации,
   предусмотреть safe-area/dynamic viewport и адаптер BackButton/SDK, не привязывать
   бизнес-компоненты к браузерному header. Старый Mini App остаётся работоспособным.
   Отложен перенос UI, а не проверка совместимости. Если сохранить совместимость
   без существенной переделки не получается — вернуться к пользователю до реализации.
   Полная приёмка нового UI в WebView состоится на отдельном этапе; обещать отсутствие
   любых будущих доработок до архитектурной проверки нельзя.
3. Исходников презентации нет. Не ждать их для завершения 001: вложения — ориентир,
   необходимые assets запрашивать заранее по [спецификации](references.md).
4. Браузерная матрица остаётся предложением; доступ к устройствам и версии указать
   при фактической проверке. Архитектурные ограничения проверяются в 003.

Владельцы следующих решений: 002 — точные визуальные правила и breakpoint;
003 — архитектура Inertia/альтернативы, alias, полная маршрутизация и совместимость
Mini App; 007–010 — постраничная проверка предметных контрактов и ролей;
011 — итоговое покрытие браузеров/устройств и допустимые ограничения релиза.
Перед каждым этапом решения согласуются с пользователем. MCP доступен,
снимки сохранены; открытых блокеров подключения браузера нет.
