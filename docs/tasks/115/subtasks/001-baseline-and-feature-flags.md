# 001 — Regression baseline и feature flags

## Цель
Зафиксировать поведение существующих броней и подготовить безопасное поэтапное включение нового flow.

## Статус
Выполнена в `feature/115`, ожидает коммита вместе с очередной согласованной порцией задачи.

## Доменные изменения
Нет. Описываются legacy-состояния, точки входа и инварианты совместимости.

## Миграции
Нет; отдельно проверить применимость будущих миграций на копии production schema.

## Handlers и сервисы
Добавить конфигурационные переключатели `rental_flow`, `coordination`, `external_payment`, `attendance_v2` с безопасным значением `false`.

## Права
При выключенных флагах сохраняется текущая авторизация без новых обходных путей.

## UI/API
Новые маршруты скрыты и возвращают предсказуемый `404/feature_disabled`.

## События и jobs
Новые listeners/jobs не запускаются до включения соответствующего флага.

## Тесты
Снимок маршрутов, smoke-тесты текущего создания Event/брони, проверка выключенных флагов.

## Обратная совместимость
Обязательна: существующие записи и интерфейсы работают без преобразования.

## Критерии приёмки
- baseline воспроизводим в CI;
- каждый этап можно включить и откатить независимо;
- выключенные возможности не меняют production-поведение.

## Результат выполнения

- добавлены четыре независимо управляемых флага с безопасным значением `false`;
- добавлены typed API `FeatureFlags` и middleware `venue-rental-feature`, пригодные
  для HTTP, handlers, listeners и jobs следующих подзадач;
- JSON-клиент выключенного маршрута получает `404` и
  `code=feature_disabled`, обычный web-клиент — стандартный `404` без раскрытия
  существования возможности;
- зафиксирован snapshot ключевых legacy entry points Event, Coordination,
  Venue Search и турнирного планирования;
- существующие smoke-тесты подтверждают создание `Event` вместе с
  `CONFIRMED/PENDING` бронью и геометрию конфликтов половин площадки;
- миграций в подзадаче нет; проверка будущих миграций на копии production schema
  остаётся обязательной перед подзадачами, которые начнут менять booking schema.

Проверка: 7 тестов, 86 assertions — feature flags, route snapshot и выбранный
legacy Event/booking baseline.
