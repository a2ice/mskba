# 115 - Добавить основу игрового персонажа в профиль игрока

## Оригинальное описание

В настройках роли игрока `/account/participation/player` нужно начать UI-фундамент геймификации профиля. Блок «Характеристики игрока» должен показывать будущего игрового персонажа в физическом масштабе и оставаться удобным на desktop и mobile.

## Подробное описание

- разделить содержимое блока «Характеристики игрока» на две responsive-колонки;
- слева разместить сцену будущего `Player Character`, справа — существующие поля роста, веса, сложения, опыта и амплуа;
- сцена представляет физическую область 200 × 250 см с метрической сеткой, шкалой высоты до 250 см и отметкой текущего роста игрока;
- на первой итерации не выбирать конкретный renderer и не добавлять растровые ассеты персонажей: использовать нейтральную полноразмерную заготовку;
- высота заготовки должна масштабироваться относительно введённого роста, а данные сцены обновляться сразу при изменении полей формы;
- сцена должна иметь renderer-agnostic data contract для будущего визуального конструктора: `gender`, `height`, `weight`, `body-type`, `skin-tone`, `hairstyle`;
- `skin-tone` и `hairstyle` пока зарезервированы в контракте со значением `default`; отдельное хранение и UI выбора появятся вместе с настоящим конфигуратором;
- будущий renderer может быть layered PNG/WebP, SVG, canvas либо JS-векторным, поэтому текущая задача не должна связывать модель с конкретным графическим форматом;
- существующий фото-аватар профиля не использовать как игровой персонаж;
- на экранах до 760px колонки должны переходить в `column`: сначала сцена персонажа, затем параметры;
- существующий backend сохранения `PlayerProfile`, объективные показатели и самооценку не менять.

## Технический контракт будущего renderer

Сцена публикует текущую конфигурацию через `data-*` атрибуты и событие `player-character:change`. В detail события должны быть доступны как минимум:

- `gender`;
- `heightCm`;
- `weightKg`;
- `bodyType`;
- `skinTone`;
- `hairstyle`.

Это позволит позже заменить placeholder отдельным renderer без переделки формы характеристик.

## Проверка

- feature-тест страницы игрока проверяет наличие stage и renderer-agnostic data contract;
- существующие `AccountPlayerProfileTest` должны продолжать проходить без изменения HTTP/DB-контракта;
- `npm run build`;
- `php artisan view:cache` либо эквивалентная проверка Blade;
- ручная проверка desktop/mobile после merge и автодеплоя.

## Результат

- блок характеристик подготовлен под `Player Character` без изменения схемы БД;
- добавлена физическая сцена 200 × 250 см с метрической сеткой и live-отметкой роста;
- существующие параметры и амплуа собраны в правой колонке;
- добавлен нейтральный полноразмерный placeholder, масштабируемый по росту и слегка учитывающий выбранное телосложение;
- создан renderer-agnostic frontend contract с резервом для пола, цвета кожи и причёски;
- мобильная версия складывает сцену и форму в одну колонку.
