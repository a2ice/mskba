# Задача 335: самостоятельное восстановление soft-deleted аккаунта

## Сценарий
После DELETE /account или DELETE /api/v1/me автоматически отзываются все Bearer-токены. Для восстановления авторизация удалённого пользователя невозможна. Поэтому добавлены два публичных endpoint без Bearer: POST /api/v1/account/restore/request и POST /api/v1/account/restore/confirm.

## Защита
- Восстановление доступно только для аккаунта, удалённого самим пользователем, по server-side маркеру self_deleted_at. Административно удалённый или заблокированный аккаунт этим API не восстанавливается.
- В этой версии поддерживаются ранее подтверждённые email-контакты. SMS/Telegram восстановление — отдельная интеграция доставки.
- Код из 6 цифр отправляется на подтверждённый email, действует 10 минут, не более 5 попыток, не более 3 писем в час на контакт, минимум 60 секунд между письмами.
- Ответ запроса кода одинаков для существующего и несуществующего аккаунта, без перечисления пользователей.
- Проверяется уникальность принадлежности email одной canonical identity, идентификаторы пользователя извне не принимаются.
- Восстанавливаются исходный canonical user и его aliases без нового аккаунта, не выдаются новые токены; после восстановления требуется обычный login.
- Используется таблица contact_verifications (meta.purpose=account_restore), без нового хранилища OTP.

## Тесты
Feature: успешное восстановление, сохранение ID и alias, отзыв прежних токенов, повторный login, запрещённое административное восстановление, неизвестный email, 5 попыток кода и истечение срока. OpenAPI contract test проверяет полноту документированных API маршрутов.
