# Task 168 — Бронирование из RTC-сетки публичной площадки

## Задача

Развить девятидневный popup занятости площадки до полноценной точки входа в аренду и добавить индивидуальную стоимость минимальных временных ячеек в редактор расписания.

## Реализация

- рабочие интервалы дня разбиваются на RTC с шагом активной `VenueBookingPolicy`;
- свободные RTC показываются отдельно, а пересекающиеся занятые интервалы объединяются в компактные карточки;
- при открытии дня прокручиваемая сетка позиционируется на первом занятом интервале;
- свободная ячейка раскрывает inline-форму длительности и области аренды;
- форма использует существующие `QuoteVenueBookingHandler` и `RequestVenueBookingHandler`, поэтому сервер повторно проверяет сроки, права и конфликты;
- гостю открывается общий popup авторизации, а выбранные дата, время, длительность и область восстанавливаются после входа;
- отправленная заявка сразу заменяет свободную карточку, а ссылка «посмотреть» открывает popup параметров заявки;
- статус popup обновляется отдельным авторизованным endpoint с серверным throttle `5/min`;
- редактор расписания строит ценовые RTC по рабочим интервалам и позволяет распространить выбранную цену на день или неделю;
- пустая индивидуальная цена наследует общую цену активной политики; quote суммирует цены каждого шага и сохраняет полный breakdown в неизменяемом snapshot.

## Данные и конкурентность

`venue_schedule_slot_prices` хранит только overrides по `venue_id + day_of_week + starts_at`. Денежные значения остаются integer minor units. Quote читает overrides перед созданием snapshot, а актуальная доступность и права зала, как прежде, повторно проверяются при превращении quote в заявку. Обновление расписания без поля `slot_prices` не стирает существующие overrides, что сохраняет обратную совместимость старых клиентов.
