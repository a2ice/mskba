# 339 — Общий визард подписок и динамическое меню

## Оригинальное описание

В «Моих подписках» нужен общий вход «Все подписки», подпункты только по существующим типам подписок пользователя и кнопка «Добавить подписку» в верхней панели. Создание через стандартный визард выбора типа, затем динамическую форму типа; игровая форма должна переиспользовать существующий игровой интерес. Проверить и опубликовать на dev и main.

## Реализация

- «С привязкой к площадке» не является другим типом: сервер уже сериализует оба варианта как `play`. Убрано искусственное разделение в UI без миграции данных.
- Динамическое меню для канонического пользователя: «Все подписки» всегда; «Игровые подписки» при наличии хоть одной игровой подписки любого статуса.
- Шаг типа → оригинальная форма `PlayIntentDialog` → настройки уведомлений; валидация шагов, сохранение состояния при движении назад и повторном открытии.
- Используются общий `.mskba-modal`, перемещение шапкой, existing UI Kit и существующий backend `PlayIntent`; новых провайдеров без реализации не показываем.
- Legacy ссылки `type=venue` приводятся к `type=play` на фронтенде; backend alias остаётся для API-совместимости.

## Проверки

- `MskbaAppAccountNavigationTest`: пустые подписки, чужие подписки, собственные и правильная активная ссылка.
- Проверить frontend build, линтер/feature тесты и GitHub CI, затем dev/main; визуально проверить desktop и mobile, вкладки фильтров, создание, сохранение и повторное открытие.
- Контентный `system_update` готовить после успешного production-deploy; не заявлять о публикации без подтверждения.
