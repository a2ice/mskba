# 022 - Модерация дублей неподтвержденных площадок

## Оригинальное описание

Если площадка не подтверждена, другую площадку с таким же названием и/или адресом можно создать. Например гость G1 создал площадку V1 с адресом A1, затем G2 создал площадку с тем же названием и адресом. После модерации одна площадка должна стать канонической, а остальные должны получить ссылку на нее.

Нужны:

- отдельный статус площадки `duplicate`;
- nullable поле `venues.canonical_venue_id`;
- таблица кандидатов `venue_duplicates`;
- фоновый worker поиска дублей после добавления площадки;
- интерфейс `/admin/venues/duplicates` для merge с выбором главной площадки и дубля;
- запись действий merge в audit log.

## Подробное описание

Подтвержденная площадка остается каноническим публичным объектом: если уже есть confirmed-площадка с таким alias или адресом, новая заявка отклоняется на форме и в use case.

Неподтвержденные площадки могут совпадать по alias и адресу. После создания площадки ставится job `FindVenueDuplicatesJob`, который сравнивает новую запись с другими неподтвержденными площадками и создает pending-кандидаты в `venue_duplicates`.

Один и тот же пользователь не может создать несколько неподтвержденных/duplicate-заявок с одинаковым названием или адресом. Для авторизованного пользователя проверка идет по `creatorActor.user_id`, поэтому она работает даже при другом fingerprint/браузере. Для гостя проверка идет по fingerprint.

Модератор открывает `/admin/venues/duplicates`, выбирает группу дублей и выполняет merge. Главная площадка не подтверждается автоматически: подтверждение остается отдельным процессом ручной модерации и проверки заполненности. Дубли получают статус `duplicate` и ссылку `canonical_venue_id` на главную площадку. Кандидаты дублей получают статус `merged`, пользователя-решателя и время решения.

Если в группе дублей уже есть подтвержденная площадка, она должна остаться главной. Если подтвержденной площадки еще нет, модератор может поменять главную площадку повторным merge группы. На странице дублей название площадки открывает модальное окно с краткой информацией о записи, чтобы проще сравнить заполненность перед выбором главной.

## Технические заметки

Для пары площадок используется упорядоченная пара id, чтобы не создавать зеркальные кандидаты A-B и B-A.

Merge блокирует обе строки площадок через `lockForUpdate()` в порядке возрастания id. Это снижает риск deadlock при параллельной модерации одной и той же пары: разные запросы берут locks в одинаковом порядке.

Audit log пишет обычные события `updated` через `Auditable` и отдельное прикладное событие `merged` для площадки-дубля. Отдельное событие нужно, чтобы потом быстро отличать ручное объединение от рядового изменения полей.
