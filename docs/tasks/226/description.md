# 226 - Разделить throttle авторизации и оформить системные страницы ошибок

## Оригинальное описание

Исправить глобальный `429 Too Many Attempts` при любом способе авторизации и заменить штатные страницы ошибок `404`, `403`, `429` и других кодов собственными страницами в дизайне текущей темы.

## Подробное описание

Числовой Laravel throttle по умолчанию формировал общий cache key по пользователю или IP. Из-за этого попытки на разных auth-маршрутах суммировались: исчерпание лимита обычного входа могло блокировать Telegram, VK и регистрацию, а режим инкогнито не помогал из-за общего внешнего IP.

Общий middleware дополняет throttle signature стабильным идентификатором текущего маршрута. Каждый endpoint сохраняет собственный установленный лимит, но больше не расходует счётчик другого endpoint. Регрессионный feature-тест проверяет одновременное исчерпание лимита обычного входа и доступность Telegram/VK.

Для browser-ответов добавлены единые отказоустойчивые страницы `4xx` и `5xx` в стилистике MSKBA с отдельными текстами и действиями для основных кодов `400`, `401`, `403`, `404`, `405`, `409`, `419`, `422`, `429`, `500` и `503`. Предметные сообщения `400`, `409` и `422` сохраняются, чтобы системная страница не скрывала объяснение бизнес-ошибки. Шаблон не использует основной layout, запросы к БД или Vite manifest, чтобы оставаться доступным при инфраструктурной ошибке приложения.
