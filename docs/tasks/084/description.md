# Задача 084. Разделить Event и Game

## Цель

Устранить предположение, что `Event` является баскетбольной игрой. `Event` остается
организационным контейнером, а конкретное спортивное действие переносится в обязательную
дочернюю сущность `Game`.

## Этапы

1. Зафиксировать ADR, целевую схему, инварианты и план миграции.
2. Добавить `Game` и новые связи без удаления legacy-структуры.
3. Перевести создание мероприятий, игровой runtime, lifecycle, ACL и статистику на `Game`.
4. Перевести маршруты и UI с сохранением прежнего пользовательского сценария.
5. Выполнить проверяемую миграцию обычных игр и дочерних мини-игр.
6. Обеспечить перенаправление старых URL.
7. Удалить legacy-связи только после проверки данных и отсутствия runtime-обращений.
8. Обновить бизнес-тесты и документацию, выполнить финальный архитектурный аудит.

## Критерии завершения

- каждая `Game` принадлежит `Event`;
- игровые стороны, составы, счет и статистика принадлежат `Game`;
- бронирование и участники принадлежат `Event`;
- `Event` может содержать ноль, одну или несколько игр;
- старые игровые URL имеют безопасную стратегию перенаправления;
- рабочий код не рассматривает `Event` как игру.

Подробное решение: [Event/Game Separation](../../specification/event-game-separation.md).
