# 113 - Исправить молчаливый отказ объединения дублей пользователей

## Оригинальное описание

При выборе canonical account и подтверждении объединения пара пользователей оставалась в статусе `pending`, alias не получал `canonical_user_id`, а в Audit не появлялась запись. Laravel возвращал redirect после POST без видимого объяснения причины.

## Подробное описание

- показывать серверные ошибки валидации формы объединения на странице дублей;
- после ошибки повторно открывать модальное окно той пары, для которой выполнялось действие;
- восстанавливать выбранный canonical account и установленные подтверждения;
- проверять на HTTP-слое, что canonical account входит в разрешаемую пару;
- записывать неуспешные попытки в runtime log и Audit как `merge_failed`, не сохраняя значения полей формы, raw IP или иные чувствительные данные;
- сохранить независимые доменные проверки `ResolveUserDuplicateHandler` и существующий Audit успешного изменения candidate;
- защитить успешный merge и оба класса отказов feature-тестами.

## Результат

- validation- и domain-ошибки больше не теряются после redirect;
- модальное окно проблемной пары открывается повторно и сохраняет безопасный old input;
- Audit и Laravel log содержат диагностическую причину неуспешного merge;
- успешное объединение меняет alias и candidate и фиксируется стандартным `updated` Audit event.
