# 316/005 — Production release gates и rollback

Статус: **запланирована**.

- CI/Deploy blocker для пробной индексации, списка missing URLs, broken canonical, 404/5xx, soft-404 шаблонов, пустого контента и отсутствующей Метрики.
- До релиза проверяются контроллеры/Blade/маршруты, SEO и подготовленные migrations на существующих моделях и тестовых фикстурах. Отдельный prod-shaped стенд **не является обязательным**; сравнение dev/prod по объектам и ID в release gate не используется.
- Предрелизный freeze и согласование плана, бэкап DB + media + nginx/env, проверка восстановления, точка rollback.
- При согласованном production деплое использовать **существующую production-БД**, создать backup БД и медиа до миграций и выполнить `php artisan migrate --force`. Затем сразу провести HTTP/SEO-аудит прежних production URL по сохранённому baseline.
- Определить, какие миграции обратимы, и в случае ошибки использовать восстановление из backup/snapshot, а не слепой `migrate:rollback`.
- Только отдельное разрешение на `main` и production.

Приёмка: проверяемый чеклист, надёжный backup/rollback и автоматический post-deploy HTTP+SEO smoke по сохранённому до релиза реестру URL. Реальные 404/soft404 или несовместимость миграций блокируют завершение релиза.
