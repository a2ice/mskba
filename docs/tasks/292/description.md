# Task 292. Контакты, доступные каналы и зависимые настройки трёх типов уведомлений

## Контекст и UX
На втором шаге универсального редактора подписки есть отдельные переключатели:
1. **Уведомлять о подходящих играх**.
2. **Получать спецпредложения площадок**.
3. **Уведомлять о новостях площадки**.

Для каждого переключателя используется **один и тот же переиспользуемый компонент выбора каналов** (личные сообщения, Telegram, Email; телефон — только после фактического появления SMS-доставки).

**Зависимость видимости:** когда главный чекбокс конкретного типа уведомлений снят, весь блок «Каналы уведомлений» для этого типа **полностью скрывается**, включая кнопки добавления контактов. Не оставлять пустую колонку/место и не ограничиваться лишь `disabled`. При включении снова показать соответствующие настройки без неожиданной потери ранее выбранных допустимых каналов.

## Требования к каждому типу
- У каждого типа уведомлений свой список каналов; смена одного типа не меняет другие.
- По умолчанию для каждого включённого типа выбран **«Личные сообщения»**.
- Для спецпредложений площадок добавить **такой же набор выбора каналов**, как для подходящих игр и новостей: UI, доступность, валидация и сохранение на сервере (например, отдельное `offers_delivery_channels`).
- Отправка реальных спецпредложений должна учитывать сохранённый выбор каналов и общие пользовательские разрешения, а не только значение `notify_offers`.
- Если уведомление выключено, доставка этого типа не выполняется независимо от запомненных каналов; при повторном включении настройки возвращаются.
- Когда основной чекбокс включён, сервер гарантирует хотя бы один доступный выбранный канал (или предлагает выбрать канал), иначе ошибка видна у соответствующего типа.
- «Личные сообщения» — канал мессенджера проекта, Telegram и Email являются внешними каналами.

## Добавление и подтверждение контактов
- «Добавить Telegram» и «Добавить Email» — кликабельные действия, открывающие **тот же переиспользуемый попап**, что и на странице «Контакты», с заранее выбранным типом.
- Подтверждение через действующий механизм (Telegram-бот или Email-код); после успешного подтверждения список доступных каналов обновляется без перезагрузки.
- Технически неподдерживаемые каналы **не показывать** (пока нет SMS, не выводить телефон, его checkbox и ссылку «Добавить Телефон»).
- Для поддерживаемых, но ещё не настроенных каналов оставить disabled checkbox и короткую рабочую ссылку добавления вместо длинных разъяснений. Учитывать индивидуальные разрешения пользователя на способ и тип уведомления.
- Обновление контактов не сбрасывает «Личные сообщения» или другие допустимые уже выбранные каналы.
- Сервер повторно проверяет права, подтверждённость контакта и разрешения для каждого канала.

## Возврат между шагами подтверждения (доработка)
- Общая кнопка «Назад» доступна на шаге ввода шестизначного кода Email и возвращает на предыдущий экран с **ранее введённым адресом**.
- Изменённый Email создаёт новую неподтверждённую запись через существующий API; уже созданный, но неподтверждённый контакт не удаляется автоматически (его можно удалить в «Контактах»). Повторная отправка неизменённого Email не создаёт дубль и возвращает к подтверждению.
- При входе через плюсик для Telegram/VK этап выбора канала не показывается; кнопка «Отмена» закрывает окно. При обычном входе из кабинета «Назад» ведёт к выбору типа.
- Для остальных промежуточных экранов (Telegram и тестовая эмуляция) работает единая логика возврата, без дублирования обработчиков. Кнопки недоступны во время асинхронного запроса.
- Проверяется сохранение фокуса и доступность кнопки, а также отсутствие регрессии с подтверждением по коду.

## Приёмка
1. Открыть второй экран игрового редактора. Выключить «Уведомлять о подходящих играх»: вся панель каналов исчезает. Включить — возвращается с прежними допустимыми выборами.
2. Точно так же проверить «Уведомлять о новостях площадки».
3. Включить «Получать спецпредложения площадок»: справа/ниже появляется такой же список каналов; выключить — панель полностью исчезает; повторно включить — сохраняется выбор.
4. Проверить независимость трёх тем, сохранение и повторное открытие подписки, отсутствие отправки отключённых уведомлений.
5. Проверить рабочие «Добавить Telegram» и «Добавить Email» с предвыбором типа, подтверждением и обновлением доступности; не показывать телефон при отсутствии SMS.
6. Проверить адаптивный вид на узком экране: при скрытых панелях нет пустых пространств.
7. Автотесты UI + API + доставки и **зелёный CI**; после squash-merge в `dev` — отдельная приёмка пользователя.
