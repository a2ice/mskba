# 064 - Синхронизировать участие в мероприятиях с основным Telegram-чатом

## Оригинальное описание

При публикации мероприятия на сайте в связанном Telegram-чате должна появляться карточка с действиями «Пойду» и «Не пойду». Выбор пользователя в Telegram должен добавлять его в участники мероприятия или отменять участие на сайте.

## Подробное описание

Публичное опубликованное мероприятие асинхронно проецируется в основной Telegram-чат сообщением с краткой информацией, текущим числом участников, inline-действиями «Пойду» и «Не пойду» и ссылкой на страницу мероприятия. Черновики и приватные мероприятия в общий чат не отправляются.

Telegram передаёт на защищённый webhook `callback_query`. Обработчик сверяет секрет webhook, опубликованное сообщение и связанный `TelegramAccount`, после чего переиспользует существующие application use cases участия. Сайт остаётся источником истины для лимита мест, статуса и времени мероприятия.

Создание, изменение, отмена, завершение мероприятия и изменение состава участников инициируют синхронизацию Telegram-сообщения через доменное событие и очередь после завершения транзакции. Повторная доставка webhook и повторный запуск job должны быть идемпотентны.

Production-интеграция должна поддерживать настраиваемый HTTP proxy либо фиксированный IP для TLS-соединения с Bot API, поскольку стандартный адрес `api.telegram.org` может быть недоступен с VDS.

## Результат

Добавлена асинхронная публикация и актуализация карточек публичных мероприятий в основном Telegram-чате. Inline-действия синхронизируют участие связанного Telegram-пользователя через существующие use cases, а защищённый webhook ставит обработку в очередь. Добавлены хранение связи сообщения с мероприятием, закрытие действий после начала, поддержка proxy/IP override, автоматическая регистрация webhook при деплое и feature-тесты основных сценариев.
