# 026 - Расширить управление площадками и пользователями для superadmin

## Оригинальное описание

Добавить в админку возможность редактировать площадку для superadmin. Добавить управление статусами пользователей, фильтр удалённых пользователей и массовое удаление/восстановление. Заменить пользовательский статус `REMOVED` на soft delete, изменив исходную миграцию создания пользователей.

## Подробное описание

Добавить в таблицу площадок административный переход к форме редактирования и отдельные admin-маршруты просмотра и сохранения формы. Доступ разрешить только пользователю с точной системной ролью `superadmin`, а не всем ролям, имеющим доступ к панели администратора.

Административное редактирование является явно привилегированным исключением из запрета изменения подтвержденной площадки владельцем. Удаленные площадки остаются недоступны для редактирования до восстановления. Обычные пользовательские маршруты и инварианты не меняются.

Форма должна использовать существующий набор полей, валидацию адреса, метро, тегов и условий бронирования. После сохранения пользователь возвращается в административную форму площадки и видит сообщение об успехе.

В списке пользователей superadmin может изменить активному пользователю статус `unconfirmed`, `confirmed` или `blocked`. Удаление отделяется от жизненного статуса аккаунта и выполняется массовым soft-delete действием; удалённые аккаунты доступны через отдельный фильтр и могут быть массово восстановлены. Обычный admin видит список и фильтры, но не получает управляющих действий. Собственный аккаунт superadmin нельзя заблокировать, разжаловать по статусу или удалить через эти действия.

## Проверка

- superadmin видит действие редактирования в таблице активных площадок;
- superadmin может открыть и сохранить неподтвержденную, подтвержденную или заблокированную площадку;
- admin и остальные пользователи не имеют доступа к административным маршрутам редактирования;
- удаленную площадку нельзя редактировать до восстановления;
- обычное редактирование подтвержденной площадки владельцем остается запрещенным.
- `UserStatusEnum` больше не содержит `REMOVED`, а таблица `users` создаётся с `deleted_at`;
- superadmin может менять статусы других пользователей;
- удаление и восстановление пользователей работают массово и отображаются через фильтр «Удалённые»;
- admin не может вызывать управляющие endpoints;
- superadmin не может изменить статус или удалить собственный аккаунт.

## Результат

- в активном списке площадок superadmin видит действие «Редактировать»;
- добавлена административная форма с существующими полями площадки, адресом, метро, тегами и условиями бронирования;
- административные GET/PUT-маршруты защищены отдельным gate с точной ролью `superadmin`;
- та же проверка выполняется внутри `AdminUpdateVenueHandler`, поэтому use case нельзя вызвать в обход HTTP middleware;
- общий код изменения полей вынесен в `VenueDetailsUpdater`, при этом пользовательский сценарий сохраняет прежнюю проверку предметных прав;
- подтвержденные и заблокированные площадки доступны superadmin для исправления, удаленные требуют восстановления.
- пользователи используют `SoftDeletes`, а `REMOVED` удалён из статусного enum;
- `/admin/users` получил фильтр удалённых, выбор строк, массовые действия удаления/восстановления и модальное изменение статуса;
- управление пользователями защищено точной ролью `superadmin` на уровне gate, FormRequest и application use case;
- собственный аккаунт superadmin исключён из управляющих действий.
