# Task 291. Единый toast-пайплайн избранного и подписок

## Проблема
У избранного появился собственный `mskba-action-toast-region`, который отличается от штатных уведомлений и перекрывает их. Дополнительно одно действие может порождать два подтверждения — попап и toast.

## Требование
- Использовать штатный контейнер и дизайн toast, без параллельных регионов и перекрытий.
- Вход по сердечку: сохранить избранное и показать контекстный попап, **не показывать отдельный toast об успешном добавлении**.
- Если из попапа оформлена подписка — единственный положительный toast «Подписка оформлена».
- Вход по «Хочу здесь играть»: по сохранении подписки один toast результата; успешное избранное вторым toast не дублировать.
- Ошибки асинхронного добавления избранного и подписки показывать явно и независимо; ошибка не означает успех. Удаление из избранного должно подтверждаться штатным уведомлением, если попап не открывается.
- Сохранить realtime-уведомления и их собственный стек.

## Приёмка
Сравнить внешний вид и позиционирование с существующими уведомлениями Reverb. Проверить два входа и случаи успеха/ошибки.
