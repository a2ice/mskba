# 296 — Прошедшие мероприятия на странице площадки: неактивное визуальное состояние

## Требование
В блоке «Игры» / «Мероприятия» страницы площадки `mskba_app/views/pages/venues/show.blade.php` сделать плашки **завершившихся по времени** событий визуально приглушёнными (серые, без интерактивного hover-акцента). Состояние не зависит только от даты в календаре: событие текущего дня тоже может уже завершиться.

## Технические ориентиры
- `ShowVenueHandler::occupancyDays / occupiedSlotData` формирует `occupancyDays[*].slots` на основе booking/event. Добавить **серверный** флаг `isPastEvent`, определённый по фактическому `Event::ends_at` (или достоверному расписанию связанного события), сравнение в UTC; не вычислять прошедшее по `timeLabel` или CSS/JS.
- Ночь/переход через полночь и часовой пояс площадки обрабатываются корректно; событие **идёт сейчас** (start в прошлом, end в будущем) остаётся активным.
- Состояние применять только к **публичным событиям с прошедшим концом**. Бронирования без доступного публичного Event не объявлять завершёнными событиями.
- На плашке сохраняются название, время, число игроков и переход на страницу прошедшего мероприятия; это «неактивно для участия», **не `disabled`**, который сделал бы историю недоступной.
- Присоединение/«Думаю» недоступно после завершения по существующей серверной проверке; UI не должен показывать активную кнопку и не должен обходить backend.
- Использовать `.app-venue-activity--past` или `data-event-past`, цветовые токены светлой/тёмной темы, проверку WCAG contrast. Никаких агрессивных opacity для контейнера (потеря читабельности) и задвоенных CSS правил.
- Обновление при переходе через время окончания: корректно после reload, дополнительное обновление без reload — по возможности без частых запросов.

## Приёмка
Прошедшее сегодня/вчера, текущее и будущее, кросс-полуночь, отменённое, timezone/DST, публичный Event vs закрытое бронирование; кнопка просмотра прошедшего работает, joining запрещён. Добавить PHP-тест генерации данных и JS/CSS-regression, проверить на dev-e.

**Приоритет:** высокий. **Зависимости:** `ShowVenueHandler`, `venue-detail.css`. **Статус:** запланировано.

## Реализация
- `ShowVenueHandler::occupiedSlotData()` вычисляет `isPastEvent` только для публичного Event, сравнивая `ends_at` с текущим абсолютным UTC-временем. Визуальная плашка с `app-venue-activity--past` остаётся кликабельной и доступной с клавиатуры, но не получает активный акцент при hover.
- Состояние не зависит от локального дня или сокращённой подписи интервала, корректно при переходе через полночь. Текущие мероприятия не приглушаются.
- Существующая проверка `canJoin` и backend-права участия не изменены. Приёмка — dev-e после зелёного CI.
