# 302 — Иерархия условий аренды и календарные цены по залам

## Цель
Расширить существующие VenueBookingPolicy, VenueScheduleSlotPrice, VenueSlotPricing и QuoteVenueBookingHandler без параллельного калькулятора: цена/ограничения площадки наследуются каждым VenueCourt, отдельный зал может переопределить конкретные настройки. Поддержать исключения цены на календарную дату + время.

## Объём
- Audit текущего venue/court, расписания, quote, timezone и существующих override; совместимость исторических policy/quote.
- В редакторе цены площадки — базовые параметры. В настройках зала — режим «наследовать» либо точечные overrides с видимым эффективным значением; `null` означает наследование, 0 — явный ноль.
- Для каждого зала: базовые цены whole/half, минимум/максимум аренды, шаг, предел заказа; запрещать неподдерживаемые физически области аренды.
- Цена по конкретной дате/времени, не только weekday, поддерживает цену целиком/половины; приоритет ручного исключения над регулярным тарифом явным режимом происхождения данных.
- Данные с точностью до minor units, валюта и TZ площадки; RTC на стыках дат, неравные тарифы, несколько шагов.
- Цена не должна переопределяться при редактировании остальных полей расписания; совместимость со старым UI.
- Правила источников извне — отдельная задача, не добавлять browser/AI/платежи в эту задачу.

## Acceptance / тесты
Feature + PostgreSQL: legacy venue, зал с наследованием, зал с выборочными overrides, ноль vs null, weekday vs дата, whole/half, DST/timezone, quote sum и immutable snapshot. Filament/публичный редактор согласно существующему гайдлайну, desktop/mobile, access 403. Обратная совместимость и rollback миграций.

## Готовность
Отдельная feature-ветка, PR в dev, зелёный CI, merge и успешный dev deploy, инструкции проверки реального зала, затем ручная приёмка пользователя. Не переходить к 303 до приёмки. main/prod не трогать.
