# Единый пайплайн подтверждения управления площадкой — 20.11.2026

## Принятое поведение
- Приглашение superadmin через Filament → «Приглашения» связывает email, площадку и роль. Принятие подтверждает только email, не назначает owner без проверки.
- После принятия owner-приглашения переход на /account/contracts/venues/{venue}; прежний /venues/{venue}/management перенаправляет на каноническую карточку.
- «Мои контракты → Площадки» включает принятые приглашения и заявки ДО создания контракта. В списке есть краткий попап и переход к полной карточке.
- В карточке: черновик (текст, документы), рассмотрение, переписка, отказ (новый черновик с сохранённым обоснованием), блокировка (запрет повторной подачи), подтверждение (контракт и права), история.
- Основание и документы приватные. Файлы — private storage через VenueOwnershipClaimDraftManager. Не больше одной незавершённой заявки на площадку от пользователя.
- «Отклонена» и «Заблокирована» — отдельные значения статуса venue_ownership_claims. Блокировка сопровождается venue_user_restrictions, запрещающим создание новых заявок. Только admin может снять ограничение, история сохраняется.
- Подтверждение полномочий отдельно от модерации и публикации самой площадки.
- Переписка переиспользует VenueOwnershipClaimConversation, существующие сообщения/файлы, авторизацию и realtime. Filament использует тот же набор сообщений.
- Filament: «Аренда и документы → Подтверждение площадок», список и модальное окно, общий диалог, ответ, запрос документов, одобрить, отклонить, заблокировать, снять ограничение.
- /account/contracts/{id} ведёт на реальный контракт только после approval; до одобрения фиктивного контракта нет.
- Юридическая ссылка в приглашении оранжевая и подчёркнута, открывается в новой вкладке.

## Переходы
draft → pending → approved | rejected | blocked. rejected → НОВЫЙ draft (история сохраняется). pending/rejected → blocked только admin с причиной; blocked → повторная подача запрещена до снятия restriction; снятие ограничения разрешает новый draft без удаления истории. cancelled — прежнее состояние.

## Приёмка
1. Filament → Пользователи и доступ → Приглашения → пригласить владельца на площадку без активного владельца на новый тестовый email.
2. Открыть письмо в приватном окне → зарегистрироваться → принять приглашение → /account/contracts/venues/{id}.
3. Проверить список «Мои контракты → Площадки», попап «Контракт», полную карточку.
4. Создать черновик, добавить объяснение, PDF/JPG, сохранить и отправить.
5. Filament → Подтверждение площадок → модалка, вопрос и запрос документов. Ответ заявителя в том же диалоге.
6. Отклонить с причиной → повторная подача с новыми документами, предыдущая заявка осталась в истории.
7. Заблокировать новую заявку → нельзя подавать через UI и прямой POST. После снятия ограничения новый черновик снова доступен.
8. Одобрить → создаётся evidence-backed owner membership + контракт. Пользователь не может одобрить себя.
9. Другая личность не видит заявку и документы, а статус модерации самой площадки не изменяется.

## Публикация
CI PHP/JS/Vite, миграция PostgreSQL, публикация на dev/main, ручная приёмка. Новость типа system_update публикуется только после успешного production deploy и smoke проверки; PR и внутренние ссылки — только в ProjectUpdateDetail.
