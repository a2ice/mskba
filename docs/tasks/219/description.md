# 219 — Универсальное superadmin-начисление бонусов с подтверждением паролем

## Оригинальное описание

Заменить одноразовую smoke-кнопку «Начислить 10 000 ₽ бонусами» на нормальный
служебный инструмент superadmin:

- произвольная сумма начисления;
- повторные начисления разрешены;
- перед операцией требуется подтверждение текущим паролем superadmin;
- начисление остаётся обычной Finance operation и полностью логируется в ledger.

Изначально обсуждалась проверка первых трёх символов пароля через JS. От неё
отказались: пароль хранится как hash, поэтому корректно проверить его префикс
невозможно, а клиентская-only проверка легко обходится. Подтверждается полный
текущий пароль на backend.

## Реализация

- карточка «Начислить бонусы» видна только подтверждённому superadmin;
- сумма вводится на странице кошелька;
- перед POST открывается стандартный modal проекта с password input;
- backend повторно проверяет роль и текущий пароль через `Hash::check`;
- для merged identities пароль может совпасть с credential любой identity;
- каждое начисление создаётся как `bonus_grant`;
- каждое начисление имеет собственный UUID idempotency key;
- повтор того же POST не удваивает баланс;
- пароль не сохраняется в metadata/ledger и не возвращается в old input;
- route ограничен throttle.

## Не меняется

- superadmin начисляет бонусы только на собственный user-wallet;
- обычные пользователи не получают этот инструмент;
- real-баланс этой формой не создаётся;
- переводы bonus между пользователями работают как в Task 218.

## Проверка

- произвольные суммы;
- несколько последовательных начислений;
- неверный пароль;
- запрет обычному пользователю;
- idempotent retry;
- отображение формы только superadmin;
- полный CI + frontend build.
