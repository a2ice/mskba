# 181 — Вместимость секции, recruitment UX и публичный preview тренера

## Контекст

После Task 179 публичная страница спортивной секции стала полноценной, но production-проверка выявила несколько UX-хвостов: основная площадка не была интерактивной, recruitment-состояния дублировались двумя badge, не было лимита мест, а карточка тренера не использовала реальный avatar и не открывала краткую информацию о публично ответственном тренере.

## Цель

Довести публичную страницу и каталог секций до понятного recruitment UX и зафиксировать минимальную публичную идентичность тренера, который является ответственным лицом активной публичной секции.

## Реализация

- Добавить nullable `sports_sections.max_trainees`.
- Настройка лимита находится в `Заявки и набор`; пустое значение означает отсутствие ограничения.
- Значение не может быть меньше текущего количества активных участников.
- Создание новой заявки и активация участника блокируются, когда лимит достигнут. Проверка выполняется под блокировкой секции, чтобы конкурентные операции не превышали лимит.
- Публично показывается один recruitment badge:
  - `Идёт набор N/M` имеет приоритет над `Принимает заявки N/M`;
  - если активного набора нет, но заявки открыты — `Принимает заявки N/M`;
  - при заполненном лимите — `Мест нет N/M`;
  - без лимита счётчик не добавляется.
- `Идёт набор` получает pulse/ripple-индикатор по мотивам online-индикатора главной страницы.
- В quick facts `Площадка` переименовывается в `Основная площадка`; пояснение сообщает, что конкретные занятия могут проходить на других площадках.
- Название основной площадки кликабельно и открывает modal с её точкой на карте; остаётся отдельная ссылка на полную страницу Venue.
- Публичные карточки ответственных тренеров используют `profile.activeAvatar` вместо постоянной icon-заглушки.
- Аватар и имя тренера открывают краткий modal preview.
- Инвариант приватности: активный тренер, являющийся ответственным лицом публичной активной SportsSection, публично раскрывает только минимальную role identity в контексте секции — имя, avatar и роль. `DISCOVERABILITY = nobody` не скрывает эту обязательную role identity; контакты и остальные приватные данные этим исключением не раскрываются.
- В preview заранее присутствует placeholder-ссылка на будущую публичную страницу пользователя с role-tab `coach`; полноценные публичные пользовательские страницы выполняются отдельной задачей.

## Acceptance criteria

- При `max_trainees = 15` и одном активном участнике recruitment badge показывает `1/15`.
- Одновременно не выводятся `Идёт набор` и `Принимает заявки`.
- При заполненном лимите новая заявка/активация не может увеличить активный состав выше лимита.
- `Основная площадка` понятна как default, её название открывает карту с одной точкой.
- Реальный avatar тренера отображается в карточке и preview; при отсутствии avatar остаётся fallback-icon.
- Имя и avatar кликабельны и открывают один и тот же preview.
- Минимальная identity ответственного тренера остаётся доступной на публичной странице секции даже при закрытой discoverability пользователя.
- PHP tests и production frontend build зелёные до merge в `main`.
