# 041 - Добавить локальное хранение и загрузку аватаров профиля

## Оригинальное описание

Локально сохранять аватар, полученный при Telegram-авторизации, и дать пользователю возможность загрузить новый аватар нажатием на изображение в аккаунте. Для профиля хранить не более трёх изображений, одно из которых активно. Проверять тип и размер файла, а прошедшее проверку изображение уменьшать до 200 пикселей по большей стороне.

## Подробное описание

Аватар относится к `Profile` и хранится через существующую полиморфную модель `Media`. В базе сохраняются метаданные и путь, а сам файл размещается на публичном Storage-диске. Оригинал не сохраняется: JPEG, PNG или WebP размером до 5 МБ и геометрией до 6000×6000 преобразуется в WebP, вписанный в 200×200 без увеличения исходника.

Новая ручная загрузка становится активной, предыдущие остаются историей, но суммарно профиль может иметь не более трёх аватаров. Ограничение обеспечивается внутри транзакции с блокировкой профиля, чтобы параллельные загрузки не нарушили инвариант. Самые старые лишние записи и файлы удаляются окончательно.

При Telegram Mini App авторизации внешний `photo_url` используется как источник асинхронной локальной копии. Telegram-аватар обновляется только пока пользователь не выбрал собственный файл; ручная загрузка имеет приоритет и не перезаписывается следующей авторизацией.

В аккаунте аватар становится доступной кнопкой загрузки. Ошибки валидации и успешный результат отображаются штатными сообщениями страницы. Локальный активный аватар используется также в мобильной шапке.

## Проверка

- feature-тест загрузки, валидации, лимита трёх файлов и единственного активного аватара;
- тест асинхронной синхронизации Telegram-аватара и приоритета ручной загрузки;
- полный набор backend-тестов;
- production-сборка frontend-ассетов;
- `git diff --check`.

## Результат

Профиль получил polymorphic media-коллекцию `avatar`. Ручная загрузка доступна по нажатию на аватар в sidebar аккаунта, проходит двойную проверку формата/размера и сохраняет только нормализованный WebP до 200 пикселей по большей стороне. Последняя загрузка становится активной; транзакционная блокировка сохраняет не более трёх файлов и не допускает нескольких активных записей.

После Telegram-авторизации отдельная queued job локально копирует внешний аватар. Хеш источника предотвращает повторную обработку той же ссылки, а ручной аватар имеет приоритет над последующими Telegram-входами. Шапка и аккаунт используют единый локальный активный файл с временным fallback на Telegram URL или стандартную заглушку.

Production PHP-образ дополнен GD с JPEG/WebP, а install/deploy гарантируют наличие публичной Storage-ссылки. Пройдено 194 теста с 1118 assertions, production frontend build, сборка Docker-образа и runtime-проверка `gd-webp-ok`; `git diff --check` выполнен успешно.
