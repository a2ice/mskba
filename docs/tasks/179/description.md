# 179 — Предсказуемые страницы создания и справка из FAQ

## Оригинальное описание

B0440: кнопка добавления ведёт на страницу создания; гость видит авторизацию вместо формы. При недостатке прав показываются причины и ссылки для устранения в новой вкладке. После перехода появляется кнопка «Проверить», обновляющая страницу.

B044: под заголовком страницы добавления показывается раскрывающаяся bordered-карточка «Как добавить …» с intro соответствующего раздела FAQ и ссылкой на полную инструкцию в новой вкладке.

## Подробное описание и план

1. Общая проверка доступа для GET страниц площадки, мероприятия (включая wizard), команды, турнира, опроса и секции. Сохранить защиту POST, API и вспомогательных поисковых маршрутов.
2. Переиспользовать существующую авторизацию и безопасный intended redirect с query-параметрами; различать блокировку, подтверждение аккаунта/контакта, роль тренера и явный запрет администратора.
3. Заменить перехват кнопок создания авторизационным popup обычными ссылками.
4. Добавить разделы FAQ: сейчас существует только «Первые шаги». Intro хранить в одном источнике для полной страницы и карточки создания.
5. Проверить guest/denied/allowed доступ, возврат после входа, сохранение POST-защиты, сборку и адаптивный интерфейс. Обновить документацию.

## Результат

- Общая проверка GET/HEAD страниц создания показывает встроенную авторизацию либо конкретные условия доступа. Сохранение сущностей и служебные поисковые endpoints сохраняют серверную защиту.
- Контакт, подтверждение аккаунта и роль тренера открываются в новой вкладке. После перехода появляется «Проверить» с обычной перезагрузкой исходной страницы.
- Пароль, регистрация, VK и Telegram сохраняют адрес создания с параметрами; явный запрет администратора не заменяется предложением повторно подтвердить контакт.
- Кнопки добавления в каталогах и мобильной панели ведут на страницы создания и для гостей.
- Добавлены шесть инструкций FAQ и общий источник вводных текстов. Справка раскрывается нативным `details/summary` под заголовком, в том числе до авторизации.
- Новые блокировки БД не добавлены: используется прежний порядок автоматической выдачи прав через блокировку canonical user. GET не гарантирует сохранение прав до POST; при записи действуют прежние проверки.

## Проверки
