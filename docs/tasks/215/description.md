# 215 — Управляемый прайс-лист и версионные цены

## Оригинальное описание

Вынести цены внутренних платных возможностей MSKBA в отдельный управляемый
Pricing-контур вместо захардкоженных сумм в бизнес-логике.

Первая версия должна дать администратору каталог категорий, услуг и вариантов,
хранить историю изменения цен и предоставить стабильный resolver, которым
следующий Purchase/Order flow сможет зафиксировать цену в момент покупки.

Базовая стартовая цена AI-генерации — 100 ₽ за операцию. Это рабочие начальные
значения прайса, а не тестовые записи.

## Реализовано

Создан отдельный модуль `Pricing`:

- категории услуг;
- услуги с постоянным code;
- необязательные варианты услуги;
- версионные цены в integer minor units;
- currency `RUB` в первой версии;
- soft-delete каталога без уничтожения финансовой истории;
- административный интерфейс `/admin/pricing`;
- стандартный audit log изменений;
- `PricingPriceResolver` как application-контракт для будущих покупок.

При изменении цены старая версия закрывается через `valid_until`, а новая
создаётся отдельной записью. Исторические записи не переписываются.

## Начальный каталог

Категория AI-генерации содержит:

- `avatar_generation`;
- `team_generation`;
- `game_highlights_generation`.

Стартовая цена каждой услуги — 10 000 minor units = 100 ₽.

## Граница с Finance и Purchase

Pricing отвечает только на вопрос «какая цена услуги действует сейчас/в указанный
момент».

Pricing не:

- списывает деньги;
- создаёт кошелёк;
- создаёт покупку;
- проводит эквайринг;
- хранит статус исполнения услуги.

Будущий Purchase/Order flow должен получить цену через
`PricingPriceResolver`, сохранить snapshot суммы/currency в покупке и только
после этого инициировать списание через Finance.

Изменение прайса после создания покупки не должно менять сумму уже созданной
покупки.

## Админка и аудит

Администратор может:

- создавать и редактировать категории;
- создавать и редактировать услуги;
- создавать варианты;
- включать/отключать элементы каталога;
- задавать новую цену;
- отключать действующую цену;
- видеть историю версий.

Изменения Pricing-сущностей пишутся в общий `audit_logs`.

## Проверки

Профильные feature tests покрывают:

- стартовый каталог;
- resolver действующей цены;
- закрытие старой версии при смене цены;
- недоступность услуг выключенной категории;
- audit изменений;
- отображение прайса в админке.
