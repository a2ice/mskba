# Task 203 — Расширенное управление пользователем и удаление аккаунта

## Что делаем

- В таблице пользователей переход по логину на расширенную страницу редактирования доступен только подтверждённому `superadmin`.
- Страница редактирования пользователя разделена на вкладки: общая информация, профиль, роли и история действий.
- На вкладке «Общая информация» используется существующий безопасный admin-flow soft delete.
- В личном кабинете добавлено самостоятельное soft-удаление аккаунта с обязательным browser confirm; после удаления сессия инвалидируется.
- Для canonical identity самостоятельное удаление атомарно soft-delete-ит canonical account и aliases, чтобы не оставлять ссылки на удалённую canonical запись.
- Строки таблицы пользователей выравниваются по вертикали по центру.
- Восстанавливается корректное отображение badge количества аватаров и popup библиотеки аватаров.

## Удаление

Модель `User` уже использует Laravel `SoftDeletes`. Административное удаление переиспользует `AdminBulkChangeUserDeletionStateHandler`, который проверяет точную роль superadmin, запрещает удалять собственный аккаунт и небезопасное удаление участника canonical identity.

Самостоятельное удаление вынесено в `DeleteOwnAccountHandler`. Endpoint не принимает чужой user id и удаляет только логическую identity текущего пользователя.

## Причина регрессии стилей аватаров

Исходные стили `resources/themes/mskba_dark/css/user.css` и import в theme entrypoint присутствовали, но production deploy останавливался на сборке PHP до Vite build из-за ошибки установки PECL Redis. В результате новый Blade уже содержал элементы менеджера аватаров, а production bundle оставался старым. Deploy hotfix из PR #225 влит в `main`; дополнительно CSS import фиксируется явным расширением и покрывается regression test.
