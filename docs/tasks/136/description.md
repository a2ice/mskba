# 136 — Продолжать подачу заявки в команду после авторизации

## Оригинальное описание

Показывать неавторизованному пользователю кнопку подачи заявки в команду. По нажатию открывать
модальное окно авторизации, а после успешного входа или регистрации автоматически отправлять выбранную
заявку. После отправки показывать понятный постоянный статус вместо исчезнувшей кнопки.

## Подробное описание

Гость видит CTA как у авторизованного пользователя и явно выбирает общую заявку либо конкретную вакансию.
Модальное окно получает URL возврата с типом выбранной заявки. Браузер кратковременно сохраняет подтверждённое
пользователем намерение в `sessionStorage`; после авторизации страница создаёт обычный CSRF-защищённый POST
только при совпадении URL и сохранённого намерения. Это не превращает GET в изменяющую состояние операцию и
не позволяет внешней ссылке незаметно отправить заявку авторизованного пользователя.

Сервер повторно применяет существующие бизнес-правила: команда и вакансия должны быть активны, пользователь
не должен состоять в команде или быть заблокированным, а одновременно может ожидать только одна заявка.
Подтверждённый контакт и роль игрока не требуются. Текущая целевая заявка отображается непосредственно в
карточке вакансии статусом «Заявка на рассмотрении».

## Статус

Выполнено.

## Результат

Гость видит кнопки общей и целевой заявки. Кнопка открывает общий auth modal, все способы входа получают
одинаковый URL возврата, а после успешной авторизации браузер продолжает выбранное действие обычным POST.
Прямая ссылка без сохранённого пользовательского намерения заявку не отправляет. В карточке вакансии теперь
видны состояния заявки на рассмотрении, принятия, отклонения и блокировки; целевой статус не дублируется в
нижнем блоке общих заявок.
