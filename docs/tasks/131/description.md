# 131 — Continuous / «Открытая лига»

## Цель

Добавить режим турнира для этапа роста MSKBA, в котором постоянные команды могут присоединяться уже после начала соревнования, а сыгранная спортивная история не перестраивается.

## Границы V1

- continuous доступен только при `recruitment_mode=preformed_teams`;
- balanced / `individual_draft` сохраняет существующий fixed-pool lifecycle и собственный механизм позднего присоединения игроков;
- аренда площадки остаётся границей Event/Game/Booking и не встраивается в алгоритм continuous tournament;
- текущая отдельная ветка развития booking не смешивается с этой задачей.

## Модель

Независимые измерения турнира:

- `recruitment_mode`: готовые команды / individual draft;
- `enrollment_policy`: `fixed_pool|continuous`;
- `round_robin_legs`: `1|2`;
- `ends_on`: nullable календарная дата окончания;
- `recruitment_closed_at`: явное закрытие набора новых команд;
- `tournament_closed_at`: явное окончательное завершение турнира.

Для continuous `ends_on=null` — штатный сценарий открытой даты окончания.

## Lifecycle continuous

1. Организатор создаёт «Открытую лигу».
2. Первая команда допускается без необходимости ждать полного состава турнира.
3. При добавлении каждой следующей команды система создаёт только отсутствующие встречи новой команды со всеми активными командами по правилу 1/2 кругов.
4. Уже существующие `TournamentMatch`, назначенные `Game` и подтверждённые результаты не регенерируются и не удаляются.
5. `Закрыть набор команд` запрещает новые заявки/приглашения, но не завершает турнир.
6. Набор можно снова открыть до окончательного завершения; история матчей при этом сохраняется.
7. `Завершить турнир` — отдельное явное действие. Уже назначенные игры к этому моменту должны быть завершены или отменены. Неназначенные матчи могут остаться несыгранными.
8. После завершения нельзя добавлять, назначать, переносить или переставлять матчи.

Continuous tournament не переходит в `COMPLETED` только потому, что все существующие на данный момент игры сыграны. Итоговая фаза наступает по `tournament_closed_at`.

## Матчи и расписание

- сыгранные, начатые и ожидающие подтверждения результата игры являются фиксированной историей;
- будущие матчи можно менять по `sequence`;
- изменение `sequence` не меняет дату/время/площадку;
- назначенную, но не начатую игру можно отдельно перенести по существующему Event/Game/Booking flow;
- continuous позволяет добавлять будущие TournamentMatch после старта турнира;
- full round-robin regeneration по-прежнему запрещена после назначения первого Game;
- поздние команды используют incremental expansion вместо regeneration.

## Booking boundary

`TournamentMatch` отвечает за «кто с кем должен сыграть». `Game/Event` отвечает за «когда и где». `Booking` отвечает за получение площадки/слота. Поэтому будущая реализация аренды несвободной площадки должна подключаться на этапе назначения/переноса Game и не менять lifecycle открытой лиги.

## Публичный UX

- отображается «Открытая лига» и состояние набора;
- пользователь с правом `team.manage_tournament_participation` для активной постоянной команды может подать заявку командой с публичной страницы;
- после принятия команды новые пары появляются автоматически;
- standings продолжают строиться из актуальных entries и подтверждённых результатов: новая команда естественно начинает с 0 игр / 0 очков.
