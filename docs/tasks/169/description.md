# Task 169 — Уведомления и счётчики заявок на аренду

## Результат

- Ответственные с полномочием принятия решений получают внутреннее realtime-уведомление о новой заявке без дополнительной очередной задержки.
- Email-доставка выполняется через очередь, повторяется при временной ошибке и учитывает отдельную настройку пользователя.
- Новые заявки, требующие решения, считаются по статусу `requested`; счётчик показан у «Моих площадок», на карточке площадки и у пункта «Заявки на аренду».
- Во входящем списке показаны начало, окончание и длительность аренды.
- Пользовательское отображение рублей унифицировано как `руб.`; ISO-код `RUB` сохранён в данных и интеграциях.

## Архитектурные замечания

Transactional outbox остаётся границей надёжной публикации события бронирования. Создание внутреннего уведомления выполняется в обработке outbox-события, а внешняя email-доставка отделена идемпотентной записью `user_notification_deliveries` и очередной job. Такой подход не задерживает пользовательский запрос и не создаёт дубликат успешно отправленного письма при повторной обработке.

Счётчики вычисляются одним агрегирующим SQL-запросом и ограничиваются площадками, для которых пользователь имеет `decide_booking_requests`. Завершённые и уже взятые в работу заявки счётчик не увеличивают.
