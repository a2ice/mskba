# Task 202 — Делегируемое управление системными ролями

## Цель

Добавить отдельное операционное право на установку и сброс системных ролей из списка пользователей админки, сохранив строгую иерархию полномочий.

## Право

Добавлено `user.system_role.manage` / «Управление системными ролями».

- без персонального snapshot право включено только у `superadmin`;
- `superadmin` может выдать право `admin` через существующий popup операционных прав;
- явный snapshot по-прежнему имеет приоритет над значением по умолчанию.

## Иерархия

Изменение разрешено только если:

- оператор подтверждён и имеет системную роль не ниже `admin`;
- у оператора есть `user.system_role.manage`;
- оператор не меняет самого себя;
- текущая роль пользователя строго ниже роли оператора;
- новая роль также строго ниже роли оператора.

Поэтому `admin` не может назначить `admin`, а `superadmin` не может создать второго `superadmin` через этот flow. Выбор `user` используется как сброс административной системной роли.

Проверка выполняется и Gate/FormRequest, и повторно в transactional use case с блокировкой пользователя.

## Админка

- значение в колонке «Системная роль» становится кликабельным, когда оператор может его менять;
- по клику открывается popup со всеми допустимыми по иерархии ролями;
- popup операционных прав автоматически показывает новое право и корректное default-value;
- admin action modals при инициализации переносятся непосредственно в `body`, а их слой поднят выше sticky header, поэтому header больше не перекрывает popup.

## Проверки

Feature tests покрывают:

- default права только для `superadmin`;
- назначение и сброс роли `superadmin`;
- делегирование права `admin`;
- запрет назначения роли собственного уровня;
- запрет управления peer-role;
- запрет назначения `superadmin` через UI flow;
- наличие нового popup/permission в списке пользователей.
