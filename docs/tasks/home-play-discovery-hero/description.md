# Главная MSKBA — вводный слайд «Найди свою игру» (18.11.2026)

## Продуктовый посыл

Портал помогает ответить на три вопроса: **с кем, где и когда играть**. Пять следующих слайдов раскрывают отдельные возможности: площадки, игры, команды, форма, рейтинги. Первым становится обобщающий слайд, **не подменяющий** каталог площадок и не обещающий автоматического создания мероприятия.

### Текст первого слайда

- Eyebrow: `01 · ТВОЯ ИГРА НАЧИНАЕТСЯ ЗДЕСЬ`.
- Заголовок: `НАЙДИ СВОЮ ИГРУ`.
- Акцент: `С КЕМ. ГДЕ. КОГДА.`.
- Описание: `Укажи, где, когда и в каком формате тебе удобно играть. MSKBA поможет найти подходящие площадки и игроков с похожими интересами.`
- CTA: `Хочу играть` → `/account/subscriptions` (для гостя стандартный вход, после входа возвращение по intended URL).

### Что реально работает сейчас

- `PlayIntent` — техническое имя пользовательской **игровой подписки**. Пользователь задаёт параметры поиска, включая площадку/радиус, время, формат, регулярность, удобства и доступность.
- `RecommendVenuesForIntent`, `RecommendPlayableSlots`, `VenueSubscriptionAudience` реализуют подбор по условиям, проверку доступности и проекцию интересующихся игроков. Потенциальное совпадение не означает согласия на игру или свободный слот на момент оформления.
- `/account/subscriptions` — основной UI создания и управления игровыми предпочтениями; на страницах площадок с 18.11.2026 действие «Хочу здесь играть» предлагает отдельно аренду или избранное (task 330).
- Список группы интересов конкретной площадки доступен, а совместная аренда использует существующий coordination flow.

### Что пока не обещаем

- Автоматическая сборка полноценной игры из совпадений (`PlayOpportunity`/`PlayAssembly`, task 287).
- Универсальные голосования и персональное подтверждение даты/состава/цены.
- Автоматическое бронирование/оплата по одному интересу.
- Автоматические предложения владельцев и рассылка спроса по task 288.

## Техническая реализация

- `HomePlayDiscoverySlide::slide()` — данные типизированных слоёв, управляемые Filament.
- Production-only миграция добавляет шестой слайд **первым** только если и черновик, и опубликованный компонент имеют ожидаемые пять слайдов с «Площадками» на первом месте.
- Существующие пять слайдов, медиа, CSS, публикационные параметры не перезаписываются. Перед вставкой создаётся `page_builder_revisions` с исходными `draft_slides` и `published_slides`; миграционный rollback не перетирает редакторские правки.
- Фон использует штатный `indoor`, мобильный экран — `mobile_layout: flow`. Добавленный слайд можно менять в `Сайт → Компоненты → Hero Slider`.

## Проверка публикации

1. CI и unit tests, `HeroSliderSettings::validate()`.
2. После release на `https://mskba.ru/` убедиться, что слайдов **6**, новый первый, прежние пять на местах.
3. Проверить 360/390/768/1024/1280+ px, keyboard navigation, CTA для гостя/пользователя.
4. Если migration выдала `skipped (unexpected editor content)`, не пытаться переиграть изменения вслепую: необходим просмотр актуальной CMS-структуры и ручное редактирование через Filament.

## Следующий продуктовый этап (отдельно)

Сформировать единый понятный сценарий «Хочу играть» от просмотра возможностей до создания/согласования игры. Не смешивать `Favorite`, подписку, совпадение интересов, сбор, Event и Booking. Отдельно решить вопросы уведомлений, приоритета подходящих живых игр, приватности и действий в группе.
