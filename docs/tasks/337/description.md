# 337 — Воронка «Хочу здесь играть»: единый контур мероприятий

Утверждено 19.11.2026. Основа: Event-first, без дополнительных групп, выборов администраторов и параллельных систем избранного.

## Пользовательский путь

1. Hero площадки: свайпы/drag фото влево-вправо, превью и клавиатура работают. Справа две основные кнопки: **«Хочу здесь играть»**, **«В избранное»**.
2. Избранное добавляется одним кликом, после сохранения информационный попап (НЕ подтверждение). Кнопка становится «В избранном». Повторное нажатие требует подтверждения удаления. Один базовый интерес PlayIntent к площадке создаётся автоматически для авторизованного пользователя; гостевое избранное переносится с созданием интереса при входе. При удалении паузится только автоматически созданная подписка; вручную отредактированную в ЛК не менять.
3. «Хочу здесь играть» открывает **только мероприятия**. Первый экран показывает предстоящие публичные доступные мероприятия площадки (пустое состояние, если нет), и всегда предлагает «Создать мероприятие».
4. Выбор мероприятия открывает следующий экран В ТОМ ЖЕ визарде: название, тип, дата, описание, организатор, аватары/логины участников, переходы к публичным профилям. Для открытых мероприятий видны обсуждение и история ответов.
5. Ответы «Пойду», «Подумаю», «Не пойду» учитывают текущий статус. Все действия и комментарии не чаще 3/60 секунд на пользователя; комментарии не длиннее 200 символов. Сервер валидирует и ограничивает эти операции; RSVP отражается системным сообщением. При отсутствии авторизации сначала показывается информационный попап о сохранении выбора, затем обычная авторизация, после которой операция продолжается в визарде.
6. Единое создание из площадки или каталога: тип, редактируемое автоматически предложенное название, площадка (при запуске с площадки предвыбрана), параметры/видимость; необязательный шаг расписания (публичная сетка статусов с пояснениями) и подтверждение. Неавторизованный пользователь заполняет форму до конца; на подтверждении — информационный попап, затем существующая авторизация и возобновление сохранённого процесса, переход к созданному Event.
7. Можно выбрать несколько интервалов (другие дни и время). Пользователь явно указывает, это **альтернативное время одного Event** или **несколько самостоятельных Events**. Общие параметры вводятся один раз. При отсутствии даты создаётся черновик без публикации/уведомления. Время при выборе предварительное; сохраняются все предложения; создаётся предзаявка для разговора с менеджером, **не резервируется ни один слот**. Занятость в расписании — подсказка, не запрет предложить время. При последующем бронировании применяется существующая серверная проверка и обычный процесс оплаты/согласования.
8. Прямой вход в аренду размещается **только в блоке расписания**, не в игровом сценарии.
9. После публикации нового открытого мероприятия активные PlayIntent сопоставляются с площадкой/условиями/временем; уведомления внутри портала и по разрешённым подтверждённым каналам, с защитой от дублей. Игра, игровая тренировка и тренировка; нельзя рассылать черновики, чужие/скрытые или завершённые события. Сохранение в избранное — согласие на базовый интерес, его уведомления настраиваются в ЛК.

## Event / Game: независимость контейнера (уточнение 19.11.2026)

- **Event — контейнер**, независимо от типа (`game`, `training`, `tournament` и др.). Он может иметь 0, 1 или несколько вложенных `Game`. Тип `game` не означает обязательного наличия `primaryGame`.
- В первом шаге нового визарда при типе «Игра» показывается чекбокс **«Создать игру внутри мероприятия»**, отмеченный по умолчанию. Снятая галочка создаёт только Event; с галочкой создаётся Event с одной первичной Game. Это не изменяет другие процессы создания до их отдельной ревизии.
- Страница Event типа «Игра» без вложенной Game должна показывать самостоятельную страницу мероприятия (участники, обсуждения, информация), а не 404.
- Механика Game (составы, роли, периоды, счёт, статистика, отношение Game к разным типам Event, множественность и логика первичной игры) будет изучена и согласована отдельно; **не считать нынешнюю реализацию окончательно утверждённой**.

## Границы и правила

- Все данные пользователя и шаги визарда сохраняются в памяти компонента; при внешнем редиректе на авторизацию — в sessionStorage текущей вкладки с TTL. Пароли и секреты не сохраняются.
- Попап закрывается по backdrop только если pointerdown И pointerup произошли на самом backdrop; при выделении/drag изнутри не закрывается. Enter валидирует текущее поле и переводит фокус; ошибки снимаются при вводе. На мобильных не должно быть горизонтального переполнения.
- Сервер, а не только JS, гарантирует авторизацию, идемпотентность запросов создания, допустимые типы, статус, права чтения приватных мероприятий, лимиты действий, CSRF, проверку принадлежащего площадке зала и отсутствие фиктивных броней.
- В будущем отдельной задачей: в чате предзаявки менеджер после подтверждения клиента одной кнопкой преобразует альтернативные интервалы в несколько самостоятельных мероприятий-копий и отдельно связывает их с бронями. **Не создавать копии без явного согласования.**

## Проверки перед production

- Feature: добавление/удаление избранного, гостевой claim, активные и персонально настроенные PlayIntent; уведомления по совпадению и защита от дублей.
- Feature: создание мероприятия с нулём, одним и несколькими интервалами, оба режима, занятое время, повторный submit, права на черновик и публикацию.
- Feature: guest→auth→возобновление, RSVP/чат, лимиты/права, публичные аватары и приватность.
- UI: обе темы, desktop/mobile, галерея свайпами, модальные окна, focus/Enter, пустые состояния, формы, возвращение после авторизации и отсутствие ложного «забронировано».
- CI → review → merge main → контроль production. Случайного промежуточного изменения данных production не допускаем.

## Уточнение по устаревшему типу мероприятий (19.11.2026)

«Игровая тренировка» (`game_training`) выведена из всех публичных меню/селектов/отдельных фильтров создания и поиска; новый Event такого типа создавать нельзя (валидация сервером). Тип НЕ удаляем из enum и БД: существующие мероприятия отображаются и открываются, находятся при фильтре «Все» (без ограничения по типу). Позднее выполняется плановое выведение остальных внутренних веток и миграция истории, но не в текущем релизе.

Название нового мероприятия по умолчанию зависит от выбранного типа и адресной локации площадки: ближайшая станция метро, иначе улица, с сохранением ручного переименования. Предиктивный ввод площадок + стандартная карта не меняют бизнес-логику аренды и предзаявок.
