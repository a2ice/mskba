# 083 - Устранить регрессии после интеграции игровых составов и обновить проверки

## Оригинальное описание

Разобраться с ошибками автоматических тестов и прочими замечаниями после
обновления локального контура из GitHub.

## Подробное описание

После интеграции factual lifecycle и спортивных ролей полный набор тестов
содержит как реальные пробелы в защите бизнес-инвариантов, так и проверки,
оставшиеся на прежних продуктовых контрактах.

Задача включает:

- перенести проверку live-фазы счёта и статистики в application service, чтобы
  инвариант соблюдался независимо от HTTP middleware;
- сохранить единый порядок блокировок: родительское мероприятие, игра, детали;
- актуализировать сценарии ролей, исторического состава, списка мини-игр и
  единой оценки разметки площадки;
- устранить нестабильность проверки постановки пересчёта показателей в очередь;
- обновить frontend-зависимости с опубликованными исправлениями безопасности;
- повторить профильные тесты, полный suite, frontend build и npm audit.

## Результат

- Инварианты factual lifecycle перенесены в `GameManagementService`: счёт и
  статистика принимаются только во время фактического проведения, подтверждение
  и завершение — только после фактического окончания.
- Проверки выполняются внутри транзакции после блокировок родительского события,
  игры и деталей. Порядок блокировок не изменён, новых источников deadlock не
  добавлено.
- JSON-запрос подтверждения статистики теперь получает предсказуемый ответ 422 с
  сообщением бизнес-ошибки.
- Событие подтверждения отправляется после успешной сервисной транзакции, а job
  пересчёта показателей сохраняет `afterCommit`, включая внешний transaction.
- Устаревшие ожидания тестов приведены к текущим контрактам игровых ролей,
  составов, мини-игр и единой оценки разметки площадки.
- Проверка уникальной job изолирована на array cache, не меняя Redis-сценарии
  остальных тестов.
- Обновлены `vite` до 8.2.0 и `concurrently` до совместимой с Node 20 версии
  9.2.4; `npm audit` не обнаруживает уязвимостей.
- Добавлен отдельный идемпотентный `GameLifecycleDemoSeeder`, доступный только в
  `local/testing`: он создаёт организатора, игроков, две команды со спортивными
  ролями, самостоятельные игры и игровую тренировку с мини-играми в разных
  factual lifecycle-состояниях. Production-safe `DatabaseSeeder` не изменён.
- Турнирные данные не имитируются через мероприятия: доменная модель турниров
  ещё не реализована и остаётся отдельной продуктовой задачей `B0191`.
- Регистрация media morph map дополнена alias `team`; без него каталог впервые
  падал при загрузке логотипов после появления реальных demo-команд.
- Каталог команд приведён к общему паттерну категорий: полноширинная страница,
  sticky-панель фильтров и создания, поиск, фильтр размера активного состава,
  карточки с логотипом или локальной тематической заглушкой.
- У постоянной команды появились независимые множественные спортивные профили:
  стритбол и/или баскетбол. Они доступны в формах, карточках и фильтрах, не
  ограничивают общий состав и не переписывают формат конкретной игры.
- Карточка команды показывает тренера и капитана из активного состава; при
  отсутствии роли выводится прочерк, данные загружаются без N+1-запросов.

Проверено:

- профильные feature-тесты — успешно;
- полный suite в Docker-контуре — 390 тестов, 2678 assertions;
- Laravel Pint — 626 файлов без замечаний;
- `npm run build` — успешно;
- `npm audit` — 0 уязвимостей.
