# 174 — Перевести каталог команд на `default_category`

## Цель

Перевести `/teams` на общий `default_category`, сохранив текущие составы, статусы, hiring-индикацию и права.

## Требования

- общий shell, full-width `inner`, desktop sidebar, sticky toolbar и mobile filter popup;
- `cards|list|map`, default `cards`;
- сохранить текущие фильтры по размеру состава, типу команды и активному набору;
- поиск остаётся в toolbar;
- card/list partials не должны дублировать вычисления состава и статусов: подготовить presentation data до view либо вынести повторяемое форматирование в безопасные helper/view-model элементы;
- текущие badges статуса, sport type, неполного состава и набора сохранить;
- map capability использовать только по подтверждённым Team↔Venue связям (`confirmed`). Желаемая площадка не должна выдавать себя за фактическое место команды;
- одна команда может иметь несколько подтверждённых площадок, поэтому map view должен корректно поддерживать несколько точек на одну команду;
- команда без подтверждённой площадки остаётся доступна в `cards/list`;
- sidebar navigation согласовать в ходе задачи. Кандидаты: все/популярные, идёт набор, мои команды, создать команду.

## Критерии приёмки

- каталог следует `default_category` без регрессии Team ACL/hiring;
- query state сохраняется во всех представлениях;
- map не использует `desired` relation как подтверждённую географию;
- профильные Team tests, `npm run build`, `git diff --check`;
- ручной production smoke после merge.

## Реализовано

- `/teams` переведён на общий `default_category` с `cards`, `list` и `map`, карточки используются по умолчанию;
- sidebar содержит базовую навигацию каталога, ссылку на «Мои команды» для авторизованных пользователей и вход в создание команды с сохранением существующего ACL/auth-flow;
- существующие фильтры по размеру состава, sport type и активному hiring сохранены, поиск расположен в toolbar;
- повторяемая подготовка данных карточек/списка/карты вынесена в `TeamCatalogPresenter`;
- сохранены status/sport/hiring/roster badges и важные данные в mobile list;
- карта использует только `confirmed` Team↔Venue relations к подтверждённым площадкам; `desired` relations не интерпретируются как фактическая география;
- одна команда может отображаться в нескольких подтверждённых точках, несколько команд могут группироваться в одной точке;
- команды без подтверждённых координат остаются в cards/list;
- добавлен focused feature-test карты, который декодирует фактический JSON map-points и проверяет включение `confirmed` и исключение `desired` связей.
