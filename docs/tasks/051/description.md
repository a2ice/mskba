# 051 - Реализовать регулярное расписание и исключения площадки

## Оригинальное описание

Реализовать интерфейс работы с регулярным расписанием площадки как основу будущих слотов и бронирований. Доступ должен быть у superadmin, владельца и пользователей с договорным правом `edit.schedule`.

## Подробное описание

Существующая недельная модель расписания расширяется исключениями на конкретную дату: площадка может быть закрыта весь день либо работать по заменяющим недельный шаблон интервалам. Один общий редактор используется в личном кабинете и административной части. Backend проверяет права, состояние площадки, формат времени, порядок и отсутствие пересечений интервалов. Публичная карточка применяет исключение раньше регулярного шаблона.

Модерационный статус не описывает физическую доступность. Отдельное поле `operational_status` хранит базовое состояние `active|temporarily_closed`, а итоговое `Открыта|Закрыта` вычисляется только из него, расписания и текущего времени.

Площадка без заполненного расписания может отображаться как открытая по действующему UX, но не создаёт доступных для бронирования слотов. Сами события, материализация слотов и бронирования не входят в задачу.

Расписание является операционной сущностью и не проходит модерацию паспортных данных площадки. Оно недоступно для удалённой и заблокированной площадки. Обновление начинается с блокировки строки `venues`; будущая логика слотов и бронирований должна соблюдать тот же порядок блокировок.
