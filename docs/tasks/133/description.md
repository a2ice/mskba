# 133 — Перевести мастер создания мероприятий на booking-first аренду

## Оригинальное описание

Унифицировать создание мероприятия на платной или подтверждаемой площадке с новым `VenueBooking` flow. Сейчас wizard создаёт legacy-бронирование в `pending` и draft-мероприятие, для которого нет рабочего сценария подтверждения; из-за этого мероприятие не появляется в публичном каталоге и Telegram.

## Подробное описание

Мастер создания мероприятия должен использовать один из двух явно разделённых сценариев:

1. Площадка без активной коммерческой политики и со свободным доступом сохраняет существующий простой flow: бронь и Event создаются атомарно, Event сразу публикуется.
2. Площадка с активной политикой аренды использует booking-first flow: сервер формирует неизменяемый quote, создаёт заявку нового агрегата `VenueBooking` и сохраняет intent мероприятия. Event ещё не существует и автоматически создаётся ровно один раз только после перехода брони в `confirmed`.

Для несвободной площадки без активной политики мастер должен возвращать понятную ошибку настройки, а не создавать неподтверждаемый legacy draft. Intent сохраняет все параметры Event/Game и выбранные Telegram-чаты. После подтверждения создаётся полноценная standalone-игра с выбранным форматом, составом сторон, scoring/timing/recruitment-настройками; Telegram-публикации готовятся после появления опубликованного Event.

## Архитектурные границы

- `VenueBooking` остаётся отдельным агрегатом и единственным источником коммерческого статуса слота.
- До `confirmed` хранится только event intent, а не draft Event.
- Подтверждение обрабатывается через существующее transactional outbox-событие `VenueBookingConfirmed`; listener обязан быть идемпотентным.
- Порядок блокировок остаётся `venue → venue_booking → event intent/Event`.
- Ошибка Telegram-публикации не должна откатывать уже подтверждённую аренду или бесконечно блокировать outbox.
- Существующие legacy-мероприятия не мигрируются автоматически этой задачей.

## Пользовательские сценарии

- организатор создаёт мероприятие на свободной площадке и сразу получает опубликованную страницу;
- организатор отправляет заявку на аренду и переходит на страницу брони, где видит, что мероприятие появится после подтверждения;
- владелец принимает заявку, при необходимости проходит оплата/финальное подтверждение, после чего Event создаётся автоматически;
- повторная доставка события подтверждения не создаёт дубликат Event;
- выбранные настройки игры и Telegram-чаты не теряются между заявкой и подтверждением;
- несвободная площадка без опубликованных условий аренды не создаёт «вечный» draft.

## Результат

Мастер создания мероприятий переведён на booking-first flow для площадок с
активной политикой аренды. До подтверждения брони хранится intent с параметрами
Event/Game и Telegram-чатами; после `confirmed` опубликованное мероприятие создаётся
идемпотентно через transactional outbox. Для свободных площадок сохранён немедленный flow,
а несвободная площадка без опубликованной политики возвращает явную ошибку. Предварительная
цена в мастере показывается только для длительности, соответствующей ограничениям
активной политики.
