# 330 — Единое действие «Хочу здесь играть»: аренда по залу или избранное

**Целевая среда:** production (`main`), по утверждённому 18.11.2026 порядку. **Приёмка:** зелёный CI, merge PR в `main`, подтверждённый production deploy и адаптивная проверка.

## Запрос

На странице площадки кнопка «Хочу здесь играть» больше не должна автоматически открывать конфигуратор игровой подписки. Сначала показать понятный выбор из двух действий — **«Аренда площадки»** и **«Добавить в избранное»**. Сложные игровые предпочтения и похожие площадки настраиваются только в ЛК «Мои подписки».

### Аренда

1. Краткое описание шагов: выбор зала → дата и реальные свободные слоты → вход/регистрация при необходимости → штатное оформление аренды и подтверждение.
2. Для единственного зала или страницы конкретного зала автоматически установить зал. Для нескольких залов на общей странице обязательно предложить селект без ложного выбора первого.
3. Кнопка «Выбрать дату» открывает существующий диалог расписания. `venue_court_id` должен совпадать на всех этапах: выбор, запрос публичной доступности, выбор слотов, quote.
4. Отдельные расписания разных залов не смешиваются. При смене зала на общей странице сбрасывать неактуальные часы/показатели занятости до загрузки данных конкретного зала.
5. Даже если пользователь открыл обычную дату из общей ленты расписания, при нескольких залах сначала получить его явный выбор.

### Избранное и интересы

1. «Добавить в избранное» открывает отдельный компактный диалог подтверждения. Используется **существующий** Favorite API; создание PlayIntent или бронирования не требуется.
2. Авторизованный пользователь с активным избранным данной площадки должен учитываться в группе прямого интереса «Площадкой интересуются» независимо от игровой подписки. Гостевое избранное не создаёт публичного профиля, но переходит к аккаунту по штатной процедуре `claim`.
3. Ранее оформленные прямые игровые подписки остаются в прежней группе как совместимые исторические записи. Один канонический пользователь учитывается лишь раз, даже при подписке + избранном; согласие на показ игровых данных нельзя выводить из самого факта избранного.
4. «Подходят по условиям» остаётся второй группой, с существующим механизмом сопоставления предпочтений.
5. Изменения избранного на странице обновляют и сердечки, и аудиторию без полной перезагрузки. Сердечки на странице больше не открывают большой конфигуратор игровой подписки.

## Проверки

- Одна площадка / одна зона, несколько залов и переход на страницу отдельного зала.
- Переключение двух залов с различной занятостью; ни один слот или цена не приписывается другому залу.
- Неавторизованный пользователь может видеть слоты и пройти предусмотренную авторизацию; предпочтения не создаются автоматически.
- Создание, удаление и повторное создание избранного, возврат после гостевой авторизации; корректные toast и ошибки.
- Дедупликация в direct, сохранение matched, отсутствие утечки скрытого аватара/характеристик.
- Мобильные экраны, десктоп, клавиатура, native dialog/top layer, корректная работа остальных диалогов.
- `node --test`, релевантный PHPUnit, сборка `npm run build`, зелёный GitHub Actions и production deploy.
