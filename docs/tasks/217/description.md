# 217 — UI кошелька пользователя в личном кабинете

## Оригинальное описание

После Task 214 финансовый контур уже умеет хранить пользовательский кошелёк,
разделять real/bonus остатки и вести immutable ledger, но пользователь пока не
видит эти данные в интерфейсе.

Добавить первый пользовательский UI кошелька в личный кабинет без преждевременной
реализации эквайринга, вывода или Purchase flow.

## План

- добавить пункт «Кошелёк» в навигацию аккаунта;
- добавить страницу `/account/wallet`;
- показывать общий доступный баланс;
- отдельно показывать основной (real) и бонусный остатки;
- показывать последние завершённые операции с разложением суммы по real/bonus;
- читать кошелёк канонической identity для user alias;
- не создавать кошелёк как побочный эффект GET-запроса;
- не добавлять пока кнопки пополнения, вывода, P2P или покупки;
- покрыть UI и чтение кошелька feature-тестами;
- обновить Finance-документацию.

## Архитектурные границы

Presentation получает read model через Finance Application query. UI не должен
читать ledger напрямую из Blade и не должен самостоятельно менять финансовые
остатки.

Если кошелёк ещё не создан, страница отображает 0 ₽ и пустую историю. Создание
кошелька остаётся обязанностью финансового use case в момент первой реальной
операции.

История первой версии ограничивается последними 50 операциями. Полноценная
пагинация, фильтры и экспорт остаются отдельным развитием.

## Не входит в задачу

- эквайринг и реальные пополнения;
- вывод средств;
- P2P;
- Purchase/Order;
- оплата конкретной Pricing-услуги;
- UI кошельков Team/Event/Venue;
- административные корректировки баланса.

## Проверка

- профильные Feature tests Finance;
- полный CI PR: PHP tests + production compose validation + frontend build;
- ручной smoke `/account/wallet` на desktop/mobile после deploy.

## Статус

В работе.
