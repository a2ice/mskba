# 089 - Приём заявок от неподтверждённых пользователей в balanced-турниры

## Оригинальное описание

Добавить на уровне турнира в режиме формирования balanced-команд настройку, разрешающую принимать заявки от пользователей с неподтверждённым аккаунтом. По умолчанию настройка выключена. Если подача заявки запрещена, пользователь должен увидеть точное сообщение: «Для подачи заявки необходимо подтвердить аккаунт».

## Контекст

В турнире с формированием команд из отдельных участников пользователь подаёт персональную заявку, после чего организатор рассматривает её и формирует balanced-команды. Сейчас попытка неподтверждённого пользователя может завершаться без понятного результата: заявка не появляется у организатора, а заявитель не получает точного объяснения причины.

Ограничение должно быть явной настройкой конкретного турнира, а не неявным глобальным условием.

## Требуемое поведение

- Для турниров, в которых команды формируются из заявившихся участников, добавить настройку «Принимать заявки от неподтверждённых пользователей».
- Значение по умолчанию — выключено.
- Если настройка выключена, неподтверждённый пользователь не может подать заявку.
- При отказе нужно показать точное сообщение: «Для подачи заявки необходимо подтвердить аккаунт».
- При отказе заявка не создаётся, уведомления организатору и ответственным не отправляются.
- Если настройка включена, заявка неподтверждённого пользователя создаётся в обычном статусе ожидания и проходит стандартный процесс рассмотрения.
- Подтверждённые пользователи продолжают подавать заявки независимо от значения настройки.
- Приглашения, отправленные организатором конкретному пользователю, не должны блокироваться этой настройкой: приглашённый пользователь может принять или отклонить приглашение.
- Сценарий турнира с заранее определёнными командами и командные заявки не должны измениться.

## UI/UX

- Показывать настройку в форме создания и управления турниром только для режима формирования команд из отдельных участников.
- Использовать фирменный переключатель с понятной подписью и пояснением последствия выключенного состояния.
- При переключении турнира на другой режим скрывать настройку; сервер не должен сохранять активное значение для неподходящего режима.
- Ошибка неподтверждённого аккаунта должна отображаться на публичной странице турнира рядом со сценарием подачи заявки, а не как безликая HTTP-ошибка или ложное сообщение об успешной отправке.

## Данные и backend

- Хранить настройку как boolean-поле турнира со значением `false` по умолчанию.
- Добавить приведение типа в модели.
- Проверять настройку и подтверждение аккаунта на сервере до создания заявки.
- Не полагаться только на скрытие или блокировку элементов интерфейса.
- Для режимов турнира, к которым настройка неприменима, принудительно нормализовать значение в `false` либо игнорировать входное значение.
- Сохранить существующие проверки повторных и уже активных заявок.

## Уведомления

- После успешно созданной заявки организатор и пользователи с соответствующими правами получают существующее уведомление и realtime toast.
- При отклонённой до создания заявке никаких уведомлений не формируется.

## Критерии приёмки

1. Новый balanced-турнир создаётся с выключенным разрешением заявок от неподтверждённых аккаунтов.
2. Неподтверждённый пользователь при выключенной настройке видит сообщение «Для подачи заявки необходимо подтвердить аккаунт»; записи заявки и уведомления не появляются.
3. После включения настройки тот же пользователь может отправить заявку, а организатор видит её и получает уведомление.
4. Подтверждённый пользователь может подать заявку при любом значении настройки.
5. Персональное приглашение от организатора доступно неподтверждённому пользователю независимо от настройки.
6. Турниры с готовыми командами и их заявки работают без изменений.
7. Подмена запроса на клиенте не позволяет применить настройку к неподходящему режиму турнира.

## Проверки

- Feature-тест создания и обновления настройки турнира.
- Feature-тест отказа неподтверждённому пользователю с проверкой точного текста ошибки и отсутствия заявки/уведомления.
- Feature-тест успешной заявки неподтверждённого пользователя при включённой настройке.
- Регрессионные тесты заявки подтверждённого пользователя, приглашения пользователя и режима готовых команд.

## Результат выполнения

- В Tournament добавлено boolean-поле `accepts_unconfirmed_participants` со значением `false` по умолчанию и приведением типа в модели.
- Формы создания и управления показывают фирменный переключатель только для режима формирования balanced-команд; при другом режиме сервер принудительно сохраняет `false`.
- Сервер отклоняет самостоятельную заявку неподтверждённого пользователя до создания admission и уведомления с точным сообщением «Для подачи заявки необходимо подтвердить аккаунт».
- Разрешённая заявка создаётся в статусе ожидания и использует существующую доставку уведомления организатору.
- Подтверждённые пользователи, командные заявки и персональные приглашения продолжают работать независимо от настройки.
- Добавлены feature-тесты default/нормализации настройки, отказа без побочных эффектов, разрешённой заявки, подтверждённого пользователя и приглашения неподтверждённого пользователя.
- Гость видит основную оранжевую CTA «Подать заявку», которая открывает существующий popup авторизации и возвращает пользователя на страницу турнира.
- Авторизованный пользователь выбирает в popup одну или несколько ролей игрока, тренера и менеджера; непустой набор сохраняется в admission и показывается организатору.
- Каталог турниров показывает записи от более поздней даты начала к более ранней; одинаковые даты стабилизируются по убыванию ID.
- Решение по заявке помечает исходное уведомление организатора прочитанным, отправляет заявителю realtime toast с результатом и убирает CTA подачи заявки на открытой странице без перезагрузки.
- Ответ на персональное приглашение также помечает исходное уведомление приглашённого прочитанным.
- Mutation- и sync-URL realtime-уведомлений формируются относительными, поэтому toast корректно закрывается при локальном порте и любом фактическом origin.
- В preview balanced-команд строка амплуа и полноты раскрывает две независимо сворачиваемые группы: игровые показатели и физические данные. Все характеристики идут единым списком, отсутствующие значения обозначаются прочерком.
- В preview название каждой команды редактируется до утверждения и сохраняется вместе с составом; действие называется «Утвердить команды».
- Каждая preview-команда автоматически получает одну из 12 нейтральных эмблем MSKBA; организатор может выбрать другую или загрузить собственный логотип. Выбранное изображение сохраняется у участника турнира и фиксируется в стороне созданного матча для страницы игры и live-трансляции.
- Закрытие набора хранится в `participant_pool_locked_at`: balanced-пул фиксируется утверждением команд, а для готовых команд организатор явно завершает или возобновляет набор до назначения первой игры.
