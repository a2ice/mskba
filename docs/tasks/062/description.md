# 062 - Добавить универсальный предикативный выбор площадки и выбор на карте

## Оригинальное описание

Централизовать выбор площадки: искать по названию, метро, тегам и улице, поддержать контекстные фильтры и выбор подтверждённой площадки на Яндекс Карте. Для формы создания мероприятия учитывать физическую доступность и выбранное время. Использовать Redis с инвалидацией при изменении условий площадки.

## Подробное описание

Универсальный endpoint поиска сохраняет прежние необязательные фильтры и дополняется параметрами:

- `confirmed_only` — только публично подтверждённые площадки;
- `operational_status` — физическое состояние площадки;
- `starts_at` и `duration_minutes` — доступность конкретного будущего интервала;
- `limit` — размер выдачи.

Форма создания мероприятия использует удалённый предикативный select. Запрос ищет по названию, адресу/улице, метро и тегам, а также передаёт подтверждённость, физическую активность, начало и длительность. Ссылка «На карте» открывает Яндекс Карту с доступными подтверждёнными площадками; клик по метке выбирает площадку в той же форме.

Redis хранит версионированную поисковую проекцию и короткоживущие результаты публичных запросов. Изменение площадки, тегов, адреса, метро, расписания или брони увеличивает версию и тем самым инвалидирует старые ключи. Динамический результат по времени кэшируется недолго, но `CreateEventHandler` по-прежнему выполняет транзакционную проверку БД: кэш не является источником истины для бронирования.

## Результат

- `/venues/search` стал универсальным источником с опциональными фильтрами подтверждения, физического состояния и временного интервала;
- поисковая проекция и публичные результаты кэшируются через основной Laravel cache store, в production — Redis;
- централизованный observer инвалидирует версию при изменении площадочных условий, расписания или брони;
- форма создания мероприятия использует удалённый предикативный select и ищет по названию, адресу, метро и тегам;
- рядом с избранными площадками добавлен выбор на Яндекс Карте, клик по метке заполняет форму;
- холодная проверка временного интервала не создаёт N+1: расписания eager-load, пересечения броней выбираются одним запросом;
- транзакционная проверка `CreateEventHandler` сохранена как окончательная защита от конкурентного двойного бронирования.
