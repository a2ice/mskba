# 143 — Переработать location mini-wizard поиска мероприятий

## Контекст

Production smoke-check Task 140/141 показал, что текущий nested flow локации перегружает мобильный интерфейс:

- общий footer `Назад / Пропустить / Далее` продолжает управлять внешним wizard даже когда пользователь находится внутри mini-wizard географии;
- горизонтальные шаги `Город → Район / округ → Метро → Улица и площадка` не отражают реальные зависимости и показывают нерелевантные шаги, например метро для Химок;
- Tom Select со всем списком метро увеличивает высоту modal и может перекрываться sticky footer;
- для поиска около метро и около текущей геопозиции нужен единый радиус поиска по координатам.

## Цель

Сделать location mini-wizard условным вложенным flow, где набор следующих шагов определяется предыдущим выбором, а общий footer временно управляет mini-wizard.

## UX-контракт

### Общая навигация

Когда активен mini-wizard:

- `Назад` возвращает на предыдущий внутренний шаг;
- `Пропустить` пропускает текущий необязательный внутренний шаг;
- `Далее` подтверждает текущий внутренний шаг;
- на последнем внутреннем шаге кнопка завершает mini-wizard, после чего footer снова управляет внешним wizard;
- активная область mini-wizard выделяется оранжевой рамкой.

Шаги появляются сверху вниз. Уже пройденные значения остаются видимыми как компактные редактируемые summary-карточки. Изменение более раннего значения сбрасывает несовместимые зависимые значения ниже.

### Москва

После выбора Москвы пользователь выбирает взаимоисключающий сценарий:

1. `Рядом с метро` → predictive выбор станции → `Радиус поиска` → `Улица и площадка`;
2. `По округу` → административный округ → `Улица и площадка`;
3. `Не важно` → `Улица и площадка`.

Округ и метро не применяются одновременно.

### Другие города

Для не-Москвы:

- если у города есть районы/микрорайоны: `Город → Район → Улица и площадка`;
- если районов нет: `Город → Улица и площадка`.

Шаг метро не показывается.

### Текущая локация

`Текущая локация` определяет anchor по GPS/reverse geocode и открывает тот же reusable шаг `Радиус поиска`, затем `Улица и площадка`.

### Радиус

Reusable radius step работает только при наличии anchor coordinates (`latitude`, `longitude`). В первой версии варианты: `1 / 3 / 5 / 10 км`, default — `3 км`.

Фильтрация по радиусу выполняется по координатам площадки, а не по административному району.

### Метро

Большой dropdown Tom Select внутри mini-wizard убирается. Вместо него используется predictive input по каноническому справочнику `MetroStation` с координатами и линией. По UX это тот же паттерн, что у Yandex street suggestions, но источник станции — собственный справочник, чтобы получить стабильный station id и anchor coordinates без неоднозначного геокодинга.

## Backend

- `/home/location-options` дополнительно отдаёт станции метро с `id`, `name`, line metadata и координатами;
- event discovery принимает `latitude`, `longitude`, `radius_km` и применяет radius filter к площадке;
- `venues.search` принимает тот же anchor/radius, чтобы predictive площадки и карта не показывали площадки вне радиуса;
- точный distance считается по Haversine; фильтр применяется до пользовательского `limit`.
