# 297 — Постоянная URL-страница группы интересов площадки (MVP) и ссылка из попапа

## Продукт
В попапе «Площадкой интересуются» добавить ссылку «Перейти к группе». По ней открывать **полноценную страницу**, а не новый диалог: место встречи людей с интересами к этой площадке. Первый этап — **тот же список пользователей и счётчики**, который сейчас есть в попапе, с разделением «Подписаны на эту площадку» / «Подходят по условиям».

## Идентичность и URL
- Ввести устойчивую сущность/адрес **группы интересов площадки**. Предлагаемый маршрут (согласовать при реализации): `/venues/{venue}/interest-groups/{group}` либо `/venues/{venue}/interests` для единственной базовой группы. Адрес должен быть постоянным, каноническим, с правильными 404/redirect после смены alias площадки.
- **Не создавать страницу на каждую индивидуальную подписку или комбинацию произвольных фильтров.** Базовый MVP — одна группа интересов на конкретную площадку; допускается будущее деление на именованные подгруппы по времени/формату с собственным стабильным group ID и URL.
- Определить стабильность группы при отсутствии участников и удалении/блокировке площадки. Не создавать дубликаты при конкурентном первом заходе.
- Группа **не** равна `PlayAssembly`/`PlayOpportunity` из Task 287: здесь долговременное сообщество, там процесс подготовки конкретной игры.

## Данные и приватность
- Переиспользовать `VenueSubscriptionAudience::forVenue` как единую серверную проекцию для popup и страницы, без копирования логики совпадений в шаблоны.
- Сохранять текущие правила `show_on_venue`, каноническую дедупликацию, маскировку приватных профилей, отдельное основание для показа подробностей; никакого раскрытия личных часов, контактов и скрытых анкет.
- Прямые и подходящие по критериям пользователи могут пересекаться: в суммарном числе каждый один раз, отображать в прямой группе по принятому приоритету.
- Членство в группе производно от **актуального активного интереса**, не путать с подтверждённым участием в игре и не давать права действия только за просмотр списка.

## MVP UI
- На странице: заголовок и ссылка на площадку; общее число интересующихся; две секции участников с аватарами, статусы собственной подписки, действия «Хочу здесь играть» / «Мои подписки».
- Ссылка в попапе доступна с клавиатуры, обычный anchor c реальным `href`, сохраняет корректное поведение drag/закрытия. Также дать точку входа из самого блока площадки при желании.
- Предусмотреть навигацию и точки расширения под Task 298–300 (организация игры, бронь, спецпредложения), но **не реализовывать их имитацией** в MVP.
- Возможность открыть страницу у гостя не должна раскрывать приватные профили; действия по созданию требуют auth.
- Совместимые UI и тесты для mobile/desktop, direct URL, доступность и отсутствие утечек.

## Приёмка
1. Попап открывает нужный стабильный group URL; повторные переходы и другой пользователь видят **ту же группу**, не новую «копию».
2. Счётчики и доступные профили на странице совпадают с попапом; изменения интереса отражаются при новом запросе.
3. Пустая группа, исчезнувшая площадка, приватные подписки и чужие ID корректны.
4. Нет раскрытия скрытых профилей/контактов или двойного учёта; UI соответствует дизайн-системе.

**Приоритет:** после 295–296. **Связано:** 286, 287, 288. **Статус:** запланировано.

## Реализация MVP
- Стабильный канонический URL `/venues/{venueId}/interest-group` привязан к числовому ID площадки, не зависит от изменяемого alias. В первой версии одна базовая группа интересов на площадку; создание отдельных именованных подгрупп, сборов и брони — задачи 298–300.
- Для страницы и существующего попапа один и тот же `VenueSubscriptionAudience::forVenue` и Blade partial списка. Не показывать больше данных, чем существующий popup разрешает `show_on_venue`/`can_view_details`.
- Группа открывается гостем, но только для подтверждённой площадки; ответ `private, no-store`, действия ведут к существующему сценарию подписки на Venue. Добавлены feature/UI tests, приемка на dev-e после CI.
