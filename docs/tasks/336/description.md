# 336 — Социальные группы MSKBA, выборы админа, обсуждения и RSVP мероприятий

**Основная задача:** [GitHub #849](https://github.com/a2ice/mskba/issues/849). **Статус:** реализация по инкрементам. Производственная публикация только после CI, security и smoke.

Объединяет [PlayIntent](../../project/play-intent.md), [группы и подбор](../287/group-interest-workspace-20261118.md), [выборы, названия и роли](../287/group-governance-20261118.md), [287](../287/description.md), [297](../297/description.md), [298](../298/description.md).

## Жёсткие требования

1. При проверенном пересечении активных интересов создаётся стабильная группа с UUID, понятным автоматически сформированным названием, необязательным кастомным названием (избранный администратор или Filament), списком участников и общими подходящими площадками/временем. Отдельные игры/Event/Booking имеют свои циклы.
2. Выборы администратора: кандидат — подтверждённый участник; мотивация ≥20 символов; один действующий администратор; порог строго >50% от голосующего состава и минимум 3 (исключение — 2 человека, требуется согласие обоих). Один голос на канонического пользователя, перенос голоса с кандидата на кандидата, мгновенный пересчёт. Смена администратора — тем же механизмом.
3. **Каждая реальная заявка/отданный голос/перенос голоса/отзыв, избрание, смещение, служебная замена и переименование** сопровождаются серверным системным сообщением в хронологической стене конкретной группы. Например: «Игрок_17 подтвердил назначение Игрока_23 администратором группы». При переносе голоса старая запись остаётся, но текущая поддержка переходит новому. Ни два голоса, ни два администратора одновременно недопустимы.
4. Только групповой администратор запускает group-scoped опросы, групповые сборы, мероприятия и аренды. Обычные личные маршруты Event и VenueBooking не ограничиваются задним числом; group-admin не получает прав владельца площадки, плательщика или право подтверждать чужое участие.
5. У каждого мероприятия отдельная стена: обычные комментарии (до 200 символов) и системные сообщения о каждом **реальном изменении** «Пойду/Думаю/Не пойду». Лимит **3 пользовательских social-действия за скользящие 60 секунд на канонического пользователя**, включая комментарии, RSVP, голос за админа; серверный rate limit. Создание системного сообщения бесплатно. Повтор того же статуса — no-op. Текущие счётчики — из EventParticipant, история не изменяется.
6. Авторское удаление обычного сообщения оставляет **зачёркнутый исходный текст** и статус. Модератор может скрыть опасный текст полностью; системные сообщения недоступны авторскому удалению.
7. API/сервер: проверка identity/confirmed, group membership, версии RSVP, ограничения Event/Booking, CSRF/auth, атомарность записи + системного события, idempotency, лимиты и ошибки 422/403/404/409/429.
8. UI существующей темы и гайдлайна: полноценные вкладки обсуждения/участников/истории, breadcrumbs, sidebar, общий header/footer/mobile bar/FAQ; не переписывать layout, не дублировать функции сайта. Mobile/TMA/desktop/клавиатура.

## Техническая декомпозиция

- **336-A — Основание:** единый activity stream с типизированными событиями `scope: event|play_opportunity`, автором и `payload`, модерацией, append-only лентой, rate limit/idempotency. Системные действия и сообщения не равны простым пользовательским комментариям.
- **336-B — Мероприятия:** интеграция действующего `SetEventParticipationHandler`, транзакционный history ledger, актуальные счётчики, общая стена, AJAX и вкладки без потери layout.
- **336-C — Группы:** `PlayOpportunity`, реальное совпадение формата/времени/площадок у **всех** членов группы, стабильный URL, ЛК /account/subscriptions и права просмотра.
- **336-D — Администрирование:** один администратор, кандидаты и 20+ символов, >50%/мин.3, смена голоса и append-only запись на стене на каждый голос, Filament override, custom title, действия только group-admin.
- **336-E — Рабочая группа:** рейтинг 1–10 по предложенным площадкам, выбор времени/дат, комментарии, общий FAQ, передача в штатные Coordination/Event/Booking без дублей и обхода прав.
- **336-F — Надёжность:** concurrency/permissions/regression/frontend tests, UI Kit, production smoke, TMA/mobile.

## Приёмка

- Разовая подписка и регулярная дают только реальные совместимые даты/окна/места; ложная транзитивная группа A↔B↔C не создаётся.
- Конкурирующие POST дают один election/administrator, одна кандидатура на пользователя. Для 5 нужны 3, для 6 — 4, для 2 — 2. Голос меняет суммарную поддержку и оставляет отдельный trace, не заменяя старую запись.
- Четыре пользовательских действия за 60 секунд: первые три проходят, четвёртое 429 (без расхода за системное логирование), никаких двойных голосов алиасов. Серверная точность 20/200 Unicode-символов.
- RSVP `confirmed → left`: confirmed_count уменьшается ровно на один, `left` текущий; оба события видны на стене с датой и участником. Повтор same-status не создаёт запись.
- Старые Event/Booking, Sidebar, breadcrumbs, header, вкладки, профиль, Filament, нижнее меню не регрессируют.
