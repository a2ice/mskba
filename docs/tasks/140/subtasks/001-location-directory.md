# 140/001 - Location directory

## Цель

Добавить канонические справочники городов и районов/округов, связать их с `Address` и подготовить начальные данные для Москвы и Химок.

## Статус

Выполнено.

## Реализация

- добавлены `City` и `District` в модуле `Location`;
- добавлены factories для обеих сущностей;
- добавлена отдельная migration с таблицами `cities`, `districts` и nullable FK `addresses.city_id`, `addresses.district_id`;
- строковое поле `addresses.city` сохранено как snapshot внешнего структурированного адреса;
- `CreateLocationDTO` и `CreateLocationHandler` умеют сохранять directory FK и проверяют принадлежность района выбранному городу;
- добавлен production-safe `GeographySeeder` с `firstOrCreate`, чтобы повторный запуск не затирал будущие ручные изменения администратора;
- начальные города: Москва (`moscow`) и Химки (`khimki`);
- для Москвы добавлены 12 административных округов;
- для Химок добавлены 9 районов/территорий;
- существующие адреса с очевидными значениями `Москва`/`Химки` получают `city_id`, а `district_id` намеренно не угадывается;
- добавлены проверки сохранения FK, city/district consistency, initial seed, backfill и идемпотентности seed.

## Следующий шаг

`002-yandex-location-resolution`: расширить структурированный ответ Yandex административными компонентами и добавить resolver `Yandex -> City/District` без автоматического создания неизвестных справочных записей.
