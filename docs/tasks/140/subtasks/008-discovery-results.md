# 140/008 — Discovery endpoint и результаты поиска

Статус: выполнено.

## Что реализовано

- добавлен публичный read-only endpoint `GET /home/event-discovery` для homepage popup;
- endpoint объединяет в один список:
  - игры;
  - тренировки;
  - игровые тренировки;
  - турниры;
- публичные Event выбираются только со статусом `published` и visibility `public`;
- турниры выбираются только со статусом `confirmed`;
- поддержаны фильтры wizard-а:
  - тип мероприятия;
  - формат игры/турнира;
  - режим набора standalone-игры;
  - enrollment policy турнира;
  - город;
  - район/округ;
  - одна или несколько станций метро (OR внутри списка станций);
  - улица;
  - конкретная площадка;
  - диапазон дат;
- география фильтруется по каноническим связям `Venue -> Location -> Address/MetroStation`, а не по строковому поиску по всему адресу;
- для турнира локацией считается `defaultVenue`;
- турнир попадает в диапазон, если его период пересекается с выбранным диапазоном дат;
- Event и Tournament после выборки сортируются в единой временной ленте;
- результат содержит URL, тип, дату/время, площадку, адрес и применимые игровые параметры.

## Шаг `5 · Результаты`

Homepage wizard получил отдельный финальный UI-шаг `5 · Результаты`.

При переходе с `Когда`:

1. текущие значения фильтров собираются из UI;
2. выполняется запрос к `/home/event-discovery`;
3. поверх контейнера результатов показывается существующий стандартный `image-upload-loading` overlay/spinner;
4. после ответа выводятся карточки мероприятий и турниров в одном списке;
5. доступны empty-state, error-state и повторная загрузка через `Обновить`.

На финальном шаге правая кнопка общего footer меняется на `Готово`. `Назад` возвращает на диапазон дат. Возврат к предыдущим фильтрам и повторный переход к результатам запускает поиск заново.

## Compatibility

Основной event search flow из `005` по-прежнему владеет шагами `Тип -> Параметры -> Где -> Когда`. Срез `008` добавляет финальный discovery-state поверх него и перехватывает только переход `Когда -> Результаты`, поэтому legacy catalog redirect больше не выполняется при финальном `Далее`.

## Проверки

Добавлен feature test `HomeEventDiscoveryControllerTest`, который защищает:

- объединение Event + Tournament;
- географические фильтры City/District/Metro/Street;
- фильтр конкретной игровой конфигурации `format + recruitment_mode`;
- исключение неподходящих по географии результатов.

В итоговом verification-срезе остаются обязательными полный backend test run, `npm run build` и ручной desktop/mobile smoke-check popup-а.
