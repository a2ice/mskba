# 002 - Yandex location resolution

## Цель

Связать структурированный ответ Yandex address suggest/reverse geocode с внутренними справочниками `City`/`District`, чтобы новые и изменяемые адреса автоматически получали `city_id` и `district_id` без создания географии из внешнего ответа.

## Статус

Выполнено.

## Реализация

- `AddressSuggestionDTO` расширен нейтральным списком административных компонентов `administrativeAreaNames`.
- `YandexAddressSuggestProvider` извлекает административные компоненты типов `district` и `area` вместе с уже существующими городом, улицей, домом, координатами и метро.
- добавлен `GeographyResolver`, который:
  - нормализует названия городов и административных территорий;
  - понимает варианты вроде `г. Москва`, `городской округ Химки`, `мкр. Сходня`;
  - сопоставляет город по `name`, `short_name`, `alias`;
  - сопоставляет район/округ только внутри найденного города;
  - при отсутствии распознанного города может вывести его из единственного совпавшего района;
  - никогда не создаёт неизвестные города/районы автоматически.
- `AddressSuggestService` возвращает `city_id`, `district_id`, канонические названия города/района и исходные административные компоненты.
- desktop и Telegram address suggest формы получили скрытые `city_id`/`district_id`; `address-suggest.js` заполняет и сбрасывает их вместе с остальными структурированными полями.
- `CreateVenueRequest` и `UpdateVenueRequest` валидируют и передают новые FK в `CreateLocationDTO`.
- `VenueRevisionManager` сохраняет `city_id`/`district_id` в snapshot/draft и восстанавливает их при применении ревизии.
- `CreateLocationHandler` дополнительно пытается сопоставить канонический `City` по строковому городу, если `city_id` не передан, и при найденном справочнике сохраняет каноническое русское название.

## Проверки

Добавлено/расширено покрытие для:

- нормализации Москвы и московских административных округов;
- нормализации микрорайонов Химок;
- вывода города из уникального района;
- отсутствия автоматического создания неизвестной географии;
- полного Yandex -> AddressSuggestService mapping для `city_id`/`district_id`;
- reverse geocode с определением района;
- серверного fallback-сопоставления города при создании `Location`.

Фактический запуск тестов выполняется на итоговом этапе проверки Task 140, когда доступно исполняемое Laravel-окружение.
