# 140/005 — Тип и параметры поиска мероприятий

Статус: выполнено.

## Что реализовано

- eyebrow popup `Игры и тренировки` заменяется на `Мероприятия`;
- основной поиск мероприятий получил четыре рабочих шага на текущем этапе: `Тип -> Параметры -> Где -> Когда`; финальный `Результаты` будет добавлен в срезе `008` вместе с discovery endpoint;
- на шаге `Тип` добавлен вариант `Не важно`, выбранный по умолчанию;
- выбор типа больше не переводит пользователя автоматически на следующий основной шаг;
- для каждого типа добавлена проектная tooltip-кнопка `?` без underline;
- шаг `Параметры` динамически зависит от выбранного типа;
- для `Игра` доступны:
  - формат: `Не важно`, `Баскетбол 5×5`, `Стритбол 3×3`, `Стритбол 1×1`;
  - режим: `Не важно`, `Готовые команды`, `Отдельные игроки`;
- для `Турнир` доступны:
  - формат: `Не важно`, `Баскетбол 5×5`, `Стритбол 3×3`, `Стритбол 1×1`;
  - порядок набора: `Не важно`, `Открытая лига`, `Фиксированный состав`;
- значения фильтров совпадают с доменными enum:
  - `GameFormatEnum`: `basketball_5x5`, `streetball_3x3`, `streetball_1x1`;
  - `GameRecruitmentModeEnum`: `preformed_teams`, `individual_draft`;
  - `TournamentEnrollmentPolicyEnum`: `continuous`, `fixed_pool`;
- для `Тренировка`, `Игровая тренировка` и общего типа `Не важно` показывается понятный empty state и доступен `Пропустить`;
- выбранные тип/формат/режим/порядок набора отображаются в редактируемых summary badges;
- нажатие на summary badge возвращает пользователя к соответствующему шагу;
- общий footer из `004` используется без отдельной реализации навигации;
- legacy event wizard оставлен только как compatibility layer для старой разметки, но его progress/type UI нейтрализован: новый event flow использует отдельный progress state, поэтому старый auto-advance больше не управляет основными шагами;
- существующий predictive venue selector пока остаётся на шаге `Где` и будет полностью перестроен в `006`.

## UI/UX детали

Tooltip использует существующий проектный контракт `.ui-tooltip-trigger + data-tooltip`, поэтому работает тем же floating tooltip, что и остальной интерфейс MSKBA.

В параметрах `Не важно` является реальным выбранным состоянием, а не отсутствием значения. Это позволит discovery read model в `008` однозначно отличать отсутствие фильтра от конкретного доменного значения.
