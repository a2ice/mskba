# 140/006 — Location mini-wizard для поиска мероприятий

Статус: выполнено.

## Что реализовано

- шаг `3 · Где` получил верхний выбор `Не важно / Указать локацию`;
- `Не важно` выбран по умолчанию и считается завершённым выбором без фильтрации;
- `Указать локацию` раскрывает вложенный mini-wizard:
  1. город;
  2. район / округ;
  3. метро;
  4. улица и площадка;
- справочники городов/районов загружаются из отдельного public read-only endpoint `/home/location-options`;
- endpoint использует реальные `City` / `District`, поэтому изменения из админ-справочника автоматически попадают в homepage flow;
- город выбирается из справочника, рядом доступен `Не важно`;
- районы зависят от выбранного города; если у города нет районов, район автоматически считается `Не важно`;
- при выборе города `Не важно` район также автоматически становится `Не важно`;
- метро переиспользует существующий `MetroStation` / TomSelect selector и существующие фильтры площадок;
- выбранные подшаги превращаются в редактируемые badges; клик по badge возвращает к соответствующему подшагу;
- вложенные подшаги автоматически переходят вперёд после валидного выбора, при этом основные шаги popup по-прежнему переключаются только footer-кнопками `Назад / Далее`;
- добавлена кнопка `Текущая локация` с тем же browser/Telegram geolocation + backend reverse-geocode + Yandex flow, который используется для адресов площадок;
- при ошибке выводится согласованный текст:
  `Не удалось получить геопозицию. Попробуйте ещё раз или введите вручную ниже`;
- reverse geocode автоматически подставляет известные `city_id`, `district_id`, метро и улицу;
- улица реализована как predictive Yandex input; при выбранном городе его название добавляется к запросу;
- улицы дедуплицируются по структурированному `street`, а результат другого известного города отбрасывается;
- после выбора улицы predictive площадки автоматически прогревается запросом по этой улице, а отображаемые варианты дополнительно фильтруются по выбранным городу/улице;
- при изменении улицы ранее выбранная площадка очищается;
- площадка остаётся необязательным уточнением: можно завершить location step на уровне города/района/метро/улицы;
- существующий predictive venue selector переиспользован для финального выбора площадки;
- map action внутри этого вложенного selector скрыт, чтобы не показывать карту без нового city/street contract до его отдельной доработки;
- основной summary шага `Где` получает человекочитаемое значение выбранной локации.

## Backend contract

Добавлены:

- `HomeLocationOptionsController`;
- route `home.location-options`;
- feature test публичного read model.

Ответ endpoint содержит:

- города;
- вложенные районы;
- URL существующего Yandex suggest endpoint;
- URL существующего reverse-geocode endpoint.

## Технические детали

Для browser/Telegram coordinates + reverse geocode добавлен небольшой reusable helper `current-location.js`. Он повторяет проверенный механизм существующего address flow и используется homepage mini-wizard без изменения доменной модели.

До реализации discovery endpoint (`008`) location state живёт внутри frontend wizard. Для совместимости с уже существующим footer/state слоя используется внутренний sentinel в hidden venue value; наружу он не отправляется и не является доменным идентификатором площадки.
