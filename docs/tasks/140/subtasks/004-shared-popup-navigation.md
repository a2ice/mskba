# 140/004 — Общая навигация homepage popup-wizard

Статус: выполнено.

## Что реализовано

- добавлен единый footer/navigation contract для поисковых wizard-ов `Мероприятия` и `Площадки`;
- footer содержит две постоянные кнопки: `Назад` слева и `Далее` справа;
- на первом шаге `Назад` остаётся видимой, но disabled, чтобы геометрия панели не менялась между шагами;
- центральная зона footer зарезервирована под контекстную ссылку `Пропустить`;
- `Пропустить` уже подключён для текущего пропуска локации в поиске мероприятий;
- footer закрепляется у нижней границы scrollable popup и имеет отдельную mobile/safe-area адаптацию;
- старые локальные CTA навигации скрыты из интерфейса, но используются адаптером как переходный слой к существующей логике шагов;
- клики по варианту типа в обоих popup теперь только меняют выбранное значение и не оставляют пользователя на следующем шаге;
- выбор реальной площадки в текущем event selector больше не оставляет wizard автоматически на следующем шаге — переход подтверждается через `Далее`;
- кнопка `Назад` делегирует существующему механизму step/summary navigation, поэтому очистка зависимых значений остаётся в одном месте;
- финальная `Далее` временно делегирует существующему catalog action до реализации отдельного шага результатов в `008`.

## Технический контракт

Добавлен `home-flow-navigation.js` с экспортируемой функцией `mountHomeFlowNavigation(...)`.

Контракт не знает о доменных полях wizard-а. Адаптер передаёт:

- текущий набор progress steps;
- `canNext(step)`;
- `canSkip(step)`;
- `onBack(step)`;
- `onNext(step)`;
- `onSkip(step)`.

Это позволяет следующим срезам `005–008` менять количество и содержимое шагов, не пересобирая footer и его визуальное поведение.

Существующие `home-flow.js`, `home-event-venue-bridge.js` и `home-venue-flow-fixes.js` пока остаются источниками состояния старых шагов. В `004` добавлен совместимый adapter, который нейтрализует их прежнее auto-advance поведение без дублирования доменной логики. При дальнейшей переработке event flow adapter можно постепенно упростить.

## Проверка перед PR

В итоговом verification-срезе необходимо выполнить:

- `npm run build`;
- desktop проверку обоих popup;
- mobile проверку обоих popup;
- проверку tab switching `Найти / Создать`;
- проверку `Назад / Далее / Пропустить`;
- проверку, что выбор типа и площадки сам по себе не переводит на следующий шаг.
