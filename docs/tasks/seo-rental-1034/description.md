## Стратегия
Один основной коммерческий URL (кандидат /venues/rent/moscow, проверить конфликт с venue alias); /venues остаётся существующим каталогом. /venues/rent/moscow-oblast и /venues/rent/moscow/{district} — только после оценки спроса и качества предложения. Не создавать дубли /venues/rent и Москвы; произвольные фильтры не индексировать. Стабильные серверные HTML-ссылки, пагинация для роботов, сохранение прежних URL. Переиспользовать ListVenuesHandler, VenueCourtDiscoveryAccess, PageSeoResolver, PageSeoSetting, SeoSitemapController, City/District/Address, темы и действующие карточки. Данные только публичных подтверждённых площадок/зон, условия аренды и цены из действующих источников; неизвестное не выдавать за подтверждённое.
Пользователь может смотреть зал, расписание, цену и выбирать слот без лишней авторизации; заявка/предзаявка/подписка через действующие сценарии. Не менять booking/payment/auth в рамках SEO. 
Постоянный цикл: аудит → маленькая задача → тесты → PR → CI → merge → smoke → метрики → следующий шаг.
