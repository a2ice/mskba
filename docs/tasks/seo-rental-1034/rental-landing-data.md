DEV ONLY. Предыдущий PR #1051 merged 07acedf; деплой и выполнение inventory на dev отдельно подтверждаются. Этот этап не добавляет HTTP route, Blade, sitemap, навигацию, внешнюю аналитику, публикацию и не меняет БД.

## Контракт данных
- `RentalSeoLandingData::forGeography('moscow', null)` или district alias (например sao) разрешает реальные справочники текущей БД. Не фиксирует ID из production. Неизвестный город или округ вне города — null; известная география без предложения — 0.
- Используется `ListVenuesHandler` с guest visibility независимо от текущего пользователя, type=sports_hall, operational_status=active и внутренним параметром configuredRentalOnly. Это публичные подтверждённые площадки, только реальные открытые indoor-зоны с настроенной арендой и хотя бы одним допустимым scope. Повторно используем критерий EffectiveCourtPolicy в inventory и discovery.
- DTO выбирает конкретный подходящий зал (URL, название, фото, условия, метро); несколько подходящих залов одной площадки не увеличивают число площадок. Не показываем private/owner-only, закрытые и отключённые зоны. Это конфигурация, а не свободные слоты, цена, гарантия транзакции или фактическая доступность.
- `rental_flow_enabled` передаёт feature flag; будущий UI не обещает оформление при отключённом флаге. `catalog_url` — более широкая выборка работающих крытых площадок, не только аренда; подпись «Все крытые площадки». Не меняем существующий публичный GET-контракт и результаты.
- Тестируем совпадение inventory/landing, реальные alias, неизвестную географию, private/closed/disabled, paid-only исключение, точный вторичный зал, отсутствие результатов и прежнюю широкую выдачу.
