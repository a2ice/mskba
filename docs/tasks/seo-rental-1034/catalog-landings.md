# Универсальные SEO-посадочные каталога площадок

Согласовано владельцем 25.11.2026. DEV ONLY до отдельного разрешения на production. Задачи #1036 (интеграция каталога) и #1039 (управление подборками). Аренда Москвы — первый сценарий, а не отдельный каталог.

## Архитектура

- Один каталог /venues, один механизм выборки, одни фильтры, DTO, карточки, карта, сортировка и пагинация. Landing — редакционная конфигурация каталога, не новая копия страницы и не отдельная выборка.
- Filament → Контент → SEO-посадочные страницы: внутреннее название, уникальный ЧПУ, статус черновик/активна, H1, meta title/description, вводный текст над результатами, основной текст под результатами (безопасный редакционный HTML), связанные подборки/FAQ, отдельные флаги допуска индексации и sitemap. Проверить существующий PageSeoSetting/PageSeoResolver и редактор; не создавать параллельную SEO-систему.
- Семантические критерии каталога из явного allowlist: city/district, тип игровой зоны, состояние, условия доступа, настроенная аренда. Географию хранить по существующим справочникам, проверять принадлежность округа городу, не фиксировать ID из другой среды.
- configuredRentalOnly — внутренний критерий PR #1064, использует EffectiveCourtPolicy и VenueCourtDiscoveryAccess. Следующий этап: подключить общий валидируемый фильтр настроенной аренды к каталогу (форма, счетчик, карта, пагинация, сортировка и mobile), не подменяя его платным доступом. Все остальные вызовы каталога по умолчанию неизменны.

## Маршруты и сопоставление

- Целевой пример /venues/rent/moscow; /venues/rent/moscow/sao; /venues/free/moscow. До реализации проверить существующие alias/court/legacy маршруты и Page Builder. Не добавлять неограниченный catch-all, который перехватывает действующие URL. Если конфликт — выбрать безопасный namespace и зафиксировать.
- ЧПУ разрешает ровно одну активную конфигурацию. Неизвестный или неактивный slug не раскрывает черновик (404; отдельный авторизованный preview). Запрос по ЧПУ предустанавливает семантические фильтры. При изменении фильтров форма ведёт через общий каталог; точно совпавшая комбинация активной подборки переводится на её ЧПУ, иначе остаётся /venues с GET. Не менять смысл запроса, не перенаправлять несовпадающие комбинации, не создавать циклы.
- Нормализовать валидированные значения, типы, пустые значения, порядок ключей, смысловые defaults. Сравнение точное: лишние семантические ограничения (поиск, события, мои интересы, георадиус и т.п.) не должны ошибочно совпадать с базовой посадочной. Персональные/координатные условия не включать в редакционные SEO-конфигурации на первом этапе.
- sort/view/page — параметры представления, не идентификаторы новой подборки; сохранять при переходах по ЧПУ, пагинации, карте и AJAX. На странице с отличающимися семантическими условиями не оставлять чужой SEO-текст. Не разрешать дубли активных нормализованных комбинаций и slug; устойчивое ограничение уникальности, не только UI-validation.
- Canonical чистой посадочной — её ЧПУ. Содержательная пагинация имеет корректный canonical для собственной страницы; сортировка/карта не образуют новые индексируемые посадочные. Точные GET-дубли и noindex фасетов проверить отдельно. Не считать canonical заменой noindex там, где это нужно; не менять текущие правила dev.
- Индексация разрешается только на production-host, после редакционной и релизной приёмки, с отдельным флагом. Sitemap содержит только утверждённые пригодные страницы, без произвольных фасетов. В DEV ONLY не менять robots/X-Robots-Tag, не отправлять sitemap, не подключать внешнюю аналитику. Пустая выдача не обещает аренду; fallback — обычный каталог и существующие сценарии подбора. Правила допуска пустых/малонаполненных страниц уточнить перед production.

4. UI Studio: существующий каталог с H1/вводным текстом/расширенным текстом/FAQ/перелинковкой, desktop/mobile и обе темы. Приёмка владельца, затем интеграция маршрута и редактора; не копировать UI.
5. Первая черновая посадочная аренды Москвы, проверить предложение и ссылки по данным среды. Не переносить dev данные на production.
6. После разрешения на main: проверка фактических данных, canonical/sitemap/индексации, публикация, внешние метрики.

Acceptance: гостевой и авторизованный каталог не раскрывает черновики/приватные данные; прямой ЧПУ и соответствующий GET имеют одинаковую выборку; дополнительные фильтры корректно возвращают общий каталог или другую посадочную; не ломаются legacy URLs, карта, сортировка, JSON fragment, infinite scroll, мобильный счётчик, noindex dev. Не обещать наличие свободного времени по одному rental_enabled.

## Внутренний этап модели (25.11.2026)

- Добавлена таблица `venue_catalog_landings` и модель `VenueCatalogLanding`: имя, H1, slug, ссылочные city/district, разрешённые критерии, два текстовых поля, флаги активности/индексации/sitemap по умолчанию false. Миграция аддитивная; никаких seed/публикаций. Тексты пока не рендерятся; HTML-санитизация, FAQ и связи — этап редактора. Meta Title/Description подключить через действующие PageSeoSetting/PageSeoResolver, не дублировать поля.
- `VenueCatalogLandingCriteria` нормализует разрешённые фильтры и исключает представление (view/sort/page/fragment), пустые значения и false. Дополнительные действующие search/events/interests/geo или неизвестные параметры не совпадают. `VenueCatalogLandingResolver` возвращает только активные конфигурации, по slug или точной комбинации, с проверкой равенства после поиска по SHA-256.
- Уникальность slug для всех записей, уникальность комбинации для активных на уровне БД (nullable unique signature; черновики могут совпадать). Сигнатура пересчитывается model saving, использовать штатное сохранение модели, не bulk update. Проверка принадлежности района городу; slug синтаксически ограничен, окончательный namespace и проверка коллизий с действующими маршрутами перед интеграцией. Пустые комбинации не разрешены. Все флаги сами по себе пока ничего не публикуют.
- Этот PR независим от UI фильтра #1066: работает только с конфигурацией, не подключается к контроллеру/маршрутам/Filament. Проверки exact matching, defaults, draft, unique, invalid geography/slug. После merge dev нужна штатная миграция и smoke; никаких изменений main, robots/sitemap или внешней аналитики.
