# 068F — цепочки согласований

Статус: реализовано.

## Реализовано

- два последовательных процесса: подготовка нового мероприятия и перенос
  существующего;
- отдельные poll для даты, интервала времени и площадки с устойчивым
  `step_order`;
- следующий poll активируется только после принятия решения по предыдущему;
- площадки последнего шага повторно фильтруются по актуальному расписанию,
  физической доступности и занятым броням;
- выбранные для первого poll Telegram-чаты автоматически наследуются
  следующими шагами цепочки;
- завершённую цепочку создания можно передать в существующую форму мероприятия;
- завершённую цепочку переноса организатор явно применяет отдельным действием;
- перенос выполняется через `UpdateEventHandler`, повторно проверяющий
  инварианты мероприятия и бронирования;
- после изменения площадки или времени прежние ответы участников помечаются
  устаревшими и требуют явного повторного подтверждения.

## Конкурентный доступ

Переход к следующему шагу выполняется под блокировками
`coordination_sessions -> coordination_polls`. Применение переноса начинается
только после завершения транзакции Coordination: блокировки опроса не
удерживаются одновременно с блокировками площадок и броней. Это сохраняет
единый порядок доменных блокировок и снижает риск взаимной блокировки между
параллельным решением опроса и изменением мероприятия.

## Проверка

Feature-тесты покрывают последовательную активацию шагов, наследование
Telegram-публикации, исключение занятой площадки, применение переноса и
повторное подтверждение участия.
