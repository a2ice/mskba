# 229 — Раздельные атрибуты экипировки и повторная генерация

## Изменения

- схема character extra поднята до v5;
- налокотники задаются отдельно: левый / правый;
- напульсники задаются отдельно: левый / правый;
- наколенники задаются отдельно: левый / правый;
- повязка остаётся одиночным атрибутом;
- старые значения `elbow_both`, `wristbands`, `knee_pads` автоматически разворачиваются в левую+правую стороны;
- frontend больше не содержит отдельной логики взаимоисключения «оба»;
- если пользователь выбрал фото, но оно не прошло AI-проверку и осталось только локальным preview, ошибка генерации явно говорит, что фото ещё не подтверждено AI.

## Повторное использование лица

Подтверждённые face references сохраняются в private storage с
`source_reference=player-character-ai-validated-v1`. При каждой следующей генерации backend
повторно читает сохранённый анфас и доступные боковые ракурсы из private storage и передаёт их
в `PlayerCharacterAiGateway`. Повторная загрузка лица не нужна, пока пользователь не хочет
заменить reference.

## Порядок preflight генерации

1. получить актуальную цену из Pricing;
2. проверить наличие сохранённого AI-confirmed анфаса + левого или правого ракурса;
3. проверить текущий баланс real + bonus;
4. проверить выбранную команду;
5. вызвать AI provider.

AI-валидация ракурса выполняется при загрузке/замене face reference до его сохранения и
повторно на каждой генерации не выполняется.
