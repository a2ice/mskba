# 005 - Доработать главный экран главной страницы по новому макету с блоками `Сейчас играют` и `Highlights`

## Оригинальное описание

Нужно доработать главную страницу по макетам:

- `../backlog/images/home page main screen.png`
- `../backlog/images/home page main screen adaptive.png`

Ключевые изменения:

- доработанный главный экран `welcome`;
- новый блок `Сейчас играют` как отдельный partial;
- новая следующая секция `Highlights` как отдельный partial;
- пока данные демо, не завязанные на backend, но с учетом будущей замены на реальные данные.

Критичные требования и ограничения:

- сохранять текущий подход к верстке: общие глобальные CSS-классы для повторно используемых элементов (`btn`, заголовки, подзаголовки и т.д.) и частные классы для конкретных блоков;
- не терять и не ломать существующие атрибуты, уже завязанные на JS, включая модальные обработчики;
- не ломать текущую динамическую логику отображения кнопки в шапке, которая зависит от авторизации пользователя;
- внимательно сохранить рабочий header behavior и существующие пользовательские сценарии.

## Подробное описание

На этапе планирования дополнительно зафиксировано:

- доработка относится к `resources/themes/mskba_dark`;
- сейчас главная страница реализована одним простым hero-блоком в `pages/home.blade.php`;
- в макете главная страница становится составной:
  - обновленный `welcome` / hero;
  - блок `Сейчас играют`;
  - блок `Highlights`;
- `Сейчас играют` и `Highlights` должны быть вынесены в отдельные partials;
- данные для новых блоков пока должны быть демо-данными, без backend-интеграции, но структура partials должна допускать последующую замену на реальные данные;
- при переделке header нельзя ломать:
  - `@guest / @else` логику пользовательской кнопки;
  - modal-атрибуты и `js-handler` у кнопки входа;
  - существующую навигационную структуру и burger behavior;
- при переделке hero нельзя терять существующие JS-атрибуты на CTA-кнопках, если их сценарий сохраняется;
- CSS нужно развивать в текущем стиле:
  - общие глобальные классы переиспользуемых элементов сохранять и расширять;
  - частные классы держать на уровне конкретных блоков страницы;
  - не превращать разметку в набор одноразовых глобальных utility-классов.

План реализации:

1. Пересобрать `pages/home.blade.php` под новую композицию главного экрана.
2. Добавить partial для блока `Сейчас играют`.
3. Добавить partial для блока `Highlights`.
4. Доработать `partials/header.blade.php` под макет, не ломая auth-логику и JS-атрибуты.
5. Доработать CSS темы для desktop/tablet/mobile-раскладки.
6. Сохранить и при необходимости адаптировать существующие `btn` и другие общие классы вместо изобретения параллельной системы.
7. Проверить страницу визуально и собрать frontend assets.
8. Обновить описание задачи итогом и проверками.

Проверки:

- визуальная проверка desktop/tablet/mobile;
- `npm run build` или `make npm CMD='run build'`;
- проверка, что модальная кнопка входа и auth-dependent кнопка в header работают по прежней логике.

## Результат выполнения

Главный экран главной страницы переработан под новый макет:

- `pages/home.blade.php` собран заново под композицию `welcome` + `Сейчас играют` + `Highlights`;
- добавлен partial `home-currently-playing.blade.php` с демо-данными активных игр и нижней статистикой;
- добавлен partial `home-highlights.blade.php` с демо-блоками преимуществ;
- `partials/header.blade.php` стилизован ближе к макету без потери:
  - `@guest / @else` auth-логики;
  - modal-атрибутов кнопки входа;
  - burger/navigation behavior;
- CSS темы расширен в текущем подходе:
  - общие button-классы в `default.css` дополнены для многострочных CTA;
  - частные классы hero/live/highlights вынесены в `app.css`;
- адаптивная раскладка добавлена для desktop/tablet/mobile по мотивам второго макета.

Замечания по текущему состоянию:

- данные блока `Сейчас играют` и `Highlights` пока демо и живут в `home.blade.php`;
- CTA-кнопки сохраняют существующий JS-подход через `js-handler` и modal-атрибуты;
- отдельного backend-потока под новые блоки пока нет.
