# 105 — Унифицировать формирование участников самостоятельных и турнирных игр

Самостоятельная игра использует общие с турнирными матчами принципы и переиспользуемую balanced-механику формирования состава, но сохраняет собственный recruitment flow и не зависит от агрегата Tournament.

Для самостоятельной игры поддерживаются два режима:

- готовые команды: при создании можно указать ноль, одну или две команды. Одна известная команда становится подтверждённым кандидатом и позволяет опубликовать сценарий «моя команда ищет соперника», но GameSide создаются только после утверждения обеих сторон. Организатор может приглашать команды, а представители команд — подавать заявки, если приём заявок включён;
- отдельные игроки: игроки подают заявки, организатор принимает их, после чего формирует ровно две balanced-команды той же версионируемой механикой, что используется в турнире. Preview можно пересчитывать и вручную корректировать до применения.

Турнирный матч получает стороны из TournamentMatch/TournamentEntry. После материализации любой сценарий сходится в единый Game runtime: `GameSide + GameRosterEntry`, lineup, фактический старт, live, счёт и статистика.

У самостоятельной игры есть явное состояние `sides_confirmed_at` — «стороны утверждены». Утверждение можно снять до фактического начала игры, заменить состав/стороны и утвердить заново. Заявки при этом сохраняются. EventParticipant синхронизируется из финального roster, но не является источником спортивного состава.

Участием постоянной команды в самостоятельной игре управляет создатель команды либо активный подтверждённый участник с глобальным правом «Управлять участием команды в играх» (`team.game_participation.manage`). Выдавать право может создатель либо участник с правом управления правами команды по существующей Team ACL.

## Критерии готовности

- единые доменные правила и переиспользуемый balanced engine/UI не дублируют турнирную механику;
- заявки и приглашения защищены ACL, транзакциями и стабильным порядком блокировок;
- сценарий с одной известной командой не создаёт половинчатую GameSide;
- одна команда не может занимать обе стороны;
- стороны имеют явный флаг утверждения, который можно снять только до фактического старта;
- при утверждении roster синхронизируется с EventParticipant;
- Game нельзя фактически запустить без двух утверждённых сторон и корректного lineup;
- после начала игры стороны, состав и основные настройки изменять нельзя;
- balanced preview использует fingerprint и отклоняет stale apply;
- ключевые переходы и конкурентно-чувствительные сценарии покрыты тестами;
- продуктовая и техническая документация актуализированы.

## Реализация

- `Game.recruitment_mode`, `accepts_applications`, `sides_confirmed_at`, `sides_confirmed_by_actor_id`;
- `game_admissions` для team/user application, invitation и initial selection;
- `GameAdmissionService` с повторной ACL-проверкой после locks;
- `StandaloneGameFormationService` для team/individual materialization, unconfirm/reconfirm и pre-start configuration;
- общий `BalancedTeamFormationEngine`, используемый Tournament и standalone individual draft;
- общее UI-ядро balanced preview/drag-and-drop;
- публичная и управляющая recruitment-панель standalone Game;
- новое Team permission `team.game_participation.manage`;
- уведомления о заявках, приглашениях и решениях;
- lifecycle guard перед фактическим стартом.
