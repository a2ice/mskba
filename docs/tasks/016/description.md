# 016 - Добавить публичный вход в создание площадки

## Оригинальное описание

Пользователь предложил добавить на страницу `/venues` кнопку "Добавить площадку" в одной строке с заголовком. Кнопка должна вести на `/venues/create`, доступ к которой есть только у подтвержденных пользователей.

Если пользователь не авторизован, на месте действия должен быть текст о необходимости войти на сайт и кнопка "Войти", открывающая модалку авторизации. Если пользователь авторизован, но не подтвержден, должен отображаться соответствующий текст и ссылка на страницу профиля.

## Подробное описание

Нужно обновить публичный flow площадок:

- на странице публичного списка площадок показать CTA рядом с заголовком;
- для подтвержденного пользователя CTA ведет на страницу создания площадки;
- для гостя CTA объясняет необходимость входа и открывает существующую auth-modal;
- для авторизованного неподтвержденного пользователя CTA объясняет необходимость подтверждения и ведет на страницу подтверждения аккаунта;
- добавить route `/venues/create`, который использует существующую форму создания площадки;
- использовать один канонический URL создания площадки: `/venues/create`;
- право `add_venue` должно означать "подтвержденный пользователь", без дополнительного требования роли участия `venue_related`.

Затронутые сценарии:

- просмотр публичного списка площадок;
- переход к созданию площадки из публичного раздела;
- ограничение создания площадки по статусу подтверждения аккаунта.

Затронутые модули и файлы:

- routes публичного раздела площадок;
- `VenueAccessServiceProvider`;
- публичный controller/view площадок;
- общий `section-sidebar` layout для header action;
- документация `docs/project.md` и `docs/specification.md`;
- feature tests для CTA и доступа.

## Проверки

- `php artisan test --filter Venue`
- `npm run build`
- `git diff --check`

## Результат

Реализован публичный entry point создания площадки:

- на `/venues` добавлен action рядом с заголовком;
- гость видит текст о необходимости входа и кнопку открытия auth-modal;
- авторизованный неподтвержденный пользователь видит текст о необходимости подтверждения и ссылку на подтверждение аккаунта;
- подтвержденный пользователь видит кнопку "Добавить площадку";
- добавлен маршрут `GET /venues/create`;
- добавлен маршрут `POST /venues`;
- публичная страница создания использует layout раздела площадок и показывает контекстные состояния доступа вместо 403;
- если пользователь потерял подтверждение между открытием формы и отправкой, `POST /venues` возвращает его на `/venues/create` с понятным сообщением и не вызывает use case;
- старые account create/store routes убраны, чтобы создание площадки имело один канонический URL;
- ссылка из личного кабинета "Мои площадки" ведет на `/venues/create`;
- форма создания вынесена в общий partial;
- Gate `add_venue` теперь разрешает создание любому подтвержденному пользователю.

Проверки выполнены:

- `php artisan route:list --path=venues` - пройдено, маршруты `/venues/create` и `POST /venues` зарегистрированы;
- `php artisan test --filter Venue` - пройдено, 10 tests / 37 assertions;
- `npm run build` - пройдено;
- `git diff --check` - пройдено.
