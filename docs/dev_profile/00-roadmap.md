## Правило честного ответа

Говори «в проекте реализовано» только если можно открыть файл. Говори «мы сделали» — если реально участвовал в решении. Нельзя подменять «я изучил архитектуру» на «я лично проектировал каждый модуль». Для текущего черновика тредов указывай статус WIP.

## Структура устного ответа STAR для технической задачи

- **S — ситуация:** повторное подтверждение брони могло конфликтовать с одновременным запросом.
- **T — задача:** получить не более одного бизнес-результата и сохранить историю переходов.
- **A — действие:** транзакция + receipt и idempotency key + row locks + state machine + outbox.
- **R — результат:** повтор с тем же ключом возвращает прежний результат, конфликтующий payload отклоняется; поведение покрывается тестами. **Не придумывай проценты ускорения.**

## Мини-экзамен

Объясни без подсказок: почему transaction ≠ idempotency; почему Event ≠ Queue; чем ACL отличается от RBAC; зачем cache version; чем Inertia отличается от REST SPA; почему WebSocket не отменяет серверную авторизацию; зачем Outbox; чем index отличается от unique constraint.
