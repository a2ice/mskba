# FindSport / Basketpoint: публичное расписание на dev (первый этап Task 308)

Скоуп: **только `APP_ENV=staging`**, `VENUE_INTEGRATIONS_FINDSPORT_PUBLIC_SNAPSHOT_ENABLED` по умолчанию включён на staging и выключен в production. В коде не делается ни одного сетевого запроса с публичной страницы, используются только сохранённые snapshots из Task 307.

## Как проверить

1. Filament → Площадки → Basketpoint (venue #26) → Интеграции → Источники и залы.
2. У источника FindSport нажать «Получить данные», затем «Сохранить снимок». Убедиться, что в истории появился snapshot с 238 слотами.
3. Открыть публичную страницу Basketpoint. Если у площадки один зал, на странице площадки в разделе «Расписание» появится отдельный блок **«Занятость и цены · FindSport»**. Для площадок с несколькими залами блок появляется только на странице того зала, к которому привязан источник.
4. Раскрыть день, сверить получасовые интервалы, статусы, цены и время снимка. Брони MSKBA показываются отдельно в разделе «Игры и мероприятия». Внешняя занятость туда не подмешивается.
5. По истечении TTL блок должен помечать снимок устаревшим. За пределами семидневного ответа указано «Нет данных», не «Свободно».
6. Проверить соседние площадки: изменений нет. При `VENUE_INTEGRATIONS_FINDSPORT_PUBLIC_SNAPSHOT_ENABLED=false` остаётся прежнее расписание без FindSport.

## Ограничения

- Публичный слой **замещает только отображение занятости тестового зала**; данные в `VenueSchedule`, `VenueCourtSchedule`, `VenueBookingPolicy`, `VenueBooking` и платежи не перезаписываются.
- Внешние 30-минутные слоты имеют статус «наблюдение» и цену на момент снимка; они **не являются ценовым предложением MSKBA**. В пилоте у них нет кнопки бронирования и ни один внешний слот не включается в заявки автоматически.
- Нет автообновления и фонового polling; это следующий этап. Возвращаемый календарь берётся из последнего **сохранённого** снимка, а не из неподтверждённого предпросмотра.
- Ровно `external_id=4805`, `permission_status=testing_only`, `adapter_key=api`, `mode=test`; источник обязан быть привязан к выбранному залу. Последний snapshot относится именно к этому источнику/залу.
- `main`/production не затрагиваются.
