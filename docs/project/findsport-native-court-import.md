# FindSport → штатное расписание MSKBA (staging pilot, Task 309)

## Цель

Не создавать отдельный календарь или публичный виджет FindSport. Администратор
настроенного источника #4805 должен **применить сохранённый снимок** к штатному
расписанию единственного зала Basketpoint в MSKBA. Данные будут использовать
существующие модели часов, цен и проверку занятости.

## Пошаговая проверка на dev

1. Filament → Площадки → Basketpoint (#26) → Интеграции → Источники и залы.
2. «Получить данные», проверить 7 дней, 30-минутные цены и занятость.
3. «Сохранить снимок» (или использовать уже сохранённый полный снимок).
4. **«Применить к расписанию MSKBA»** → подтвердить явное предупреждение.
5. «Сохранённые данные» показывает номер активного применённого снимка.
6. В штатных настройках расписания площадки и зала проверить время
   **07:00–23:59** (ограничение текущего редактора: 24:00 недоступно),
   7 дней недели, а в исключениях зала — свободные фрагменты по датам снимка.
7. В ценах зала по конкретным датам проверить значения в рублях за 30 минут:
   например, 162500 коп. = **1625 ₽ / 30 мин**. Это
   `venue_court_calendar_slot_prices`, не новая таблица с параллельной
   тарифной политикой.
8. API штатной доступности учитывает занятые слоты импортированного источника
   (`busy[].source=findsport`) и сохраняет уже существующие брони MSKBA.
   Запрос/цитата на пересекающийся слот блокируется. За пределами покрытия
   и при истёкшем TTL бронирование закрыто до следующей проверки.
9. Повторно применить тот же снимок: дублей цен и исключений нет.
10. При следующей загрузке и применении обновляются цены и занятость **только
    для связанного зала и импортируемого периода**, а не другой площадки.

## Ограничения первого пилота

- Тестовый, вручную запускаемый импорт без фонового polling, публичного блока,
  оплаты и создания внешних бронирований/мероприятий.
- Учитываются только **полные** недельные снимки FindSport в RUB на 30 минут
  и минимальную аренду 60 минут; один физический зал на площадке.
- Если у площадки опубликована несовместимая политика бронирования, действие
  сообщает о необходимости 30-минутного шага вместо тихого создания
  неправильного прайса. Версии опубликованных политик не меняются.
- Применяемый снимок указан в `venue_court_external_schedule_imports`,
  предыдущие snapshots остаются в истории.
- Часы площадки расширяются только для площадок с **единственным** залом.
  Другие площадки и залы не меняются; внешние слоты не превращаются в записи
  `venue_bookings` или `events`.
- Из-за текущего формата HTML `time` край 24:00 приводится к 23:59.
  Бронирование с переходом через полночь в MSKBA и раньше не поддерживалось.
- Применение доступно по умолчанию только при `APP_ENV=staging`:
  `VENUE_INTEGRATIONS_APPLY_FINDSPORT_NATIVE_ENABLED` — отдельный флаг.
  На production по умолчанию выключено.
- Публичный слой PR #700 откачен в этой ветке: стандартная публичная
  страница осталась без отдельного блока FindSport.
