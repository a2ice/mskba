# Task 307 — этап 1: сохранение наблюдений FindSport

**Область:** только read-only ручное сохранение в test mode. Task 307 не закрыт целиком.
До реализации Tasks 308–309 **нет автоматического polling, Reverb и публичной выдачи
внешней доступности**. Внешние данные не влияют на бронирование и оплату.

## Использование на dev

1. Открыть Filament → площадка Basketpoint → Интеграции → Источники и залы.
2. У существующего источника `FindSport BASKETPOINT` нажать «Получить данные»
   и сверить его с FindSport (это работает как в Task 306).
3. Выбрать **«Сохранить снимок»**, подтвердить действие. Тот же ответ
   повторно используется из короткого кэша; при истечении кэша происходит
   новый ручной read-only запрос с ограничением частоты.
4. Нажать **«Сохранённые данные»**. Убедиться в наличии `snapshot #id`,
   `observed_at`, идентификатора зала, состояния **в пределах TTL/устарел**,
   полноты и списка получасовых слотов.
5. Повторно сохранить неизменившийся кэшированный ответ — должен остаться
   тот же snapshot ID (идемпотентность).
6. После TTL проверить отображение «устарел»; исторический snapshot не
   удаляется и не становится автоматически доступной бронью.

## Схема и инварианты

- `external_availability_snapshots`: append-only; `source_id`, `venue_id`,
  `venue_court_id`, внешняя зона, UTC observed/coverage, timezone,
  `parser_version`, `checksum`, `snapshot_key`, `complete`, TTL,
  диагностические агрегаты без секретов, автор ручной операции.
- `external_availability_slots`: append-only; `snapshot_id`, `local_date`,
  UTC start/end, status `available|booked|unavailable|unknown`,
  `price_minor` в копейках (nullable), `currency=RUB`,
  `price_unit_minutes=30`, `day_complete`.
- Строгая проверка семи последовательных дат и сетки **07:00–24:00**
  для Basketpoint, минимум аренды 60 минут, единый court mapping.
  Дни без данных допускаются только с явным `unknown`. Отрицательная
  цена, неправильный source/court, разрыв сетки или невалидная зона
  приводят к отказу до записи в БД.
- По одной ручной выборке создаётся **один batch snapshot с 238 слотами**.
  Снимки не перезаписываются; повторение того же `observed_at` и checksum
  не создаёт дубликатов. Ошибка следующего импорта не затрагивает предыдущий.
- При других физических залах или источниках — отдельные записи; не
  объединять противоречивые статусы и не переписывать `VenueSchedule`,
  `VenueCourtSchedule`, регулярные тарифы или `VenueBooking`.
- Сохранённые цены — наблюдение, не предлагаемый MSKBA checkout quote.
  `available` значит «не отмечено занятым в полном ответе»,
  **не** «подтверждено к бронированию».
