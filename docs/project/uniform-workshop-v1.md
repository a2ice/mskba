# MSKBA: «Форма» и Мастерская — MVP (05.11.2026)

## Цель
Единая история «Команды → Форма → Рейтинги»: готовая экипировка для игроков и команд, собственный дизайн, интерес поставщиков. MVP демонстрационный: нет каталога продаж, оплаты, автоматического заказа и сохранения проекта на сервере.

## Переиспользуемые компоненты
- resources/themes/mskba_app/js/uniforms/UniformKitPreview.vue — SVG-макет майки и шорт, общий для превью и мастерской.
- UniformWorkshop.vue — интерактивный редактор (расцветка, номер, надпись, размер, ракурсы, копирование спецификации); один компонент в диалоге и на отдельной странице.
- UniformDialog.vue — доступный нативный dialog (Escape, фокус, клик по подложке).
- UniformExperience.vue — контент подсекции «Форма», переключатель сценариев, попапы FAQ и CTA поставщикам.
- uniform-options.js — палитры и стабильные соответствия разделов/статей FAQ.
- uniform-entry.js — точечное монтирование в Page Builder и на отдельной странице.
- resources/themes/mskba_app/css/uniform-workshop.css — изолированное оформление.
- resources/views/uniforms/workshop.blade.php — самостоятельная страница /uniforms/workshop.

## Интеграция с главной DEV
Главная публикуется через Filament Page Builder, а не из git. На DEV существует секция #venues-story-uniforms с .mskba-v3-story__body. В resources/js/page-builder.js добавлена условная динамическая загрузка Vue-расширения только для этой секции. После успешного монтирования исходные описательные абзацы скрываются; при отключённом JS остаётся старое содержимое. Мяч, игроки, scroll director и CSS/JS Page Builder не изменяются.

## FAQ
Добавлены четыре системных материала через FaqContentSeeder (идемпотентно, без перезаписи редакторского контента):
1. faq.uniforms.selection → /faq/faq-uniform-selection
2. faq.uniforms.workshop → /faq/faq-uniform-workshop
3. faq.uniforms.production → /faq/faq-uniform-production
4. faq.uniforms.partnership → /faq/faq-uniform-partnership

Разделы FAQ: uniforms («Форма и экипировка»), partnership («Сотрудничество»). Сценарии обращаются к существующему GET /faq/help-content с section и article, сервер санитизирует SAFE_HTML. Штатный workflow `deploy_dev` уже запускает сидер автоматически. Для ручной публикации без CI (только если её действительно проводили) выполнить на DEV:
    php artisan db:seed --class=FaqContentSeeder --force
Команда не затрагивает тексты существующих статей. Созданные материалы не публикуются в новости/Telegram. Для предложения сотрудничества — support@mskba.ru. Маркетплейсы показываются как возможные каналы продаж, не как партнёры MSKBA.

## Ограничения
- Изделие на рисунке — эскиз, не лекало; размер предварительный.
- Номер и надпись локальные, не сохраняются на сервер; копирование сопровождается подтверждением или ошибкой.
- Для будущего сервиса: проекты дизайна, модели комплектов, размерные сетки, связь с Team, права через контрактную систему, ассортимент и верификация поставщиков, сметы, производство, оплата и статусы.
- Смена цвета PNG-контуров на действующих больших изображениях игроков пока НЕ включена: дополнительные фильтры могут вернуть микрорывки при прокрутке. Требуется отдельный performance-QA с оптимизированными ассетами. Взаимодействие с цветом уже работает в мини-превью и мастерской.

## Проверка DEV
1. На / найти «ФОРМА»: обе вкладки должны переключаться без изменения положения игроков/мяча.
2. Готовая экипировка → «Подробнее», «Как стать партнёром» → работающие FAQ-попапы и ссылка связи.
3. Своя форма → превью, выбор цветовой схемы, попап Мастерской.
4. В мастерской: номер, надпись, размер, переключение ракурса, копирование.
5. Перейти на /uniforms/workshop: проверить, что тот же редактор, а не отдельная копия.
6. Проверить Escape, фокус, backdrop, скролл внутри диалога и обратную прокрутку арены.
7. Проверить 1440/1024/768/390/360 px, отсутствие горизонтального overflow и сохранение дизайна на остальных четырёх подсекциях.
8. Проверить prefers-reduced-motion и отсутствие ложной возможности отправить заказ или оплатить товар.
9. FAQ доступны напрямую, даже если AJAX временно недоступен.

## Откат
Git revert изменений из ветки dev. HTML/CSS/JS, опубликованные в Filament, остаются нетронутыми; новые FAQ управляются редактором отдельно.
