# Настраиваемый дашборд пользователя — этап 1

Маршруты: `/account`, авторизованный `/account/dashboard/widgets`, редактор `/admin/account-dashboard`.
В новой теме `mskba_app` администратор управляет количеством, видом и порядком карточек (полная/половинная ширина), включением и признаком `can_hide`. Пользовательское скрытие и перестановка будут реализованы следующим этапом в `/account/settings`.

Типы: статус аккаунта, знакомство с порталом, сообщения, информационные карточки, реклама (с изображением, ссылкой и явной пометкой «Реклама»), а также `custom_html` (только суперадмин). Содержание, стили и JavaScript последнего исполняются в iframe с `sandbox="allow-scripts"`, **без allow-same-origin**. Дополнительно применяется iframe CSP: запрет сетевого JavaScript (`connect-src 'none'`), форм, вложенных iframe и внешних скриптов. Изображения/шрифты могут загружаться с HTTPS. Встроенный код не имеет доступа к cookies, localStorage и DOM портала. Это всё равно активный пользовательский код: включать только с отдельным ревью суперадминистратора.

Аудитория: статусы аккаунта, системные роли, роли участия (любая из отмеченных), проверенный основной контакт. Незаполненная категория не ограничивает аудиторию. Категории сочетаются через AND, внутри списка ролей — OR. Точечный include по каноническому/алиасному ID переопределяет категории; exclude имеет приоритет даже над include. Видимость не является авторизацией к доменным API; они продолжают проверять права отдельно.

Административные изменения коммитятся в БД, затем посылается публичное событие `account-dashboard / dashboard.changed` без конфигурации, пользовательских идентификаторов и персональных данных. Авторизованная вкладка запрашивает уже отфильтрованный HTML. Reverb используется как уведомление об инвалидации, предусмотрено восстановление при reconnect/focus и редкое сверочное обновление. Публичный broadcast не раскрывает аудиторию.

Таблица: `account_dashboard_widgets`; начальные карточки создаются миграцией с признаком обязательности статуса аккаунта. Обновление через AJAX не выдаёт скрытые чужие карточки. Пока пользовательские настройки не подключены, `can_hide` остаётся правилом для следующего этапа.
