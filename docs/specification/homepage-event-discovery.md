# Homepage Event Discovery

## Назначение

Главная страница предоставляет popup-wizard `Мероприятия -> Найти`, который позволяет подобрать публичные мероприятия без перехода в отдельный каталог на промежуточных шагах.

Wizard объединяет поиск обычных `Event` и `Tournament` в один пользовательский сценарий.

## Шаги

Основной flow состоит из пяти шагов:

1. `Тип`;
2. `Параметры`;
3. `Где`;
4. `Когда`;
5. `Результаты`.

Выбор значения и переход между основными шагами разделены: нажатие на option только меняет состояние, а переход выполняется общим footer `Назад / Пропустить / Далее`. На финальном шаге правая кнопка меняется на `Готово`.

Popup `Площадки` использует тот же navigation/footer contract, но его содержимое в рамках Task 140 не перестраивается глубоко.

## Тип и параметры

Типы поиска:

- `Не важно`;
- `Игра`;
- `Тренировка`;
- `Игровая тренировка`;
- `Турнир`.

Для `Игры` доступны:

- формат: `basketball_5x5`, `streetball_3x3`, `streetball_1x1`;
- режим набора: `preformed_teams`, `individual_draft`.

Для `Турнира` доступны:

- тот же набор форматов;
- порядок набора через `TournamentEnrollmentPolicyEnum`: `continuous` / `fixed_pool`.

Для типов без дополнительных параметров шаг можно пропустить. Каждая опция использует штатный tooltip проекта.

## Локация

Верхний уровень шага `Где`:

- `Не важно`;
- `Указать локацию`.

Второй вариант открывает вложенный mini-wizard:

1. город;
2. район / округ;
3. метро;
4. улица и площадка.

Города и районы загружаются из `GET /home/location-options` и основаны на канонических `City`/`District`. Справочник не захардкожен в frontend.

`Текущая локация` переиспользует общий browser/Telegram geolocation helper и `POST /integrations/address-reverse`. Неуспешное определение координат не блокирует ручной ввод.

Улица использует Yandex address suggest с выбранным городом как контекстом. Площадка использует существующий predictive venue selector. Изменение улицы очищает ранее выбранную площадку.

Выбранные части локации отображаются как редактируемые badges; нажатие на badge возвращает на соответствующий вложенный шаг.

## Даты

По умолчанию используется диапазон в timezone приложения:

- `date_from = сегодня`;
- `date_to = сегодня + 7 дней`.

`date_to` не может быть раньше `date_from`.

## Discovery endpoint

Публичный read-only endpoint:

`GET /home/event-discovery`

Он объединяет две read-модели:

- публичные Event со статусом `published` и visibility `public`;
- Tournament со статусом `confirmed`.

Поддерживаемые фильтры:

- `type`;
- `format`;
- `game_mode`;
- `enrollment`;
- `city_id`;
- `district_id`;
- `metro_station_ids[]`;
- `street`;
- `venue_id`;
- `date_from`;
- `date_to`;
- `limit`.

География применяется по канонической цепочке `Venue -> Location -> Address` и `Venue -> Location -> MetroStation`. Несколько станций метро объединяются логикой OR.

Для `Event` дата определяется по `starts_at`. Для `Tournament` используется пересечение периода `starts_on..ends_on` с выбранным диапазоном. Локацией турнира считается `defaultVenue`.

## Результаты

Финальный шаг отображается внутри того же popup. Во время запроса контейнер блокируется стандартным loading overlay/spinner проекта.

Карточка результата содержит применимые данные:

- тип;
- название;
- дату/время или период;
- площадку;
- адрес;
- формат;
- режим набора либо enrollment policy;
- ссылку на каноническую страницу Event/Tournament.

Поддерживаются empty-state, error-state и повторная загрузка через `Обновить`.

Закрытие popup или возврат назад должно отменять активный discovery request и сбрасывать финальное состояние, чтобы следующее открытие начиналось с обычного wizard flow.

## Frontend lifecycle

Общий footer создаётся модулем `home-flow-navigation.js` при открытии modal. Поэтому discovery layer загружается лениво через `home-event-discovery-loader.js` после события открытия popup: это гарантирует, что navigation DOM уже смонтирован до инициализации финального шага.

Этот порядок является частью контракта и не должен заменяться статическим импортом `home-event-discovery.js` раньше монтирования footer.

## Проверки

Backend tests должны защищать:

- объединение Event + Tournament;
- публичность результатов;
- фильтры формата/режима набора/enrollment policy;
- City/District/Metro/Street/Venue;
- пересечение диапазона дат.

Frontend verification включает:

- `npm run build`;
- полный проход пяти шагов desktop/mobile;
- возвраты назад и редактирование badges;
- geolocation success/failure;
- empty/error/loading/result states;
- закрытие и повторное открытие popup;
- отсутствие автоматического перехода после выбора option.
