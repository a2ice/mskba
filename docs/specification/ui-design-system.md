## Источники и визуальный характер

| Наблюдение в презентации | Правило предлагаемой системы |
| --- | --- |
| Чёрная среда, оранжевая подсветка краёв | графитовые поверхности + деликатный тёплый свет только у ключевого блока/активного элемента |
| Крупное белое название с оранжевой частью | тяжёлый display-заголовок; оранжевым выделяется смысловой фрагмент, не весь текст |
| Телефон с событиями и быстрыми действиями | compact app-home: короткий hero, действия и ближайшие события, не бесконечный лендинг |
| Панели аренды и уведомления | плотные, но читаемые карточки с одним главным действием и ясным статусом |
| Фото, глубокие тени, скруглённые края | выразительность строится композицией и материалом поверхностей, а не множеством эффектов |

На desktop используем свободную композицию с акцентным hero и вспомогательной
колонкой; на mobile — прямой вертикальный поток и нижнюю навигацию. Не рисуем
наклонённые телефоны вокруг каждой формы. Не заменяем бренд нейтральной админкой.
Старая тема — источник сценариев, а не визуальный эталон.

## Интерактивный UI Kit тем оформления — 2026-10-19

Каталог реальных базовых компонентов доступен из **Filament → Дизайн → Темы оформления → открыть тему → UI Kit / Гайдлайн**. Также есть одноимённое действие непосредственно в строке списка.

- Маршрут просмотра: `/backoffice/design-themes/ui-kit/{theme}` (`design-themes.ui-kit`); требуется авторизация и разрешение `BACKOFFICE_THEME_VIEW`. Доступны в том числе неопубликованные темы для проверки редактором.
- Образцы используют общий CSS `resources/themes/mskba_app/css/app.css` и результат `DesignThemeCss::render($theme)` из базы; палитра/шрифты не копируются вручную.
- Доступны переключение между темами, preview 1440/768/390/360 внутри iframe того же origin, состояния кнопок, фильтров, форм, карточек, таблиц, модального окна и уведомления.
- Режим `?embed=1` рендерит только образцы и применяет настоящие CSS breakpoints по размеру iframe. Изолирован от пользовательской темы, формы и действия демо ничего не сохраняют.
- `Cache-Control: private, no-store`, `X-Robots-Tag: noindex, nofollow`; просмотр не включает публикацию, не меняет настройку темы по умолчанию или пользовательские предпочтения.
- Старый маршрут `design-themes.preview` сохраняется для существующего компактного предпросмотра; открытый локальный каталог `resources/themes/mskba_app/catalog/` остаётся историческим прототипом.
- Hero Slider и композиционная сцена «Площадки» — предметные компоненты. Их добавляем в UI Kit после стабилизации контрактов и только затем используем как единые образцы для всех тем.

## Обязательный цикл обновления UI Kit — ревизия процесса 2026-10-29

Этот процесс обязателен для каждой задачи и замечания приёмки по `mskba_app`.
Он **дополняет**, но не изменяет визуально принятые токены версии 1.0.

1. **До кода:** в PR/задаче указать эталонный компонент в UI Kit,
   конкретный CSS-примитив и применимые параметры из этого документа.
   Сначала искать готовое решение; собственные похожие чекбоксы, поля,
   кнопки, заголовки, диалоги и иконки не создавать.
2. **При новом устойчивом решении:** до повторного использования получить
   согласование владельца; тем же PR обновить **этот файл** (контракт,
   варианты, состояния, брейкпоинты, ссылки), соответствующий общий
   компонент и эталон UI Kit. Не ограничиваться `docs/mskba_app/tasks/*`.
3. **При косметическом исправлении:** использовать существующий контракт,
   фиксировать ссылку на него в карточке задачи и PR. Если контракт
   фактически изменился — оформить ревизию гайдлайна в том же PR.
4. **Перед merge:** проверить desktop и mobile, hover/focus/disabled,
   клавиатуру и реальные размеры. Ни PHPUnit-тест, ни успешная сборка
   не заменяют визуальную приёмку владельца на `dev`.
5. **Неизвестный компонент или конфликт с эталоном:** остановить
   внедрение затронутой части и согласовать вариант, а не придумывать
   одноразовый override. Применять [CaseRule15](agent-rules.md#caserule15---сверять-ui-с-гайдлайном-до-реализации-mskba-app).

**Закреплённые решения приёмки 056–057:**

- Нативные чекбоксы в формах `mskba_app`: общий `.check-label`
  из `css/design-system.css`, `input` 20×20 px, `label` не ниже
  44 px, `accent-color: var(--accent)`, одинаковая вертикальная ось
  подписи и контрола. Локальное уменьшение или собственная окраска
  запрещены. Для изменения сторон аксессуара используется такой же
  компонент.
- В диалоге **выбора стороны аксессуара** есть крестик (и Escape)
  для закрытия без изменений и единственное нижнее действие
  «Применить». Дублирующая кнопка «Отмена» в footer не нужна.
  Это решение касается данного диалога, а не отменяет кнопку
  «Отмена» в других подтверждениях, где она необходима.
- Ссылка «Изменить» в строке аксессуара должна быть выровнена
  **вертикально по центру** с чекбоксом; размеры зоны взаимодействия
  не меньше 44 px. Состояния сторон: `(л)`, `(п)`, `(л/п)`.
- Маркер роста аватара: линия 1 px, раскрывающая компактное значение
  при hover/focus/drag; единая шкала 0–225 см и разрешённый рост
  150–220 см. Риску можно перемещать мышью и пальцем, синхронно
  с ползунком. Изображение не должно ограничиваться по ширине так,
  чтобы переставать расти до отметки 220 см.

## Цвет и поверхности

Имена соответствуют CSS custom properties прототипа. Непрозрачные поверхности —
основа; glass допускается у sticky header/bar с непрозрачным fallback.

| Токен | Значение | Применение |
| --- | --- | --- |
| `--bg` | `#090A0B` | страница |
| `--surface` | `#141618` | карточка |
| `--surface-raised` | `#1D2023` | вложенная/hover-поверхность |
| `--field` | `#0E1012` | ввод |
| `--text` | `#F5F6F7` | основной текст |
| `--muted` | `#ADB3BB` | описания, placeholder |
| `--faint` | `#929AA4` | вторичные метаданные; не снижать opacity текста |
| `--accent` | `#FF7900` | primary, выделение, active |
| `--accent-hover` | `#FF922E` | hover primary |
| `--accent-active` | `#E86C00` | pressed primary |
| `--on-accent` | `#14100A` | текст/иконка на оранжевом, **не белый** |
| `--line` | `#30353B` | декоративный разделитель карточек |
| `--control-line` | `#707A86` | значимая граница input/secondary control |
| `--success` | `#7CDCAB` | подтверждено |
| `--warning` | `#FFD078` | требуется внимание |
| `--danger` | `#FF9398` | ошибка, destructive action |
| `--info` | `#8CCBFF` | нейтральное уведомление |

Обычный текст: контраст не ниже 4.5:1, крупный (24 px либо 18.66 px bold) — 3:1.
Границы значимых контролов и focus — 3:1 с соседней поверхностью. Декоративная
граница карточки не служит единственным способом распознать интерактивный control.
Статус всегда содержит текст/иконку, не только цвет. Disabled исключается из
контрастного требования WCAG, но остаётся читаемым. На фото текст размещается над
достаточно тёмной подложкой: проверка зависит от изображения, не только токена.

### Деликатная угловая подсветка поверхностей — 2026-10-13

**Утверждено на визуальных референсах 2026-10-13, MSKBA App 031.** Это дополнение
к системе 1.0 для темы `mskba_app`; legacy `mskba_dark` не меняется.

- Тёмная серо-графитовая поверхность `.panel` сохраняет свой основной фон, контур
  и радиус. Поверх него — **статичный**, еле заметный радиальный градиент из
  правого нижнего внутреннего угла (`at 100% 100%`). Радиусы пятна по осям:
  `min(35%, 200px)` по горизонтали и `min(35%, 100px)` по вертикали.
- Общий CSS-слой `--surface-corner-layer` задаётся **на самом компоненте**;
  `--surface-corner-glow` определяет обычный оранжевый цвет при низкой opacity.
  Цвета для явных состояний — `--surface-corner-glow-success` (зелёный) и
  `--surface-corner-glow-error` (красный). Нельзя применять статусный цвет из-за
  цвета CTA или наличия локального текста ошибки в соседнем поле.
- **Единое модальное окно** `.mskba-modal` — одна поверхность, один градиент
  на корневом `<dialog>`. Header/body/footer не имеют отдельного фона/градиента;
  их границы остаются видимы. `data-surface-tone="success|error"` на корне меняет
  только тон. Отсутствие атрибута и `neutral` дают оранжевый вариант.
- Активный `.app-account-nav__link` и его `hover` используют ту же геометрию
  и мягкий оранжевый акцент внутри плашки; active сохраняет свои текст/бордюр,
  hover отличается фоновым слоем. Клавиатурный focus всегда остаётся различимым.
- Эффект не должен перекрывать текст, поля, клики, скролл или менять размеры.
  Медиа-карточки с фотографией, отдельные hero и специальные промо-композиции
  сохраняют собственные фоновые контракты; локальный градиент не дублируется.
- Референс и интерактивные состояния: `resources/themes/mskba_app/catalog/surface-glow.html`.

## Типографика

Предложение: **Inter** с кириллицей, веса 400/500/600/700/800/900. Fallback:
`Arial, sans-serif`. В прототипе Google Fonts; перед релизом — локальные WOFF2
с сохранённой лицензией, subset с кириллицей и `font-display: swap` (этап 004).
Не использовать Latin-only display-шрифт для русского заголовка.

| Роль | Desktop size/line-height/weight | Mobile | Дополнительно |
| --- | --- | --- | --- |
| display (hero) | 64/64/900 | 40/42/900 | tracking −0.045em; максимум 3 строки |
| h1 страницы | 40/44/800 | 32/36/800 | −0.035em; display может быть h1 |
| h2 секции | 28/34/800 | 24/30/800 | −0.025em |
| h3 карточки | 20/26/700 | 20/26/700 | −0.015em |
| h4 | 18/24/700 | то же | без uppercase |
| h5 | 16/24/700 | то же | роль определяется иерархией, не размером |
| h6 | 14/20/700 | то же | не заменять label |
| body | 16/24/400 | то же | длинный текст ≤65ch |
| small / helper / error | 14/20/400 | то же | ошибка не уменьшает размер |
| label / button | 14/20/600 | то же | input text 16 px во избежание iOS zoom |
| caption / badge | 12/16/600 | то же | не для основного описания |
| eyebrow | 12/16/700 | то же | uppercase, tracking 0.12em |

Выравнивание обычно влево. Uppercase — eyebrow, короткая навигационная метка или
hero, но не длинные подписи полей. Числа счёта/времени — tabular-nums. Заголовки,
кнопки и юридически значимые подписи не обрезаются ellipsis; краткие metadata
можно сокращать при наличии полного значения в доступном detail.

Общие выразительные варианты: hero 56/56 при 1024–1199 px; display внутри
каталога образцов 48/48 (mobile 40/42); promo-card heading 28/34;
compact panel heading 20/26; dialog heading 28/34. Эти роли не меняют семантический
уровень HTML-заголовка. Число времени: 48/48 desktop, 40/40 mobile.

## Пространство и композиция

Базовая шкала: **4, 8, 12, 16, 20, 24, 32, 40, 48, 64 px** (`--s1`…`--s10`).
2 px допустимы для оптической коррекции и рамок, не для произвольной сетки.

| Отношение | Desktop | Mobile |
| --- | --- | --- |
| eyebrow → heading | 12 | 12 |
| heading → description | 12 | 12 |
| description → основное действие | 24 | 24 |
| header секции → content | 24 | 16 |
| секция → секция | 48 | 32 |
| label → input | 8 | 8 |
| input → helper/error | 8 | 8 |
| поле целиком → следующее поле | 20 | 20 |
| группа полей → действия | 24 | 24 |
| padding карточки/формы | 24 | 20 |
| padding compact event row | 16 | 16 |
| gap карточек | 16 | 16 |
| icon → текст | 8 | 8 |
| соседние кнопки | 12 | 12 |
| последний content → footer карточки | 24 | 24 |

**Правильно:** label, поле и его ошибка — одна группа; 20 px до следующей группы.
**Неправильно:** error добавлен с отрицательным margin и залезает на соседнее поле.
**Правильно:** карточки одного ряда имеют одинаковые padding и footer alignment.
**Неправильно:** одна карточка с 17 px, другая с 23 px ради подгонки текста.
**Правильно:** короткая секция использует общий header+body pattern.
**Неправильно:** под каждый заголовок придуман свой gap или лишний eyebrow.

Hero — отдельный композиционный вариант: padding 40 px (32 при 1024–1199,
24 ниже 640), eyebrow → display 24, display → description 16,
description → actions 24. Footer отделён auto-space и минимум 32 px (mobile 24).
Quick tiles: gap 16 / 12 mobile, padding 20×16 / 16; icon → text 12.
Dialog: padding 32 / 24 mobile. Стандартные карточки сохраняют таблицу выше.

## Адаптивный layout

Минимум: 320 CSS px. Container: максимум 1280 px; боковые gutters 32 px
от 1024, 24 px от 640 до 1023, 16 px ниже 640. Grid gap 24 desktop, 16 mobile.

**Композиционная основа MSKBA App:** единственный корневой `<main>`
всегда полноширинный и **не содержит класс `.container`**. Внутри него
размещаются `<section>` на полную ширину; уже внутри секции по
необходимости используется стандартный `.container`. Секции-баннеры
могут не иметь внутреннего контейнера. Нельзя добавлять второе
`width:min(...)`/`max-width` на уровне контента страницы без отдельного
согласования.

**Аккаунт:** переиспользуемый Blade-layout `theme::layouts.account`
выводит `.app-account-section > .container > .app-account-layout`:
слева sticky aside (260 px), справа fluid-контент без дополнительного
ограничения ширины. Меню — строго `MenuResolver::resolve('account')`,
включая права видимости, счётчики и ссылки. Sticky offset для новой темы
с контекстной строкой — `var(--header-height) + var(--context-bar-height) + 16px`.
Чтобы sticky имел диапазон работы даже в краткой сводке, grid сохраняет
минимальную высоту доступной области; меню при переполнении скроллится
внутри доступной высоты, а весь aside перестаёт прилипать после
окончания своей секции. До 900 px — доступное раскрываемое
`details/summary` вместо боковой колонки. Общий `main` не дублируется.

- **≥1024:** desktop navigation; app-home 2fr/1fr, форма/aside до 440 px;
  каталоги 3 колонки при достаточной ширине. Header 80 px.
- **640–1023:** две колонки карточек, крупные смысловые блоки в одну колонку;
  нижняя навигация, header 64 px. Toolbar переносится, не сжимает поиск.
- **<640:** одна колонка; primary action на ширину формы; summary cards могут
  оставаться двумя колонками только при читаемых названиях. Header 64 px.
- Toolbar: поиск `min-width: 0`, основная строка на доступную ширину;
  при нехватке места дополнительные действия переходят во вторую строку.
- Layout шире 1 колонки использует `minmax(0, …)`; в текстовых children `min-width: 0`.
- Bottom bar: 72 px + safe-area, максимум 5 пунктов, icon 22 px + label 12 px;
  страница резервирует 96 px + safe-area снизу. Не перекрывать submit/footer.
- Mobile section-nav: локальный горизонтальный scroll, доступные названия;
  нельзя маскировать поломку сетки через `body { overflow-x: hidden }`.
- Sticky header + anchors: `scroll-margin-top` учитывает высоту header,
  при наличии context bar — также высоту закреплённой полосы, и 24 px.
  Mini App позже подставляет safe-area/viewport через адаптер, а не новый набор страниц.

Проверки: 320, 360, 390, 639/640, 768, 1023/1024, 1440 px, крупный текст и 200% zoom.
Брейкпоинты — не названия устройств, а моменты перестройки композиции.


### Правая колонка публичной страницы площадки (#1059/#1061)

По согласованию 26.11.2026 сохраняем существующие панели и sticky offset.
После «Хочешь здесь играть?» — независимая панель «Контакты площадки»,
затем будущая панель представителей. Не рисуем пустые блоки. Публичный контакт
не зависит от верификации; длинные email переносятся, телефон/email доступны
как обычные ссылки с видимым фокусом. Колонка использует общую sticky-группу

## Поведение и доступность

- DOM-иерархия h1–h6 семантическая, CSS роль не навязывает уровень заголовка.
- Один видимый основной heading экрана; landmarks, skip link, настоящий label.
  Исключение для публичной шапки `mskba_app` (согласовано 2026-11-26): ссылку «К содержимому» не выводить в общем header partial, в том числе в Telegram WebView. Сохранять семантические landmarks и видимый focus остальных элементов.
- Focus 2 px accent + offset3, не скрывается без замены. Открытие dialog перемещает
  focus внутрь, Tab остаётся внутри, Esc закрывает, focus возвращается инициатору.
- Error связывается через `aria-describedby`, поле `aria-invalid`; сводка ошибок
  получает focus при failed submit. Не превращать каждый helper в assertive live-region.
- Навигация SPA должна обновлять title, heading focus и history/scroll; dialogs
  и формы не должны терять данные без предупреждения. Реализация — этапы 003–005.
- Financial/booking статусы приходят с сервера; оптимистическая анимация не выдаётся
  за подтверждение оплаты/брони. Стенд 002 содержит только демоданные.
- Auth/permission остаются на сервере. Disabled button — не защита доступа.

## Диалоги и прокрутка

### Актуализация 2026-10-08: Modal 1.1 — согласованное общее правило

По прямому запросу пользователя [задача MSKBA App 011](../mskba_app/tasks/011/description.md)
для **всех модальных окон новой темы** действует следующий контракт,
имеющий приоритет над историческими размерами старого образца 1.0 ниже:

- **Верхний слой:** вызывать нативный `<dialog>.showModal()`, обеспечивающий
  browser **top layer** над обычными stacking contexts и любым CSS `z-index`.
  Не создавать произвольные конкурирующие `z-index:999999`.
- **Центр экрана:** модальное окно центрируется по обеим осям, включая mobile.
  Mobile bottom sheet — только отдельный явно согласованный вариант.
- **Высота:** `max-height: 90vh` и предпочтительно `90dvh` для динамической
  высоты viewport (в Safari и при экранной клавиатуре дополнительно учитывать
  `visualViewport` при выявлении проблем). Никогда не превышать 90% видимой
  области; на коротких экранах уменьшать прокручиваемое тело, не прятать кнопки.
- **Структура:** `header / body / footer`. Только `body` прокручивается с
  `flex:1 1 auto; min-height:0; overflow-y:auto`; header с close и footer с
  действиями `flex-shrink:0` и остаются видимыми. Диалог центрируется
  независимо от длины формы.
- **Один scrollbar:** `.mskba-scroll` — общий узкий тематический скроллбар
  с `--accent` thumb, `--surface-raised` track, hover `--accent-hover`.
  Firefox — `scrollbar-color/scrollbar-width`, Chromium/WebKit —
  `::-webkit-scrollbar`. Native overlay-скроллбар некоторых OS/WebView
  может быть скрытым или не полностью настраиваемым; не подменять его JS.
- **Фокус только на элементах управления (для обеих тем):** статические
  заголовки, обычные подписи/лейблы, метаданные и контейнеры
  диалога не получают `tabindex="0"`, не включаются в Tab-последовательность
  и не обводятся как интерактивные элементы. Обработчики drag не должны
  автоматически назначать фокус шапке; перетаскивание мышью/касанием
  сохраняется, клавиатурное перемещение может вызываться с настоящей кнопки
  в шапке. При открытии попапа начальный фокус должен попадать на штатную
  кнопку/поле, если такое доступно; при закрытии — возвращаться на инициатор.
  Подсказки статических элементов не должны превращать обычный текст в
  самостоятельную фокусируемую кнопку без действия. Нативная индикация
  `:focus-visible` сохраняется у кнопок, ссылок, полей и других реальных
  управляющих элементов.
- **Общая реализация:** `resources/themes/mskba_app/css/modal.css`
  (`.mskba-modal`, `.mskba-modal__header/body/footer`, `.mskba-scroll`).
  Новые диалоги обязаны использовать эти классы, блокировать прокрутку фона,
  сохранять focus/Escape и иметь корректное имя/роль.

**Исторический эталон 1.0 ниже** описывал потолок **95%** и размещение через
`visualViewport`; для новой разработки он **заменён** на 90% в Modal 1.1,
без изменения остальных утверждённых визуальных токенов/компонентов.


- Диалог центрируется по обеим осям относительно **видимого visualViewport**,
  а не документа или только layout viewport. Native `dialog`, fixed-позиция
  по центру видимой области и `translate(-50%,-50%)`; не `margin:auto` по layout.
  При открытии и на resize/scroll visualViewport обновляются центр и ограничения;
  учитываются offsetLeft/offsetTop, width/height, эффективный CSS zoom элемента.
  Fallback без API — innerWidth/innerHeight, до JS — CSS viewport-значения.
- Высота по контенту: минимум 300 CSS px, максимум **95% видимой высоты**.
  Когда этот максимум меньше 300 px (landscape/zoom/маленькое окно), приоритет
  у видимой области. Не допускать ухода кнопок за экран ради минимума.
- Ширина стандартного диалога до 560 px, разумный минимум 300 px, жёсткий
  максимум **90% видимой ширины**; минимум также ограничен этим максимумом.
  Более широкий вариант потребует согласования; не задавать все диалоги на 90vw.
- Flex-column: header и footer `flex-shrink:0`, body `min-height:0; overflow-y:auto`.
  Scroll только внутри body; header с закрытием и footer действий остаются видимыми
  и не зависят от прокрутки. Footer не fixed относительно страницы.
- Padding по горизонтали 32 / 24 mobile, header 24 по вертикали, body 24 снизу,
  footer 20 по вертикали. При доступной высоте ≤400 px или ширине ≤360 px
  (после учёта zoom) compact-dialog: padding по горизонтали 12, header/footer
  по вертикали 8, body снизу 12; две flex-кнопки с gap 8, декоративная иконка
  подтверждения скрыта. Размер текста не уменьшается ради помещения диалога.
  Footer отделяется border `--line`, кнопки на mobile в две равные колонки.
- Фоновая страница блокируется от прокрутки; её положение сохраняется при закрытии.
  Focus переходит внутрь, Tab/Shift+Tab цикличны, Esc/закрытие возвращают focus.
  Прокручиваемый body доступен клавиатуре и имеет имя. Не вкладывать всю страницу
  в transform-контейнер, меняющий containing block фиксированного overlay.
- Стрелка native select стилизуется отдельно, сам список и доступность остаются
  браузерными. Системное выпадающее меню нельзя обещать одинаковым между ОС.
  В forced-colors возвращается `appearance:auto`, декоративный SVG скрывается.

## Wizard 1.1 — принятый визуальный контракт

**Дата приёмки: 2026-10-08.** Пользователь подтвердил интерактивный
[образец Wizard](../../resources/themes/mskba_app/catalog/wizard-proposal.html)
словами «да, выглядит супер — принимается», включая финальную анимацию
кнопки. Образец **принят как визуальный и поведенческий стандарт**, но
не является готовым Vue-компонентом и не создаёт пользователей.

**Общий контракт** (специфика сценария регистрации вынесена отдельно):

- Конфигурируемые шаги со стабильными ID, условной видимостью,
  общим состоянием значений и контекстной конечной кнопкой. Навигация
  «Назад» сохраняет значения и не проводит валидацию.
- Визуальный состав: компактный eyebrow сценария, **прогрессбар
  и счётчик «ШАГ X / N» на одной горизонтальной оси**: полоса слева,
  счётчик справа по вертикальному центру полосы (зазор 10px mobile,
  14px desktop), затем заголовок активного шага, опциональная
  подсказка шага, поля, неподвижный footer с «Назад» и основным
  действием. Для модальной версии использовать [Modal 1.1](#диалоги-и-прокрутка):
  центрирование, top layer, максимум 90dvh, прокручивается только body,
  тематическая полоса прокрутки.
- Во **всех** необязательных шагах полностью пустые поля показывают
  «Пропустить», а при наличии хотя бы одного введённого значения
  кнопка меняется на «Далее»; при очистке возвращается обратно.
  Если есть хотя бы одно обязательное поле — «Далее» постоянно.
  Последний шаг показывает заданное конфигурацией действие,
  например «Создать аккаунт».
- Валидировать обязательные и заполненные необязательные значения
  до продвижения. Ошибки отображать под полями, задавать `aria-invalid`
  и `aria-describedby`, переходить к ошибочному полю и ставить фокус.
  При серверной 422 сопоставлять поле с видимым шагом, раскрывать
  нужную группу и фокусировать поле.
- **Жизненный цикл ошибок Wizard:** ответы 422 с ошибками полей
  относятся к конкретным значениям и сохраняются при Back/Forward
  до изменения соответствующего поля. Ответы 5xx, сбои сети и прочие
  ошибки отправки **не принадлежат полям**: показываются только после
  соответствующего запроса, удаляются при уходе с шага и не возникают
  вновь без следующей попытки отправки. Начало нового POST очищает
  старую системную ошибку, но не введённые значения.
- Нельзя показывать сырой текст исключения Laravel/SQL, стек вызовов
  или конфигурацию БД из ответа сервера. Для 5xx выводить безопасное
  нейтральное сообщение; детали должны оставаться в серверных логах.
  Это общая политика для Wizard, а не частное правило регистрации.
- Подсказки на шаге, поле и варианте доступны по необходимости,
  но не повторяют одну и ту же информацию. Необязательные поля
  не должны иметь лишних постоянных пояснений; обязательность
  отмечать `*` в одной строке с текстом label; декоративную
  звёздочку не делать отдельным focusable-элементом. Подсказка
  «Обязательное поле» принадлежит всему родительскому label
  (hover/click на всей подписи, не только на звёздочке). **Не делать
  `label` отдельной остановкой Tab и не показывать focus-ring на подписи**;
  клавиатурный фокус переходит непосредственно к соответствующему
  `input` / `checkbox` и ссылкам. Подсказка закрывается по Escape
  или клику снаружи; без общего текста в footer.
- Декоративный эффект `pulse + moving sheen` **500 мс**
  (`ease-in-out`) запускается **только при изменении действия
  «Пропустить» → «Далее» в пределах текущего шага**. Если
  уже показано «Далее», смена роли/пола/позиции и дозаполнение
  полей не запускают его снова. Навигация Back/Forward и submit
  эффекта не вызывают. Если все необязательные поля снова очищены,
  кнопка становится «Пропустить»; при новом вводе эффект допустим.
  Масштаб **1.06 до 480px**, **1.07 выше**; не пересекать «Назад».
  Уважать `prefers-reduced-motion: reduce`.
- При hover карточек radio/role нейтральная рамка усиливается
  до 75% примеси `--control-line`. Выбранная оранжевая обводка
  сохраняет приоритет, hover не заменяет checked/focus-состояния.
- Общая визуальная база — токены и уже принятые поля, кнопки,
  focus и error-состояния дизайн-системы 1.0. Нельзя создавать
  самостоятельный вариант на каждой странице.

**Регистрация — утверждённый образец использования:** шаг роли
(группы «Основные»/«Другие», выбор может отсутствовать; выбор
сворачивает группы, выбранная роль — компактный бейдж **без слова
«Выбрано»**, с маленьким **белым крестиком внутри** для сброса) →
для игрока пол/дата рождения → спортивные параметры →
для всех ФИО → логин/пароль/согласие. Для остальных ролей
пока только роль → ФИО → аккаунт. Указанные данные сохраняются
между шагами, а скрытые по условию поля не отправляются.

**Завершение регистрации (задача 019, новая версия для MSKBA App):**
Wizard создаёт аккаунт, затем браузер открывает кабинет /account и
показывает закрываемую модалку приватности. В отличие от прежней задачи
014, GET-страницы доступны; изменяющие запросы до завершения настройки
сервер блокирует. Клиент MSKBA App откладывает одну HTML-форму или

прежний обязательный redirect сохраняется. Нельзя вынуждать пользователя

Подробности: [задача 019](../mskba_app/tasks/019/description.md).

## Проект 021 — контекстная строка и смысловые eyebrow

В `mskba_app` по запросу пользователя подготовлена под header контекстная строка: слева breadcrumbs из `BreadcrumbsResolver` (ссылка на родителей, `aria-current` у текущей страницы), справа `details/summary` «Действия». Контекстные действия получают данные от `ContextSubmenuResolver`, постоянные — «Назад», «Поделиться», «Помощь». Оформление — существующие токены `--surface/--muted/--accent/--line`, кнопки и focus 2px, минимальные области нажатия 44px, responsive без horizontal overflow. За реализацию отвечают `partials/context-bar.blade.php`, `css/context-bar.css`, `js/context-bar.js`.

**По уточнению приёмки 2026-10-09:** высота контекстной полосы
`--context-bar-height: 44px` при сохранении 44px hit areas. На desktop
sidebar получает достаточную минимальную высоту родительского grid для
коротких страниц. Из sidebar удалён дублирующий заголовок; mobile navigation
остаётся раскрываемой.

**Поведение header на dev (2026-10-26):** основной `.app-site-header`
остаётся в потоке, при прокрутке вниз уходит вместе со страницей
(`position: sticky; top: calc(0px - var(--header-height))`), а при
прокрутке вверх или наведении курсора на первые 18px окна плавно выезжает
через `.is-scroll-revealed`. Контекстная полоса `.app-context-bar`
не уходит: она закреплена сверху с `top: var(--app-visible-header-height)`.
Появляющийся header сдвигает полосу и расположенные ниже sticky-элементы.

`resources/themes/mskba_app/js/header.js` публикует на `html`:
`--app-visible-header-height` (0 либо фактическая высота раскрытого header)
и `--app-sticky-offset` (видимая часть header + высота context bar).
Изменение оповещается событием `window.mskba:header-visibility` с
`detail: { visible, stickyOffset, headerHeight, contextHeight }`. 
Sticky-навигация площадки, sidebar площадки и мобильный sidebar кабинета
используют живую границу навигации, а не постоянное `--header-height`.
Для scroll-to-anchor оставляем запас под **полный** header, потому что он
может раскрыться во время прокрутки к якорю. Учитываются открытые меню,
keyboard focus и `prefers-reduced-motion`. При наведении курсора мыши непосредственно
на основной header он остаётся раскрытым **даже при прокрутке вниз**.
После `pointerleave` разблокируется обычное правило направления прокрутки;
hover на breadcrumbs эту блокировку не устанавливает. Сенсорный ввод
не имитирует удержание hover.

**Уточнение 2026-10-26 (фикс скачка):** показанный на обратной прокрутке
header **не теряет** класс `.is-scroll-revealed` на границе
`scrollY <= --header-height` и при `scrollY = 0`. На нулевой
прокрутке липкая и естественная позиции совпадают, переключать
состояние не нужно. Только следующее уверенное движение вниз
(порог 6 px) снимает раскрытие. Критичный регрессионный сценарий:
прокрутить вниз >300 px, вверх через 80 px до самого начала и проверить
непрерывное положение обеих полос и отсутствие внезапного скачка.
Проверяется `tests/JavaScript/app-header-scroll.test.mjs`.

### Floating tooltip внутри Modal 1.1 (уточнение 023)

## MSKBA App — индикаторы требующих внимания действий (10.10.2026)

Контекстное меню «Действия» помечается маленькой зелёной точкой `--success`, **только когда внутри есть доступное пользователю действие, требующее внимания**. Тот же индикатор показываем напротив конкретного пункта в раскрытом меню. При закрытом меню точка у «Действия» мягко пульсирует; при открытом — **остаётся видимой, но статичной** (без пульса/ореола). Точка напротив нужного действия остаётся видимой. При закрытии пульсация у «Действия» возобновляется. Учитываем `prefers-reduced-motion`.

Индикатор не используется для декоративных элементов, общих пунктов («Поделиться», «Помощь») или уже завершённого действия. Не показываем его на целевой странице действия, если там это было бы избыточно. Первое применение: подтверждение аккаунта (неподтверждённый пользователь, страницы раздела аккаунта кроме страницы подтверждения). Это визуальное правило, а не отдельная модель статусов; новые условия вводим с самостоятельной проверкой доступности действия.

При выборе новой оценки, если комментарии разрешены, общий модальный диалог предлагает необязательный комментарий до 200 символов и действия «Отмена»/«Принять». В стене показываются никнейм, время и зелёный палец вверх или красный палец вниз, затем необязательный комментарий обычным цветом текста; фразы «понравилось»/«не понравилось» остаются только доступными названиями иконок и текстовым представлением API. Без комментария показывается только иконка оценки под никнеймом. После отправки комментария список прокручивается к этой записи. Редактирование комментария не затрагивает оценку. Повторное нажатие активной оценки снимает её без диалога. При закрытых комментариях оценка сохраняется без диалога. Под списком комментариев при отсутствии права записи размещён отделённый линией текст ограничения размером 75%, «Оценивать и комментировать могут только участники мероприятия.» Текущая оценка единственная на канонического пользователя; отмена/смена оценки обновляет счётчик активных лайков с контурным сердцем в бейдже «Завершено». История обсуждения и история комментариев изолированы, composer и JS общие. Организатор и подтверждённый суперадминистратор управляют двумя независимыми настройками, включёнными по умолчанию; закрытие комментариев не отключает оценки. Сам статус суперадмина не даёт права оценки. Не переносить демонстрационные фикстуры в production. UI/CI/миграции и ручная приёмка живого портала обязательны.

Лимиты отчёта для существующего транспорта production: JPEG/PNG/WebP и MP4/WebM до 10 МБ на файл, суммарно до 18 МБ на один запрос; несколько загрузок допустимы до квоты 12 фото и 6 видео. Не поднимать глобальные лимиты Nginx/PHP без проверки инфраструктуры. При отмене попапа входа отложенный RSVP не сохраняется; сохраняем его только после явного «Войти».

### Тарифная сетка площадки — 23.11.2026

Единый компонент \`venue-tariff-grid\` используется в MSKBA App и классической теме; в Filament его открывают через ссылку из «Аренда» и действия зала, а не через самостоятельный несовместимый конструктор. Базовая единица — минимальный шаг действующей политики; последовательные шаги с одинаковыми целой/половинной ценами и источником объединяются в \`details/summary\`. Внутри раскрытого диапазона видны каждый шаг, цена, источник (наследование, интеграция, ручная корректировка) и при наличии статус внешней занятости. ### Расписание площадки: 00:00 как конец текущего дня — 24.11.2026

Во всех формах рабочего расписания площадки и залов (Filament, публичный кабинет в темах MSKBA App и Dark) поле **«До» = 00:00** означает **эксклюзивную границу 24:00 того же локального календарного дня**, включая последний шаг 23:30–00:00. В поле «С» значение 00:00 по-прежнему означает начало текущего дня. Интервалы 07:00–16:00 + 16:00–00:00 смежные и допустимы; 07:00–00:00 + 18:00–23:00 перекрываются и запрещены. Реальные ночные интервалы, переходящие через полночь в следующий рабочий день, не вводятся одним интервалом: разбиваются по дням.

Технически time-input не может хранить 24:00. В БД конец хранится как 00:00; VenueScheduleClock нормализует его в 24:00 **только для сравнений и выдачи EffectiveVenueHours** (публичная сетка, доступность, слоты, пересечения родительского графика и залов). Не подменять ручной конец 23:59 полноночным маркером: 23:59 остаётся отдельным значением и не открывает слот 23:30–00:00. В Filament и обеих темах подсказка явно разъясняет 00:00. Тесты на реальные сохранения Livewire, GET/PUT публичного кабинета, исключения и финальный слот обязательны.

При сбое принятие сохраняется, пользователь может установить пароль в ЛК/восстановить доступ. Публичный email читается из support.email; редактируемый телефон и единая настройка публичных контактов ещё требуют отдельной реализации. Без миграций. Ручная сквозная приёмка #1063.
