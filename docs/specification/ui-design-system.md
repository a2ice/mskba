# MSKBA — дизайн-система новой темы

**Версия 1.0 · принята 2026-09-06 по ревизии 3 стенда.** Не применяется автоматически
к `mskba_dark`. Точные числа ниже — предложение, а не извлечённые из растра измерения.
«Строгость» означает соблюдение принятой системы; визуальный характер — выразительный,
современный, application-like, как в предоставленной презентации.

## Источники и визуальный характер

| Наблюдение в презентации | Правило предлагаемой системы |
| --- | --- |
| Чёрная среда, оранжевая подсветка краёв | графитовые поверхности + деликатный тёплый свет только у ключевого блока/активного элемента |
| Крупное белое название с оранжевой частью | тяжёлый display-заголовок; оранжевым выделяется смысловой фрагмент, не весь текст |
| Телефон с событиями и быстрыми действиями | compact app-home: короткий hero, действия и ближайшие события, не бесконечный лендинг |
| Панели аренды и уведомления | плотные, но читаемые карточки с одним главным действием и ясным статусом |
| Фото, глубокие тени, скруглённые края | выразительность строится композицией и материалом поверхностей, а не множеством эффектов |

На desktop используем свободную композицию с акцентным hero и вспомогательной
колонкой; на mobile — прямой вертикальный поток и нижнюю навигацию. Не рисуем
наклонённые телефоны вокруг каждой формы. Не заменяем бренд нейтральной админкой.
Старая тема — источник сценариев, а не визуальный эталон.

## Цвет и поверхности

Имена соответствуют CSS custom properties прототипа. Непрозрачные поверхности —
основа; glass допускается у sticky header/bar с непрозрачным fallback.

| Токен | Значение | Применение |
| --- | --- | --- |
| `--bg` | `#090A0B` | страница |
| `--surface` | `#141618` | карточка |
| `--surface-raised` | `#1D2023` | вложенная/hover-поверхность |
| `--field` | `#0E1012` | ввод |
| `--text` | `#F5F6F7` | основной текст |
| `--muted` | `#ADB3BB` | описания, placeholder |
| `--faint` | `#929AA4` | вторичные метаданные; не снижать opacity текста |
| `--accent` | `#FF7900` | primary, выделение, active |
| `--accent-hover` | `#FF922E` | hover primary |
| `--accent-active` | `#E86C00` | pressed primary |
| `--on-accent` | `#14100A` | текст/иконка на оранжевом, **не белый** |
| `--line` | `#30353B` | декоративный разделитель карточек |
| `--control-line` | `#707A86` | значимая граница input/secondary control |
| `--success` | `#7CDCAB` | подтверждено |
| `--warning` | `#FFD078` | требуется внимание |
| `--danger` | `#FF9398` | ошибка, destructive action |
| `--info` | `#8CCBFF` | нейтральное уведомление |

Обычный текст: контраст не ниже 4.5:1, крупный (24 px либо 18.66 px bold) — 3:1.
Границы значимых контролов и focus — 3:1 с соседней поверхностью. Декоративная
граница карточки не служит единственным способом распознать интерактивный control.
Статус всегда содержит текст/иконку, не только цвет. Disabled исключается из
контрастного требования WCAG, но остаётся читаемым. На фото текст размещается над
достаточно тёмной подложкой: проверка зависит от изображения, не только токена.

## Типографика

Предложение: **Inter** с кириллицей, веса 400/500/600/700/800/900. Fallback:
`Arial, sans-serif`. В прототипе Google Fonts; перед релизом — локальные WOFF2
с сохранённой лицензией, subset с кириллицей и `font-display: swap` (этап 004).
Не использовать Latin-only display-шрифт для русского заголовка.

| Роль | Desktop size/line-height/weight | Mobile | Дополнительно |
| --- | --- | --- | --- |
| display (hero) | 64/64/900 | 40/42/900 | tracking −0.045em; максимум 3 строки |
| h1 страницы | 40/44/800 | 32/36/800 | −0.035em; display может быть h1 |
| h2 секции | 28/34/800 | 24/30/800 | −0.025em |
| h3 карточки | 20/26/700 | 20/26/700 | −0.015em |
| h4 | 18/24/700 | то же | без uppercase |
| h5 | 16/24/700 | то же | роль определяется иерархией, не размером |
| h6 | 14/20/700 | то же | не заменять label |
| body | 16/24/400 | то же | длинный текст ≤65ch |
| small / helper / error | 14/20/400 | то же | ошибка не уменьшает размер |
| label / button | 14/20/600 | то же | input text 16 px во избежание iOS zoom |
| caption / badge | 12/16/600 | то же | не для основного описания |
| eyebrow | 12/16/700 | то же | uppercase, tracking 0.12em |

Выравнивание обычно влево. Uppercase — eyebrow, короткая навигационная метка или
hero, но не длинные подписи полей. Числа счёта/времени — tabular-nums. Заголовки,
кнопки и юридически значимые подписи не обрезаются ellipsis; краткие metadata
можно сокращать при наличии полного значения в доступном detail.

Общие выразительные варианты: hero 56/56 при 1024–1199 px; display внутри
каталога образцов 48/48 (mobile 40/42); promo-card heading 28/34;
compact panel heading 20/26; dialog heading 28/34. Эти роли не меняют семантический
уровень HTML-заголовка. Число времени: 48/48 desktop, 40/40 mobile.

## Пространство и композиция

Базовая шкала: **4, 8, 12, 16, 20, 24, 32, 40, 48, 64 px** (`--s1`…`--s10`).
2 px допустимы для оптической коррекции и рамок, не для произвольной сетки.

| Отношение | Desktop | Mobile |
| --- | --- | --- |
| eyebrow → heading | 12 | 12 |
| heading → description | 12 | 12 |
| description → основное действие | 24 | 24 |
| header секции → content | 24 | 16 |
| секция → секция | 48 | 32 |
| label → input | 8 | 8 |
| input → helper/error | 8 | 8 |
| поле целиком → следующее поле | 20 | 20 |
| группа полей → действия | 24 | 24 |
| padding карточки/формы | 24 | 20 |
| padding compact event row | 16 | 16 |
| gap карточек | 16 | 16 |
| icon → текст | 8 | 8 |
| соседние кнопки | 12 | 12 |
| последний content → footer карточки | 24 | 24 |

**Правильно:** label, поле и его ошибка — одна группа; 20 px до следующей группы.
**Неправильно:** error добавлен с отрицательным margin и залезает на соседнее поле.
**Правильно:** карточки одного ряда имеют одинаковые padding и footer alignment.
**Неправильно:** одна карточка с 17 px, другая с 23 px ради подгонки текста.
**Правильно:** короткая секция использует общий header+body pattern.
**Неправильно:** под каждый заголовок придуман свой gap или лишний eyebrow.

Hero — отдельный композиционный вариант: padding 40 px (32 при 1024–1199,
24 ниже 640), eyebrow → display 24, display → description 16,
description → actions 24. Footer отделён auto-space и минимум 32 px (mobile 24).
Quick tiles: gap 16 / 12 mobile, padding 20×16 / 16; icon → text 12.
Dialog: padding 32 / 24 mobile. Стандартные карточки сохраняют таблицу выше.

## Адаптивный layout

Минимум: 320 CSS px. Container: максимум 1280 px; боковые gutters 32 px
от 1024, 24 px от 640 до 1023, 16 px ниже 640. Grid gap 24 desktop, 16 mobile.

- **≥1024:** desktop navigation; app-home 2fr/1fr, форма/aside до 440 px;
  каталоги 3 колонки при достаточной ширине. Header 80 px.
- **640–1023:** две колонки карточек, крупные смысловые блоки в одну колонку;
  нижняя навигация, header 64 px. Toolbar переносится, не сжимает поиск.
- **<640:** одна колонка; primary action на ширину формы; summary cards могут
  оставаться двумя колонками только при читаемых названиях. Header 64 px.
- Toolbar: поиск `min-width: 0`, основная строка на доступную ширину;
  при нехватке места дополнительные действия переходят во вторую строку.
- Layout шире 1 колонки использует `minmax(0, …)`; в текстовых children `min-width: 0`.
- Bottom bar: 72 px + safe-area, максимум 5 пунктов, icon 22 px + label 12 px;
  страница резервирует 96 px + safe-area снизу. Не перекрывать submit/footer.
- Mobile section-nav: локальный горизонтальный scroll, доступные названия;
  нельзя маскировать поломку сетки через `body { overflow-x: hidden }`.
- Sticky header + anchors: `scroll-margin-top` учитывает высоту header и 24 px.
  Mini App позже подставляет safe-area/viewport через адаптер, а не новый набор страниц.

Проверки: 320, 360, 390, 639/640, 768, 1023/1024, 1440 px, крупный текст и 200% zoom.
Брейкпоинты — не названия устройств, а моменты перестройки композиции.

## Геометрия, изображения и движение

- Radius: input/button 12 px, badge pill 999 px, вложенная плитка 16 px,
  card/dialog 24 px, hero 32 px (mobile 24). Никаких случайных вариантов 13/19/27.
- Иконки: **Tabler Icons Outline 3.46.0**, MIT, grid 24×24, stroke 2, rounded caps;
  UI 20 px, nav 22 px, feature 24 px. Баскетбол — `ball-basketball`.
  Только готовые иконки, без ручной отрисовки/правки path и смешения пакетов.
  Сохранять viewBox и квадратные размеры, `flex-shrink:0`, не растягивать по одной оси.
  [Источник и лицензия subset стенда](../tasks/139/preview/icons/README.md).
  В этапе 004 — официальный `@tabler/icons-vue`, явные импорты; в стенде оригинальные
  path упакованы в inline symbols. Emoji и текстовые стрелки не заменяют UI-иконки.
- Avatars: 32/40/56 px, круг; интерактивный header-avatar 44 px;
  team logos могут иметь rounded-square 12 px.
- Логотип бренда — предоставленный `public/images/logo-image.png`, а не UI-иконка
  мяча. Для header/footer подготовлен `public/images/logo-mark-100.png` (98×100,
  прозрачный PNG). Высота отображения 40 px, пропорции сохраняются, максимальная
  сторона asset и CSS-ограничение не более 100 px. UI-иконки остаются Tabler.
- Media: фото карточки события **16:9**, компактное событие 1:1, исходник hero 16:9 с индивидуальным crop.
  Сам hero не фиксируется в 16:9: min-height 512 desktop, 480 tablet, 460 mobile;
  при длинном тексте растёт по содержимому. Компактное venue-photo: 88×88 / 72×72 mobile.
  `object-fit: cover`, focal point задаётся asset; существенный объект не обрезается.
- Media-card: поверх нижней части фото — вертикальный gradient от прозрачного
  к **точному цвету фона карточки** (`--surface`), без шва. Высота зоны — 25%
  всей карточки (не фотографии), ограничена высотой фото. Hover на устройствах
  с hover и keyboard focus-within увеличивают зону до 35% (+10 процентных пунктов)
  и усиливают затемнение; transition height/opacity 240 ms ease-out.
  Непрозрачный нижний край сохраняется в обоих состояниях. Бейдж находится поверх
  градиента, overlay не перехватывает клики; высота карточки не меняется.
  Для reduced motion состояния переключаются без анимации.
- Градиент — псевдоэлемент **внутри изображения**, `bottom:0`, а не позиция,
  вычисленная по ширине карточки. Последние 2 px картинки дополнительно маскируются
  до прозрачности на фоне `--surface`, чтобы дробный layout не оставлял светлый шов.
  ResizeObserver задаёт только высоту fade как 25%/35% border-box карточки;
  без JS fallback 70%/90% фото. Размеры самой карточки от observer не зависят.
- Компактная media-card: body перекрывает нижние 56 px фотографии как общий
  композиционный вариант, а не случайная подгонка конкретной записи.
  Бейдж формата — сверху слева, 16 px; body padding 24 / 20 mobile,
  date → title 8 px, title → location 8 px, content → actions 16 px.
  Карточка растёт по своему содержимому (`align-self:start`), не растягивается
  до высоты соседнего promo. Длинные заголовки переносятся, не обрезаются.
- Compact venue row: превью не сжимается, текст центрируется относительно него.
  Badge 12/16 с padding 2×8, heading 20/26, адрес 12/16, gap внутри текста 4 px.
  В типовом примере текстовый блок 70 px, mobile-photo 72 px; длинный текст
  переносится и увеличивает строку без обрезания, отрицательных отступов и
  дальнейшего уменьшения шрифта. Это общий compact-вариант, не стиль одной страницы.
- Primary shadow: `0 8px 24px #FF790026`; overlay shadow `0 24px 80px #00000080`.
  Glow — акцент, не постоянная обводка всех controls. Borders 1 px, focus 2 px.
- Layers: normal 0, sticky local 10, header 20, bottom bar 30, backdrop 100,
  dialog 110, tooltip 120, toast 130. Native dialog использует top layer;
  tooltip/toast внутри него должны быть в том же top-layer контексте.
- Motion: hover 160 ms ease-out, panel 240 ms; без bounce, parallax и бесконечного
  декоративного движения. `prefers-reduced-motion` убирает transitions/animation.

## Компоненты и состояния

Обозначения: D default, H hover, F keyboard focus, P pressed, S selected,
X disabled, L loading, E error, OK success. Неприменимые состояния не добавлять
ради заполнения матрицы. Таблица — обязательный контракт будущих компонентов,
не утверждение, что весь функционал реализован в статическом образце.

| Семейство | Разрешённые варианты | Состояния / правила |
| --- | --- | --- |
| Button | primary / secondary / ghost / danger; h44, large h48 | D/H/F/P/X/L; loading сохраняет ширину, блокирует повторную отправку, `aria-busy` |
| Link / icon button | inline underline / icon h44 | D/H/F/P/X; имя обязательно; icon-only не заменяет непонятное действие |
| Input / textarea | default, leading icon; h48, textarea min112 | D/H/F/X/L/E/OK; label всегда виден, border control-line, focus accent, invalid danger |
| Checkbox / radio | native control 20 px внутри label min44 | D/H/F/S/X/E; radio single choice, checkbox multiple choice |
| Switch | track44×24, knob18; label min44 | D/H/F/S/X; не применять для согласия или отправки формы |
| Predictive select | search + listbox + selected chip | D/F/L/S/X/E, empty; debounce, отмена stale, Esc/Arrow/Enter; текст не равен выбранному ID |
| Date/time | native или согласованный picker | D/F/S/X/E; локальная дата/часовой пояс явно, минимум 44 px touch |
| Upload | click/drop zone + preview + progress | D/H/F/L/E/OK/X; формат/лимит видны до выбора; file не уходит без действия |
| Tabs | underline или segmented (не смешивать в одной роли) | D/H/F/S/X; стрелки/Home/End, tabpanel; фильтр-toggle — button с `aria-pressed`, не tab |
| Badge | accent / success / warning / danger / neutral | D; текст + при необходимости icon/dot; не притворяется кнопкой |
| Tooltip | короткая подсказка над/под anchor | H/F; Esc, delay200; важное объяснение/ошибка остаётся в тексте |
| Card / event row | media / text / compact | D/H/F/S/L/E, empty; одна явная primary ссылка, вложенные кнопки не внутри ссылки |
| List / table | separated rows, table с captions | D/H/F/S/L/E, empty; numeric right, text left; локальный scroll, не всей страницы |
| Pagination | previous / numbered / next | D/H/F/S/X/L; `aria-current=page`, кнопки 44 px, фильтры сохраняются |
| Header / sidebar / bottom nav | desktop/mobile композиции | D/H/F/S; active orange + форма/маркер, не только цвет; максимум 5 bottom items |
| Toolbar | search + secondary filters + primary action | D/F/L/E, empty; фильтры URL-backed, wrap согласно ширине |
| Native select | короткий статический список, не поиск сущности | D/H/F/S/X/E; appearance:none, Tabler chevron-down 20 px, отступ 16 px от inline-end, padding-inline-end 48 px; SVG pointer-events:none; dropdown остаётся системным |
| Dialog / bottom sheet | стандартный / confirmation / form | open/close/F/L/E; правила размеров и независимого footer ниже; mobile sheet только как отдельно согласованный вариант |
| Toast | info / success / warning / error | show/dismiss/action; noncritical status polite, critical alert; ошибка не исчезает до прочтения |
| Skeleton | форма будущего content | L; `aria-busy` на регионе, скрыт от AT; при reduced motion статичен |
| Empty / error panel | empty-search / initial / network | explanation + одно действие; введённые данные сохраняются, error не выглядит пустым результатом |

Все кликабельные области ≥44×44 px. Для компактной иконки увеличивается hit area,
а не её картинка. Body/label не делаются мельче для помещения toolbar.

## Поведение и доступность

- DOM-иерархия h1–h6 семантическая, CSS роль не навязывает уровень заголовка.
- Один видимый основной heading экрана; landmarks, skip link, настоящий label.
- Focus 2 px accent + offset3, не скрывается без замены. Открытие dialog перемещает
  focus внутрь, Tab остаётся внутри, Esc закрывает, focus возвращается инициатору.
- Error связывается через `aria-describedby`, поле `aria-invalid`; сводка ошибок
  получает focus при failed submit. Не превращать каждый helper в assertive live-region.
- Навигация SPA должна обновлять title, heading focus и history/scroll; dialogs
  и формы не должны терять данные без предупреждения. Реализация — этапы 003–005.
- Financial/booking статусы приходят с сервера; оптимистическая анимация не выдаётся
  за подтверждение оплаты/брони. Стенд 002 содержит только демоданные.
- Auth/permission остаются на сервере. Disabled button — не защита доступа.

## Диалоги и прокрутка

- Диалог центрируется по обеим осям относительно **видимого visualViewport**,
  а не документа или только layout viewport. Native `dialog`, fixed-позиция
  по центру видимой области и `translate(-50%,-50%)`; не `margin:auto` по layout.
  При открытии и на resize/scroll visualViewport обновляются центр и ограничения;
  учитываются offsetLeft/offsetTop, width/height, эффективный CSS zoom элемента.
  Fallback без API — innerWidth/innerHeight, до JS — CSS viewport-значения.
- Высота по контенту: минимум 300 CSS px, максимум **95% видимой высоты**.
  Когда этот максимум меньше 300 px (landscape/zoom/маленькое окно), приоритет
  у видимой области. Не допускать ухода кнопок за экран ради минимума.
- Ширина стандартного диалога до 560 px, разумный минимум 300 px, жёсткий
  максимум **90% видимой ширины**; минимум также ограничен этим максимумом.
  Более широкий вариант потребует согласования; не задавать все диалоги на 90vw.
- Flex-column: header и footer `flex-shrink:0`, body `min-height:0; overflow-y:auto`.
  Scroll только внутри body; header с закрытием и footer действий остаются видимыми
  и не зависят от прокрутки. Footer не fixed относительно страницы.
- Padding по горизонтали 32 / 24 mobile, header 24 по вертикали, body 24 снизу,
  footer 20 по вертикали. При доступной высоте ≤400 px или ширине ≤360 px
  (после учёта zoom) compact-dialog: padding по горизонтали 12, header/footer
  по вертикали 8, body снизу 12; две flex-кнопки с gap 8, декоративная иконка
  подтверждения скрыта. Размер текста не уменьшается ради помещения диалога.
  Footer отделяется border `--line`, кнопки на mobile в две равные колонки.
- Фоновая страница блокируется от прокрутки; её положение сохраняется при закрытии.
  Focus переходит внутрь, Tab/Shift+Tab цикличны, Esc/закрытие возвращают focus.
  Прокручиваемый body доступен клавиатуре и имеет имя. Не вкладывать всю страницу
  в transform-контейнер, меняющий containing block фиксированного overlay.
- Стрелка native select стилизуется отдельно, сам список и доступность остаются
  браузерными. Системное выпадающее меню нельзя обещать одинаковым между ОС.
  В forced-colors возвращается `appearance:auto`, декоративный SVG скрывается.
