# Пароли: установка, смена и восстановление (18.11.2026)

Единственный формат проверки пароля — PasswordVO (от 6 до 255 символов, заглавная и строчная латиница, цифра, спецсимвол; без внешних пробелов). SetUserPasswordHandler централизует обновление всех связанных физических идентичностей, password_updated_at, is_temporary_password и remember_token.

## Публичный аккаунт

- ЛК → Настройки → Пароль и безопасность: первый пароль устанавливается без старого, смена существующего требует текущий пароль и подтверждение нового.
- Вход → Забыли пароль?: пользователь выбирает подтверждённый email или Telegram-контакт с доступным личным чатом бота, вводя точный email или @username. Сервер никогда не показывает список чужих контактов и не сообщает, существует ли контакт, подтверждён ли он.
- На подтверждённый контакт отправляется новый временный пароль, после входа пользователь меняет его в настройках.
- SMS и VK не предлагают сброс до появления настоящей инфраструктуры доставки; подтверждённый телефон без работающей доставки не выдаёт секрет.
- Неоднозначные контакты у разных канонических пользователей, заблокированные аккаунты, неподтверждённые и удалённые контакты не инициируют сброс.
- Ограничение: 5 запросов/минуту на endpoint с IP + 3 попытки/час на контакт; для ключа контакта используется HMAC.
- Результат публичного запроса всегда нейтральный. Пароль не обновляется при недоступном транспорте или ошибке доставки; данные для доставки не сохраняются в аудит.

## Filament

Редактор пользователя → действие «Установить пароль». Только подтверждённый superadmin, с повторным вводом своего текущего пароля, двумя полями нового пароля и обязательным основанием. Действие повторно проверяет права на сервере, не позволяет редактировать недоступные учётные записи, записывает факт в аудит без значения пароля, делает пароль временным. Старые remember-cookie сбрасываются.

## Эксплуатация

Для восстановления по email необходим реально работающий MAIL_MAILER (не log / array / null). Для Telegram — токен бота и ранее открытый доступный приватный чат. Проверка SMTP и Telegram на production проводится после CI-деплоя без отправки реальных паролей на произвольные адреса. Секреты не логировать и не показывать административным пользователям после отправки формы.

## Ошибки установки пароля в Filament — 26.11.2026

В модальном действии superadmin отображаются требования PasswordVO и явное уведомление «Пароль не установлен» с причиной при неверном пароле администратора, несовпадении подтверждения, ошибке политики или недоступности операции. Модальное окно остаётся открытым. Прежняя авторизация, атомарность, аудит и временный пароль сохраняются; пароль никогда не выводится и не записывается в аудит. Проверить ошибки и успешную смену для системного пользователя на DEV; production отдельно после CI и приёмки.
