# VK Publisher: two credentials, one publication mode

Community 174334075, Mini App 54729290; VK ID login app 54729329 unaffected. The real provider rejected PKCE and custom callback. Use legacy https://oauth.vk.com/authorize with redirect_uri=https://oauth.vk.com/blank.html, response_type=code, scope=photos and single-use session state. Keep the original .com redirect URI in both requests, even if the browser displays .ru. Admin opens authorization in a new tab and completes it in the first-party MSKBA superadmin form with the VK code/state response. Live VK blank page returns #code=... (fragment). Accept code/state from either fragment or query, but never both. Reject other hosts, bearer tokens and unmatched/expired state. No code or URL should be shared with third parties or chat. POST only, CSRF and session/actor binding; no query-string callback on MSKBA. Exchange on server with client secret using form POST to https://oauth.vk.com/access_token and no redirects. Save encrypted token only after photo probe. No raw provider error/body, token or code in logs or views. No live wall post in connection checks.

Separate user photo token and community wall token. Full publication requires a cover. No text-only mode. Reauthorize after expiry. Automatic refresh is not confirmed; reference implementation reports ~24 hours and no refresh token. Never claim autonomous long-term posting until confirmed. Live acceptance on MSKBA remains required: verify state survives provider blank redirect, exchange, upload and saved attachment in post. Telegram and VK ID unchanged.

Reference: https://github.com/tequilex/factory/blob/main/factory/core/vk_auth.py and its documentation. Evidence is third-party live experience, not a VK guarantee.

Pending authorization is stored for ten minutes in the server cache keyed by a digest of the authenticated session ID and actor ID; the state is hashed and consumed under a cache lock only after validation. This avoids overwrites by parallel browser session requests. Local validation errors VK-A01–A07 distinguish URL format, missing state/code, missing flow, mismatch, changed configuration and concurrent completion; never include secret values. A valid OAuth code is opaque printable ASCII and is transmitted only as form body data. Actual reason for earlier generic validation failure is unknown.
