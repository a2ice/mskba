# Page Builder — JS редактор (фаза 2)

## Область

Изолированная реализация поверх уже введённых `backoffice.page_builder.js.view/edit/publish`.
Не меняет `UserOperationalPermissionEnum`, `BackofficePermissionManager`,
профили системных ролей или UI выдачи разрешений — это отдельно развивается в соседнем PR.

В существующих экранах редактирования **Страниц, Шаблонов, Компонентов**
есть действия:

* «Просмотреть JS» — только `js.view`.
* «Редактировать JS» — отдельный черновик; только `js.edit` (+ базовый `builder.edit`).
* «Тест JS · песочница» — сохраняемый черновик выполняется в ограниченном
  `iframe sandbox="allow-scripts"` с *opaque origin*, CSP `sandbox`,
  `default-src 'none'`, `connect-src 'none'`, `form-action 'none'`.
  Фрейм содержит **тестовый DOM**, а не настоящую страницу. Черновой JS
  никогда не выполняется в авторизованном окне Filament.
* «Опубликовать JS» — отдельная публикация; не включает отключённый скрипт.
* «Включить JS» — отдельное подтверждаемое действие для публикации на сайт.
* «Отключить JS» — немедленно убирает ссылку из новых HTML-ответов и закрывает
  публикацию JS URL. Уже исполняющийся JS в открытой вкладке не остановить без
  обновления страницы.
* «Откатить JS» — меняет местами текущую и предыдущую опубликованные версии;
  состояние включения сохраняет.

Каждое действие проверяет разрешения **на сервере**, а не только скрывает
кнопку. Право редактирования HTML не даёт права редактировать/публиковать JS.

## Публичная загрузка

Публикуется **только** код, для которого `is_enabled=true` и существует
`published_hash`. Текущая запись находится в БД, отдельных JS-файлов нет.
Laravel отдаёт JS по URL:

`/page-builder/scripts/{page|template|component}/{id}/{sha256}.js`

Заголовки: `text/javascript`, `nosniff`, `ETag`,
`Cache-Control: public, max-age=0, must-revalidate`.

Новая версия имеет другой адрес; отключённая или старая версия получает 404.
Список URL формируется из опубликованной страницы, её опубликованного шаблона и
компонентов, на которые страница ссылается. Повторный компонент в HTML не
создаёт двойное подключение.

JS выводится в конце `<body>` через `@stack('scripts')`, не внутри `<main>`.
Предпросмотр HTML Page Builder по-прежнему **никогда** не запускает черновый JS.

## Безопасность и ограничения

Это **намеренно доверенный исполняемый код** сайта — даже редактор с правами
`js.publish` и `js.enable` может изменить DOM или делать API-запросы как
посетитель. Назначать доступ только доверенным людям. Браузер не является
песочницей для **опубликованного** JS. Включение и выключение фиксируются
в `page_builder_script_audit`.

Изолированный предпросмотр не является визуальным предпросмотром живой
главной: в нём нет реального DOM/паркетного слайдера, assets и сетевых вызовов.
Для тестирования на настоящей главной использовать только DEV с резервной
возможностью отключить JS.

Время выполнения уже активного JS нельзя гарантированно прервать на открытой
странице. Отключение рассчитано на последующие загрузки HTML и проверки
публичного JS endpoint.

## Тестирование

- черновик не исполняется и не попадает в HTML;
- публикация без включения не меняет сайт;
- новая версия меняет URL и делает старый endpoint недоступным;
- отключение убирает URL, rollback возвращает предыдущий код;
- шаблон и компоненты подключаются без дублирования;
- предпросмотр требует авторизации и получает CSP opaque sandbox.

Только `dev`; `main` и production не менять.
