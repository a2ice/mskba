# VK publication of editorial content

Issue #922. The content editor offers a separate, default-off VK checkbox. Existing VK ID login is unrelated. Enable on production only with VK_WALL_ENABLED=true, VK_WALL_GROUP_ID (positive numeric group ID), VK_WALL_USER_TOKEN (authorized user token with wall and photo permissions), and optionally VK_WALL_API_VERSION (default 5.199). Secrets belong in the protected server environment, never Git or chat. Confirm the actual target community and permissions before enabling. Configure APP_URL=https://mskba.ru. DEV is fail-closed; mock API requests in tests.

Published non-FAQ materials visible in the site feed may be selected. Queue job takes title, short description, canonical material URL, and optional cover. With no cover, send text and the material URL directly via wall.post using the community token; photo authorization is not required. The cover is converted to JPEG for VK photo upload. It uses photos.getWallUploadServer, photos.saveWallPhoto, then wall.post with owner_id negative and from_group=1. Telegram remains independent. When the community is configured and photo authorization has expired, expressly selected full-photo publications wait with status awaiting_auth; the scheduler resumes only that status for the same enabled community and still-public material once authorization has returned. No retries of unknown/sending/published results. No text-only fallback for a photo job. The persisted requires_cover flag records the initial selected mode (existing rows retain photo mode); adding/removing a cover later does not silently change queued VK publication mode. A single publication row records status, target, post ID and safe error. Repeat save never creates a second post after success; if VK explicitly rejects a request, a subsequent explicit save can retry. Ambiguous wall-post outcomes require manual reconciliation and are not retried. No historical material is automatically selected, no live test post is created, and unchecking cancels pending publication but does not delete an already published VK post. Editing a material does not edit an existing VK post in this initial implementation.

Official method schema: https://github.com/VKCOM/vk-api-schema/blob/master/wall/methods.json and https://github.com/VKCOM/vk-api-schema/blob/master/photos/methods.json.
