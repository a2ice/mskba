## Назначение

Статус \`UserStatusEnum::CONFIRMED\` означает, что пользователь заявил основные персональные сведения и подтвердил принадлежащий ему **основной контакт**. Это не независимая юридическая верификация реальной личности.

## Условия

Для подтверждения **обязательны все пять условий**:

1. \`primary_verified_contact\`: хотя бы один подтверждённый *основной* контакт. Принимается любой поддерживаемый подтверждённый канал (\`email\`, \`telegram\`, \`vk\` и др.), а не только email;
2. \`first_name\`: непустое имя;
3. \`last_name\`: непустая фамилия;
4. \`birth_date\`: дата рождения раньше текущей даты, возраст вычисляется из даты;
5. \`gender\`: установленный пол из поддерживаемого enum.

Отчество, фотография, никнейм и роль участия не относятся к условиям статуса аккаунта.

При регистрации и входе через Telegram/VK может появиться подтверждённый контакт, но он становится основным только согласно правилам Contact. Подтверждённый **неосновной** контакт не выполняет условие. Для подтверждённых аккаунтов замена основного контакта на неподтверждённый запрещается.

## Роли участия

Подтверждение аккаунта и выбор роли участия — **разные процессы**. Выбор \`player\`, \`coach\` и других ролей выполняется на экранах ролей, не входит в заявку на подтверждение аккаунта и не вызывается при обновлении его статуса. Правила дополнительных данных роли будут задаваться независимо.

## Интерфейс

- \`GET /account\`: статус пользователя и пульсирующая кнопка «Подтвердить аккаунт» для \`unconfirmed\`;
- \`GET /account/confirmation\`: единая страница с отдельными карточками условий (без wizard для подтверждения **аккаунта**) и отображением выполненности;
- \`POST /account/confirmation\`: проверка и фиксация персональных данных и статуса;
- карточка «Основной контакт» в \`mskba_app\` открывает отдельный модальный **контактный** wizard (в отличие от снятого wizard подтверждения самого аккаунта): выбор канала → проверка / авторизация → подтверждение;
- Email проверяется через существующий \`ContactValue\` и \`CreateContactForUserHandler\`; AJAX \`POST /account/confirmation/contact\` отправляет код и возвращает ID ожидающего подтверждения контакта, \`POST /account/confirmation/contacts/{contact}/verification/confirm\` принимает код, а \`POST /account/confirmation/contacts/{contact}/verification\` отправляет повторно с серверным cooldown. До подтверждения контакт имеет статус \`unverified\`; подтверждённым считается только после проверки кода;
- Telegram подтверждается через подписанный Telegram Login Widget и \`account.telegram.link\` (Telegram ID), VK через \`account.vk.link\` / OAuth VK ID с возвратом на страницу подтверждения. Ввод произвольного username запрещён для верификации Telegram/VK;
- Телефон в контактном wizard отображается отключённым до реализации SMS-подтверждения;
- \`GET /account/contacts\` в новой теме предоставляет список контактов, статусы, смену основного, отправку/ввод Email-кода и удаление. Серверный \`SetPrimaryContactForUserHandler\` запрещает подтверждённому аккаунту назначить неподтверждённый контакт основным;
- в навигации «Действия» уже есть отдельная ссылка на подтверждение.

Старая тема \`mskba_dark\` пока сохраняет наследованный UI wizard; новая тема \`mskba_app\` использует карточки. Серверная проверка одинакова и не доверяет никакому клиентскому представлению.

### Добавление и управление контактами

В разделе \`/account/contacts\` используется отдельный контактный pop-up:
выбор Email/телефона/Telegram/VK → для Email и телефона ввод значения с
клиентской и серверной проверкой через AJAX → сообщение об успешном добавлении
с действиями «Добавить ещё контакт» / «Закрыть». Список контактов обновляется
без перезагрузки страницы. Новый Email или телефон остаётся неподтверждённым
до отдельного подтверждения в списке. Email использует существующий код,
телефон можно сохранить, но SMS-подтверждение пока не реализовано.

В письме с шестизначным Email-кодом срок действия (15 минут) отображается
в часовом поясе Europe/Moscow с явной отметкой «МСК» независимо от
часового пояса Carbon-даты, возвращённой из БД. Это только форматирование
для получателя: сохранённое значение expires_at, сравнение с now() и
серверная проверка срока действия не изменяются.

Telegram и VK добавляются **только** через официальную подписанную авторизацию
(соответственно Telegram Widget и VK OAuth), без ручного ввода username/ID.
Контакт при такой привязке становится подтверждённым сразу.

### Эмуляция Telegram / VK ID для тестирования (технический долг реальных провайдеров)

Пока независимые dev-каналы Telegram webhook и VK ID OAuth не подключены,
реализован контролируемый эмулятор только для local и staging. Он нужен
для проверки UI/UX добавления контакта в /account/contacts и на странице
/account/confirmation, включая успех и обработку отказов, без обращения
к Telegram и VK.

- В приватной конфигурации окружения необходимо установить
  CONTACT_PROVIDER_EMULATION_ENABLED=true. По умолчанию false.
- Сервер разрешает эмуляцию только при APP_ENV=local|staging|testing
  и APP_URL с хостом localhost, 127.0.0.1 либо dev.mskba.ru.
  В production POST /account/contacts/provider-emulation возвращает 404
  даже при случайно выставленном флаге.
- Требуется авторизация и CSRF, ограничение throttle:12,1. Произвольный
  Telegram/VK username от браузера не принимается.
- Выбираемые исходы: success (HTTP 201), denied (403), cancelled (422),
  unavailable (502), timeout (504), conflict (409).
  Ошибки показываются внутри попапа и не создают контактов.
- Успех добавляет только Contact типа Telegram или VK. Синтетический ID:
  test_emulate_{userId}_001, затем _002 и далее; в интерфейсе
  @test_emulate_001 (Telegram) или test_emulate_001 (VK), плюс метка
  «Тестовый контакт». Метаданные: source=test_provider_emulation,
  is_emulated=true. Синтетический ID не совпадает с числовыми ID провайдеров.
- Тестовый контакт считается подтверждённым только в тестовой среде,
  следует обычным правилам основного контакта и уведомлений. Можно
  тестировать подтверждение аккаунта, но запрещено переносить эту БД или
  подобные тестовые контакты в production.
- TelegramAccount, VkAccount, реальные OAuth-токены, внешние сессии и
  webhook не создаются. Эмуляция не доказывает владение реальной
  учётной записью, не подтверждает работу внешних провайдеров и не
  заменяет настоящие E2E-проверки.
- При отключённом флаге сохраняется текущий официальный внешний flow;
  production не показывает тестовую эмуляцию.

**Незакрытый техдолг:** безопасная доставка Telegram dev-событий
(отдельный bot или защищённый proxy), настройка VK ID приложения и callback,
проверка реальных OAuth/webhook E2E, отключение тестового флага и очистка
тестовых контактов на dev.

Первый успешно подтверждённый контакт назначается основным автоматически;
если ранее был временный неподтверждённый основной, он утрачивает основной
статус. Явная смена основного допускается только на подтверждённый контакт.
Временный неподтверждённый основной разрешено удалить; удаление подтверждённого
основного требует предварительного назначения другого подтверждённого контакта.

## Подтверждение и защита

\`CompleteAccountConfirmationWizardRequest\` проверяет входные поля, а \`CompleteAccountConfirmationWizardHandler\` сохраняет их атомарно с блокировкой canonical user и вызывает \`User::confirmAccount()\`.

Доменный метод \`User::confirmAccount()\` **самостоятельно** повторно проверяет подтверждённый основной контакт и все четыре защищённых поля и меняет статус на \`confirmed\` только для \`unconfirmed\`. После commit генерируется \`UserAccountConfirmed\` (как прежде). Клиент не может отправить роль для обхода требований; выбор роли не сохраняется при подтверждении.

После подтверждения \`UpdateAccountProfileController\` отклоняет прямое изменение \`first_name\`, \`last_name\`, \`birth_date\`, \`gender\`; при этом отчество остаётся обычным редактируемым полем.

## Изменение подтверждённых данных

Пользователь подаёт заявку через \`/account/profile\`, указывает новые значения и обязательную причину. Исходные и предлагаемые данные хранятся отдельно и **не влияют на профиль до одобрения**. По canonical user допускается одна активная заявка типа \`confirmed_profile_change\`.

Модератор с правом \`manage-users-as-superadmin\` видит закрытую очередь \`/admin/profile-change-requests\`. Одобрение применяет snapshot только после сверки исходного профиля; отклонение и блокировка требуют причину. Отклонение/отмена позволяют подать повторно, блокировка запрещает новые заявки того же типа до \`unblock\`. История решений хранится отдельно, включая факт блокировки и разблокировки. Снятие блокировки не одобряет изменения. Подробнее: [Паттерн модерации заявок](request-moderation-pattern.md).

## Совместимость

Прямая смена статуса из админки является отдельной административной операцией, не пользовательским flow подтверждения; этот endpoint не должен восприниматься как доказательство выполнения пяти условий. Перед переносом новых правил в production необходимо отдельно проверить существующие административные исключения и исторически подтверждённые записи с неполными данными.

### UX подтверждения аккаунта — локальная переработка 2026-10-12 (ожидает визуальной приёмки)

В теме mskba_app, на странице /account/confirmation данные профиля представлены
одной карточкой «Профиль»: имя, фамилия, необязательное отчество, дата рождения,
пол. «Основной контакт» расположен ниже. Ссылка — «Управлять контактами».

До подтверждения аккаунта каждое поле отдельно или все изменённые поля
сохраняются через PATCH /account/profile с JSON-ответом, без дублирования
серверной валидации или обхода блокировки подтверждённой личности.
Сохранённое значение каждого поля хранится в data-saved-value; локальные
изменения активируют дискету, успешный серверный ответ обновляет эталон,
а ошибки 422 показываются рядом с полем. После запуска запроса действует
пятиисекундный минимум блокировки с обратным отсчётом.
Нельзя подтвердить аккаунт при несохранённых локальных изменениях.

Сообщение возле кнопки подтверждения содержит ссылку к первому незаполненному
условию и количество остальных условий. Ссылка на поле ставит в него фокус.
Все контактные модальные окна используют Modal 1.1, шапку-eyebrow «Добавить
контакт» и icon-button #close без дублирующего H2 и вводного текста.
