# Editorial news agent API

Separate from the project-updates API. Backoffice superadmin issues a 24-hour scoped token for existing system account dev under Контент → Доступ агента · Публикация новостей. Publication is opt-in; default token can only create/read drafts. A separate opt-in editorial-news:social ability is issued only together with editorial-news:publish; existing tokens retain their original site-only access. Revoke on the same page. Production superadmin may separately opt into a 30-day GitHub Actions bridge token with exactly the three editorial abilities. Ordinary tokens retain existing lifetime limits. Store only in the dedicated editorial-production environment secret MSKBA_EDITORIAL_NEWS_TOKEN; rotate before expiry. See ops/editorial-news/README.md. Tokens are environment-specific; never put them in chat, git or logs.

Base route: /api/v1/internal/editorial-news. JSON Accept header and Bearer authentication are required.

- POST /: multipart/form-data with alias (unique lower-case slug), title, summary, content (Markdown), optional cover (JPEG/PNG/WebP, max 5 MiB, 6000×6000). Creates draft of type material. Cover uses existing ContentCoverManager; stored as WebP. Requires editorial-news:write. Repeating alias returns 422; GET returns existing owned material to recover after a lost response.
- GET /{alias}: requires editorial-news:write. Returns status, cover presence, title and public URL when published.
- POST /{alias}/publish: requires editorial-news:publish, publishes an owned material draft to the site feed. No body means site-only. Optional JSON telegram_chat_ids (local active chat IDs), publish_in_vk (boolean), vk_group_id (required when true) require editorial-news:social as well. Social requests are production-only for actual delivery; VK requires a cover and available authorization by default. Explicit defer_vk_until_authorized=true permits site/Telegram now with VK awaiting_auth until photo authorization is restored, retaining the same full-photo mode. Invalid targets fail before publishing. Chosen destinations use existing queue managers after commit. Explicit repeat with the same destinations does not requeue; different destinations on a published item return 409. No-body repeat leaves existing destinations unchanged. No automatic retry of ambiguous external deliveries is introduced.
- GET /destinations/list: requires publish and social abilities; returns active local Telegram IDs/titles/types and VK availability/can_defer/group ID, no secrets. Nonproduction returns no available destinations.
- Responses include enabled Telegram chat_id/status/message_id and VK group_id/status/post_id (or null). Pending and awaiting_auth are not confirmation of delivery; GET again to check status. Raw provider errors are not returned.
- No access to system updates, FAQ, other authors' materials or archived content; no editing or deletion via API.

The existing project-update draft API and verification rules remain unchanged. No secret is committed to the repository. Reviewed public news cover assets may be stored under ops/editorial-news/covers for the bridge.
