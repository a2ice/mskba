# MSKBA — универсальные раскрываемые уведомления (этап 02)

## Границы и UX

Все постоянные уведомления пользователя, доставленные через существующий
UserNotification/notification-toasts.js, имеют действие «Развернуть».
Эфемерные тосты о сохранении форм не открывают дополнительное окно.

- direct и support: ConversationView внутри одного поповера с историей,
  отправкой через существующий HTTP API, системными записями и ошибками.
  Новые таблицы сообщений не создаются.
- Прочие типы: NotificationDetails. Приглашения в команду можно принять или
  отклонить с подтверждением и серверной проверкой. Остальные события
  открываются на целевой странице.
- Одновременно раскрыто только одно окно. На десктопе его можно
  перемещать указателем или клавишами-стрелками, менять размер.
  Положение и размер сохраняются в sessionStorage конкретного пользователя.
  На узком экране/в Telegram Mini App — bottom sheet с safe-area.
- На /account/notifications и всех её вложенных страницах второй плавающий
  чат не появляется: обычный тост ведёт к полной переписке.
- Не сохраняем сообщения и историю в браузерном хранилище. В пределах
  текущей вкладки сохраняются только ID открытого уведомления и черновик;
  черновик переносится в полную переписку после перехода. Прочитанный
  тост тоже можно восстановить по ID через приватный GET notice/{id}:
  сервер проверяет владельца, а не доверяет ключу из sessionStorage.
- «Скрыть», «Отметить прочитанным», «Развернуть» независимы. Скрытие
  не уменьшает счётчик и действует до конца вкладки.
- Очередь тостов по-прежнему ограничена тремя элементами.

## Безопасность и нагрузка

- GET /account/notifications/popover/{support|direct}/{id}: авторизованный
  endpoint с ограничением 30 запросов/мин, без кеширования. Проверяет
  конкретный доступ и не отдаёт историю — только адреса уже существующих
  авторизованных API и приватный Reverb-канал действительной сущности.
- История — keyset pagination; Reverb только сигнал изменения без текста;
  при событии, возвращении фокуса и каждые 30 секунд при видимом окне
  выполняется серверная проверка актуального доступа. 403/404 скрывает историю.
- Ссылки строго same-origin. HTML сообщений производится сервером в Blade,
  где пользовательские тексты экранируются.
- Действия команды доступны только для source team.invitation.created,
  PATCH team-invitations/{id}; сервер отдельно проверяет владельца и статус.

## Проверки

PHPunit на запреты чтения чужих диалогов, закрытие support и auth.
Node на маршруты, режим страницы сообщений, очередь тостов,
раздельное прочтение, скрытие, раскрытие и безопасные ссылки.
Vite build, Laravel Pint, CI и dev deploy. Браузерная визуальная
приёмка отдельно для desktop/mobile/Telegram Mini App.
