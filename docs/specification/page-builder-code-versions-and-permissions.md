# Page Builder · ограниченные версии CSS/JS и права кода

## Текущее состояние (этап 1)

* Существующие `draft_css` / `published_css` страниц, шаблонов и компонентов продолжают работать без новых CSS-файлов или запуска Vite при публикации. Добавлены `previous_css` и `has_previous_css` — самостоятельная предыдущая версия именно CSS. Публикации одного HTML её не затирают; при изменении CSS предыдущий опубликованный CSS заменяется. Отдельная кнопка «Откатить CSS» возвращает предыдущую версию атомарно, не откатывая HTML.
* После каждой публикации максимум **две последние** записи `publish` содержат полноценные снимки страницы/шаблона/компонента (текущая + предыдущая). Более ранние становятся `publish_audit` с контрольной суммой; имя действия, автор и дата сохраняются. Старые снимки восстанавливать нельзя. Эта очистка также применяется один раз миграцией к существующей истории.
* Переключение между Laravel/CMS больше не дублирует HTML/CSS внутри audit snapshot.
* Новый `page_builder_script_assets` содержит по одной строке для каждого владельца (page/template/component) с `draft_js`, `published_js`, `previous_js`, SHA-256 и `is_enabled=false`. Ранее опубликованный JS заменяется при третьей публикации; старая полная версия не накапливается. Аудит публикаций и откатов — только SHA, действие, автор и дата.
* ВАЖНО: на данном этапе `published_js` **не подключается к страницам**. Даже если сервис его опубликовал, он не исполняется. JS-редактор, запуск, безопасный preview, CSP и kill switch требуют отдельного этапа.

## Права в Филаменте

В `Пользователи → [пользователь] → Filament` добавлены:
- просмотр / редактирование / публикация CSS;
- просмотр / редактирование / публикация JS.

Первоначально права только у superadmin, как у остальных высокоуровневых прав Page Builder. Superadmin вправе делегировать их поштучно. Для работы дополнительно требуются `backoffice.access`, базовые `backoffice.page_builder.view/edit/publish` согласно операции.

CSS-поле скрыто без права просмотра и недоступно для ввода без права редактирования. Серверные обработчики сохранения и публикации проверяют права независимо от отображения кнопок: публикация страницы с изменённым CSS требует отдельного `css.publish`, даже если право обычной публикации HTML выдано.

## Кеш браузера

CSS пока встроен в `<head>`; Vite используется только для системных CSS/JS. Дополнительные кешируемые URL вида `/assets/{id}.css?v={hash}` будут нужны лишь при переходе на отдельную отдачу кода из БД. Не создавать физические файлы на каждую ревизию и не компилировать JS на сервере без отдельного решения.

## Границы следующего этапа (JS-редактор)

Отдельные поля Filament с правами и безопасной передачей кода, изолированный preview (не запускать код из черновика в авторизованном backoffice), явная кнопка включения/отключения, аудит, безопасные HTTP-заголовки и кешируемая раздача по хешам. Не внедрять инъекцию JS напрямую через `<script>{!! $code !!}</script>`.
