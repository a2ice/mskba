# Identity Tracking Retention

## Разделение данных

Online presence — краткоживущая Redis-проекция с TTL. Browser fingerprint и
`game_live_view_sessions` хранятся в SQL, но не являются источником online-
состояния или авторизации.

## Ограничение записи

Чтобы heartbeat и внутренние web-запросы не создавали write amplification,
обновление SQL-активности fingerprint и его связи с пользователем ограничено
атомарным cache throttle. Интервал по умолчанию — 10 минут. Недоступность cache
не должна ломать пользовательский запрос: middleware сохраняет прежнее
best-effort поведение и выполняет SQL-запись.

Production должен использовать Redis:

```dotenv
IDENTITY_FINGERPRINT_ACTIVITY_STORE=redis
```

## Retention и очистка

Неактивные fingerprint и подробные live-сессии имеют независимый настраиваемый
retention по 90 дней. Ежедневная команда `privacy:prune-tracking` сначала
удаляет просроченные live-сессии, затем fingerprint ограниченными пакетами.
Nullable-ссылки actor и ещё актуальных аналитических строк обнуляются внешними
ключами; actor attribution и доменные сущности при этом сохраняются.

Очистка выбирает ID в стабильном порядке и повторяет cutoff в `DELETE`. Поэтому
fingerprint, обновившийся между выборкой и удалением, не будет удалён. Каждый
пакет — отдельный короткий запрос без длинной общей транзакции.

## Операционный контроль

`privacy:tracking-diagnose` показывает без идентификаторов:

- общее число fingerprint и live-сессий;
- число новых строк за последние 24 часа;
- число строк, уже вышедших за retention.

Полные `COUNT` выполняются только при ручном запуске диагностики. Ежедневная
очистка автоматически проверяет только остаток просроченных строк по индексам
`last_seen_at`; суточные выборки ручной диагностики используют индексы
`created_at`.

Существенный суточный скачок может означать bot traffic или проблему с cookie.
Ненулевой и растущий `expired` после планового запуска означает, что scheduler
не работает либо лимит пакетов недостаточен. Плановая очистка записывает такой
остаток как warning в application log; успешный запуск фиксируется как info.
