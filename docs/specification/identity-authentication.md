# Identity Authentication

## Назначение

Аутентификация объединяет аккаунты, созданные обычной регистрацией и через Telegram Mini App. Telegram-пользователь не должен создавать второй web-аккаунт: он устанавливает пароль существующему пользователю и входит по username либо подтверждённому контакту.

## Пароль

`users.password` nullable, потому что доверенная Telegram-авторизация может создать пользователя без локального пароля.

Установка и смена выполняются через отдельный `SetUserPasswordHandler`:

- первый пароль не требует текущего пароля;
- последующая смена требует корректный текущий пароль;
- новый пароль проходит `PasswordVO`;
- обновляются `password_updated_at` и `is_temporary_password`;
- `remember_token` меняется, чтобы старые remember-cookie перестали давать долгоживущий доступ;
- строка пользователя блокируется `FOR UPDATE`, поэтому параллельные смены не перезаписывают друг друга без повторной проверки актуального пароля.

## Разрешение логина

`UserLoginResolver` принимает одно строковое значение и собирает совпадения среди:

- `users.username`;
- подтверждённых email-контактов пользователя;
- подтверждённых телефонных контактов пользователя;
- подтверждённых Telegram-контактов пользователя;
- актуального Telegram `@username` из metadata подтверждённого Telegram Mini App контакта.

Вход разрешается, только если после нормализации найден ровно один пользователь. Это защищает от неоднозначности, когда строка теоретически одновременно совпадает с username одного пользователя и контактом другого. Удалённые контакты и soft-deleted пользователи стандартными global scope в поиск не входят.

Резолвер только определяет пользователя. Проверка пароля, блокировки аккаунта, создание Laravel-сессии и событие первого входа остаются в `AuthHandler`.

Ошибки отсутствующего идентификатора и неверного пароля имеют одинаковый публичный текст, чтобы форма входа не использовалась для перебора зарегистрированных контактов.

## Telegram

Стабильная идентичность Telegram хранится как `telegram_user_id`. `@username` удобен для человека, но может измениться; при каждом доверенном Telegram-входе его нормализованная копия обновляется в metadata подтверждённого контакта. Наличие одного только совпавшего `@username` без активного подтверждённого Telegram-контакта не позволяет войти.
