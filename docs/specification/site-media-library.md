# MSKBA Site Media Library

**Статус:** реализация для DEV на основе спецификации 19.10.2026. Рабочая задача: [285](../tasks/285/description.md). Production/main не затрагивать.

## Назначение

Медиафайлы оформления сайта управляются в Filament, без коммита изображения в Git или деплоя. Не заменяет загрузчики пользовательских аватаров, фотографий площадок и других entity Media.

## Модель

- site_media_folders: название и уникальный slug, только логическая группировка, не физическая директория; один уровень; пустая папка удаляется без удаления ассетов.
- site_media_assets: UUID, папка, название, описание, alt, исходное имя, необязательный legacy_path, current_media_id/previous_media_id; stable identity.
- Media: polymorphic owner site_media_asset, collection site_assets, disk public; конкретный физический blob. Только две актуальные версии. Все прочие коллекции остаются без изменений.
- Stable same-origin URL /media/site/{uuid}, Cache-Control public/no-cache/must-revalidate, ETag от Media ID, nosniff.
- Файлы в storage/app/public/site-media/{uuid}/{version-uuid}.{extension}; физический путь не является публичным контрактом. Для DEV убедиться, что этот storage переживает deploy_dev и включён в backup.

## UI

- Filament → Контент → Медиафайлы: таблица с миниатюрами, поиском, фильтром папок, названием, форматом, размером, копируемым URL; экран редактирования метаданных, загрузка, замена, оптимизация, откат и удаление.
- Filament → Контент → Папки медиа: создание, переименование, изменение slug, удаление пустой папки.
- Загрузка принимает JPEG, PNG, WebP (в том числе пакетную загрузку) до 10 MiB, до 6000 px каждой стороны. По умолчанию сохраняет исходные байты; опционально WebP через существующий WebpImageNormalizer. AVIF/SVG/анимации не поддерживаются в первом выпуске.
- Замена переводит прежний current в previous, удаляет старую previous только после успешного изменения БД; откат переставляет current/previous без создания третьего файла. Редактирование названия/папки/alt не создаёт новую версию.
- Delete блокируется при найденном опубликованном использовании в Page Builder. Внешние ссылки на URL невозможно обнаружить полностью.
- Атомарные права backoffice.site_media.view/upload/edit/delete/restore/folder_manage; подтверждение и backoffice.access обязательны; стандартно все права есть у superadmin.

## Hero Slider

В layers-slides для desktop/mobile background, image-layer и custom icon-link добавлены селекторы media UUID с приоритетом над существующими FileUpload. Сохраняются старые поля image/path и old draft/published JSON; компонент рендерит безопасную public media URL. Файлы из page-builder/hero после импорта legacy_path автоматически разрешаются через библиотеку с тем же визуальным содержимым.

## Миграция (отдельная управляемая операция)

Команда php artisan site-media:import-hero по умолчанию — DRY RUN. php artisan site-media:import-hero --apply создаёт папку hero-slider и импортирует реально используемые файлы по ссылкам из слайдов/HTML/CSS/JS: page-builder/hero на диске public и /images в Git. Повтор безопасен; найденные отсутствующие файлы выводятся явно.

При каждом DEV deploy сразу после migrate вызывается site-media:import-hero --apply --skip-missing от www-data. Отсутствующие исходники выводятся в лог и должны разбираться отдельно. Принципиально нельзя запускать импорт от deploy/root и оставлять каталог site-media недоступным на запись PHP-FPM.

Команда НЕ публикует новый HTML, НЕ переписывает JS/CSS ссылок главной, НЕ удаляет исходные /images. После импорта изображения доступны в новом каталоге, а затем их ссылки в HTML/CSS/JS заменяются редактором с независимой публикацией и DEV QA. Не считать импорт слайдов единственной частью миграции: спрайт мяча и сцена Площадок также входят в инвентаризацию.


## LQIP — производные предпросмотры (DEV, 26.10.2026)

- При загрузке и замене JPEG/PNG/WebP SiteMediaManager автоматически пытается создать
  прозрачную WebP-копию с длинной стороной до 96px (при необходимости 80/64/48/32px),
  quality 32 и размером до 10 КиБ; используется существующий WebpImageNormalizer,
  включая EXIF-ориентацию и alpha-канал. Если генератор/GD недоступен,
  **оригинал всё равно сохраняется и отображается**, ошибка регистрируется.
- Производная копия лежит рядом с **конкретным Media-файлом** под именем
  `<version-uuid>.lqip.webp` и не добавляется в таблицу Media.
  Замена создаёт собственный preview, откат возвращает preview прежней версии,
  очистка второй старой версии и удаление ассета удаляют соответствующие preview.
  `current_media_id` и `previous_media_id` продолжают означать только реальные
  версии основного изображения.
- В Filament медиа-каталоге доступны колонки LQIP и состояние, кнопка
  «Создать недостающие LQIP» (пакеты по 25 в очереди), «Прогресс LQIP»
  (число обработанных/созданных/пропущенных/ошибок), а при редактировании
  «Создать / пересоздать LQIP» и URL копии. Проверяются существующие
  права `backoffice.site_media.edit` и `backoffice.site_media.view`.
- Для серверной миграции — `php artisan site-media:lqip` (без изменений),
  `php artisan site-media:lqip --apply` (создать недостающие),
  необязательные `--limit=N` и `--force`; всё выполняется только по запросу.
  Автоматического массового backfill при deploy нет.
- Маршрут `/media/site/{uuid}/lqip` обслуживает **текущую** Media-версию,
  отдаёт image/webp, валидируемый ETag и 404, если миниатюры нет.
  `SiteMediaAsset::lqipUrl()` проверяет наличие файла на сервере и возвращает
  null при отсутствии — **без клиентского HEAD/404**.
- Hero Slider передаёт URL миниатюр вместе с оригиналами для подключённых
  library UUID и импортированных legacy_path. JS темы `mskba_app`
  показывает миниатюру до декодирования оригинала и делает fade-in без
  изменения координат; при отключённом JS оригинальная ссылка в `src`
  остаётся рабочей. Есть универсальный Blade `<x-site-media-image :asset="$asset"`
  для новых мест использования медиатеки. Все изображения, не имеющие LQIP,
  выводятся стандартно; исходные статические `/images` и CMS-authored CSS
  не переписываются.
- **Исключение**: анимированные спрайты (например мяч) намеренно не конвертируются
  в движущуюся LQIP-анимацию; для кадрированных анимаций нужен отдельный pipeline.
  Этот сервис работает с одиночными JPEG/PNG/WebP.

## Автоматическое использование LQIP в Page Builder (DEV, 27.10.2026)

- В стандартном `PageBuilderRenderer` после сборки опубликованных HTML/CSS
  формируется ограниченный read-only manifest (`PageBuilderLqipManifest`)
  для **реальных** ссылок `/media/site/{uuid}` в HTML компонентов/страниц
  и CSS Page Builder. Ссылки проверяются по текущей версии Media и
  наличию её `.lqip.webp` в storage. Нет лишних сетевых HEAD/404.
  Manifest размещён в безопасном `<script type="application/json">` отдельно
  от редакторского HTML (JSON-экранирование). Изменений опубликованных
  Filament HTML/CSS, версий и файлов **нет**.
- Vite-модуль темы `mskba_app/js/features/page-builder-auto-lqip.js`
  автоматически использует manifest для обычных `<img>` внутри
  `.mskba-page-builder` и CSS `background-image: url(...)`, когда в
  свойстве ровно **одна** картинка из медиатеки (градиент вместе с одним
  фоном поддерживается). Отдельный декоративный слой LQIP не участвует
  в раскладке и плавно исчезает после decode полноценного изображения.
  Игроки/секции и текстовые слои остаются в своих координатах.
- Уже обработанные Hero Slider изображения и `<x-site-media-image>`
  пропускаются, чтобы не дублировать предзагрузку.
  При отсутствии миниатюры или JS всегда остаётся оригинальный `src` /
  исходный CSS-фон. CSS с несколькими URL-фонами и анимированные
  спрайты намеренно не обрабатываются до специализированного pipeline.
  URL из `/images`, не включённые в Site Media Library, также не
  подменяются.
- Действует и на редакторский preview, но текущие опубликованные данные
  не меняет. Тесты PHP проверяют HTML/CSS, отсутствие миниатюры и
  восстановление версии, а тесты Node.js проверяют клиентскую подмену.
