# Filament — операционные разрешения

## Источник истины
Используем существующие \`user_operational_permissions\`, \`UserOperationalPermissionEnum\`, \`UserOperationalPermissionChecker\`. Отдельного набора ролей Filament не создаётся, системные роли и пользовательские роли участия не меняются.

### Матрица прав
- \`backoffice.access\`: вход в /backoffice; не даёт доступа ни к одному ресурсу сам по себе
- \`backoffice.widget.view\`: доступ к каталогу стандартных виджетов
- \`backoffice.widget.create\`: создание виджетов
- \`backoffice.widget.edit\`: редактирование виджетов
- \`backoffice.widget.delete\`: удаление виджетов
- \`backoffice.button_style.view\`: просмотр справочника CSS-стилей
- \`backoffice.button_style.manage\`: создание/редактирование/удаление CSS-стилей

Для ресурса одновременно необходимы \`backoffice.access\`, просмотр ресурса и соответствующее право на действие. Все проверки выполняются на сервере на каждом запросе. Исполняемые HTML/CSS/JS виджеты остаются доступными только подтверждённому superadmin.

### Значения по умолчанию
- Superadmin: все административные действия (неотзываемый доступ к управлению); подтверждённый, не блокированный аккаунт.
- Admin: исторически существовавшие вход, просмотр, создание и редактирование обычных виджетов. Удаление и управление стилями не разрешены по умолчанию.
- Moderator/editor/user: доступ запрещён, пока superadmin не выдаст конкретные права.

Явные разрешения/запреты имеют приоритет над значениями по умолчанию, кроме superadmin — его собственный доступ не может быть случайно отключён. Заблокированные, неподтверждённые и удалённые пользователи не получают доступ, даже если для них выставлены разрешения.

### Выдача прав
Раздел Filament **«Доступ к Filament»** (\`/backoffice/backoffice-users\`) доступен исключительно подтверждённому superadmin. Список показывает основные аккаунты (без alias), кроме superadmin и system. В форме можно включить/отключить 7 галочек и сохранить.

Форма Filament записывает исключительно 7 административных разрешений через отдельный сервис \`BackofficePermissionManager\` с блокировкой строки canonical-пользователя и транзакцией. Она не перезаписывает права техподдержки, создания мероприятий, назначения ролей и прочие операционные права. Изменение не требует менять системную роль. Сохранение не обновляет таблицу users.

Исторический интерфейс операционных разрешений сохраняется; пользователь в роли admin не может выдать Filament-права через старую форму, включая подмену POST. На старом резервном редакторе виджетов также действуют разрешения Filament, поэтому им нельзя обходить явно отозванное право на изменение.

### Проверка / приёмка
1. На /backoffice/backoffice-users найти editor/user и выдать вход + просмотр виджетов.
2. С этой учётной записи подтвердить видимость каталога и запрет создания/редактирования.
3. Добавить разрешение редактирования, убедиться в доступе к обычному виджету и запрете custom_html.
4. Отозвать вход, убедиться, что новый запрос и действие закрыты 403 (проверяется сервером, не только скрытием меню).
5. Подтвердить, что системная роль и разрешения техподдержки остались неизменными.
