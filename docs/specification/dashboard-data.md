# Динамические данные дашборда

Epic [#1073](https://github.com/a2ice/mskba/issues/1073). Серверные источники, редактор Filament и отображение в существующих карточках ЛК.

## Контракт

- Существующие `AccountDashboardWidget`, `AccountDashboardService` и preferences сохраняются. Новые nullable `source_key`, `source_settings` задают источник и его конфигурацию для типа `dynamic`.
- `DashboardDataRegistry` разрешает только явно зарегистрированные ключи, не произвольные классы, SQL или код из БД. Неизвестный источник недоступен. `DashboardDataProvider` проверяет доступ отдельно от targeting; принудительное включение по ID не обходит эту проверку. Блокированный канонический пользователь не получает динамические данные.
- `GET /account/dashboard/widgets/{widget}/data` требует auth, активную тему mskba_app, доступность и видимость виджета; повторно проверяет провайдер, возвращает `widget_id` и `data: {total, items}`, private/no-store. Пилотный источник `unread_messages` переиспользует существующий счётчик уведомлений.
- Тип `dynamic` доступен в Filament для публикации. Новые карточки не создаются автоматически: администратор выбирает источник и аудиторию. По прямому решению владельца для этого этапа используется существующая оболочка карточек без отдельной приёмки UI Studio; проверка на dev.

## Персональные источники (серверный этап)

- `my_interests`: текущие активные PlayIntent и прямые VenueSubscription канонической identity; публичные будущие игры с открытым индивидуальным набором, тренировки и игровые тренировки на опубликованных активных площадках в пределах 30 дней. Использует существующие правила совпадения площадки/времени, исключает собственные события, дедупликация по Event, сортировка по времени. Уведомления и каналы доставки не определяют наличие совпадения в ленте. Пока без состояния «новое», свободных слотов, ценовых предложений и live-инвалидации.
- `wallet_summary`: существующий GetAccountWalletOverview; собственные балансы в minor units, последние операции (total — число возвращённых операций), без чужих кошельков, платежных реквизитов и комиссий. `summary` — опциональные агрегаты DTO; базовый контракт сохраняется.
- `upcoming_events`: опубликованные мероприятия с текущим/будущим временем окончания; подтверждённое участие с актуальной версией, принятая заявка или организатор. Общий scope с «Мои игры», приватные мероприятия дополнительно проходят существующую авторизацию просмотра. Один Event — одна запись. Пока без отдельных записей аренды и внешних тренировочных расписаний.
- `my_rental_requests`: собственные rental-заявки (ожидание, hold, предстоящие подтверждённые) и активные собственные предзаявки, только при доступности rental_flow и portal с учётом rollout. Для заявок используется тот же requester scope, что в личном кабинете; для предзаявок — канонический requester по текущему ACL. Раздельные счётчики, без чужих заявок, финансовых снимков и контактов. Предзаявка и заявка — отдельные записи.
- Персональные источники поддерживают limit 1–10 (по умолчанию 5). Данные отображаются в существующей оболочке карточек.

## Настройка в Filament

«Сайт и дизайн → Виджеты дашборда»: тип «Динамический виджет», источник из реестра, лимит 1–10 (для источников со списком). Аудитория, ширина, порядок, скрытие и перемещение используют существующие настройки. Установка аудитории не выдаёт доступ к доменным данным. Настройки источника нормализуются на сервере; при смене на статический тип очищаются. Публикация регулируется существующим переключателем enabled; старый fallback-редактор не позволяет создавать, изменять или удалять динамические виджеты. Существующие типы не меняют поведение. Настройки live, пустого состояния и операционных источников добавляются вместе с их реализацией, не имитируются действующими.

## Отображение

Blade dashboard-dynamic-content использует тот же DTO, что и защищённый endpoint; повторная проверка провайдера выполняется перед чтением. Существующие panel/grid/richtext/actions, без нового UIKit и без автоматической публикации. Пустые списки и отказ чтения не показывают старых данных. Ссылки из провайдера валидируются как внутренние. Если администратор не настроил действия, используется стандартная ссылка на соответствующий раздел. Существующее обновление HTML на уведомлениях, reconnect/focus и периодической сверке работает и для новых карточек; персональные данные не задерживаются таймером административного обновления. Отдельная доменная Reverb-инвалидация остаётся следующим этапом.

## Инвалидация

`DashboardWidgetsInvalidatedBroadcast` — контракт приватного сигнала для канонического пользователя, `users.{id}`, после commit, с ключами источников и флагом изменения каталога. Не передавать личные записи. Подписка клиента, доменные listeners, debounce, reconnect, fallback и проверка отзыва прав относятся к следующим PR; существующий публичный сигнал общей конфигурации не меняется.

## Следующие этапы

Подключить интересы, расписание, заявки, финансы и центр действий через существующие read models. Операционные провайдеры используют реальные permissions и текущий scope по площадкам/залам; не выводят сведения на основании глобального targeting. Зависимость: Epic #987. Для текущего этапа по решению владельца — существующий дизайн, тесты отрицательных сценариев, CI и dev smoke; отдельная ветка UI Studio не интегрируется.
