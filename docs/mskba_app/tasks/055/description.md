# 055 — Пол и полный редактор «Личных данных» в попапе игрока

## Цель и критерии приёмки
Убрать readonly поле «Пол» из формы физических параметров, под аватаром разместить «Пол: мужской/женский/не установлен» (метка «Пол» обычная, **значение** оранжевая ссылка), открыть разъясняющий попап и из него полноценную вкладку «Личные данные» профиля в модальном окне с сохранением всех подтверждённых/неподтверждённых состояний и кнопками. «Сохранить все» → «Применить» также в основном профиле. «Запросить изменение подтверждённых данных» открывает существующий вложенный диалог (с сохранением UX и ACL).

## Технические границы
Переиспользовать фактический компонент/эндпоинты аккаунта, не дублировать логику и модальные операции. Проверить ошибки/доступность/сохранение.

## Процесс
CI (PHP, JavaScript, сборка frontend, PostgreSQL 16/17) → PR/merge в `dev` → проверка развёртывания → визуальная приёмка владельца. `main` не затрагиваем. Следующий этап выполняется после приёмки текущего.

## Статус
Принято пользователем 29.10.2026. PR #502 и #503 опубликованы в `dev`; блокирующая ошибка при сохранении физического профиля исправлена hotfix #504 в задаче 054.

## Реализация 29.10.2026

- Пол больше не дублируется в физической форме. Под визуальным блоком персонажа — обычная метка «Пол:» и оранжевая ссылка на **фактически сохранённое значение** (`мужской`, `женский`, `не установлен`); ссылка раскрывает объяснение и затем редактор личных данных.
- Личные данные и заявка на изменение подтверждённых сведений вынесены из страницы аккаунта в общие Blade-partials и используются **обоими** интерфейсами. Сохранение остаётся через исходный PATCH endpoint и штатный JS inline-save, модерация — через действующий endpoint/диалог.
- В обоих местах кнопка общей формы «Сохранить всё» переименована в «Применить»; серверный формат и права не меняются.
- В контроллер роли добавлена только необходимая загрузка canonical профильных данных и существующих заявок для темы `mskba_app`. Legacy-тема не изменена.
- Приёмка: открыть попап пола на /account/participation/player, отредактировать неподтверждённый профиль, проверить подтверждённый профиль и заявку, открыть обсуждение заявки, протестировать закрытие и возврат фокуса. Повторить редактор на /account/profile.

## Замечания визуальной приёмки 29.10.2026

- Кнопку «Закрыть» внизу личных данных удалить: для закрытия есть крестик в заголовке и Escape.
- Перенести в **непрокручиваемый footer** попапа общие кнопки «Применить» и «Запросить изменение подтверждённых данных» (только при разрешённом состоянии); внутри тела формы их не дублировать. Страница `/account/profile` сохраняет исходное размещение кнопок под полями.
- Ссылкой является **само значение пола**, а не слово «Пол». При пустом поле отображать «не установлен»; нормализация пола для временной картинки аватара не должна выдавать ненастоящий мужской пол пользователю.
- При успешном изменении неподтверждённого пола обновить подпись на странице игрока из возвращённого сервером значения без перезагрузки.
- Сохранить общий механизм inline-save, модалку заявки, независимые правила редактирования/ACL, корректный scroll/top layer и доступность на мобильном.
