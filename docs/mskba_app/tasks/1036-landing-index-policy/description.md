# #1036 — Технический механизм индексации SEO-посадочных

DEV ONLY. PR #1114 merged 26.11.2026, d90932e525fa; добавлен редакционный чеклист. Данный этап готовит код, но не разрешает реальную индексацию.

- Общий FEATURE_VENUE_CATALOG_LANDINGS=true сохраняется; отдельный FEATURE_VENUE_CATALOG_LANDING_INDEXING=false по умолчанию во всех средах. Не включать в .env сервера или main в рамках этой задачи. Только HTTPS на хосте, одновременно совпадающем с APP_URL и входящем в существующий seo.indexable_hosts, допускается к индексации даже при ошибочном запросе с production Host на dev. DEV всегда закрыт по текущему списку indexable_hosts. Существующий middleware, robots.txt и инфраструктура не меняются.
- Общий policy для HTML и sitemap: активная запись, allow_indexing, непустая фактическая гостевая выборка, непустой очищенный вводный/основной текст и индивидуальные Title/Description. Это минимальные технические условия, не оценка качества. Ориентир в 3 площадки рекомендательный, одна площадка не блокирует технически непустую подборку.
- Только чистый публичный ЧПУ (без query) допускает index, follow. Варианты готовой посадочной (sort, map, page, tracking, явные дубли фильтров) — noindex, follow, canonical/HTML ссылки сохраняются. Не готовая landing, preview, fragment — noindex, nofollow, noarchive. При включённом gate произвольные GET-фасеты обычного каталога — noindex, follow; чистый каталог и его page-only pagination прежние. Gate off сохраняет существующее поведение.
- Sitemap при включённом gate добавляет только чистый URL записей, удовлетворяющих тем же условиям и include_in_sitemap=true. Не добавляет варианты, черновики, пустые страницы и dev. Существующие источники sitemap сохраняются, ошибки отдельных записей изолируются. При выключенном gate нет дополнительного чтения каталога для sitemap. При включении проверяется актуальная выдача по каждой разрешённой записи; перед реальным релизом измерить время sitemap на фактическом количестве записей и при необходимости оптимизировать до масштабирования.
- Тесты: обе темы, симулированный production HTTPS и dev, выключенный флаг, чистая готовая landing, пустая, draft, запрещённая, незаполненная, sitemap-флаг отдельно, page/map/sort/tracking, произвольный фасет, несовпадение APP_URL и Host. Никаких внешних запросов в тестах.
- Отдельное решение владельца нужно для переноса в main и фактического запуска индексации после проверки production данных, содержимого/мета, географии, canonical и наличия рабочих сценариев аренды. Не отправлять sitemap в поисковые системы без отдельного согласования. Никаких DB/migration/booking изменений. После merge dev проверить отсутствие изменения noindex/sitemap; авторизованный редактор видит корректное состояние общего режима.
