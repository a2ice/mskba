# MSKBA App / 318 — единый каталог лиг

Связанная задача: [docs/tasks/318](../../../tasks/318/description.md). Эталон: `/venues`, общий `theme::layouts.category` и UI Kit через Filament → Дизайн → Темы оформления → UI Kit / Гайдлайн.

## Контракт оформления

- Общий светлый shell со sticky sidebar, toolbar, двумя режимами карточек/списка и адаптивными фильтрами; без локального второго shell и без CSS из `mskba_dark`.
- Публичные карточки используют `.app-category__card` / `__card-cover` / `__card-body` / `__badges` / `__details`; стили только через токены текущей дизайн-темы.
- Текстовый поиск и фильтры `status`, `season` используют `.app-category__filters` и общий `.select-control` с декоративным SVG chevron. Дубли desktop/mobile работают с одинаковыми query-полями, скрытый `view=list` сохраняет список при отправке.
- Режимы карточки/список и сброс фильтров — общий `theme::components.catalog-toolbar`. Ссылки сохраняют текущий поиск и фильтры при переключении режима.
- Логотип лиги вписывается в cover с `object-fit:contain`, заглушка — существующий SVG-символ `#ball`. Не добавлять темные локальные стили или случайные цвета.

## Критерии проверки

- Desktop: `/leagues` визуально совпадает с композиционным паттерном `/venues`: отступы, sidebar, toolbar, карточки, селекты, состояние кнопки «Создать лигу».
- Mobile: отдельный блок «Категории и фильтры» открывается и отправляет те же поля; карточки и режим `list` не теряют статус, название, счётчики и ссылку.
- Гость видит только активные/архивные записи; черновики скрыты; `q`, `status`, `season`, пагинация и `view=list` сохраняются.
- Проверить состояния hover/focus и отсутствие переполнения длинных названий/логотипов на desktop и mobile.
- Ручная визуальная приёмка остаётся открытой до проверки на `dev`.
