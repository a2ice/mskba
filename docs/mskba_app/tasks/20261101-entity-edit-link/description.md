# Публичные сущности — быстрый переход к редактированию

## Задача
Для авторизованного пользователя, который может редактировать конкретную публичную сущность, показывать компактный карандаш справа напротив заголовка. По нажатию открывать существующую страницу управления сущностью.

## UI/UX
- Только иконка карандаша, без технического текста рядом; подсказка `Редактировать` при наведении, доступное название `Редактировать` для скринридеров.
- Размер интерактивной области 38 × 38 px, скругление 9 px, контрастный фокус для клавиатуры, hover с акцентным цветом.
- Расположение на одной строке с заголовком, с отступом от текста и соседних действий. На узких экранах иконка не сжимается, длинный заголовок переносится без горизонтального скролла.
- В темы `mskba_dark` и `mskba_app` вынесены отдельные минимальные повторно используемые компоненты; действующий дизайн-системный набор цветов сохранён.

## Доступы и поведение
- Гость и пользователь без действительного права не видят карандаш.
- Право определяется по действующим проверкам редактирования сущности, включая разрешения в действующем принятом контракте; не подменять эти проверки глобальными разрешениями бэкофиса.
- Для лиг/сезонов иконка ведёт на `leagues.manage` / `leagues.seasons.manage` только при контрактном праве `EDIT` и доступном статусе. Проверка баннерного редактора остаётся независимой, для сохранения совместимости с существующим поведением.
- При редактировании профиля пользователя ссылка для владельца учитывает выбранную публичную роль; обладатель разрешения на администрирование других пользователей переходит в экран бэкофиса.
- Для мероприятий ссылка не показывается после завершения или отмены.

## Приёмка
1. Проверить отображение и переход для владельца / уполномоченного контрактом, а также отсутствие у гостя и пользователя без права.
2. Проверить лиги, сезоны, площадки и команды в `mskba_app` и поддерживаемые страницы в `mskba_dark`.
3. Проверить размеры, отступы, вертикальное выравнивание, длинные заголовки, наведение, фокус, мобильные экраны.
4. Убедиться, что backend продолжает возвращать отказ в доступе при прямом обращении к форме без права.
5. Провести существующие PHP-тесты и Vite-сборку; сохранить прежнюю видимость редакторов баннера.

## Уточнение интерфейса (1 ноября 2026)
- На публичных страницах лиг и сезонов оставить **только карандаш** для перехода к редактированию. Убрать отдельные кнопки «Изменить баннер», «Редактировать лигу» и «Редактировать сезон» — это дублирование уже доступного действия.
- В бэкофисе для лиг, сезонов, команд, турниров и площадок убрать отдельную вкладку «Баннер»: тот же редактор добавляется в основную форму рядом с логотипом, обложкой или другими настройками изображений. В редакторе пользователя баннер находится во вкладке «Профиль», не в «Роли и права».
- Вкладка «Основное» должна быть первой для всех перечисленных сущностей. Остальные вкладки и проверки прав сохраняются.
- В публичном редакторе команды баннер размещается рядом с загрузкой логотипа; у площадки — рядом с фотогалереей; у турнира — в блоке основных данных и обложки. У лиги и сезона баннер редактируется на той же странице, куда ведёт карандаш.
- Для лиги в публичном редакторе доступна загрузка логотипа (JPG, PNG, WebP до 5 МБ), текущий файл сохраняется, пока пользователь не выберет новый.
- Редактор баннера по-прежнему сохраняет изображение отдельно через защищённый API; не вкладывать дополнительные формы внутрь HTML-форм и не ослаблять проверки контрактов, модерации и прав.
- На мобильном экране заголовок, изображения, формы и кнопки не должны слипаться; сохранить вертикальные отступы между плашками и выравнивание иконок в текстовых строках.
