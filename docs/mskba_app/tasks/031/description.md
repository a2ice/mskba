# 031 — Единый тонкий corner glow у поверхностей, модалок и sidebar

**Статус:** на визуальной приёмке (локально, без публикации). **Дата:** 2026-10-13.

## Решение пользователя

После визуального сравнения утверждены: очень деликатный оранжевый градиент в правом нижнем углу серых плашек (максимальная зона 200×100 px и 35% ширины/высоты), вдвое слабее первоначального концепта; у модального окна — **один** эффект на весь dialog, не по секциям; состояния модалки success/error меняют тон на зелёный/красный. Такие же мягкие оранжевые акценты нужны у активного и hovered пункта меню sidebar.

## Объём и контракт

- Только действующая локально тема `mskba_app`: общие CSS-токены и `.panel`, `.mskba-modal`, `.app-account-nav__link`, без переопределений отдельно на каждой странице.
- Для модалок единая поверхность на корневом `<dialog>`; header, body и footer не создают своих градиентов. Смена цвета на success/error при изменении состояния, а не по наличию оранжевой primary-кнопки.
- Навигация: active, hover и focus-visible с сохранением доступности и читаемости. Mobile и reduced-motion без регрессий.
- Существующие особенности фотографий/промо, исходные фоновые изображения, status-badges и интерактивные контролы не перерисовывать. Бизнес-логика, данные, маршруты, а также `mskba_dark` вне объёма.
- Сначала локальная реализация и приёмка, **ни commit, ни push в origin/dev до команды пользователя**.

## Локальный результат (2026-10-13)

- Добавлены единственные color-токены и градиентный слой для `.panel` и `.mskba-modal`, одно место настройки геометрии (35%, max 200×100), радиус `farthest-side` исключает видимые прямоугольные швы.
- Фон контактного диалога больше не переопределяет общую modal-оболочку; футер прозрачен. `account-contacts-add.js` переключает root `data-surface-tone` между neutral/error/success.
- Active/hover sidebar используют этот же слой; специальных фоновых эффектов по дочерним секциям не добавляли. Фото-карточки и promo имеют собственный фон и исключены из обычной обработки.
- Эталон: http://127.0.0.1:8014/catalog/surface-glow.html (включая `?tone=success` и `?tone=error`). Локальный реальный экран: http://localhost:8000/account/contacts (нужна авторизация).
- Chrome: обычная поверхность, success/error modal без прямоугольных швов визуально проверены. Реальное поведение страницы за авторизацией, mobile и hover должны пройти пользовательскую приёмку.
- Сборка Vite PASS (изолированный `/tmp`, только существующие предупреждения о крупных чанках и статическом изображении), JS syntax PASS, diff-check PASS.
- **Без commit/push/PR/deploy.** Чужое незакоммиченное изменение `docs/specification/identity-account-confirmation.md` сохранено без вмешательства.

### Уточнение в ходе приёмки 2026-10-13

На реальном окне «Контакт добавлен» статусное зелёное свечение отсутствовало: ранее существовавший `.app-contact-wizard__dialog { background:var(--surface) }` переопределял `.mskba-modal`. Удалён только конфликтующий фон; status по-прежнему выставляется через `data-surface-tone` общего dialog. Сопутствующие правки профиля/контактов ведутся в [032](../032/description.md).
