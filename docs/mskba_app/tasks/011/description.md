# 011 — Унифицированная модальная оболочка и тематическая прокрутка

**Статус:** На проверке · **Запрос:** 2026-10-08 · **Контекст:** [#139](../../../tasks/139/description.md), [008 — AuthDialog](../008/description.md), [010 — Wizard](../010/description.md).

## Обязательное правило пользователя

Любой **модальный popup** в `mskba_app` должен:
1. Находиться **выше всех остальных UI-слоёв**, включая sticky header, меню, сторонние overlays; стандарт — **браузерный top layer через нативный `dialog.showModal()`**, а не произвольный z-index. Для невозможных случаев top layer — заранее утверждённое решение, не локальная магическая константа.
2. Быть **центрирован относительно видимой области экрана** (включая mobile), не превращаться в bottom sheet по умолчанию.
3. Иметь **максимальную высоту 90% видимой высоты**: `max-height: 90vh; max-height: 90dvh` с учётом браузерных safe areas и клавиатуры при необходимости. При малой высоте сохранять доступность элементов.
4. Состоять из `header / body / footer`: header (заголовок, close) и footer (кнопки) НЕ прокручиваются, только body имеет `overflow-y: auto; min-height: 0`. Ими можно управлять даже в длинных формах.
5. На внутренних прокручиваемых областях использовать **общий тематический scrollbar** (цвета токенов: `--accent`, `--surface-raised`/`--line`, узкая ширина, hover). Firefox через `scrollbar-color` и `scrollbar-width`, WebKit/Chromium через `::-webkit-scrollbar`. Если ОС скрывает/подменяет overlay-scrollbar, не строить кастомную JS-полосу.
6. Поддерживать клавиатуру и focus, ESC, возврат фокуса, lock background scroll, overlay backdrop, reduced-motion, мобильный zoom.

## Предварительная проверка

В принятом [гайдлайне](../../../specification/ui-design-system.md) уже закреплены flex-column, прокрутка только body, focus; однако **старое ограничение 95% видимой высоты** и прежняя нецентрированная мобильная версия AuthDialog противоречат новым пожеланиям. Это новая конкретизация общего modal-контракта, согласованная прямым запросом пользователя 2026-10-08, и должна быть отражена как **ревизия**, а не тихий override.
Существующий AuthDialog сейчас использует `z-index: 110` и прокрутку всего диалога на mobile — нужно исправить. Тестовый Wizard в каталоге пока не в popup, но его оболочка `wizard-frame` должна иллюстрировать те же ограничения.

## Проверки и ограничения

- Headless Chromium: реальные нативные `:modal` поверх элемента с
  `z-index:2147483647`; viewport 360×640 / 390×844 / 440×956 /
  768×780 / 1440×900 / 900×360; диалог центрирован
  (отклонение центра 0), высота не более 90% viewport, body overflow:auto,
  неподвижные header/footer при прокрутке, тематический scrollbar;
  mobile горизонтального overflow нет; переключение режимов и Escape работают.
- Реальный Safari/iOS, экранная клавиатура, browser-managed
  overlay-scrollbar требуют ручной проверки: CSS не способен гарантировать
  отображение нестандартной полосы поверх системного scrollbar.
- Повторные реальные POST проверки: 401 для несуществующего логина,
  422 для неправильной регистрации, 503 для восстановления; сообщения
  видимы в нативном диалоге. Динамические ветки тестового Wizard на
  360/390/440/768/1440 по-прежнему работают.
- Полный тест 401/422/503 после смены HTML семантики выполнен;
  серверную логику задача не затрагивает.
