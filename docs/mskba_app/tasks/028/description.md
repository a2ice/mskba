# 028 — Статус staff-ролей на аватаре и realtime-счётчики уведомлений

Дата: 2026-10-11. Тема: `mskba_app`. Статус: реализовано локально; требуется CI и визуальная приёмка на Dev.

## Решение

- Общий Blade partial `theme::partials.user-avatar` сохраняется и переиспользуется. Административный уровень (superadmin, admin, moderator, editor) теперь кодируется **рамкой аватара** того же цвета, что уже описан в `UserSystemRoleEnum::avatarBorderColor()`. Для обычного пользователя и системного аккаунта специальной рамки роли нет. Буквенных бейджей больше нет.
- Только для размещения в header выводится отдельный бейдж непрочитанных уведомлений: оранжевый круг диаметром 21.6px (90% от предыдущих 24px), значение `1..9` или `∞` при 10+ уведомлениях. Бейдж скрыт при нуле и для гостя. Admin-цвет никогда не влияет на его цвет. Его доступное имя содержит исходное числовое значение без ограничения `∞`.
- Когда фото не загружено, общий avatar partial рендерит ту же SVG-иконку `<use href="#user"/>`, что и форма загрузки `/account/profile`; буквенные инициалы не генерируются. Загруженное фото показывается без изменений.
- Подпись рядом с аватаром — `User::username` (логин), а не `UserAddressing::greetingName()`. Общее правило обращения по имени, включая приветствия кабинета, **не меняется**.
- Колокольчик в шапке сохраняется как прямая ссылка на `account.notifications`; это отдельный функциональный shortcut, без дополнительного бейджа. Страница `/account/notifications` в `mskba_app` остаётся пока пустым shell и требует самостоятельного развития в будущем, не подменяем демонстрацией фиктивного списка.
- У счётчика «Уведомления» в desktop/mobile sidebar и у аватара **один источник данных** — `CountNewUserNotificationsHandler`. Даже при нуле `<span data-notification-count hidden>` остаётся в DOM, чтобы WebSocket мог показать значение без перезагрузки. Значение и атрибут `hidden` синхронно меняет `notification-counts.js`. Число в sidebar остаётся точным (`99+` после 99), только на аватаре используется `∞`. Первичное число JS берёт из `data-unread-count`, а не из текста `∞`.

## Reverb / надёжность

- Переподключаем **существующий** Echo/Reverb в `resources/js/realtime.js`, приватный канал `users.{canonicalUserId}` и событие `.notification.created` с `unread_count` (бизнес-правила создания уведомлений не переписываем).
- На успешное прочтение одного/всех уведомлений backend дополнительно публикует `.notification.count-updated` с новым точным `unread_count`; ошибка WebSocket репортится, но не ломает сохранённую отметку прочтения.
- При загрузке, возвращении на вкладку, фокусе и восстановлении WebSocket синхронизация идёт через существующий защищённый маршрут `account.notifications.new`. Если между запуском fetch и ответом пришёл более свежий push, устаревший ответ не перезаписывает счётчик. При отказе сети сохраняется последнее отображаемое значение.
- `account-roles.js` после замены HTML sidebar генерирует `mskba:account-sidebar-updated`, чтобы актуальное значение вновь оказалось на обоих счётчиках. Никаких слушателей для каждого бейджа — обновление через document.
- Канал авторизует пользователя и его canonical identity для случаев связанных логинов; чужие каналы остаются закрытыми. Telegram Mini App, legacy `mskba_dark`, хранилище уведомлений, их статусы и внешние каналы доставки не меняем.
