# 058 — Генерация аватара: цена, баланс, пополнение, доступность

## Цель и критерии приёмки
Заголовок «Генерация аватара»; получить стоимость 1 генерации из текущего прайса, бонусный баланс из Finance, доступные генерации floor(balance / price), без hard-code 100. При нуле — «Недостаточно средств», иначе — форма фото анфас + слева или справа, выбор команды/логотипа, кнопка «Сгенерировать» с серверной проверкой стоимости. Оранжевое «Как пополнить?» открывает попап с существующими вариантами: карта (пока заглушка), подтверждённое добавление площадки, приглашение друга и только реально предусмотренные бонусные сценарии; FAQ и попап из «Действия → Помощь» должны ссылаться на тот же источник. Внизу сумма и заглушка пополнения без реального банка, не начисляющая деньги. Обновлять баланс/доступность после успешного списания.

## Технические границы
Разобрать PriceList/Finance и корректную валюту (баллы vs RUB), не обещать 100 без SKU; безопасность, идемпотентность, отсутствие фантомных платежей и бонусов.

## Процесс
CI (PHP, JavaScript, сборка frontend, PostgreSQL 16/17) → PR/merge в `dev` → проверка развёртывания → визуальная приёмка владельца. `main` не затрагиваем. Следующий этап выполняется после приёмки текущего.

## Статус
Зарегистрирована, ожидает приёмки предшествующих задач.

## Реализация 30.10.2026 (PR → CI → dev)

- Единственный источник цены — действующий Pricing avatar_generation в RUB; 100 ₽ только начальный seed, не константа.
- SSR и mutation generation_quote используют одну read-only модель. Finance: кошелёк canonical user/main/RUB, показывать bonus, total=bonus+real, доступные генерации floor(total/price). Списание BONUS_THEN_REAL сохраняется.
- Без цены / достаточного баланса не запускать генерацию; при 0 средств скрывать форму и показывать ссылку «Как пополнить?». При наличии — фото анфас + левый/правый профиль, команда/логотип и «Сгенерировать», подтверждение стоимости и обновление остатка после операции.
- Двойная проверка цены и locked wallet при фактическом вызове генерации, идемпотентный debit и refund уже реализованы. Клиентский расчёт не заменяет серверный.
- Пополнение: нативный диалог. Бонусы только из включённых и действующих Rewards (venue_first_approval, referral_user_confirmed, referral_second_level_user_confirmed) с реальными суммами RewardVersion; FAQ/help API использует тот же каталог бонусных возможностей.
- Сумма для карты — UI-заготовка, действие оплаты отключено. Никакого начисления, банковского запроса или фиктивной транзакции.
- Приёмка: нулевой баланс, смешанные реальные/бонусные средства, изменение или выключение прайса, выключение Reward, форма загрузки, обновление доступности после списания, возврат средств при ошибке, отсутствие фантомных оплат. Только зелёный CI → merge dev → проверка staging, production без изменений.
