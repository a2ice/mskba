# #1036 — Редакционные блоки SEO-посадочной

DEV ONLY. Зависимость при включении: PR #1071, маршрутизация и exact match. Этот PR независим по файлам от #1071; без переданного активного landing ничего не выводит.

- В существующих layouts category (app) и default-category (dark) только для каталога площадок используются два необязательных редакционных блока: вводный под H1, до каталога; расширенный после каталога (включая карту). Пустой блок не занимает место. Использованы штатные классы описания площадки, без нового CSS, копии каталога и нового JS.
- Вывод только при включённом FEATURE_VENUE_CATALOG_LANDINGS, разрешённом активном landing и первой странице. На следующих страницах не повторяем большой текст; обычный каталог не меняется. При отсутствии вводного текста остаётся стандартное описание app.
- Повторная очистка HTML через ContentBodySanitizer на выводе (в дополнение к сохранению). H2–H4, списки, ссылки, обычные редакционные элементы; FAQ на первом этапе в нижнем HTML-блоке, без отдельной сущности и структурированных данных. Перелинковка только через проверенные ссылки. Отдельный структурированный FAQ/связи — дальнейший этап.
- Тесты общего partial: безопасный HTML, ссылки, отсутствие скриптов/onclick, пустой контент, draft, gate off, page>1, отсутствие landing. Сквозные проверки с #1071 и визуальная приёмка ещё нужны.
- UI Studio недоступен через Desktop Commander (ранее подтверждён месячный лимит). Feature gate остаётся false, новый интерфейс не включаем до приёмки. Проверить обе темы, ширины 360/390/768/1440, длинные заголовки/списки/ссылки, карты, infinite scroll и отсутствие изменения обычного каталога. Не считать CI визуальной приёмкой.
- Не менять main, robots, sitemap, внешние сервисы, БД, booking/auth. Редакционный пример хранится в docs, не публикуется и не переносит dev-данные.
