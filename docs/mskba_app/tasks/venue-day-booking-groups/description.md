# Группировка занятых слотов по бронированию

Дата: 2026-11-17. Ветка: `feature/venue-booking-groups-20261117`. Целевая: `dev`.

## Задача и UX-контракт

- В дневном календаре площадки каждый интервал по-прежнему участвует в расчёте доступности и выборе свободного времени; группировка относится **только к отображению занятого времени**.
- Склеивать непосредственно соседние шаги расписания только если весь каждый шаг занят **одним и тем же** объектом `VenueBooking` MSKBA. Не склеивать разные брони, внешние слоты FindSport, пересекающиеся неоднозначные брони или непоследовательные интервалы.
- Один визуальный блок показывает время начала и конца всей брони. Метка `Занято (m)`; при присоединённом мероприятии `Занято (m, e)`. Внешняя/неидентифицированная занятость остаётся `Занято`.
- Если мероприятие опубликовано и публично, блок становится доступен с клавиатуры и по клику. Открывается отдельный popup с названием, описанием, типом, статусом, количеством подтверждённых / думающих участников, лимитом и организатором; также переход к мероприятию.
- Контакт с организатором запускается через действующую форму личного сообщения с проверкой доступности. Если форма недоступна, имя остаётся видимым как текст.
- Приватные и неопубликованные мероприятия **не раскрывают** на публичном API название, участников, организатора, URL или описание. Доступность определяется сервером, а не в браузере.
- Переключатели дней остаются в popup, но визуально стоят **по бокам области слотов** с вертикальной центровкой. При прокрутке только списка интервалов стрелки не перемещаются. Даты сверху занимают всю ширину; на мобильном уменьшаются боковые отступы без перекрытия контента.
- Дизайн следует текущим токенам темы, сохраняет текущее расположение цены и доступности для одиночных слотов; у объединённой брони вместо условной цены отдельных шагов отображается продолжительность, без разглашения договорной стоимости бронирования.

## Права, доступность и тесты

- Изменение только в GET `venues.schedule.day`, при этом цена и выбор свободных слотов не изменяются.
- Публичность события сверяется с `EventVisibilityEnum::PUBLIC` и `EventStatusEnum::PUBLISHED`; количества по каноническим участникам — из `EventIdentityParticipationService`.
- Регрессионные Node-тесты: несколько шагов одной брони, два соседних разных бронирования, внешние интервалы, разрыв, переход к полуночи и свободное время.
- После зелёного CI проверить на dev в desktop/mobile: один блок MSKBA брони, закрытое/публичное событие, работа приватности, чат, прокрутка, навигация в пределах 9 дней, существующее бронирование и внешний FindSport.

Production не затрагивать; слияние только при зелёном CI.
