# Группировка занятых слотов по бронированию

Дата: 2026-11-17. Ветка: `feature/venue-booking-groups-20261117`. Целевая: `dev`.

## Задача и UX-контракт

- В дневном календаре площадки каждый интервал по-прежнему участвует в расчёте доступности и выборе свободного времени; группировка относится **только к отображению занятого времени**.
- Склеивать непосредственно соседние шаги расписания только если весь каждый шаг занят **одним и тем же** объектом `VenueBooking` MSKBA. Не склеивать разные брони, внешние слоты FindSport, пересекающиеся неоднозначные брони или непоследовательные интервалы.
- Один визуальный блок показывает время начала и конца всей брони. Метка `Занято (m)`; при присоединённом мероприятии `Занято (m, e)`. Внешняя/неидентифицированная занятость остаётся `Занято`.
- Окно подробностей мероприятия **не является блоком страницы**: закрытый `dialog` строго скрыт (`:not([open])`), даже если ещё нет ни одной брони с мероприятием. Оно отображается только через `showModal()` после клика по публичному событию. Существующий вид сгруппированных слотов и положение стрелок не меняются.
- Если к брони прикреплено **любое мероприятие**, даже приватное или пока не опубликованное, группа доступна по клику/клавиатуре и открывает один общий popup. Для всех посетителей минимальный набор: время, тип, режим доступа (по приглашению / подробности не опубликованы), текст ограничения. Приватные названия и другие сведения не раскрываются.
- Для **публичного опубликованного/завершённого/отменённого** мероприятия тот же popup дополнительно показывает название, описание, статус, подтверждённых/думающих участников, лимит, организатора и переход на страницу мероприятия. Для открытого набора выводятся «Присоединиться» / «Думаю» / «Подтвердить участие» согласно правам, вместимости и действующим обработчикам участия. Для гостя «Присоединиться» ведёт на страницу мероприятия, откуда доступна авторизация. Сам popup никогда не обходится без серверной проверки участия.
- Контакт с организатором запускается через действующую форму личного сообщения с проверкой доступности. Если форма недоступна, имя остаётся видимым как текст.
- Приватные и неопубликованные мероприятия **не раскрывают** на публичном API название, описание, участников, организатора, URL или действия. Передаются только безопасные общие метаданные о наличии мероприятия, его типе и ограниченном доступе. Доступность участия определяется сервером, а не в браузере.
- Переключатели дней остаются в popup, но визуально стоят **по бокам области слотов** с вертикальной центровкой. При прокрутке только списка интервалов стрелки не перемещаются. Даты сверху занимают всю ширину; на мобильном уменьшаются боковые отступы без перекрытия контента.
- Дизайн следует текущим токенам темы, сохраняет текущее расположение цены и доступности для одиночных слотов; у объединённой брони вместо условной цены отдельных шагов отображается продолжительность, без разглашения договорной стоимости бронирования.

## Права, доступность и тесты

- Изменение только в GET `venues.schedule.day`, при этом цена и выбор свободных слотов не изменяются.
- Публичность события сверяется с `EventVisibilityEnum::PUBLIC` и доступными публично статусами (`PUBLISHED`, `COMPLETED`, `CANCELLED`); количества по каноническим участникам — из `EventIdentityParticipationService`. Для участия требуется статус `PUBLISHED`, время до окончания и место (либо повторное подтверждение), как в существующем `ShowVenueHandler` / обработчиках событий; guest получает ссылку, а не POST/PATCH.
- Регрессионные Node-тесты: несколько шагов одной брони, два соседних разных бронирования, внешние интервалы, разрыв, переход к полуночи и свободное время.
- После зелёного CI проверить на dev в desktop/mobile: один блок MSKBA брони, закрытое/публичное/черновое событие, private popup без утечки, public popup с CTA для открытого/заполненного/закрытого набора, гостя/авторизованного, чат, прокрутка, навигация в пределах 9 дней, существующее бронирование и внешний FindSport.

Production не затрагивать; слияние только при зелёном CI.
