# #1037 / #1039 — Управляемая перелинковка посадочных

DEV ONLY. По результатам приёмки 26.11 live московская landing доступна, #1099 и #1100 доставлены: подпись подходящего зала исчезла, четыре карточки ведут на конкретные зоны, фильтры и footer разделены в HTML, canonical корректен, noindex сохранён.

- В существующей секции «Контент» Filament — штатный multiple Select «Связанные подборки площадок» (до 12 записей). Явное направление: родитель/дочерняя/соседняя подборка выбираются редактором; обратная ссылка настраивается отдельно. Без автоматического создания страниц и без навязывания связей по городу. Черновики доступны в селекте для подготовки, но не публично.
- Nullable JSON related_landing_ids, без backfill. Храним идентификаторы, не HTML/URL; при выводе одним запросом получаем активные записи, используем актуальный slug и H1, сохраняем порядок, пропускаем отсутствующие записи, self и дубликаты. Editor проверяет права, существование, self, distinct, max 12; сохранение вместе с остальными полями в существующей транзакции. Никаких изменений criteria/signature.
- Ссылки в нижнем редакционном блоке «Другие подборки площадок», обычные SSR href, экранированные подписи. Только первая страница активной landing или закрытый preview, не обычный каталог и не AJAX fragment. При отсутствии доступных ссылок заголовок и список не выводятся; при отсутствии body_text список может выводиться отдельно. Feature gate off скрывает ссылки. Используем существующие стили и шаблоны обеих тем, без нового визуального компонента.
- Редактор самостоятельно проверяет фактическое предложение и содержание каждой активируемой подборки: активация не означает достаточную выборку или разрешение индексации. Проверка минимального количества залов автоматически не вводится, чтобы не добавлять N запросов каталога на каждый показ. Не генерируем пустые страницы. Пилот: Москва → конкретные округа только после инвентаризации; обратно — на Москву. Существующие ручные HTML ссылки не переписываем.

Визуально проверить штатный список на desktop/mobile после DEV deploy. Тесты editor и HTTP; штатная миграция, без прямых записей в БД. main, robots/sitemap, внешние сервисы и booking не меняются.
