# #1035 — Географические фильтры каталога площадок

Связано с #1034, #1035, #1036, #1037 и PR #1042. Цель: прямые ссылки из SEO-материалов в существующий каталог, без отдельного каталога и изменений аренды.

## UX
- В существующей форме фильтров /venues, после поиска, перед геопоиском, добавить «Город» и «Округ или район»; переиспользовать существующие label, select-control/form-select, без новых стилей.
- Город и округ — независимые необязательные поля; округа сгруппированы по городам. Несовместимая комбинация даёт пустую выдачу, а не расширяет её. Сброс — через существующие механизмы. Значения отражаются в GET и сохраняются при поиске, смене вида и пагинации.
- Обе темы, desktop/mobile, без новых попапов. Не менять существующие карточки, кнопки, финансовые условия и видимость площадок.

## Контракт
- city_id и district_id: nullable integer, существующий ID соответствующего справочника. Ссылки формировать по подтверждённым ID production, не по ID fixtures.
- ListVenuesHandler фильтрует structured location.address до формирования DTO/карты/пагинации; ограничения публикации и доступа сохраняются.
- Пустые поля не ограничивают выдачу; неизвестный адрес не выдаётся как совпадение. Условия access=paid и type=sports_hall сами по себе не гарантируют доступность аренды.
- Не индексировать произвольные комбинации как отдельные посадочные без утверждённой политики SEO.

## Проверки
- Feature: город, округ, несовместимая комбинация, скрытая площадка, адрес без округа, JSON-пагинация, карта, валидация.
- Smoke после зелёного CI и релиза: обе темы, desktop/mobile, выбранные значения, переходы из ссылки, сброс, смена вида, сортировка, пустая выдача, исходный каталог без параметров. Проверить фактический SHA деплоя. Визуальная проверка ещё не выполнена; не закрывать #1035 до фиксации результатов.
