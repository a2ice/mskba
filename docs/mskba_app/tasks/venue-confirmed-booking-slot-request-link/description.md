# Ссылка на подтверждённую заявку из занятого слота — 17 ноября 2026

## Сценарий

В текущей теме `mskba_app`, в дневном расписании зала при открытии занятого интервала, который однозначно соответствует **подтверждённой** брони MSKBA, в информационном popup появляется ссылка **«Перейти в заявку»**. Она открывает существующую страницу заявки `account.venue-bookings.show` в новой вкладке (`target="_blank"`, `rel="noopener noreferrer"`), чтобы пользователь не терял календарь.

## Разграничение доступа

- **Заказчик / владелец подтверждённой брони** (каноническая учётная запись) получает только ссылку на собственную заявку, без дополнительного показа своего логина.
- **Superadmin** получает ссылку и строку **«Заказчик: {логин}»**.
- **Представитель площадки, который непосредственно подтвердил данную бронь**, получает ссылку и логин заказчика, пока сохраняется актуальное право просмотра этой заявки. Подтверждающий определяется по истории переходов в статус `confirmed`, а не по произвольному представителю площадки.
- Остальные посетители, включая гостей, не получают ни URL заявки, ни идентификатор брони, ни логин клиента.
- Вся информация о ссылке и логине формируется сервером, с повторной проверкой действующего `VenueBookingAuthorization::assertCanView`; открытие самой заявки дополнительно проходит штатную проверку контроллера.
- Для неподтверждённых броней, внешних занятых интервалов и неоднозначных наложений бронирований ссылка отсутствует. Для публичных/приватных прикреплённых мероприятий ранее действовавшие ограничения на сведения сохраняются.
- Новые системные пермишены в этой итерации не добавляются; возможность дальнейшего делегирования рассматривается отдельно.

## UI и проверка

- У ссылки используется действующий компонент `button secondary` дизайн-системы; никаких дополнительных рамок вокруг неинтерактивных подписей.
- Когда доступна ссылка, не дублировать её текстом «Действия недоступны». Кнопка создания мероприятия из собственной брони по прежним условиям остаётся доступна независимо.
- Используется действующий серверный JSON-ответ `venues.schedule.day` с `Cache-Control: private, no-store` и известной клиенту группировкой занятых шагов расписания. Другие правила календаря, FindSport и оплаты не меняются.
- Feature-тест: клиент, подтвердивший представитель, superadmin, посторонний пользователь и гость. JS-тест: ссылка/логин и отсутствие утечек, новая вкладка, сосуществование с прежними кнопками.
- Слияние в `dev` строго после зелёного CI; production не затрагивать.
