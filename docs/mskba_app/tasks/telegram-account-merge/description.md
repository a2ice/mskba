# Объединение аккаунтов после подтверждения Telegram

PR #980. Продолжение задачи 101 (канонизация).

- При подтверждённой привязке через Telegram-бота и конфликте двух обычных пользователей выдаётся одноразовый proof текущей браузерной сессии; существующие ограничения безопасности не меняются.
- Новая тема использует существующий native dialog `mskba-modal`, общий header/body/footer, фирменную кнопку закрытия и стандартные кнопки primary/secondary. Отмена и Escape возвращают к контактам. Явный выбор основного аккаунта обязателен. Контент доступен и без JS через открытый dialog.
- Карточки выбора показывают имя, ID, дату регистрации, привязку Telegram, текущий аккаунт, процент заполненности и количества связанных сущностей. Процент — округлённая доля из 28 равновесных признаков: значимые поля профиля, активный аватар, типы подтверждённых контактов, активные роли, поля профиля игрока, позиции, 10 навыков самооценки, наличие участия в мероприятиях и командных связей. Не учитываются технический ник `tg_*`, пароль, токены, системные роли. Это ориентир, не рейтинг и не условие доступа; необязательные поля могут быть пустыми.
- Старый шаблон тоже показывает процент. История остаётся на alias, данные профиля читаются с основного аккаунта. Физическая миграция всех данных и финансовый аудит отдельно.
- Приёмка: создать браузерный аккаунт A, открыть Mini App без привязки (B), подтвердить тот же Telegram в A через бота, проверить диалог, выбрать A, подтвердить и проверить `canonical_user_id`. Отдельно проверить отмену и истёкший proof. Проверить мобильный и desktop вид.
