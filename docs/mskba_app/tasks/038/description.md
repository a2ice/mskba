# 038 — Системные уведомления в общем интерфейсе чатов и приватная техподдержка

**Статус:** реализовано локально, требуется визуальная приёмка. **Дата:** 2026-10-13.

## Цель и разграничение данных

`Система MSKBA` остаётся **персональной лентой автоматических уведомлений**, а **`Техподдержка MSKBA`** является самостоятельным двусторонним диалогом, который включён в общий список переписок. Сотрудникам техподдержки **запрещено** просматривать чужую системную ленту. Нельзя объединять эти потоки в одну таблицу/тред из-за иной приватности.

## Реализация

1. `/account/notifications/threads/system`: тот же компактный трёхколоночный макет, что у profile/direct. Системные карточки — слева, ограничены шириной, с оранжевым фоном; timestamp HH:mm, единый разделитель дня, история пачками по **10** с ID-cursor, прокрутка внутри чата, read-only. Нижняя плашка предлагает «Написать в техподдержку». Рендер через отдельный `system-notification-bubble` сохраняет контекстные action-ссылки и безопасные формы.
2. `/account/notifications/support/start` → создание отдельного `support_ticket` (subject/body), один `request_thread(type=support)` с `request_thread_messages` и участниками. Существующие таблицы и UI тредов переиспользуются. Не требуется новая системная роль.
3. Операционное право `support.ticket.handle`, отдельная группа в `PermissionCatalog`, доступно делегированию через админку; для новых сотрудников исходно **запрещено**, подтверждённый супер-администратор имеет право по умолчанию. `support_permission_cursors.after_ticket_id` ограничивает видимость **только новыми обращениями**, начиная с момента выдачи права. Ранее созданные обращения становятся доступными только через явную передачу/приглашение. Отзыв запрещает GET, history, POST и WebSocket; удаляет lead, снимает membership и обезличивает связанные уведомления. Никаких больших JOIN: `EXISTS` и ограниченные выборки.
4. При создании новый тред получает **главного супер-администратора с эффективным правом** (детерминированно по ID); при отсутствии подходящего остаётся без главного. Разрешённый сотрудник с доступом к обращению может его взять. Главный может закрыть или передать обращение доступному сотруднику, в том числе историческое; передача уведомляет получателя. Система не добавляет автоматическую роль `support` в `UserSystemRoleEnum`.
5. Браузер: поддержка Reverb `support-tickets.{threadId}` с серверной авторизацией; событие без тела, обновление через серверный GET, `Cmd+Enter` / `Ctrl+Enter` через общий composer. В `ListAccountConversationsHandler` обращения отображаются только по авторизованной выборке. Сообщения техподдержки не попадают в автоматический поток `Система MSKBA` и не открывают чужие уведомления.
6. Безопасность: проверка каждого endpoint сервером, для отправки/закрытия проверка `status=open`, для transfer проверка действующего главного. При отзыве permission старый участник не восстановит доступ после regrant; для новых обращений создаётся новый ID cursor.

## Локальная БД, QA и выпуск

- Применена только новая миграция `2026_10_13_150000_create_support_tickets.php` **к локальной базе Mac**, без прод/dev удалённых операций; исходные данные не изменены. Тесты используют отдельную database с `RefreshDatabase`.
- На чекпоинте реализации 108 PHPUnit тестов / 990 assertions PASS; после privacy-redaction отдельная регрессия 4 теста / 55 assertions PASS. Vite, Blade, PHP syntax и Pint PASS (исходные warning о крупном JS bundle без новых ошибок).
- Осталась пользовательская визуальная приёмка localhost desktop/mobile, проверка настоящих двух браузеров Reverb, диагностика UX выбора главного; **без commit/push/merge/deploy до команды**.

## UI follow-up: создание обращения и интро страницы сообщений (2026-10-13)

- Кнопка «Написать в техподдержку» перенесена из отдельного `.app-messages__inbox-toolbar` **в общую интро-плашку** страницы `account.notifications` через два опциональных параметра `section-heading`: `introActionUrl` и `introActionLabel`. Контент справа от краткого описания, на мобильной ширине переносится внутрь той же плашки. Остальные интро-плашки без действий не изменены.
- `/account/notifications/support/start` теперь использует `compactSidebar=true` и общий `.app-message-workspace`: компактный сайдбар с иконками, слева от формы авторизованный список других диалогов (`AccountConversationRail`, без нового ACL). На узких экранах rail скрыт по существующему правилу до 1200 px. Форма занимает доступную ширину правой колонки.
- Существующие «Отмена» и «Отправить обращение» остались внутри формы (POST/CSRF/HTML5 validation), выровнены вправо. Под ними добавлен mailto с **`config('support.email')`**, уже используемым в проекте (`SUPPORT_EMAIL`, по умолчанию `support@mskba.ru`). Значение не дублируется хардкодом в шаблонах.
- Новый Feature-тест проверяет отсутствие старой отдельной кнопки, наличие intro CTA, компактного макета, реального rail с авторизованным обращением, DOM-порядок rail/form/button/mailto, конфигурационный e-mail; первоначальный прогон 5 тестов / 79 assertions PASS.
- Только локальный вариант для визуальной приёмки; без commit/push/deploy.
