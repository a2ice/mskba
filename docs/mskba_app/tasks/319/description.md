# 319 — Подтверждение игрока и предупреждающий попап подтверждений

## UI Kit и референсы

- Тема MSKBA App (светлая): все изменения выполнены через уже существующие классы `panel`, `app-profile__panel`, `button primary/secondary`, `mskba-modal`, `mskba-modal__header/body/footer`, `app-profile__request-*` и `select-control`; нативных браузерных select без дизайн-обёртки не добавлено.
- Подтверждающий попап — стандартный HTML `<dialog>`, по существующему шаблону попапа заявки на изменение профиля, с закрытием Esc/крестиком и отказом от подтверждения через «Вернуться».
- Унифицированный Blade partial `account/partials/confirmation-review-dialog.blade.php`; один клиентский обработчик `account-confirmation-review.js` для аккаунта, игрока и будущих ролей.
- На странице подтверждения аккаунта список значений синхронизируется с реально сохранёнными значениями после inline-save; нельзя подтверждать несохранённые изменения. На странице игрока подтверждаются сохранённые значения роста и года «Играю с».

## UX-поведение

- Сначала пользователь сохраняет профиль/игровые характеристики; затем нажимает «Подтвердить аккаунт» или «Подтвердить игрока».
- В модальном окне перечисляются подтверждаемые данные и предупреждение о том, что в будущем часть данных можно будет исправить только по заявке.
- Для подтверждённого игрока рост и «Играю с» заблокированы без `identity.profile.self_edit`; рядом с общим статусом игрока отображается кнопка запроса изменения. Масса, телосложение, амплуа и другие характеристики остаются редактируемыми.
- Заявка использует существующий попап, те же классы и элементы форм, с причиной min=10/max=2000; список статусов/ссылка на обсуждение и отмена заявки.
- Проверять клавиатуру, Esc, tab-order, адаптивность модалок и отсутствие скачков в физических характеристиках и game-tab.

## Проверка

CI: PHP/unit/feature, JS, Vite, PostgreSQL migration. На `dev` вручную проверить оба подтверждения, появление диалога, запрос изменения, администраторскую модерацию и наличие ролей. Production не изменять.
