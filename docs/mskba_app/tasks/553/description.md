# MSKBA — 553. Контракты спортивных секций и границы контуров Event/Game

## Цель
Привести управленческие права спортивной секции к общим контрактам, исключить получение прав без акцепта и зафиксировать безопасные границы последующей миграции мероприятий/игр. Существующее участие игроков, тренировочная статистика и коммерческое владение площадками не меняются.

## Текущее согласованное поведение
- Создатель секции — тренер с подтверждённой ролью; получает бессрочный, немедленно принятый контракт владельца с полным набором section permissions.
- Приглашённый тренер получает индивидуальный контракт с названием, сроком действия и необязательным комментарием.
- Контракт приглашённого в статусе ожидания **не** даёт доступа к настройкам, занятиям, набору, публичной карточке тренера и связанным командам.
- После принятия пользователь получает только выбранные права, до истечения срока или отзыва.
- Расширение полномочий требует повторного согласия, сокращение прав не создаёт скрытых полномочий.
- Главным тренером можно назначать только принявшего контракт пользователя.
- Главного тренера нельзя удалить через обычный отзыв договора; предварительно требуется назначить нового.
- Передача владения секцией через универсальный обработчик отключена до отдельной процедуры, которая согласует владельца и главного тренера.
- Контракты секций видны в личном кабинете и общем административном реестре. Административный доступ определяется только глобальными permission бэк-офиса.

## UI/UX
- В блоке «Тренеры» показывать статус приглашения, не выдавать ожидающего тренера за активного.
- Действия «Пригласить тренера», «Управлять контрактами», «Назначить главным» должны быть понятными и не дублировать друг друга.
- Срок окончания и комментарий необязательны. Пустая дата означает бессрочный контракт, если полномочия выдающего тоже бессрочны.
- Выравнивать действия внутри строк; выдерживать вертикальные интервалы между панелями, формой и списком тренеров.
- Никаких служебных кодов статусов и permission keys в UI.

## Границы следующего этапа
- Event остаётся агрегатом полномочий организатора/ответственных; Game не получает отдельного владельца.
- Перед переходом Event нужен один источник effective rights, backfill, миграция всех create/accept/revoke/update путей, проверка событий из броней и тренировок.
- Участие спортсменов, судейство, запись и результаты не превращаются в управленческие контракты по умолчанию.

## Приёмка
1. Новый владелец секции имеет все права и бессрочный контракт.
2. Приглашённый тренер **до** согласия не видит секцию в своём управлении и не виден как активный тренер на публичной странице.
3. После принятия действуют только выбранные права; в конце срока права исчезают.
4. Расширение прав требует нового акцепта.
5. Pending не может стать главным тренером.
6. Главный тренер и владелец защищены от обычного отзыва.
7. У superadmin полный административный доступ, но публичное управление другого пользователя не расширяется автоматически.
8. PHP feature tests, миграции PostgreSQL и фронтенд CI — зелёные до merge и dev-деплоя.
