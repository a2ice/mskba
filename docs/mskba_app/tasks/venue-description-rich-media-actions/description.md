# MSKBA: фото, сетка и интерактивные ссылки в полном описании площадки

Дата: 23.11.2026. Админка: `/backoffice/venues/{id}/edit`. Публичные темы: `mskba_app`, `mskba_dark`.

## Пользовательский сценарий

* Поле «Полное описание» остаётся HTML-редактором исходного кода, но под ним есть действия «Добавить фото / галерею» и «Добавить ссылку / действие».
* Для фото разрешена загрузка JPEG, PNG и WebP, до 10 МБ на файл, от 1 до 8 за раз. Изображения размещаются в публичном диске `venues/descriptions`, а форма вставляет в поле готовый HTML. Изображения НЕ заменяют основную галерею площадки, ограниченную тремя кадрами.
* Один кадр вставляется как кликабельное превью, несколько — как сетка `<div class="content-gallery d-flex flex-wrap gap-3">` с миниатюрами. Редактор может переместить вставленный HTML-фрагмент к нужному абзацу до сохранения.
* Ссылка из редактора может открывать аренду площадки (`data-venue-rental-open="1"`) или попап «Хочу здесь играть» (`data-venue-play-open="1"`), либо переходить по обычному HTTPS/локальному URL.
* После вставки необходимо сохранить площадку. Существующие описания не изменяются.

## Безопасный HTML-контракт

Санитайзер по-прежнему удаляет JS, обработчики `onclick`, произвольные CSS-стили и атрибуты. Добавлены только классы `content-gallery`, `content-gallery__item`, `content-lightbox`, `d-flex`, `flex-wrap`, `gap-2/3/4`, `img-fluid` и именованные атрибуты ссылок: `data-venue-rental-open`, `data-venue-play-open`, `data-venue-lightbox` (также допустим `data-lightbox`). Ссылки с опасными схемами по-прежнему очищаются.

Лайтбокс использует реальные `<a href="..."><img ...></a>`, открывается только по клику в описании площадки, имеет закрытие по Escape/крестику/нажатию на фон, переключение стрелками и возвращает фокус исходному превью. Никакой HTML не формируется из пользовательских URL при открытии.

В основном шаблоне аренда открывается уже существующим диалогом поиска; в классическом шаблоне ссылка перенаправляется в существующее окно занятости по первой дате. Открытие «Хочу здесь играть» использует общий `venue-play-funnel.js`.

## Приёмка

1. Сохранение `<div class="d-flex flex-wrap gap-3">...</div>` сохраняет допустимые классы, фотогалерея показывает карточки в ряд, на мобильном — в 2 колонки.
2. Нажатие на изображение в описании открывает лайтбокс, стрелки листают фотографии одной группы, Escape закрывает.
3. Ссылки на аренду и «Хочу здесь играть» открывают нужный диалог без перехода, а обычные ссылки остаются кликабельными.
4. Сценарии с `onclick`, `javascript:`, неизвестными `data-*` и вредоносными классами не проходят санитайзер.
5. PHP unit/feature tests, Node tests и production Vite build выполняются в CI.

## Исправление позиционирования (23.11.2026)

В галерее площадки №8 после открытия фотографии её лайтбокс оказывался в левом верхнем углу окна, хотя фон перекрывал всю страницу. Причина на уровне раскладки: визуальная карточка была непосредственно `<dialog>` с расчётом позиции через auto-margin; такой расчёт ненадёжен при наложении стилей модалок/разной высоте изображений.

Теперь нативный `<dialog>` — прозрачный полноэкранный top-layer (`position:fixed; inset:0; width:100vw; height:100dvh`), а видимая карточка `.venue-description-lightbox__frame` центрируется через `display:grid; place-items:center` на корне. Фон, переключение снимков, Escape, закрытие по нажатию и восстановление фокуса сохранены. Ограничение карточки — не более `min(92dvh, 900px)` по высоте и `min(1100px, 100vw - 24px)` по ширине. Проверить desktop и mobile, вертикальные и горизонтальные фото, после прокрутки страницы.
