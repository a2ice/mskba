# MSKBA — 557. Сквозной аудит адаптивных таблиц бэк-офиса

## Основание

Повторная ручная проверка мобильного Safari (iPhone) показала, что после задачи 556 карточка контракта команды по-прежнему нечитабельна: подписи «Пользователь», «Статус», «Действие», а также значения разбиваются по 1–3 символа в строке. Значения прав и принадлежности верны; ошибка представления затрагивает разные экраны бэк-офиса.

## Первопричина

`public/css/backoffice-contracts.css` применял к ячейкам `td:nth-child(...)` десктопную ширину 19%, 20%, 14% **за пределами** медиазапроса. Мобильный `td { width: auto }` проигрывал селектору десктопной ячейки по специфичности. Итого даже `display: grid` давал поля шириной в десятки пикселей.

Исправить только переполнение таблицы горизонтальной прокруткой или `overflow-wrap:anywhere` недостаточно: необходимо устранить сам конфликт размеров.

## Граница аудита

Проверены пользовательские Blade-таблицы Filament/Livewire (11 таблиц):
- вкладки «Контракты» у сущностей/пользователей;
- история изменений контракта;
- документы-основания контракта;
- системные роли пользователя;
- назначения ролей участия;
- контракты площадок и залов в карточке пользователя;
- журнал изменений персональных данных;
- история операций кошелька;
- команды пользователя, участие в мероприятиях, проведённые игры/статистика в редакторе роли.

Обычные Filament `Table`/resource tables получают нативное оформление и прокрутку от Filament; **не** переопределять их CSS глобально. Чат поддержки и инструменты API не содержат собственных HTML-таблиц и требуют отдельной проверки удобства на мобильном, но не наследуют дефект `td:nth-child`.

## Реализованная адаптивность

- **Контракты и история:** ширины по `:nth-child` применяются только начиная с 1051 px; до 700 px карточки всегда одноколоночные, 700–1050 px допускаются две колонки с полным названием договора. Все мобильные поля `width:100%;min-width:0`. Естественный перенос слов, без искусственного вертикального набора букв.
- **Простые пользовательские таблицы:** стили `mskba-bo-table--cards` и поля `data-label`, одна колонка на телефонах до 760 px.
- **Плотные таблицы:** `mskba-bo-table--scroll`, отдельный скролл внутри блока, минимальная читаемая ширина по количеству колонок; это кошелёк, мероприятия, команды и статистика.
- Отдельные CSS-файлы (без зависимости от Tailwind JIT) подключаются через `BackofficePanelProvider` со сменой версии для кеша; стили изолированы и не затрагивают Filament Table.
- Предусмотрены светлая/тёмная темы, перенос длинных названий, контролируемая ширина текста и удобные действия.

## Проверка

1. На iPhone (375/390/430 px): команда → вкладка «Контракты»; каждая пара подпись–значение занимает полную ширину, слово «Активен» горизонтально, логин и «Изменить» не вертикальны.
2. Контракт → «История изменений», «Основание полномочий»: те же карточки, без разрывов слов.
3. Пользователь → «Роли», «Права», «Площадки», «История изменений», «Кошелёк»: короткие таблицы карточками, плотные — с горизонтальной прокруткой *внутри*, а не всей страницы.
4. Редактор конкретной роли → «Команды», «Участие», «Игры и статистика»: таблица не уменьшает колонки до пары букв, внутри прокручивается.
5. Повторить на планшете (768/820/1024 px), на ноутбуке и десктопе (1280+). У контракта desktop — таблица; телефона — карточка.
6. Проверить мобильные и десктопные светлую/тёмную темы, отсутствие горизонтального скролла страницы и сохранность кликабельных действий.
7. CI: `ResponsiveTablesAuditTest` обеспечивает наличие адаптивного оформления для **каждой** кастомной таблицы; основной PHP CI и Vite build — до merge; повторный CI и deploy_dev после слияния.

## Ограничение проверки

Автотесты структуры и локальная проверка сетки в Chromium не равны E2E в авторизованном мобильном Safari на сервере. После выкладки нужна ручная приёмка по перечисленным маршрутам; все выявленные отличия должны быть исправлены до закрытия задачи.
