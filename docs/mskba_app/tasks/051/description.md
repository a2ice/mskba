# 051 — Публичность игрока по подписке при нескольких совпадениях

## Проблема
При наличии нескольких активных подписок одного канонического пользователя, подходящих под площадку, агрегатор VenueSubscriptionAudience ранее складывал show_on_venue с AND (privacy veto). Даже после включения «Показывать мои данные» в подписке «На ШК» гостевой список скрывал аватар и кнопку «Подробнее», если в другой подходящей подписке показ данных отключён.

## Требование / решение
- Публикация — независимое согласие в рамках каждой подписки. В списке конкретной площадки профиль игрока доступен, когда **хотя бы одна действующая и совпадающая с этой площадкой подписка** содержит show_on_venue=true.
- При отсутствии такого согласия игрок остаётся в численности и списке под логином, но без аватара и игровых характеристик, без кнопки «Подробнее».
- Совпадение условий проверяется до агрегации; публичная подписка для другой площадки **не** открывает профиль на текущей площадке.
- Итоговый список дедуплицирован по каноническому пользователю, приоритет группы «Подписаны на эту площадку» сохраняется; подсчёт не меняется.
- Отзыв последнего согласия вновь скрывает аватар, характеристики и кнопку «Подробнее». Собственные данные владелец видит независимо от этой настройки.

## Проверки
- Feature test создаёт две приватные подписки одного игрока на конкретную площадку, плюс публичную на другую площадку. В гостевом режиме профиль закрыт.
- Редактирование только одной из двух подписок с show_on_venue=true немедленно открывает аватар и кнопку «Подробнее» у одного игрока; другая подписка не меняется.
- При отзыве согласия гостевой профиль снова скрыт, счётчик остаётся 1.
- Проверяются CI, PostgreSQL 16/17, squash-merge в dev и успешный deploy_dev. Production не затрагивается.
