# MSKBA App / 316 — SEO metadata (no visual layout changes)

Связанная задача: [docs/tasks/316](../../../tasks/316/description.md).

Изменения касаются только `resources/themes/mskba_app/views/layouts/app.blade.php` и общего head partial: `html lang=ru`, `title`, `meta description/robots/keywords`, `canonical`, JSON-LD, Open Graph, Twitter Card, Яндекс-верификация и подключение Метрики только на основном хосте.

**Визуальные элементы UI Kit не изменять.** Запрещены изменения DOM основного контента, заголовка секций или пользовательских стилей в рамках этого шага.

Проверки: валидный HTML head, единственный Metrika init на `mskba.ru`, noindex для dev, правильные fallback title/description и отсутствие production analytics в dev.

Приёмка: автоматические feature tests и просмотр исходного HTML на dev. Перенос старого H1/новостей/FAQ — отдельно в 316/004.

## Этап 316/004 — публичные каталоги новой темы и временный fallback (PR #683)

Изменения визуального слоя в рамках **отдельного этапа 316/004**:

- `news.index`, `events.index`, `faq.index`: отдельные Blade-шаблоны `mskba_app` с общим `theme::layouts.app`, контекстной панелью, существующей `container` / `panel` / `app-team-*` UI Kit-композицией; новые CSS-токены и сторонняя разметка не добавляются.
- `news.index`: сохраняются реальные опубликованные карточки, обложки, дата, описание, пагинация и SEO canonical.
- `events.index`: реальные события с ссылками `events.show`, состояние, место, дата, серверные фильтры, пагинация. Полный функционал старого вида (включая карту и переключение представлений) остаётся отдельной итерацией; пока не заявлять полную функциональную эквивалентность.
- `faq.index`: только опубликованные FAQ либо существующие инструкции создания, ссылки на индивидуальные статьи. Вкладки и глобальная панель аккаунта остаются в app-layout.
- Для ещё не перенесённых детальных **публичных** страниц применяются только разрешённые legacy dark Blade-шаблоны (без подмены БД и URL). Пользовательские и админские шаблоны исключены.
- UI-проверка: контекстная панель для подтверждения аккаунта остаётся на каталогах; переход из fallback на новый app-layout не загрязняет кэш Blade; SEO 200/без soft-404.

Данное изменение UI дополняет предыдущий этап 316/002, **не меняет** утверждённую стилистику раздела площадок и личного кабинета. Временный fallback не считать готовым финальным дизайном.
