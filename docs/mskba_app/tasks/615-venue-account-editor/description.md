# MSKBA App — редактор площадки в личном кабинете

## Эталон и UI Kit
Основой служат `docs/specification/ui-design-system.md`, `player-profile-workspace.blade.php` (вкладки, поля, карточки) и `components.entity-banner-editor` (баннер как в профиле). Новый тип кнопок и собственные UI-токены не создаются. Функции ориентируются на Filament VenueResource и используют существующие серверные обработчики.

## Разделы
- **Основное:** название, тип, описания, теги, доступ/подтверждение бронирования. Алиас и модерационный статус read-only: backoffice-only. Рядом компонент баннера с обрезкой.
- **Адрес и метро:** структурированный адрес, координаты, метро и существующий Yandex AddressSuggest API.
- **Удобства:** характеристики и общие удобства; оснащение отдельных залов на вкладке зон.
- **Залы и корты:** перечень и ссылка на действующий специализированный редактор.
- **Расписание:** недельные интервалы и исключения по датам через существующий backend `UpdateVenueScheduleHandler`.
- **Фотографии:** загрузка, выбор основной, удаление через `VenueGalleryManager` с сохранением ревизий.
- **Контракты:** переход к контрактному менеджеру при наличии `venue.contracts.manage`.
- **Аренда:** отдельные пункты для аренды, тарифов, промокодов, коммерческих ролей с соответствующими правами. Комиссии остаются только в Filament.

Все вкладки остаются видимыми, а недоступные — disabled; прямые URL и операции проверяются сервером.
Разрешение `venue.edit` открывает основные разделы, `edit.schedule` — расписание; остальные права проверяются отдельно.
Суперадмин без контракта не получает публичный редактор по роли; ему предоставлен Filament. Bootstrap-создатель без контракта сохраняет доступ в период первоначального заполнения созданной площадки.

Сохранение подтверждённой площадки — только через `VenueRevision` и модерацию. Баннер — через `VenueBannerDraftManager`.
Breadcrumbs: Главная / Аккаунт / Мои контракты / Мои площадки / Название площадки.

## Приёмка
1. Действующий контракт EDIT: вкладки, настоящая форма, сохранение черновика, crop баннера.
2. EDIT_SCHEDULE без EDIT: расписание доступно, редактирование основных данных закрыто.
3. Без контракта, истёкший контракт, SUPERADMIN без контракта: запрет публичного редактора.
4. Залы, фото, контракты и аренда: переходы к существующим проверенным endpoints; disabled без прав.
5. Desktop, tablet, mobile: sticky-tabs, клавиатура, focus-visible, отступы по UI Kit.
6. CI зелёный, деплой только dev до приёмки.


## Приёмка 07.11.2026 — подтверждённые площадки, вложенная навигация и UI Kit

Основание: скриншоты вкладок general / courts и вложенной страницы courts; замечания владельца о публично редактируемых паспортных полях, чекбоксах/селектах, потере breadcrumbs и баннере.

**Нормативные источники:** docs/specification.md → «Инварианты изменения площадки», docs/specification/venue-conditions.md, docs/specification/ui-design-system.md → цикл UI Kit, css/design-system.css → .check-label и .select-control.

- Для confirmed название, тип, alias и статус в общей форме, а также адрес/город/улица/дом/индекс/координаты во вкладке адреса отображаются disabled. Только Filament вправе административно менять паспортные поля. Backend VenueController::update запрещает подменять их через MSKBA App независимо от HTML.
- Описания, теги и удобства по-прежнему используют VenueRevision и проходят модерацию. Unconfirmed может заполняться по прежнему сценарию.
- Признаки оплаты и подтверждения бронирования убраны из общей формы: их меняют специализированные VenueConditionsController и правила аренды.
- Метро меняется отдельным PUT /account/venues/{alias}/metro, только с контрактным EDIT и без ожидающей модерации. Для confirmed меняется поле metro_station_ids в черновике, без публикации адреса. Для unconfirmed Location клонируется, чтобы не изменять связи другого объекта.
- Метро: предикативный поиск по названию станции/линии; активные станции в плашках с крестиком; управление с клавиатуры, Enter/Escape и адаптивность. HTML select multiple остаётся серверным полем.
- Селекты — общий .select-control со встроенным SVG chevron, чекбоксы — только .check-label (20×20, вертикальный центр). Новые глобальные токены/примитивы не вводятся.
- Баннер с crop/scale/drag и удалением перенесён в «Фотографии» рядом с галереей; общий компонент как в профиле.
- «Залы и корты», «Условия аренды», «Тарифные условия», «Промокоды» используют общую sticky-навигацию и breadcrumbs: Главная → Аккаунт → Мои контракты → Мои площадки → площадка → подстраница. Избыточная кнопка «Мои площадки» над контентом убрана.
- Вложенные формы продолжают пользоваться прежними специализированными контроллерами и permission checks.

**Регрессии:** HTML confirmed/unconfirmed, запрет PUT паспортных полей и условий, Metro EDIT/NO EDIT, черновик станции без изменения опубликованного Location, галерея/баннер, breadcrumbs вложенных страниц, desktop/mobile/sticky/checkbox/select UI Kit. Только dev до визуальной приёмки, main и production не менять.
