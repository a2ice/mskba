# 012 — Настройка публичности после регистрации

**Дата:** 2026-10-08 · **Задача:** #139 / MSKBA App · **Статус:** Реализовано локально — на визуальной приёмке; коммит не создан.

## Контекст и цель

После успешного создания аккаунта через Vue Wizard пользователь
переходит на `/account/privacy/distribution`. Маршрут и Laravel-обработка
реализованы, но в новой теме `mskba_app` нет страницы
`account.privacy-distribution`: отображается заглушка.
Действующий образец находится в
`resources/themes/mskba_dark/views/pages/account/privacy-distribution.blade.php`.

## Ограничения

Не путать согласие на обычную обработку ПД с отдельным согласием
на публичное распространение. Сохранять существующие Laravel
контроллер, валидацию, модель согласия и аудит. Не добавлять миграции
или поля, не менять legacy-страницу и не публиковать изменения.

Успешная регистрация с переходом подтверждена пользователем.
Реальный E2E проверки сценариев серверной ошибки 500/422 в Wizard
остаётся техдолгом [задачи 010](../010/description.md).

## Выполнено и проверено — 2026-10-09

- Добавлен Blade-маршрут-шаблон
  `resources/themes/mskba_app/views/pages/account/privacy-distribution.blade.php`,
  локальный partial групп переключателей и стили
  `css/privacy-distribution.css`. Существующие 20 значений
  перечисления `distributionTypes()` отображаются без потерь,
  включая возможные новые типы в резервной группе.
- Использованы общие токены и примитивы `.panel`, `.button`,
  `.check-label.switch-label`, `.notice` из дизайн-системы.
  Внешний вид страницы не модальный, без глобального нового компонента.
- Форма отправляет `PUT` через CSRF на существующий маршрут.
  Обе кнопки используют исходные `action=save/private`.
  При выборе публичных пунктов JS помечает отдельное согласие
  `required`; без выбранных пунктов согласие не требуется.
  Кнопка закрытого профиля имеет `formnovalidate`, а серверное
  правило `exclude_if:action,private` сохранено. Дополнительно
  `UpdatePersonalDataDistributionConsentRequest` исключает
  проверку `accepted`, когда реально выбранных публичных категорий
  **нет**. Этот обнаруженный тестами дефект старой серверной
  валидации устранён точечно — иначе кнопка «Сохранить»
  требовала согласие даже при всех выключенных переключателях.
- Источник версий и текста юридического документа перенесён
  **без изменения шести смысловых разделов** в
  `views/pages/legal/personal-data-distribution-consent.blade.php`.
  Это необходимая зависимость ссылки на отдельное согласие.
  Обновлён только Blade-layout и CSS оформления документа.
- Данные и аудит согласия продолжают обрабатываться старым
  `PersonalDataDistributionConsentController` и handler; миграций
  в handler не менялись. В Request внесено только исправление
  необязательности согласия при пустом выборе, миграций нет.
- PHPUnit **12 тестов / 61 утверждение PASS** совместно с
  legacy-сценариями: GET реальной страницы,
  текст согласия, отбор категорий, отдельное согласие, сохранение
  набора, приватный выбор и сохранение **всех выключенных** настроек
  без согласия, ограничения после завершения onboarding.
- Chromium на отрендеренном HTML (без тестовых учётных записей)
  с настоящими CSS и JS: ширины 360, 440, 768, 1440,
  переключатели 44 px, две колонки на ширине 768+,
  одна колонка на телефонах, динамический счётчик, native required,
  отсутствие горизонтального overflow и JS-ошибок.
- Vite build, Blade view:cache и Pint проходят.
- Необходимо **визуальное одобрение пользователем** на настоящем
  `http://127.0.0.1:8000/account/privacy/distribution`.
  Успешный POST в браузере и видимость серверной ошибки после
  redirect подлежат дополнительному E2E; PHPUnit проверяет backend.
- После завершения этого шага перенаправление на `/account`
  пока приведёт к заглушке новой темы: перенос личного кабинета —
  **следующая отдельная задача**, не часть 012.
