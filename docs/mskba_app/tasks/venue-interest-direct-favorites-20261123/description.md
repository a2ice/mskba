# Площадка: прямой интерес из списка игроков и поиск игр — 23.11.2026

## Решение (вариант А принят)
- В окне «Площадкой интересуются» кнопка «Тоже хочу здесь играть» больше **не** открывает второе окно «Хочу здесь играть». Вместо неё общий CTA избранного с сердцем: «Добавить в избранное» либо подтверждение «В избранном». Действие добавляет существующее `Favorite(venue)` и сопровождающую стандартную подписку на площадку, не создаёт событие/бронь.
- В окне «Хочу здесь играть» всегда остаётся список будущих публичных мероприятий. Список пуст: короткий текст «Пока нет предстоящих игр»; в том же списочном шаге — общий CTA избранного; «Посмотреть занятость» и «Создать мероприятие» остаются самостоятельными вторичными действиями. Если мероприятия есть, блок избранного виден после карточек, создание остаётся доступно.
- Текст CTA до добавления: «Добавьте площадку в избранное, чтобы следить за новыми играми.» После: «Площадка в избранном — следите здесь за новыми играми.». Иконка сердца одинаковая, при сохранении заполненная. В состоянии сохранения кнопка не удаляет избранное; удаление доступно через существующую кнопку Hero с подтверждением / личный кабинет.

## Поведение и безопасность
- Используется **один** shared Blade partial `venue-favorite-follow` (обе темы) и существующий JS/маршруты `favorites.venue-statuses`, `favorites.toggle`, `addFavorite()`. Прямое добавление (idempotent add, не toggle) и существующие события `mskba:venue-favorite:updated` + счётчик на Hero. Не создаётся отдельный второй модальный механизм, API, polling или миграция.
- Для гостя нажатие закрывает исходный dialog, затем открывает согласованный общий информирующий dialog «Избранное» → «Войти» → авторизация → продолжение и информационное подтверждение. Отмена входа ничего не добавляет.
- Для авторизованного пользователя неизвестный статус означает «Проверяем избранное…» и заблокированную кнопку, а не ложное «Не добавлено». Ошибка чтения даёт действие «Повторить». Старый ответ GET не может перезаписать новый статус после мутации.
- Попапы и Hero синхронизируют надписи/сердце/счётчик по существующему общему событию. При закрытии окна новые данные не сбрасываются. Никакой из путей не удаляет избранное без отдельного явного подтверждения.
- Добавление в избранное само по себе **не** даёт согласие публиковать спортивные характеристики и аватар пользователя (остаются правила `show_on_venue`).

## Приёмка
1. Гость из «Площадкой интересуются» выбирает сохранение, видит только один общий диалог избранного, затем вход и завершение действия (или безопасную отмену).
2. Авторизованный без избранного нажимает CTA в любом попапе, получает стандартное подтверждение; кнопки обоих попапов, Hero и `(N)` становятся актуальными без reload.
3. Уже сохранённая площадка: «В избранном» с сердцем, без удаления из контекстных попапов. Снятие из Hero с подтверждением синхронизирует контекстные попапы.
4. Есть/нет мероприятий: список и переход к мероприятию работают, «Создать мероприятие» и «Посмотреть занятость» остаются независимыми.
5. Узкий мобильный экран, обе темы, Escape/outside-dismiss, сеть/error retry, нет вложенного dialog, нет дублирующего POST.
6. JS регрессии, полный PHP/JS CI, чистый Codex Review и подтверждённый деплой `main`.

Тексты — краткие и нейтральные; сохранение площадки позволяет следить за играми, но не гарантирует пуш-уведомление без отдельной настройки.
