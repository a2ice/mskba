# FindSport: последний слот 23:30–00:00 не должен пропадать

Дата: 15.11.2026. Обнаружено: /venues/30-aktiviti-kholl, источник findsport.ru/playground/4514, день 16.11.2026.

## Проблема и причина

В живом JSON /venues/30/schedule/day?date=2026-11-16 последний слот 23:30–24:00
возвращал unavailable при корректной цене и наличии в источнике, тогда как
предыдущий слот 23:00–23:30 имел available. Это не проблема полуоткрытого
интервала [start, end): 24:00 означает следующую полночь и не лишает слот
последней минуты.

ApplyFindSportSnapshotToNativeSchedule::CLOSE записывает в native weekly
and exception intervals 23:59 вместо 24:00 из-за HTML time inputs.
PublicVenueDaySchedule сравнивал конец слота 24:00 с этой границей
23:59, получая ложный inHours=false и переписывая свободный слот как
unavailable.

## Решение

Только при активном импорте внешнего снимка 23:59 в эффективном интервале
рабочих часов означает исключающую границу 24:00 для сравнения в
публичном дневном расписании. Данные графика, цены, снимки, границы в API,
занятость, ручные ограничения и логика бронирования не переписываются.
Без активного снимка реальное закрытие в 23:59 не расширяется.
Занятые и недоступные в источнике интервалы продолжают блокироваться.

## Регрессионные проверки

- FindSport 07:00–00:00 (34 слота): последний слот 23:30–24:00 доступен.
- FindSport 00:00–00:00 (48 слотов): после полностью занятого дня второй день
  показывает последний слот свободным, первый остаётся занятым.
- Обычный график без импорта с ends_at=23:59 не расширяется до 24:00.
- Через API проверяем статус и отображаемую цену. Проверка на dev
  после зелёного CI, merge и автодеплоя. Production не меняется.
