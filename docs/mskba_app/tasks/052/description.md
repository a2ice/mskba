# 052 — Селекты по гайдлайну и упрощение интерфейса профиля игрока

## Запрос и цель
Замечания по визуальной приёмке MSKBA App после PR #496/#497. Универсальное «Избранное» не должно предлагать поиск только площадки. Фильтры избранного/контрактов и поля игрока должны применять штатный native select с `.select-control`, отступами и Tabler chevron из гайдлайна, а не браузерную стрелку или локально нарисованный вариант.

## Объём
- Удалить действие «Найти площадку» со страницы избранного; оставить независимые фильтры по типу/статусу.
- Привести селекты страницы всех контрактов и вложенного списка площадок к UI Kit (доступность, hover/focus и forced-colors).
- У роли «Игрок» заменить рост/вес на ползунки с текущим числом, пределами 150–220 см и 40–140 кг. Хранение/валидация и генерация аватара остаются прежними.
- «Выраженность жировой ткани» переименовать в «Стройность», убрать медицинское пояснение, не добавлять вычисляемый диагноз. Хранимые значения `character.adiposity` и промпт не ломать.
- Убрать визуальные поля «Внешность персонажа» целиком. Сохранённые не показанные значения нельзя очищать; сервер принимает частичную настройку `character`.
- Форму и обувь сгруппировать в отдельный fieldset «Одежда и обувь» по образцу блока аксессуаров.
- Убрать заголовок/бейдж над шкалой и избыточный текст под ней; оставить шкалу, аватар, показ роста/веса.
- Закрепить вкладки при прокрутке в пределах страницы, опираясь на sticky-offset и навигацию площадки.

## Ограничения и проверки
Сохранять авторизацию, гендерные параметры, данные навыков и историю платной генерации. Проверить изменение значения range без сброса соседней вкладки; частичная форма не переписывает скрытые параметры; JS и PHP-тесты, frontend build, PostgreSQL 16/17; CI и PR в dev. Визуальную приёмку на dev не считать пройденной только по тестам.

## Статус
Реализовано в рабочей ветке: удаление действия поиска площадки, select-control для избранного и двух списков контрактов, упрощение физических параметров и UI, частичное сохранение appearance без потери скрытых данных, sticky-вкладки. PR и CI — в процессе, визуальная приёмка после публикации на dev остаётся открытой.
