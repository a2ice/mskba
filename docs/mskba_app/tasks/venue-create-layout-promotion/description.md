# Форма добавления площадки: порядок полей, удобства, акция

**Дата:** 14.11.2026. **Маршрут:** `/venues/create` (MSKBA App).

## Изменения

- Сначала показываем **адрес площадки** (выбор из подсказок/геолокация и автоподбор метро), затем название, тип и залы/корты. Никакие параметры формы, адресные идентификаторы и валидация не изменяются.
- В блоке «Общие удобства площадки» исправлено отображение двухколоночной сетки: чекбокс фиксированного размера стоит слева от текста, не растягивается вследствие общего правила `input{width:100%}`; на узком экране — один столбец.
- К служебному тексту об обязательных полях добавляем содержимое действующей **акции за первую успешную модерацию добавленной площадки**: заголовок, описание и номинал. Не обещаем вознаграждение за простое сохранение черновика.
- Добавлено место показа `venue_create` в админке Promotions; для уже существующей `reward_venue_first_approval` добавлена идемпотентная миграция размещения. Отображение использует `ResolveActivePromotions` и исчезает при выключении акции, Rewards, истечении срока или невалидном механизме. Тексты и сумма редактируются в админке, в шаблоне не зашиты.

## Границы

- В этом PR **не меняем** доступ гостя, авторизацию и сохранение; эти вопросы рассматриваются отдельным UX-решением.
- Правило прав остаётся прежним: подтверждение аккаунта для создания площадки не требуется, но сохранение требует входа; заблокированным пользователям запрещено создавать площадку.
- Публичная видимость площадки — после модерации; текущие механизмы бонусных начислений не изменяются.
