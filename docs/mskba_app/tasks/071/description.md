# Задача 071 — устранить 503 при загрузке фотографии лица

**Приоритет:** срочное исправление на `dev` (30.10.2026). Выполнять до задач 070 (логотипы команд) и управления кошельками.

## Воспроизведение и причина

В форме «Фотографии лица для генерации» на `/account/participation/player` при выборе JPG браузер отправляет `PATCH /account/player-profile` с `mutation=face_reference` (через multipart POST + `_method`).

`StorePlayerCharacterFaceReferenceHandler` после локальной нормализации WebP дополнительно вызывает `PlayerCharacterAiGateway::validateFaceReferences()`. При отсутствии `GITHUB_AI_TOKEN`/`GITHUB_AI_CALLBACK_SECRET` или другой AI-конфигурации `AiServiceProvider` возвращает `NullPlayerCharacterAiGateway`, который всегда выбрасывает `AiServiceException::notConfigured()` (HTTP 503). Это существующее поведение ранее даже закреплялось feature-тестом.

Загрузка фото — бесплатное действие по управлению профилем. Оно не должно зависеть от настройки GitHub Actions, внешнего AI-сервиса или кошелька. Сам факт `503` на скриншоте не доказывает конкретную конфигурацию среды; код и тест выявляют детерминированную ошибочную ветку, которую исправляем.

## Реализация

- Убрать зависимость хендлера загрузки от AI Gateway. Не вызывать `validateFaceReferences` при сохранении/замене фото.
- Сохранить локальную проверку формата (WebpImageNormalizer), изображения с не менее 128×128 пикселей, лимит HTTP upload 5 МБ и приватный `local` disk.
- Существующие транзакционное сохранение, замена, удаление прежнего файла, проверка владельца и защищённое превью не менять.
- В блоке «Фотографии лица для генерации» выводить отдельное сообщение под конкретным анфас/левым/правым фото: состояние сохранения, успешное сохранение/удаление либо читаемая ошибка. Для сбоя первичной загрузки сохранённых миниатюр — общее сообщение в этом же блоке. Не выводить ошибки фото под кнопкой платной генерации, которая имеет отдельную строку статуса.
- Само расположение лица в кадре **не подтверждается** на шаге загрузки. Зелёную галочку использовать только как признак участия данного Media ID в завершённой генерации, а не как доказательство распознанного ракурса. Реальная AI-классификация анфас/левый/правый — отдельная задача.
- Генерация `generate_2d` остаётся платной, с отдельной AI-проверкой и учётом средств. Сервис не должен ошибочно разрешать запуск AI при отсутствии конфигурации.

## Проверка

1. При `NullPlayerCharacterAiGateway` загрузка валидного фото возвращает HTTP 200 `stored`; защищённое превью доступно автору.
2. Замена уже сохранённой фотографии также HTTP 200 без AI, прежний файл удалён, новый приватно хранится.
3. Фото менее 128×128 — 422 с понятным сообщением, ничего не записано.
4. Генерация и кошелёк не затронуты; никаких дополнительных дебетов от загрузки.
5. Ошибка загрузки одного снимка, включая 503/413/419, отображается возле соответствующей миниатюры; статус платной генерации под кнопкой не затрагивается.
6. Зеленый CI и PostgreSQL → merge в `dev` → успешный `deploy_dev`; `main`/production без изменений.
