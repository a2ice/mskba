# 022 — Ролевое меню «Мой MSKBA» и обращение на «ты»

Дата: 2026-10-09. Ветка: feature/139. Статус: реализовано локально, на визуальной приёмке. Без нового коммита.

## Принятая модель

Активные роли участия определяют доступные подразделы независимо от существующих команд или договоров. Связи определяют содержимое разделов и доступные действия.

- Игрок: Мои команды, Мои игры, Мои тренировки.
- Тренер: Мои секции, Мои тренировки, Мои команды.
- Представитель площадки: Мои площадки, Бронирования, Расписание.
- Организатор: Мои мероприятия, Мои турниры.
- Судья: Мои игры, Судейские назначения.
- Статист: Мои игры, Статистика.
- Медиа: Мои материалы, Мои мероприятия.

Несколько ролей объединяют пункты без повторений, порядок стабилен. Без ролей группа отсутствует, при этом пункт «Роли в проекте» доступен. Навигация не является системой выдачи permissions.

## Реализация

В app-only AccountMenu используются активные participation roles канонического пользователя. Группа отображается через native details/summary по уже принятому UI паттерну, открывается на дочерней странице и управляется вручную. Для девяти ещё не разработанных экранов добавлены app-only GET маршруты с информативным заголовком и подзаголовком. mskba_dark продолжает работать по прежним правилам. Кошелёк расположен непосредственно перед Настройками. UI-тексты на «ты» по CaseRule18; юридические согласия не изменены.

## UX-правило: не группировать единственную ссылку (2026-10-10)

Условия формирования навигации **не изменены**: список «Мой MSKBA» определяется активными `UserParticipationRole` канонического аккаунта, с учётом фичефлагов и дедупликации пересекающихся разделов. Наличие команды/площадки не подменяет роли; контроллеры по-прежнему проверяют настоящие права при открытии разделов. После получения окончательного списка **видимых ссылок** `AdaptiveMenuGroup::wrap()` применяет правило:

- 0 ссылок: ни группы, ни дополнительных пунктов.
- 1 ссылка: показывается **непосредственно в sidebar** на исходном месте, без заголовка «Мой MSKBA» и `details`. Сохраняются исходные URL, состояние `active`, бейджи и атрибуты. Одиночный активный пункт дополнительно открывает мобильный аккордеон сайдбара.
- 2 и более: сохраняется привычная сворачиваемая группа «Мой MSKBA» с прежними ссылками, порядком и выделением текущего маршрута.

В действующей ролевой матрице каждая отдельная роль обычно добавляет два или три пункта. Новое правило рассчитано также на будущие фичефлаги и индивидуальные условия видимости, когда после фильтрации останется ровно один пункт. `account-roles.js` продолжает получать весь sidebar из серверной разметки после AJAX-изменения роли, без дублирования бизнес-логики в JavaScript. `mskba_dark` не изменяется.

Проверки: unit-тесты 0/1/2+ видимых ссылок, сохранение `active` и бейджей, feature-тест одноэлементной навигации на desktop/mobile, регрессии ролей и legacy.

## Итоговое уточнение 2026-10-10: «Мой MSKBA» + ссылки на параметры ролей

После рассмотрения варианта «отдельная группа для каждой роли» принято вернуть **общую группу «Мой MSKBA»**. Временная реализация групп `Игрок`/`Тренер`/и т. д. полностью отменена (revert). Исходная матрица активных participation roles, дедупликация общих разделов, порядок, `AdaptiveMenuGroup::wrap()` (0 ссылок — ничего, 1 — плоская ссылка, 2+ — группа) и обновление sidebar через AJAX сохраняются.

**Единственное функциональное дополнение:** после обычных общих подразделов для **каждой активной роли** добавляется отдельный пункт `Параметры: <название роли>` (например, `Параметры: Игрок`). Он ведёт на тот же `account.participation-role/{role}`, что и шестерёнка карточки роли на `/account/roles`. Эти пункты не дедуплицируются между разными ролями и исчезают после их отключения. На странице параметров раскрывается «Мой MSKBA», активна только соответствующая ссылка параметров; верхний пункт «Роли в проекте» активен только на `/account/roles`, а не на `/account/participation/{role}`. Права, routes, обработчики и `mskba_dark` не меняются.

Проверено: одна/несколько/отсутствующая роли, сохранение порядка и дедупликации функциональных ссылок, параметры разных ролей, подсветка и открытие группы на странице параметров, локальные 0/1/2+ тесты адаптивной группировки. Изменение только в навигационном представлении.
