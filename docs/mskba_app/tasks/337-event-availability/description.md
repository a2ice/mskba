# 337 — Просмотр занятости и шаг времени мероприятия

## Требования приёмки 20.11.2026

- Пустой список «Хочу здесь играть»: пояснение, две кнопки в footer с space-around и промежутком, мобильное перенесение без переполнения.
- В основной теме MSKBA на странице площадки оба входа в занятость используют существующий двухшаговый rental search и календарь девяти дней. Режим просмотра не создаёт бронь и не показывает CTA бронирования; зал по умолчанию любой, при явном выборе — только выбранный. Сохраняются вкладки залов и выделение диапазона.
- Шаг времени: московские дата и время (текущее московское время + минимальный срок до начала аренды из действующей политики площадки (или переопределение выбранного зала) + 10 минут на заполнение; округление вверх до целой минуты, с переходом даты через полночь), без предварительного добавления интервала. Неизменённые значения не превращают необязательный шаг в обязательный; добавление по плюсу или явно изменённая дата/время по «Далее». Используются существующие Modal 1.1, поля, цвета и ссылка как в выборе площадки, плюс с доступным названием и tooltip.
- В классической теме и при выборе иной площадки в глобальном визарде сохраняется существующий inline просмотр; общий календарь пока привязан к контексту конкретной страницы площадки. Это ограничение требует отдельного расширения.
- Не изменять API брони, цену, контракты и роли.
- Проверки: JS regression assertions и CI; ручная приёмка мобильного и desktop после деплоя, включая пропуск нетронутого шага и сохранение поведения аренды.

UI reference: [MSKBA UI Design System](../../../specification/ui-design-system.md), Modal 1.1, Form Controls, существующий rental-time-first-wizard и UI Kit.
