# Режим «Занятость уточняется» для аренды площадок

PR #1168. Целевая ветка: dev.

## Цель

Если площадка принимает заявки на аренду, но портал не имеет достоверного внешнего расписания, отсутствие бронирования в MSKBA не должно означать подтверждённое свободное время.

## Настройка

Filament → Площадки → Изменить → Аренда → Занятость уточняется. Настройка действует на площадку и её залы, по умолчанию выключена. Существующие ограничения аренды и рабочие часы сохраняются.

## Интерфейс

- На страницах площадки и зала линия занятости дня в новом режиме серая, известная занятость — красная. При выключенной настройке остаётся обычная шкала.
- В календаре не занятый известными бронированиями и подходящий по правилам аренды интервал имеет статус «Уточняется» и доступен для выбора.
- Кнопка «Отправить заявку» создаёт запрос на аренду; время не резервируется, оплата не инициируется. Гость после входа получает форму с ранее выбранным временем.
- Мастер поиска аренды не называет такие интервалы свободными.
- Кнопка «Арендовать площадку» расположена справа от заголовка расписания; заголовок календаря — название площадки и зала, без дублирования выбранной даты.
- Пользовательский термин «Предзаявка» для самостоятельных запросов заменён на «Запрос на аренду». Внутренние имена сущностей и маршрутов сохранены для совместимости.

## Границы и проверка

Используется существующий сценарий VenueRentalPreRequests, без создания нового жизненного цикла заявки. Прямое создание обычной заявки для площадки с неизвестной занятостью запрещено сервером; предложение представителя по запросу и последующее согласие клиента сохраняются. Изменения согласования альтернативных дат и дальнейшей обработки относятся к отдельному эпику #1059.

Проверить: включить опцию на dev для площадки с расписанием без внешней интеграции, увидеть серую шкалу, создать известное бронирование через согласованное предложение и проверить красную долю, отправить запрос без бронирования или оплаты, проверить гостевой сценарий и обе страницы (площадка/зал), отключить опцию и убедиться в сохранении прежнего поведения. Для legacy-темы используется её существующий интерфейс с нейтральными статусами и переходом в форму запроса.

Автоматические проверки: тест запрета прямого бронирования, создания не занимающего время запроса и совместимости предложения; JS-тест выбора и сводки интервалов с неизвестной занятостью.
