# 091 — Бронирования и предзаявки в едином центре сообщений

Дата 17.11.2026. Реализуется в `mskba_app`, сначала dev; production только после приёмки.

## UX и правила визуального гайдлайна

- Бронирование и самостоятельная предзаявка становятся отдельными контекстными чатами группы «Заявки и обращения». После создания по предзаявке предложения брони сохраняется один диалог, а не две копии истории.
- Применяется существующий app-message-workspace, compact sidebar, стандартная header panel, собственный скролл истории, одна внешняя рамка редактора сообщений и стандартная кнопка «Отправить» с внутренним отступом 5px от нижней и правой границы.
- На мобильном заголовок переносится, участников/ссылки нельзя накладывать на заголовок. Меню «Действия» использует общий app-context-actions, дополнительных обводок неинтерактивного текста нет. Подтверждение действия — стандартный dialog.
- Видимость доступных действий определяется только сервером: VenueBookingActionState (включая холд, состояние оплаты, optimistic version), VenueRentalPreRequests и действующие права. При устаревшей кнопке сервер отклоняет действие и клиент обновляет контекст.
- Сообщения, вложения, статус, unread и действия доступны из ЛК и из страницы заявки с одной общей исходной базой сообщений и приватным доступом. Непрочитанное отмечается просмотренным только в доступном авторизованном треде.

## Реализация

- BookingConversationCards: scoped SQL discovery и финальная доменная ACL проверка, карточки по booking/pre-request, без повторного хранения сообщений.
- AccountBookingConversationsController: авторизованные HTML/JSON и read markers, существующие доменные маршруты для отправки и файлов, приватные URL загрузки.
- Единственный UI-представитель account.booking-request-conversation и booking-chat-bubble; клиентская синхронизация Reverb + fallback 15s, подгрузка старых сообщений, контекстные кнопки.
- Уведомления аренды теперь ссылаются на соответствующий тред и исключаются из общего системного чата, не дублируясь. Сохраняется доставка уведомлений и исходные audit/domain snapshots.
- Между pre-request и созданной по ней booking нет нового независимого чата, их связывает уже существующий pre_request_id.

## Приёмка

- Смартфоны 320/375/390/430px, планшеты 768/1024px, десктоп 1440/1920px, проверка взаимодействия с клавиатурой и длинными названиями.
- Клиент, представитель площадки, пользователь без права, отозванное право; отправка текста/вложений/чтение с двух сторон, системные статусы, реакция без перезагрузки.
- Pending, HELD (проверка действительности холда и оплаты), CONFIRMED, REJECTED, EXPIRED, pre-request предложения, истёкшее предложение, блокировка опасных действий.
- PHP, JS/Vite, Blade, CI и проверка реального dev до публикации production.
