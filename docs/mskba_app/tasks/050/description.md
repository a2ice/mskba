# 050 — Необязательный срок действия игровой подписки

**Дата:** 26.10.2026. **Контекст:** визуальная приёмка «Мои подписки». CI → PR → dev.

## UI
- В первом шаге wizard, сразу под «Название подписки», чекбокс «Срок действия». По умолчанию выключен, текст «Бессрочно».
- При включении появляется date input «Дата окончания подписки», по дизайн-системе MSKBA с минимальной датой сегодня. Без корректной даты переход «Далее» и сохранение запрещены.
- При редактировании существующего срока чекбокс включён, дата сохранена; при редактировании null — выключен. Снятие чекбокса сохраняет null. Через авторизацию временные данные формы также передаются.

## Сервер и продолжительность
- POST/PUT /account/play-intents: необязательный expires_at в формате Y-m-d или null. Если дата отсутствует либо null, подписка бессрочная; когда есть дата — время окончания в конце выбранного дня по timezone приложения, сохранение UTC.
- Срок жизни подписки больше не назначается автоматически из cadence=flexible/regular/once, не зависит от дат отдельных игр.
- Фильтрация active учитывает null. Аудитория площадки тоже учитывает active подписчиков с null, без утечки закрытого профиля.
- Существующие исторические даты оставлены неизменными. В попапе «Посмотреть» отображается «Срок действия — Бессрочно» или дата.
- Восстановление отменённой бессрочной подписки сохраняет null. Если отменённая подписка имеет будущую дату, она сохраняется; истёкшие исторические подписки продлеваются на 30/90 суток как раньше.

## Проверка
- Тесты по умолчанию null для всех cadence, повторная редакция и снятие даты, отказ в прошедшей/некорректной дате (422), конец дня, бессрочный участник в списке площадки.
- Проверки сохранения null при восстановлении, без дублей; существующие expired legacy проверки сохраняются.
- CI PHP/JS/build, PostgreSQL 16/17, PR merge в dev и подтверждённый dev deploy; production не меняется.
