# Универсальный Enter и безопасное закрытие попапов

**Дата:** 2026-11-18 · **Целевая среда:** production после зелёного CI.

## Принятые правила

- Enter в обычном поле визарда сначала проверяет **текущее поле**. При ошибке переход блокируется, поле получает красную рамку по теме и понятное сообщение снизу. При изменении значения (input/change) ошибка сразу снимается.
- Если поле корректно, Enter переводит фокус на следующее доступное поле текущего шага. Радиокнопки с одним именем считаются одним логическим полем.
- Enter из последнего поля шага проверяет весь шаг и переходит к следующему, фокусируя первое поле.
- Enter из последнего поля финального шага валидирует всю форму и отправляет её.
- Сохраняется нативное поведение textarea, select, IME и специализированных элементов управления.
- Во всех popup-окнах обеих публичных тем закрытие по backdrop разрешено только при полном pointer-жесте, начатом **и** законченном на фоне. Перетаскивание, выделение внутри и отпускание снаружи не закрывают окно; движение указателя само по себе не закрывает окно.
- **Не показывать подтверждение закрытия** при несохранённых изменениях. Вместо него по возможности сохранять черновик и текущий шаг при повторном открытии в рамках жизни страницы. Данные регистрации, включая пароль, остаются только в оперативной памяти Vue-компонента и не сохраняются в storage.
- Успешная отправка/отдельное действие сброса могут очищать состояние по своему контракту.

## Технические точки

- Общий pointer/backdrop guard: `resources/themes/mskba_app/js/modal-dragging.js`, подключён в обеих публичных темах.
- Общая обработка Enter в Vue-мастерах: `resources/themes/mskba_app/js/components/WizardShell.vue`.
- Регистрация: `AuthDialog.vue` оставляет wizard mounted при закрытии; `RegistrationWizard.vue` показывает inline-валидацию.
- Legacy-мастера, которые не используют `WizardShell.vue`, требуют отдельного подключения такой же полевой валидации и фокусной навигации после аудита их локального состояния. Правило остаётся общим для всех мастеров, даже если внедрение будет поэтапным.
- Административные/сторонние overlay-системы (включая Filament) нужно проверять отдельно: их backdrop events могут обходить общую тему.

## Критерии проверки

1. Фамилия → Enter → Имя → Enter → Отчество → Enter → следующий шаг и фокус первого поля.
2. Некорректное поле → Enter → остаётся в поле, красная рамка и ошибка → исправление → ошибка исчезает.
3. Последнее поле финального шага → Enter → форма валидируется и отправляется.
4. Выделение изнутри попапа наружу → отпускание мыши → окно остаётся открытым.
5. Прямой клик по фону (down и up на нём) → окно закрывается.
6. Закрытие регистрации и повторное открытие без перезагрузки → текущий шаг и значения остаются прежними.
7. Проверить desktop/mobile, JS/feature tests, Vite и CI перед merge.
