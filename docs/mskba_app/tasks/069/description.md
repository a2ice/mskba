# MSKBA App 069 — генерация аватара: статусы, диагностика, фото лица

## Контекст и наблюдение (30.10.2026)

После нажатия «Сгенерировать» показывался нативный `window.confirm` со стоимостью 100 ₽. При неудачном запросе под кнопкой появлялось «Не удалось выполнить операцию.» вместо причины. Выбранные локальные JPG отображались только именами и зелёными галочками, не как сохранённые пользовательские миниатюры.

Важно: без логов HTTP-запроса конкретную первопричину старого 5xx/не-JSON ответа доказать нельзя. Исправлены ветки получения ошибок, добавлены диагностические ID для неожиданных исключений. Нельзя заявлять, что это подтверждает исправление исходного инфраструктурного сбоя. Перед повторной платной попыткой нужен E2E smoke на dev.

## Решение

- Удалить браузерный `window.confirm`: пользователь уже видит цену и правила списания в отдельной подсказке. Сервер перед списанием заново проверяет актуальную стоимость, баланс и право на генерацию. Сначала бонусные средства, затем реальные; возврат при неуспешном dispatch остаётся идемпотентным.
- Под кнопкой один `role=status` с последовательностью: «Проверяем стоимость и баланс…», «Генерация аватара…» (отправка, ожидание, обработка), «Готово! Аватар создан…» либо явная «Ошибка генерации: [причина]». Для 401/403/413/419/422/429/5xx формировать понятную реакцию даже на не-JSON. Неожиданные backend-ошибки логируются с `error_id`; клиент получает безопасный JSON с кодом.
- Фото для фронтального/левого/правого ракурсов сохранять при выборе через существующий защищённый `face_reference` workflow (`Media` профиля на private disk, нормализованный WebP до 512 px). На повторном открытии формы отдавать URL существующего приватного preview. Никаких публичных URL к raw изображениям.
- В голубом кружке показывать выбранный сохранённый портрет по ширине/высоте 100% с `object-fit:cover`; по клику загружать замену. Отдельная кнопка «Удалить фото» возвращает исходный PNG-силуэт.
- Зелёная галочка означает только то, что **тот же Media ID участвовал в завершённой успешной генерации**, а не что файл просто выбран или загружен. При замене/удалении отметка исчезает. В GitHub-hosted AI текущая `validateFaceReferences` проверяет читаемость/минимальный размер, но **не настоящий угол поворота лица**; нельзя считать галочку доказательством корректного ракурса. Настоящая классификация ракурса через vision/structured output — отдельная функциональная доработка.
- Пока есть активная генерация, защитить media от замены/удаления, чтобы входные signed references не стали недоступны. Предотвратить двойной старт генерации и параллельный запрос до завершения загрузки фото. Приватный read model — `Cache-Control: private, no-store`.

## Acceptance checklist

- [ ] Нет `window.confirm`; единственное нажатие запускает preflight без второго подтверждения.
- [ ] Статусы меняются в одном месте; ошибка HTTP без JSON содержит понятную причину или диагностический ID, если известен.
- [ ] После сохранения и перезагрузки фото остаётся в соответствующем кружке, `object-fit:cover`; галочки нет до успешной генерации.
- [ ] Замена обновляет превью и сбрасывает отметку; удаление стирает приватный Media-файл и возвращает заглушку.
- [ ] Только владелец видит свои фото; чужие ссылки не открываются.
- [ ] Pending/processing блокирует изменение своих входных фото; финансовые операции при неудаче безопасны.
- [ ] PHPUnit / JS / PostgreSQL / Vite CI зелёные, PR в `dev`; отдельно проверен фактический dev deploy и E2E без предположений.
