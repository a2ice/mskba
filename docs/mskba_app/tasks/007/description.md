# 007 — Локальная разработка и обязательный учёт новых правок

**Статус:** На проверке (документировано локально) · **Создано:** 2026-10-08 · **Связь:** [задача проекта #139](../../../tasks/139/description.md).

## Запрос пользователя

До отдельной явной команды пользователя не публиковать изменения новой темы в GitHub: копить и проверять локально. Любую новую самостоятельную правку предварительно оформлять отдельной задачей, чтобы сохранялись история решений и прогресс.

## Решения

1. **Локально до отдельной команды.** Для работ по `mskba_app` в рамках #139 разрешены локальная реализация, тесты и коммиты в текущую рабочую ветку по согласованному режиму; `git push`, force-push, PR, merge, deploy и другие способы отправки этой работы во внешнее окружение **запрещены** до явно выраженного нового распоряжения пользователя на конкретное действие. Общая просьба «продолжай» или «коммитим» не считается разрешением на push. Исключение для Telegram Mini App из CaseRule8 здесь не действует.
2. **Сначала карточка задачи, потом изменение.** Каждое новое самостоятельное поручение по UI/UX новой темы (в том числе CSS, текст, баг, документация или функциональность) сначала заносится в `docs/mskba_app/tasks.md`, получает следующий свободный локальный номер и `docs/mskba_app/tasks/NNN/description.md`. Только потом меняется код или документация.
3. **Правка в рамках существующей задачи.** Исправление недочёта, обнаруженного при проверке результата той же задачи, уточнение её согласованных критериев, тест или рефакторинг, необходимый для её завершения, фиксируются в **той же** карточке и прогрессе. Новая задача нужна, если меняется отдельное требование / появляется новая независимая работа. Сомнительные случаи предварительно согласуются.
4. **Статус, след и приемка.** Каждая карточка описывает цель, границы, критерий проверки, фактический результат, текущий статус и ссылку на связь с глобальной #139. Уточнения и решения обновляют `progress.md`; завершение задачи не означает, что работа опубликована.
5. **Область действия.** Специальный режим локальной работы и локальной нумерации применяется к `mskba_app` и #139. Процесс других задач проекта остаётся в `docs/tasks.md` и [Task Workflow](../../../specification/task-workflow.md).

## Внесённые изменения

- Правила в [стартовой инструкции темы](../../start_here.md), [прогрессе](../../progress.md) и [реестре задач](../../tasks.md).
- Сквозное правило в `docs/specification/agent-rules.md` с явным ограничением по #139 и приоритетом над CaseRule8.
- Ссылки в материалах основной задачи #139.

## Критерии проверки

- Любая будущая самостоятельная правка начинается с новой локальной карточки, а фиксы в ходе приёмки остаются частью текущей задачи.
- В рамках #139 нет push/deploy/merge без нового конкретного разрешения пользователя.
- Документы взаимно ссылаются, нет противоречий с базовым workflow и CaseRule8.
- `git status` подтверждает, что никаких изменений не отправляли в GitHub.
