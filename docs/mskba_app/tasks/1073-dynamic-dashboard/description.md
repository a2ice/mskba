# #1073 — Динамические данные в существующих карточках ЛК

PR [#1091](https://github.com/a2ice/mskba/pull/1091). DEV ONLY.

## Объём и решение владельца

Владелец разрешил для этого этапа обойтись без отдельной визуальной приёмки UI Studio: оболочка карточек уже существует, изменяется содержимое. Ветка кандидата UI Studio сохраняется отдельно, без интеграции. Проверка результата — непосредственно в dev. Это не изменение общего регламента для будущих интерфейсов.

## UI и контракты

- Эталон — текущий дашборд ЛК `/account`: `app-dashboard-grid`, `panel app-dashboard-widget`, `app-dashboard-widget__richtext`, `app-dashboard-widget__actions`, `button secondary` и существующие семантические токены темы. Общий UIKit, CSS, шрифты и палитры не меняются.
- Пять источников: интересы, расписание, заявки и предзаявки на аренду, кошелёк, непрочитанные сообщения. Счётчики, списки, ссылки, пустое состояние и нейтральная ошибка получения данных.
- В Filament существующий переключатель публикации, лимит записей, аудитория и размещение. Автоматически карточки не создаются и не публикуются. Скрытие и порядок сохраняются.
- Авторизация источника повторно проверяется перед чтением. Ссылки на записи проходят валидацию, вывод экранируется Blade. Персональные ответы private/no-store. Существующая сверка HTML обновляет содержимое; личные данные не задерживаются административным таймером при смене карточки. При исчезновении виджета из доступного каталога выполняется reconciliation.
- Отдельные доменные Reverb listeners, операционные виджеты, центр действий и специальные настройки остаются последующими этапами Epic.

## Проверки

CI: полный PHP/JS набор и сборка; тесты Filament и изоляции данных, отзыва подписки, исключения аудитории. Не отключать проверку UI guideline trace: настоящий документ задачи дополняет [технический контракт](../../../specification/dashboard-data.md).

Приёмка на dev после подтверждённого автодеплоя:
- создать и выборочно опубликовать карточку в Filament; проверить, что черновик не виден;
- проверить все пять источников с реальными разрешёнными данными и без записей; чужие данные не отображаются;
- проверить сохранение скрытия и порядка, исчезновение после отзыва доступа, обновление на focus/reconnect, ссылки и ошибки;
- проверить применимые опубликованные темы mskba_app, ширины 360/390/768/1440, длинные названия, клавиатуру и фокус. Legacy шаблоны не изменены.

Визуальная проверка и smoke пока не выполнены. Main и production не затрагиваются.

## Live-срез (26.11.2026)

Без изменения дизайна: существующий dashboard refresh подписывается на приватное событие `.dashboard.widgets.invalidated`, coalescing 250 мс / максимум 1,5 с. Источники: кошелёк, свои заявки/предзаявки, подписки, участие, EventChanged. Визуальные примитивы не меняются. Проверить две вкладки разных аккаунтов, поступление изменений после commit, отсутствие сигналов при rollback, приватные события, reconnect/focus, сохранение порядка. Ограничения первого среза и fallback — в dashboard-data.md.

## Центр действий — первый срез

Источник `needs_attention` использует существующую richtext-карточку и внутренние ссылки: подтверждение аккаунта, незавершённый onboarding публичности, ответ на актуальное предложение аренды. Счётчик нерешённых действий, не уведомлений; пустое состояние. Только собственные предложения, feature/rollout, активная предзаявка, срок и отсутствие принятия. Не выполнять действия из карточки, не дублировать доменные переходы. Проверить устранение записи после выполнения, отрицательные сценарии и обе темы на dev. Без новой вёрстки UIKit. Операционные виджеты и остальные виды действий отдельно.

## Входящие заявки площадок

Источник `venue_rental_inbox`: та же карточка/список, раздельные счётчики входящих заявок и предзаявок, штатные ссылки. Только активные подтверждённые права по площадке/залу, без глобальной выдачи доступа. Проверить на dev под агентом с правом на один зал, владельцем, посторонним и после отзыва контракта. Нет автопубликации; операционная Reverb-инвалидация отдельно, пока уведомления и fallback. #987 не изменяется.

## Приглашения площадок

`venue_invitations` в существующей карточке: раздельные счётчики процедуры, последние приглашения с названием площадки, статусом, этапом и сроком. Ссылка в существующий Filament index. Проверить менеджера с правами на одну площадку, постороннего, отключение permission и отзыв договора, отсутствие контактов/токенов в HTML/JSON, истечение ссылки. Никакой новой выдачи прав или автоматической публикации. Отдельное закрепление менеджера и адресный live — последующие этапы; #987 не изменяется.

## Выборочный refresh

Дизайн не меняется. При приватном событии обновляются только content затронутых видимых dynamic-карточек по `sources[]` существующего endpoint; общий список видимых ID и версия карточки проверяются до замены, при несовпадении полная сверка. Сохраняются порядок, скрытие, drag, административное обновление и fallback. Проверки: несколько карточек одного источника, burst разных источников, смена прав, скрытие, ошибки, reconnect, две сессии, отсутствие лишних чтений данных. PHP и JS тесты; реальная браузерная приёмка отдельно.

## Дополнительные параметры

Filament: авто-скрытие пустых списков/счётчиков (не кошелёк), мгновенное обновление по сигналам источника, горизонт интересов 7–90 дней. Пустая карточка сохраняет логическое место и preference, появляется при данных; ошибка не скрывается. Выключение мгновенного обновления не отменяет проверку прав, уведомления и полную сверку. Проверить две карточки одного источника с разными live-флагами, empty→nonempty→empty, ручное скрытие, keyboard/drag, конфигурацию и ошибки. Без изменения оформления карточек; CSS только для hidden. Браузерная приёмка отдельно.
