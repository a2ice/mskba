# #1073 — Динамические данные в существующих карточках ЛК

PR [#1091](https://github.com/a2ice/mskba/pull/1091). DEV ONLY.

## Объём и решение владельца

Владелец разрешил для этого этапа обойтись без отдельной визуальной приёмки UI Studio: оболочка карточек уже существует, изменяется содержимое. Ветка кандидата UI Studio сохраняется отдельно, без интеграции. Проверка результата — непосредственно в dev. Это не изменение общего регламента для будущих интерфейсов.

## UI и контракты

- Эталон — текущий дашборд ЛК `/account`: `app-dashboard-grid`, `panel app-dashboard-widget`, `app-dashboard-widget__richtext`, `app-dashboard-widget__actions`, `button secondary` и существующие семантические токены темы. Общий UIKit, CSS, шрифты и палитры не меняются.
- Пять источников: интересы, расписание, заявки и предзаявки на аренду, кошелёк, непрочитанные сообщения. Счётчики, списки, ссылки, пустое состояние и нейтральная ошибка получения данных.
- В Filament существующий переключатель публикации, лимит записей, аудитория и размещение. Автоматически карточки не создаются и не публикуются. Скрытие и порядок сохраняются.
- Авторизация источника повторно проверяется перед чтением. Ссылки на записи проходят валидацию, вывод экранируется Blade. Персональные ответы private/no-store. Существующая сверка HTML обновляет содержимое; личные данные не задерживаются административным таймером при смене карточки. При исчезновении виджета из доступного каталога выполняется reconciliation.
- Отдельные доменные Reverb listeners, операционные виджеты, центр действий и специальные настройки остаются последующими этапами Epic.

## Проверки

CI: полный PHP/JS набор и сборка; тесты Filament и изоляции данных, отзыва подписки, исключения аудитории. Не отключать проверку UI guideline trace: настоящий документ задачи дополняет [технический контракт](../../../specification/dashboard-data.md).

Приёмка на dev после подтверждённого автодеплоя:
- создать и выборочно опубликовать карточку в Filament; проверить, что черновик не виден;
- проверить все пять источников с реальными разрешёнными данными и без записей; чужие данные не отображаются;
- проверить сохранение скрытия и порядка, исчезновение после отзыва доступа, обновление на focus/reconnect, ссылки и ошибки;
- проверить применимые опубликованные темы mskba_app, ширины 360/390/768/1440, длинные названия, клавиатуру и фокус. Legacy шаблоны не изменены.

Визуальная проверка и smoke пока не выполнены. Main и production не затрагиваются.
