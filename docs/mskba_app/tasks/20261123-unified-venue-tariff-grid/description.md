# Единая тарифная сетка площадок и залов (23.11.2026)

## Задача и принятые решения

Нужны два самостоятельных интерфейса редактирования — нативная страница Filament и кабинет площадки — с **одной серверной моделью тарифов и общим сервисом применения**. Оба поддерживают ручные и импортированные тарифы. Диапазон — только визуальное объединение соседних минимальных тарифных шагов (RTC), а не новая независимая тарификация. Источник истины для расчёта: существующие цены по слотам, с отдельным слоем ручных переопределений для зала. Кнопки и формы используют существующую UI Kit палитру/контролы; всплывающий редактор не пересоздаёт независимые условия аренды.

## Интерфейс

1. Выбор площадки или зала и режима «недельный шаблон / конкретная дата».
2. Цена и источник каждого временного шага; соседние шаги с идентичными ценами группируются в раскрываемые диапазоны.
3. Из раскрытого диапазона можно изменить ровно один шаг через диалог. Массовый редактор задаёт интервал, дни недели, стоимость целого/половины зала и исключения внутри диапазона.
4. Очистка ручного переопределения возвращает унаследованный или импортированный тариф.
5. Filament → Площадки → Аренда / Залы → «Тарифная сетка» ведёт на **нативную ресурсную страницу Filament**; кабинет площадки → «Тарифная сетка» остаётся внутри публичного аккаунта. Обе страницы используют VenueTariffGrid::read() и ::applyMany(), а не разные алгоритмы.

## Данные, приоритет и защита импорта

- Weekly venue: venue_schedule_slot_prices; date venue: venue_calendar_slot_prices.
- Weekly/date court source: venue_court_slot_prices, venue_court_calendar_slot_prices (включая импорт).
- Manual court: venue_court_manual_slot_prices (day_of_week или date). **Эти записи не изменяются повторным применением снимка интеграции**.
- Разрешение эффективной цены: manual court date → manual court week → court calendar → court week → court base → venue calendar/week → venue base; минимальная платная стоимость площадки соблюдается.
- Для недельного шаблона и календаря все изменения записываются в минимальные слоты. Ограничение шага, цена ниже минимума, дублирующиеся исключения, права на управление и принадлежность зала проверяются на сервере. Запись атомарная, синхронизация работает независимо.
- Текущие подтверждённые бронирования и неизменяемые сохранённые расчёты не переписываются.

## Acceptance

1. Импорт с последовательными ценами 2 000 / 2 000 / 2 500 / 2 000 ₽ отображается диапазонами и локальным исключением; сохранение диапазона записывает правильное число шагов.
2. Повторный импорт заменяет исходные цены, но ручная корректировка остаётся, видна в попапе расписания и quote; очистка возвращает актуальное значение источника.
3. Выбор дня недели/даты, минимального шага и ограничения нижней цены.
4. Доступ владельца/управляющего к разрешённому залу; 403 при попытке редактировать чужую площадку.
5. В Filament отдельная страница с компонентами Filament, собственным backoffice-контролем прав; в кабинете редактор оформлен по MSKBA App UI Kit. Обе позволяют сохранить несколько диапазонов за один запрос. После merge автоматический CI и main-deploy, если он разрешён конфигурацией окружения.


## Уточнение: несколько диапазонов за одно сохранение

Типовой сценарий: Пн–Пт, 07:00–16:00 по 1 000 ₽/30 мин и 16:00–23:30 по 1 500 ₽/30 мин. Кнопка «Добавить диапазон» создаёт вторую строку; единственная кнопка «Сохранить все диапазоны» атомарно применяет их к слотам. Граница 16:00 принадлежит второму интервалу. Исключения задаются внутри соответствующей строки, при необходимости только для одного дня недели. Перекрывающиеся диапазоны на одних сутках отклоняются без частичной записи. Функция доступна и в Filament (нативный Livewire UI), и в аккаунте площадки (Blade + POST), использует одну VenueTariffGrid::applyMany().


## Уточнение UX, 24.11.2026 — редактор не должен вести на отдельную страницу

В **Filament → Площадки → Расписание** рядом с недельными интервалами отображается действие «Тарифная сетка площадки»: нативный modal Action с редактированием нескольких диапазонов, днями, ценами и исключениями, а также просмотром действующих тарифов и источника. Аналогичный modal Action доступен в «Аренда»; для **залов** — в relation manager «Залы и корты», как действие строки, без перехода на отдельную страницу. Уровень площадки задаёт общее правило, уровень зала — выборочное переопределение. В интерфейсе зала «Наследовать» сбрасывает ручную цену и открывает наследование по источникам в VenueTariffGrid.

В **публичном кабинете площадки → вкладка «Расписание»** после расписания работы расположен блок «Тарифная сетка площадки», далее блок «Тарифы залов и кортов» с нативными сворачиваемыми details по каждому залу. Используется тот же Blade-компонент тарифов, но контекст и ссылки выбора даты/типа тарифа встроены в текущую вкладку; return_to_schedule=1 после POST возвращает в неё с открытым соответствующим залом. Несколько экземпляров скрипта изолированы атрибутом root и флагом инициализации. Права коммерческого управления перепроверяются для площадки и каждого зала отдельно; простое разрешение на редактирование расписания не позволяет менять тарифы. Без опубликованного базового rental policy показано объяснение, а не неработающая форма.

Единый источник расчёта остаётся VenueTariffGrid + VenueSlotPricing; сохранён импорт цен и их приоритеты. Рабочие часы и цены сохраняются **раздельными** формами, без изменения схемы данных.


## Исправление сохранения и повторного открытия (24.11.2026)

Выявленная UX-проблема: после POST или закрытия Filament modal обе формы создавали пустую новую строку, а не загружали сохранённые тарифы. Это делало успешно записанные значения невидимыми в форме и не позволяло редактировать/удалять прежние диапазоны как набор. Filament-попапы до исправления также не были протестированы через фактический вызов Action — проверялся только рендер кнопки.

Исправлено: VenueTariffGrid::editableRanges() группирует только явно сохранённые временные шаги в редактируемые диапазоны, объединяя одинаковые диапазоны разных дней. Не подменять наследование автоматически записанными в зал ценами площадки/импорта. Filament modal fillForm и публичный редактор получают редактируемые диапазоны из БД, а при валидационной ошибке публичная форма возвращает введённые значения нужного зала. Сохранение полной формы явно сообщает replace_existing=1 и атомарно синхронизирует только соответствующие ручные записи: удалённые диапазоны действительно удаляются, пустая сетка удаляет все ручные корректировки, цены внешнего источника не затрагиваются. Устаревший вызов API с одним диапазоном по-прежнему действует как частичное обновление. Ошибки записи переводятся в nested-key диапазона, поэтому попап показывает реальную причину запрета записи.

ВАЖНО: общий минимальный оплачиваемый тариф площадки из docs/project/venue-rental-minimum-slot-pricing.md является настоящей нижней границей; он не изменён этим исправлением. Оба редактора теперь явно показывают минимальную цену **с учётом шага зала** и предупреждение о необходимости понизить минимум во вкладке «Аренда» перед установкой меньших цен.

Приёмка: реальное сохранение через native Filament action площадки и action зала, повторное открытие с восстановленными значениями, сохранение массива из 2 диапазонов, изменение и удаление одного диапазона, очистка всей сетки, контроль отсутствия изменений у импортированного источника, rollback при ошибке цены ниже минимума, сохранение через публичную вкладку «Расписание» с повторным открытием.
