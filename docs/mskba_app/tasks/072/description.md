# MSKBA App — задача 072: кошельки пользователей в Filament

**Цель:** `/backoffice/users/{id}/edit` → новая вкладка «Кошелёк» с балансами и историей операций и аккуратными финансовыми действиями. Основной баланс не пополняется вручную; используем существующий `Finance` (не создаём второй учёт).

## Сценарии

1. Редактор пользователя видит общий, основной и бонусный баланс в рублях (расчёт в копейках). Доступна история последних 100 завершённых операций: дата, тип, откуда/кому, изменение основного и бонусного баланса, итог. Журнал неизменяемый.
2. Superadmin на **своей** карточке видит «Пополнить свой бонусный баланс». В модальном окне вводит сумму, свой текущий пароль и подтверждает. Используется действующий `SuperadminWalletBonusGrant` и уникальный ключ идемпотентности; неправильный пароль не создаёт запись или начисление. Источник новых бонусов: `superadmin_manual_bonus_grant` в immutable operation.
3. Superadmin в карточке другого пользователя видит «Начислить бонусы пользователю». Указывает кошелёк-источник (по умолчанию собственный), сумму и основание 10–500 символов. Используется **не** `CreditWalletHandler` напрямую на получателе, а существующий `TransferUserWalletBalanceHandler`, который атомарно списывает бонусы с баланса superadmin и зачисляет пользователю в единой операции с двумя записями ledger.
4. У подтверждённого администратора с **индивидуально выданным** правом `wallet.user_balance.credit` появляется делегированная возможность начислений; источник выбирается из подтверждённых superadmin, основания и исполнитель сохраняются в immutable metadata и audit log. Без этого права — только просмотр. Право по умолчанию выключено, не наследуется из системной роли или шаблона, допускается только для ADMIN/SUPERADMIN. Для открытия редактора пользователя по-прежнему нужно штатное право редактирования/управления пользователями.
5. Superadmin не может списать бонусы с другого superadmin и не может перевести средства самому себе через эту операцию. На карточке другого superadmin этот функционал недоступен. Операции требуют подтверждённые, активные аккаунты и соблюдения иерархии пользователей.
6. Изолировать вывод платежных ошибок от обычных полей профиля: ошибки суммы/источника/прав в модале. Не сохранять пароль в логах/audit.
7. Упрощённый запуск требует текущего подтверждения суммы/пароля для собственного начисления; для перевода — выбора источника и основания. Повторный submit с тем же idempotency key не создаёт второй перевод или повторный audit. Недостаток средств у источника откатывает всю транзакцию.

## Реализация

- `BackofficeUserResource`: вкладка «Кошелёк» с Blade View.
- `EditBackofficeUser`: две защищённые модальные Filament Actions, независимые от сохранения профиля/прав.
- `BackofficeUserWalletFunding`: централизованная серверная авторизация и transfer, проверка источника, immutable audit.
- `TransferUserWalletBalanceHandler`: новый необязательный (с обратной совместимостью) оператор и основание в метаданных для backoffice, публичные переводы без изменений.
- `UserOperationalPermissionEnum`, `GlobalOperationalPermissionManager`, `StaffPermissionProfiles`, `UserOperationalPermissionChecker`: опасный permission только с явным индивидуальным allow для ADMIN; у SUPERADMIN все права системные и неотзываемые.
- `GetAccountWalletOverview`: существующая проекция балансов и двухсторонней истории без миграций.

## Приёмка

- [ ] ЛК и админка показывают одинаковый баланс.
- [ ] У superadmin есть собственное пополнение с паролем, ошибка пароля без финансового побочного эффекта.
- [ ] Перевод пользователю уменьшает баланс источника и увеличивает бонусы получателя; оба видят операцию, исполнитель и основание фиксируются.
- [ ] Отрицательные сценарии: роль ADMIN без явного права; пользователь вне иерархии; недостаток средств; повторный submit; попытка списания с чужого superadmin.
- [ ] CI и PostgreSQL зелёные → merge в dev → успешный deploy_dev → ручная приёмка. Production не затрагивать.

## Ограничения

Вкладка отображает последние 100 завершённых операций (без экспорта или архивного пагинирования). Это первая версия. Бонусы — отдельный баланс; возможность переводить реальные средства не открываем.
