# Task 303 — Конструктор тарифных условий

## Назначение
Расширяет базовые цены и календарные тарифы Task 302, не заменяя существующий VenueSlotPricing. Сперва сумма по временным слотам, затем опубликованные правила в VenuePricingRuleEvaluator, затем неизменяемый VenueBookingQuote.

## Данные и версии
- venue_pricing_rules: rule_key UUID, version, status draft/published/archived. Опубликованную версию нельзя редактировать или удалять; новая версия — черновик, до публикации не влияет на стоимость. Публикация архивирует прежнюю.
- Поля: name, description, venue_id, optional court, is_enabled, priority, stop_processing, conditions JSON, operation, value, funding_source venue, published_by_user_id, published_at.
- venue_court_pricing_rule_overrides: исключение общеплощадочного правила для выбранного зала по стабильному rule_key, сохраняется и при смене версии.
- История и аудит через Auditable, immutable quote snapshot с base_amount_minor, amount_minor, rule_adjustments (rule_key/id/version, before/after/delta, funding).
- Плательщик скидки сейчас venue. Деление между MSKBA и коммерческими агентами — задача 304; внешние цены не дают права обещать скидку за счёт стороннего поставщика.

## Условия и расчёт
Условия: длительность (мин/макс), количество шагов, календарный диапазон, дни недели, местное время начала и конца (аренда целиком внутри интервала), whole/half, min_base_minor, конкретный зал. Пустое ограничение не действует. TZ площадки.

Операции: процентная/фиксированная скидка, процентная/фиксированная наценка, фиксированный итог, минимальный итог. Все значения — integer minor units, проценты basis points, округление half-up. Порядок: priority ASC, venue до court при равных приоритетах, id ASC. stop_processing прекращает цепочку. Отрицательной суммы нет; обязательная оплата не может обнуляться.

## Интерфейс
- ЛК: /account/venues/{venue}/pricing-rules; вход со страниц цен площадки и залов.
- Список, создание/редактирование черновика, публикация, новая версия без изменения опубликованного правила, исключение общих правил для отдельных залов.
- Инспектор расчёта без создания бронирования, показывает пошаговые изменения цены.
- Filament → Площадки → Тарифные условия и скидки: перечень, управление через общий конструктор и публикация.
- По MSKBA App UI Kit: панели, поля, чекбоксы, кнопки и адаптивная сетка из существующих компонентов. Никаких локальных декоративных стилей вне гайдлайна.

## Безопасность
Все операции требуют rental.policy.manage, для правил конкретного зала проверяется и permission на зал; проверка принадлежности объектов. Только декларативные операции, пользовательский PHP/JS/eval не исполняется. Публикация версионируется и аудируется.

## Приёмка
1. 2000 minor units за 120 мин → скидка 30% = 1400; 90 мин без изменения.
2. Черновик v2 со скидкой 10% не меняет текущие расчёты; после публикации новые котировки 1800, прежние хранят 1400.
3. Доплата отдельному залу +200; исключение общего правила влияет только на выбранный зал.
4. Приоритет и stop-processing, дата/день/время/формат, minor rounding, нулевой paid итог, некорректные значения, права 403.
5. Публичный кабинет и Filament desktop/mobile, ручная проверка гайдлайна.
