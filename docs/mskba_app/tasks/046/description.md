# 046 — Общий центр подписок, фильтры и единое правило собственного аватара

**Контекст:** визуальная приёмка задачи 286, 26.10.2026. Реализация через PR → CI → dev.

## UX
- Канонический SEO-friendly URL личного кабинета: `/account/subscriptions`. Прежний `/account/play-interests` редиректит на него для авторизованных, сохраняя старые ссылки. Имя маршрута `play-intents.mine` и JSON API `/account/play-intents` оставляем для внутренней совместимости.
- Заголовок «Мои подписки», интро нейтральное: «Управляй подписками, настраивай уведомления и следи за обновлениями в одном месте.»
- Вместо панели «Твои подписки» с кнопками «Хочу играть» и «Найти площадку» — панель фильтров: **Тип** (Все типы / Игровые подписки; другие типы появляются по мере внедрения реальных провайдеров), **Статус** (Все / Активные / На паузе / Истекшие / Отменённые / Выполненные), «Сбросить».
- Под списком — серверная пагинация, 10 записей на страницу; счётчик записей и навигация «Назад», номера страниц, «Далее» только если есть другие страницы. URL фильтров синхронизирован с query string, восстановление при reload/Back.
- Игровые подписки продолжают поддерживать редактирование, паузу, возобновление, подбор площадок и отмену в карточках; списки иных будущих подписок пока не имитируются.
- Сайдбар: отдельная нейтральная иконка уведомлений `#bell`, а не баскетбольный мяч.
- На карточке «Площадкой интересуются» аватар текущего подписанного пользователя виден ему самому даже при `show_on_venue=false`, другим показываем общий `#user`. Попап уже применяет viewer-aware projection; компактный блок должен использовать то же правило.

## API
- PlayIntentController::index принимает `type=all|play`, `status=all|active|paused|expired|cancelled|completed`, `page`. Проверка через Laravel validation, ограничение 10 на страницу, фильтры применяются на SQL до пагинации, `meta` содержит `current_page,last_page,per_page,total`.
- Только свои подписки (`user_id` канонического владельца). `expired` определяется по `status=active` и `expires_at <= now`. В `active` не входят истёкшие.
- Тип `play` — единственный реально поддерживаемый тип; в перспективе другие провайдеры смогут расширить выдачу. API сериализует `subscription_type:play`.
- Старые JSON API пути и CRUD остаются прежними.
- Ответственный frontend для live-пагинации использует те же фильтры, обновляет интерфейс после CRUD и не заставляет переписывать старые подписки.

## Acceptance
- Новый URL и хлебные крошки «Мои подписки»; старый URL 302/301 → canonical; страница требует логин.
- В сайдбаре иконка bell. Фильтр статуса действительно исключает чужие состояния, включая просроченные; тип «Игровые подписки» отображает PlayIntent.
- При 12+ подписках появляются 2+ страницы, нет дублей/пропусков, пагинация снизу.
- Скрытый self avatar в краткой карточке видит только владелец; попап не теряет приватность у остальных.
- PHP feature tests, frontend build, CI и dev deploy без воздействия на production.
