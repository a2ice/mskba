# 544 — Универсальные баннеры сущностей

## Согласованное поведение
Отдельный широкий баннер 3:1, никак не заменяющий логотип, фото/аватар или галерею.
Объекты: лига, сезон, турнир, команда, площадка, профиль пользователя (один баннер для всех игровых ролей).

## Технология
- Переиспользование таблицы `media`, polymorphic collection `banner`; дополнительные миграции не требуются — поля `original_path`, `original_disk`, `crop_applied` уже существуют.
- `HasEntityBanner` и `EntityBannerManager`: исходник приватно (`local`), публичная производная в оптимизированном `webp` на `public`, нормализованное кадрирование 0–1 с серверной валидацией.
- Оригинал не изменяется, следующий кроп заново рендерится из исходника; старые версии заменяются; удаление не касается других коллекций.
- Единый cropper: перетаскивание мышью/пальцем, масштаб 1–3×, сброс, предпросмотр 3:1. Сервер поддерживает JPG/PNG/WebP, до 10MB и 6000×6000 пикселей.
- Маршруты `entity-banners/{context}/{type}/{id}` и `/source`: авторизация на каждом запросе, источники только владельцам и делегированным редакторам.

## Права
- Filament: permission на редактирование конкретной сущности; для пользователя — существующий профильный RBAC; сезон принадлежит выбранной лиге.
- Публичные формы: команда `EDIT_SETTINGS`, турнир `MANAGE_DESCRIPTION`, площадка `EDIT` без текущей модерации, профиль — только свой, лига и её сезон — владелец.
- Наличие одного лишь права просмотра не разрешает загрузку, чтение оригинала или удаление.

## UI
- Filament tab «Баннер» в карточках лиги, сезона (при прямом доступе), турнира, команды, площадки, пользователя; для сезона внутри лиги — действие «Баннер» у строки сезона.
- Пользовательские настройки: команда, турнир, площадка, профиль; одну и ту же Blade/JS/CSS-компоненту используют оба контура.
- Публичные витрины: команда, турнир, площадка, пользователь. У лиг/сезонов интеграция с публичным каталогом будет в отдельном PR #542 (он всё ещё черновой и не попал в dev).
- Нет изображения → не отображаем пустой блок.

## Приёмка и ограничения
- CI, права owner/manager/outsider/superadmin, отсутствие произвольного чтения private original, валидность crop.
- Пока нет самостоятельного кабинета управления лигами, их публичный editor endpoint доступен собственнику через API и Filament; полноценный публичный маршрут/панель — следующий этап связанный с PR #542.
- Серверная модерация баннера площадки не добавляется отдельной сущностью: в пользовательском кабинете изменение блокируется, пока уже существует заявка на модерацию. В дальнейшем нужно увязать с VenueRevision, если заказчик ожидает отдельную очередь проверки баннеров на опубликованной площадке.
- Production не изменять без дополнительного распоряжения.
