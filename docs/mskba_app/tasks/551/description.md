# MSKBA — контрактное управление сущностями

## Согласованное решение

Публичная часть и бэк-офис используют независимые системы прав:

- Создание сущностей на публичном сайте регулируется глобальными операционными разрешениями.
- Редактирование конкретной сущности на публичном сайте регулируется действующим membership-контрактом этой сущности и набором зафиксированных permissions.
- Полномочия Filament для создания, изменения, удаления и модерации независимы от контрактов, глобальны.
- Создание объекта из бэк-офиса с выбранным владельцем автоматически формирует его контракт; при назначении другому человеку договор требует принятия.
- Владелец сезона по умолчанию — владелец родительской лиги, а не сотрудник, добавивший сезон.

Поддерживаемые типы: лига, сезон, турнир, команда и площадка. Контракты других пользователей получают индивидуальное название и строго ограниченный набор полномочий. Приглашённый пользователь принимает или отклоняет контракт. Передача владения требует отдельного подтверждения.

Подтверждённое коммерческое владение площадкой по-прежнему оформляется отдельной модерируемой заявкой. Контракт ответственного за карточку площадки не выдаёт финансовых и арендных прав.

## Изменения

1. Общий сервис EntityContractManager с контрактами владельцев в транзакции создания сущности.
2. Контекстные permissions для лиги и сезона.
3. Именованные делегируемые договоры, уведомления, акцептование, отзыв и процедура передачи владения.
4. Личный кабинет: кнопки принятия и отказа в «Мои контракты», страница управления назначениями.
5. Страница управления контрактами для активной темы mskba_app и совместимой mskba_dark.
6. Идемпотентная миграция уже созданных объектов с сохранением истории и ранее назначенных прав.

## Гайдлайн UI/UX

- Использовать стили и паттерны текущей темы и настоящие, привычные пользователю названия полей.
- Обязательны вертикальные отступы между плашками, секциями и текстовыми блоками.
- Элементы внутри одной текстовой строки выравниваются по вертикали.
- Не писать технические идентификаторы в пользовательских лейблах, подсказках и описаниях.
- Для действий использовать понятные названия: «Название контракта», «Полномочия», «Принять», «Отклонить», «Отозвать», «Передача владения».
- Не отображать коммерческие финансовые полномочия в редакторе обычных договоров площадки.
- Не дублировать таблицы и механизмы ACL: использовать существующие contracts, contract_memberships, contract_permissions.

## Проверка

- Backoffice EDIT действительно глобален и не зависит от контрактных полномочий.
- Новый владелец получает полный snapshot прав, но до принятия договора пользоваться ими не может.
- Лига и сезон имеют отдельные контракты; сезон по умолчанию закреплён за владельцем лиги.
- Команды и турниры создают владельческий контракт вместе с объектом.
- Делегирование чужих прав запрещено сервером, договор требует акцептования.
- Отозванные контракты не дают доступ, история сохраняется.
- Передача владения активируется только после согласия нового владельца.
- Неподтверждённая площадка не получает прав коммерческого владения.
- Новая страница рендерится в mskba_app без слипшихся секций.
- Перед слиянием в dev проходят PHP/JS CI и PostgreSQL migration checks.
