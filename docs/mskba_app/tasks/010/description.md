# 010 — Конфигурируемый Wizard и многошаговая регистрация

**Статус:** Визуальный образец принят; реализация Vue и backend ожидается · **Создано:** 2026-10-08 · **Проектная задача:** [#139](../../../tasks/139/description.md) · **Связь:** [008 — AuthDialog](../008/description.md), [009 — обязательный дизайн-гайдлайн](../009/description.md).

## Запрос пользователя

Разработать конфигурируемый, потенциально многократно используемый UI-компонент Wizard/Stepper для MSKBA App и применить его к регистрации внутри попапа. Первый выбор — роль («Выберу позже» допустимо); при роли «Игрок» последовательно предлагать пол и дату рождения, спортивные характеристики, затем ФИО. Для всех ролей ФИО можно пропустить. Последний этап — создание аккаунта. Назад/Далее, проверка обязательных полей, контекстная финальная кнопка, сохранение уже введённых данных при перемещении между шагами. У других ролей дополнительные ветки запланировать позже.

## Результат исследования

- В принятом [гайдлайне 1.0](../../../specification/ui-design-system.md) и каталоге `resources/themes/mskba_app/catalog/` **нет** утверждённого общего Wizard / Stepper. По [CaseRule15](../../../specification/agent-rules.md#caserule15---сверять-ui-с-гайдлайном-до-реализации-mskba-app) требуется согласовать визуальный/функциональный контракт перед созданием общего компонента.
- В legacy `mskba_dark` есть `event-wizard.js`, `account-confirmation-wizard.js`, `venue-create-wizard.js`; рассматривать их как сценарные референсы, **не** переносить jQuery/CSS старой темы напрямую.
- `RegisterRequest` уже принимает `role`, `first_name`, `middle_name`, `last_name`, `gender`, `birth_date` как необязательные поля; `username`, `password`, confirmation и `privacy_consent` обязательны. Роли из `UserParticipationRoleEnum`.
- Спортивные данные хранятся отдельно в `PlayerProfile`: `height_cm`, `weight_kg`, `body_type`, `experience_started_year`, позиции. Endpoint регистрации этих данных **не принимает** — нужен отдельный согласованный backend change, иначе пользователь введёт информацию, которая не сохранится.
- После регистрации текущий backend направляет на `account.privacy.distribution` (экран новой темы ещё не перенесён).

## Предложение по шагам регистрации (проект)

| Шаг | Когда показывать | Поля / действие | Правило |
| --- | --- | --- | --- |
| 1. Роль | Все | Выбор из сгруппированных вариантов или отсутствие выбора | Пустой выбор → «Пропустить», выбранная роль → «Далее»; крестик сбрасывает выбор |
| 2. О себе | `role=player` | Пол, дата рождения | Необязательные; можно «Пропустить» |
| 3. Спортивные данные | `role=player` | Рост, вес, позиция, телосложение, начало опыта (предложение, подлежит согласованию) | Необязательные; валидация введённых значений, даже при частичном заполнении |
| 4. ФИО | Все | Фамилия, имя, отчество | Необязательные; можно «Пропустить» |
| 5. Аккаунт | Все | Логин, пароль, подтверждение, privacy consent | Обязательные; финальное действие «Создать аккаунт» |

При других ролях пока только 1 → 4 → 5. Для `role=null` тоже 1 → 4 → 5. Нельзя пропустить шаг создания аккаунта или обязательное согласие.

## Предлагаемый общий контракт и поведение

- Предлагаемые компоненты: `WizardShell.vue` (текущий шаг, навигация, прогресс, ошибки), отдельные step-компоненты/slots; конфиг сценария регистрации вне общего компонента. Названия/API — **черновик на согласование**, без создания UI.
- Декларативный конфиг: устойчивый `id`, `title`, `visibleWhen(form)` либо enum зависимости, `fields`, `optional`, `validateOnNext`, `component/slot`; список шагов вычисляется из текущих значений. Для кнопок: `backLabel`, `nextLabel`, `skipLabel`, `submitLabel`, `busyLabel`, `onSubmit`.
- `Back` не валидирует шаг и не сбрасывает данные. `Next` проверяет заполненные обязательные поля текущего шага и формат предоставленных необязательных; `Skip` пропускает только необязательные шаги. Ошибка — рядом с полем с переходом фокуса.
- Форма живёт в едином реактивном state выше шагов, значения сохраняются при unmount/mount содержимого, смене шага и назад-вперёд; при смене роли видимые шаги пересчитываются, скрытые player-specific значения не отправляются для другой роли. Судьбу введённых данных при смене роли согласовать отдельно.
- Индикатор прогресса считает **только видимые** шаги, на mobile не допускает горизонтального overflow; кнопки `Назад`, `Далее` (или `Пропустить`), финальная `Создать аккаунт`, busy/error состояния. Доступность: семантические заголовки, текущий шаг, фокус, aria-live, клавиатура, reduced-motion, скролл содержимого.
- Не сохранять пароли в localStorage/sessionStorage. Сохранение между шагами — in-memory; сохранение после закрытия попапа / обновления страницы пока **не требуется**, требует отдельного UX и privacy решения.
- На заключительном submit — единый POST регистрации с серверной валидацией; для спортивных данных согласовать расширение DTO/request/use-case и атомарную запись профиля игрока в той же транзакции без потери данных. Сценарий восстановления согласий и редиректа сохранять.

## Уточнения пользователя и интерактивный образец — 2026-10-08

Пользователь **согласовал предложенные пять спортивных полей и порядок
зависимых шагов**, добавив требования:

- Для каждого шага может быть общая контекстная подсказка; отдельные поля
  и варианты/опции могут иметь собственные подсказки.
- Если у текущего шага **нет обязательных полей**, основная кнопка называется
  **«Пропустить»**; если есть хотя бы одно обязательное — **«Далее»** и
  проверяется заполненность и корректность. Последняя кнопка зависит от
  сценария, для регистрации **«Создать аккаунт»**.
- Передвижение назад/вперёд не должно терять данные. Валидатор работает с
  полями текущего шага. Ошибка показана снизу под полем с фокусом; 422 из
  backend должен находить нужный шаг по полю, переключать и фокусировать.

Подробный предлагаемый контракт и возможная неоднозначность семантики
«Пропустить» при уже введённых значениях записаны в
[проекте контракта](wizard-contract.md).

**Подготовлен рабочий прототип для визуального согласования:**
[Wizard proposal](../../../../resources/themes/mskba_app/catalog/wizard-proposal.html),
локальная ссылка `http://127.0.0.1:8014/catalog/wizard-proposal.html`.
Отдельные CSS/JS находятся рядом с HTML в каталоге и **не импортированы**
в рабочую тему. Демонстрирует динамические роли, подсказки, проверку
необязательных введённых значений, условные шаги, Back/Skip/Submit,
ошибки под полем, фокус и эмуляцию серверной 422.

Headless Chromium: **PASS** на 360, 390, 440, 768, 1440 px:
условные 3/5 шагов, сохранение данных при Back/Forward, валидация,
переход и фокус по смоделированной серверной ошибке, отсутствие JS ошибок
и горизонтального переполнения. Финальная отправка в образце отключена,
реальный backend не менялся.

**Необходимо одобрение пользователя** визуального образца прежде, чем
создавать общий Vue Wizard и включать его в новую ревизию гайдлайна.
Принятая версия 1.0 не изменена.

## Доработка выбора роли — 2026-10-08

По просьбе пользователя в отдельном интерактивном образце изменён первый шаг:

- Текст общей подсказки: **«Вы можете выбрать роль сразу и в будущем её изменить или добавить новую.»**
- Добавлены две взаимоисключающие раскрывающиеся группы: **«Основные»**
  (Игрок, Тренер, Судья, Представитель площадки) и **«Другие»**
  (Медиа (блогер), Статист, Организатор мероприятий).
  По умолчанию открыта группа «Основные».
- **Историческое решение, пересмотрено позднее:** первоначально «Выберу позже» было отдельной радиоопцией; в актуальном прототипе вариант **убран** — его заменяет «Пропустить». См. раздел ниже.
- Открытие одной группы закрывает другую; при закрытии панели
  выбранная роль не сбрасывается и показывается в кратком описании
  закрытого заголовка группы. Роль остаётся единственным значением
  `role` из существующего backend enum; название «Медиа (блогер)»
  отображается только в UI и не меняет `media`.
- Проверено в headless Chromium при 360, 390, 440, 768 и 1440 px:
  только одна раскрытая группа, сохранение роли, переход назад,
  пересчёт 3/5 шагов, восстановление начального состояния и отсутствие
  JS-ошибок/горизонтального переполнения.
- Это **уточнение образца**, а не утверждение общего Vue Wizard.
  Версия гайдлайна 1.0 и реальная форма регистрации не менялись.

## Изменение выбора роли — уточнение пользователя 2026-10-08

Актуальный вариант для первого шага (заменяет отдельный пункт «Выберу позже» из предыдущего раунда):

- При открытии мастера роль **не выбрана**, раздел «Основные» открыт,
  основная кнопка показывает **«Пропустить»**. Пропуск = `role=null`;
  отдельной радио-опции «Выберу позже» **больше нет**.
- После выбора любой роли обе группы **автоматически сворачиваются**.
  Выбранная роль отображается в заголовке своей группы:
  `Выбрано: Игрок` / `Выбрано: Медиа (блогер)` и т. д.
- Рядом с выбранной ролью появляется отдельная доступная кнопка
  **«×»** (Tabler Close) для сброса. Нажатие снимает выбор,
  раскрывает соответствующую группу для нового выбора,
  возвращает основную кнопку в **«Пропустить»** и пересчитывает
  количество шагов (например, игрок: 5 → без роли: 3).
- **Первоначальное решение уточнено позднее:** в раунде проверки выбор роли переключал кнопку в «Далее» через `nextLabelWhenFilled`. По следующему замечанию пользователя правило распространено **на все необязательные шаги**: пустые поля → «Пропустить», заполнено любое поле → «Далее»; отдельный ключ больше не требуется. См. новый раздел ниже.
- Уже введённые данные сохраняются при Back/Forward и смене/сбросе роли;
  при отправке для роли, не относящейся к игроку, скрытые поля
  PlayerProfile не должны передаваться.
- Визуальная реализация изменения выполнена только в
  `wizard-proposal.html/.css/.js`. Родительский `WizardShell.vue`,
  backend-регистрация и утверждённая версия гайдлайна 1.0 пока не изменялись.
- Headless Chromium: **PASS** на 360/390/440/768/1440 px.
  Проверены пустой выбор, авто-сворачивание, выбранная подпись,
  доступный крестик, обратный сброс, пересчёт шагов,
  Back/Forward, reset, отсутствие JS ошибок и горизонтального overflow.
  Дополнительно проверен имитированный 422 для `role`: ошибка появляется
  под группами выбора, нужная группа раскрывается, фокус на видимом radio.
  Общие тесты валидации и возврата к ошибочному полю также пройдены.

## Уточнение расположения сброса и обязательных полей — 2026-10-08

В рамках визуальной приёмки [Wizard 010](../../../../resources/themes/mskba_app/catalog/wizard-proposal.html)
пользователь попросил:

- Разместить кнопку сброса **не на противоположном конце заголовка группы**,
  а **непосредственно рядом с выбранным вариантом**, сохранив независимую
  интерактивность кнопки и native `details/summary`.
- Убрать из общего footer строку «Поля со звёздочкой обязательны.
  Остальное можно заполнить позже.». Вместо общей подписи,
  каждый обязательный `*` снабдить локальной подсказкой
  **«Обязательное поле»** в тематическом стиле.
- Подсказки должны быть доступны на hover и focus (с задержкой 200 мс),
  закрываться по Escape и не заменять валидацию/сообщения об ошибке.

**Реализация:** статус «Выбрано: …» и отдельная кнопка-крестик
теперь находятся в одном flex-блоке `.wizard-role-picked` с зазором
6 px; кнопка остаётся вне `summary`, чтобы сброс не раскрывал группу
случайно. Для длинной роли текст сокращается троеточием; полная роль
остаётся в aria-label соответствующего `summary` и кнопки сброса.

Во всех четырёх обязательных отметках шагов «Аккаунт» добавлены
`data-tooltip="Обязательное поле"`, `tabindex=0`, `aria-label` и
CSS hover/focus-подсказка. Общий footer note удалён, экран не теряет
семантику `required`. Это пока часть **интерактивного образца**:
при переносе в Vue использовать общую Tooltip-компоненту из
утверждённой дизайн-системы, не копировать прототипный CSS как отдельный паттерн.

Chromium: **PASS на 360×640, 390×844, 440×956, 768×780, 1440×900**.
Крестик визуально расположен в **6 px** от выбранного значения,
все четыре подсказки показываются при focus и скрываются после Escape,
кнопки выбора/сброса и адаптивность не сломаны. Остаётся визуальное
подтверждение пользователя.

## Глобальное правило кнопок и удаление дублирующей подсказки — 2026-10-08

По итогам визуальной проверки второго шага пользователь уточнил:

- **Любой необязательный шаг:** когда все значения пустые — «Пропустить»;
  как только хотя бы одно поле заполнено — «Далее»; при очистке всех
  значений кнопка автоматически возвращается к «Пропустить».
  Правило одинаково для роли, пола/даты рождения, спортивных характеристик
  и ФИО; специальный `nextLabelWhenFilled` удалён из прототипа/контракта.
- **Обязательный шаг:** «Далее» независимо от заполненности; на последнем
  — сценарная кнопка **«Создать аккаунт»**.
- При попытке перехода валидируются **все заполненные значения**, включая
  необязательные. Невалидное значение не пропускается: ошибка под полем,
  фокус на нём, переход блокируется. Back/Forward сохраняют состояние.
- Повторная подсказка под полем **«Дата рождения»** удалена:
  «Необязательно. Поможет подобрать подходящую игру по возрасту».
  На втором шаге достаточно существующего верхнего пояснения.
  Проверить все последующие поля на подобные дубли при финальной приёмке.
- Новая логика выполняется через общую функцию `updateNextButtonLabel()`
  при input/change и при рендере шага, без отдельного флага шага.

**Тестирование:** headless Chromium на 360×640, 390×844, 440×956,
768×780, 1440×900: живое переключение кнопки для всех необязательных
шагов, очистка каждого типа поля, невалидная дата с ошибкой/фокусом,
сохранение значений при Back/Forward, смена роли и мобильная ширина —
все проверки прошли. Реальный компонент Vue и backend пока не затрагивались.

## Анимация внимания на кнопке «Далее» — 2026-10-08

По отдельной просьбе пользователя исследован эффект из старой темы
`mskba_dark/css/pages/home-flow-navigation.css` и
`mskba_dark/js/features/home-flow-navigation.js`:
`home-flow-next-pulse` (масштаб) и `home-flow-next-shine`
(диагональный светлый блик слева направо), обе анимации по 700 мс,
`ease-in-out`, запускаются при явном выборе.

**Реализовано только в неутверждённом интерактивном образце Wizard 010:**

- Основная кнопка `#wizard-next` на этапе «Далее» получает временный
  `is-choice-attention`; анимация повторяется при новом выборе роли,
  пола, игровой позиции, опции и при первом переходе текстового ввода
  «все поля пустые» → «есть значение».
- Ни обычный `Back/Forward`, ни открытие шага, ни «Пропустить»/финальная
  «Создать аккаунт» анимацию не запускают. Нет повторения на каждый символ.
  Завершение CSS-анимации удаляет временный класс, новое изменение
  может перезапустить эффект.
- Длительность и диагональный блик соответствуют legacy; исходные 110%
  пересекались с «Назад» на узкой сетке. Масштаб уменьшен до **106% до
  480px**, **107% на больших экранах**, чтобы кнопки не накладывались.
  При `prefers-reduced-motion: reduce` анимация не запускается.
- CSS и JS остаются в каталоговых `wizard-proposal.*`, без импорта в
  продуктивную тему. После визуальной приёмки эффект описан в утверждённом
  [контракте Wizard 1.1](../../../specification/ui-design-system.md#wizard-11--принятый-визуальный-контракт).
  Продуктовый общий компонент для эффекта ещё не создан.

**Статус:** анимация и интерактивный образец **визуально приняты пользователем 2026-10-08** («да, выглядит супер — принимается»). Проверены форма, тайминг, масштаб, блик, расстояние до «Назад», сброс, смена опций и reduced-motion в Chromium на 360/390/440/768/1440 px.
