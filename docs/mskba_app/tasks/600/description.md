# MSKBA — 600. Кэш изображений и повторный LQIP на главной

## Основание

При обычном обновлении главной браузер снова показывал LQIP, затем оригиналы.
Это выглядело как повторная загрузка даже ранее посещённой страницы.

## Первопричины

- Динамические оригиналы `/media/site/{uuid}` и миниатюры `/lqip` отдавались с `Cache-Control: public, no-cache, must-revalidate`: при каждом визите требовалась HTTP-проверка.
- У статических `/images/*` отсутствовал явный срок свежести, поэтому браузер не мог гарантировать повторное использование без обращения к серверу.
- Сам Page Builder каждый раз отдавал `img src` из LQIP и заменял его на оригинал только после выполнения JavaScript. При тёплом кэше пользователь всё равно видел ту же двухэтапную картинку.

## Решение

1. Для Media Library добавлена ограниченная свежесть `max-age=300` и `stale-while-revalidate=3600`, ETag/304 остаются. URL медиа изменяемые: **immutable не назначается**.
2. Nginx кэширует публичные статические изображения 7 дней, а только хешированные файлы Vite — год с immutable.
3. Page Builder сразу выдаёт оригинал в `img src` и `picture/source srcset`; LQIP — встроенный фоновый placeholder на том же изображении. При успешном декодировании оригинала фон очищается. Ни одного принудительного JS-переписывания `src` в LQIP.
4. Авторский `background-image` не перезаписывается: для CSS-сцен оригинал находится поверх миниатюры в `background-image`, а остальные стили не изменяются. Динамические фоны получают такую же схему.
5. Убраны старые `noscript`-правила, которые скрывали изображения без JS.

## Риски и границы

- Картинки не загружаются повторно как полноразмерные данные, пока кеш актуален, однако обычный Reload/Hard Reload, DevTools Disable cache и обновление версии медиа могут вызвать условный запрос или реальную загрузку.
- Изменение изображения в медиатеке может быть не видно мгновенно в уже открытой вкладке из-за короткого TTL; при необходимости выполняется принудительное обновление.
- CSS-запросы, другие страницы, интерактивные элементы, позиции мяча/игроков и порядок слоёв не изменяются.
- Архивные и авторские inline-background правила сохраняются.

## Проверка

1. Cold start: главная появляется с быстрым LQIP там, где оригинал ещё не декодирован; отсутствует пустая промежуточная фаза.
2. Повторное обычное обновление: original `src` не заменяется на LQIP, картинки берутся из HTTP-кеша.
3. В DevTools Network проверить заголовки `Cache-Control`, ETag и размер передачи повторных запросов. Для `/images/...` в ответе Nginx должен быть `max-age=604800`.
4. На мобильном `picture` автоматически выбирает оригинал в `srcset`, независимо от LQIP.
5. С отключённым JS оригиналы продолжают отображаться, нет скрытых изображений.
6. Все PHP/JS тесты, сборка и проверка Nginx, затем CI dev и фактические HTTP-заголовки на сервере.
