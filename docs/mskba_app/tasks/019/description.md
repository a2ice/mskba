# 019 — Ненавязчивый онбординг в модалке кабинета + будущие каналы уведомлений

**Дата:** 2026-10-09 · **Ветка:** feature/139 · **Статус:** Реализовано локально, на визуальной приёмке; без коммита и push.

## Решение пользователя

Вместо обязательного редиректа на /account/privacy/distribution:
- После создания аккаунта и при повторном входе переходим в обычный кабинет (или безопасный запрошенный маршрут), отображаем поверх него модальный onboarding, предлагающий завершить регистрацию.
- Онбординг можно закрыть; просмотр обычных GET страниц не блокируется. При последующем действии, изменяющем данные, незавершённому пользователю снова показывается модалка.
- Backend обязан гарантировать отсутствие любых побочных эффектов, пока завершение не зафиксировано. Защита не должна зависеть от UI.
- При успешном завершении возвращаемся к отложенному действию и выполняем его **однократно** после серверного подтверждения, не до него; запрещены автоповторы опасных/неизвестных операций.
- Реальная форма приватности и согласие остаются теми же, что на принятой странице. Единый источник разметки; состояние сохраняется сервером. В попапе — заголовок, ограничение <=90dvh, scrollable body, fixed footer, esc/backdrop/крестик, focus.
- Добавить демонстрационную секцию «Отправлять уведомления на»: для уже подтверждённых контактов — отмечаемый канал, для отсутствующих — кнопки «Добавить почту», «Добавить Telegram», «Добавить VK». Визуальные поля для добавления и обозначение будущего OTP, без реального отправления кодов, сохранения/подключения контактов или видимости, будто действие выполнено. Ни одно значение демо-полей не сохраняется.
- Для JS-off/сбоя модалки оставить доступную прямую страницу завершения регистрации, без обхода серверной защиты.

- Для темы mskba_app: после новой регистрации и входа открывается /account с настоящей страницей кабинета и sidebar. Поверх — закрываемое окно настройки приватности. Пока onboarding не завершён, пользователь может просматривать GET-страницы, но любые защищённые мутации блокируются backend.
- Обычные формы и fetch same-origin с изменяющими методами ожидают завершения. После закрытия окна действие отменяется без отправки, после успешного подтверждения выполняется один раз. Для других API/XHR клиентов сервер возвращает HTTP 409 (ONBOARDING_REQUIRED); подключение фронтового обработчика при последующей миграции Vue/Inertia — техдолг.

## Что проверить вручную

1. На localhost зарегистрировать новый аккаунт и увидеть /account с открытой модалкой.

5. Перезайти в кабинет: завершённому аккаунту попап не должен показываться.

## Исправление повторного автопоказа между вкладками — 2026-10-09

- **Симптом:** после закрытия окна в одной вкладке пользователь с незавершённым онбордингом переходил в новой/дублированной вкладке на `/account/` и видел лишь плашку. Дублированные вкладки могут унаследовать `sessionStorage` исходной, включая `mskba-onboarding-dismissed`.
- **Решение:** `sessionStorage` больше не используется для подавления автопоказа. Пока серверный флаг незавершён, каждый новый заход на маршрут кабинета автоматически предлагает модалку; закрытие влияет лишь на текущий открытый документ. На остальных GET-страницах попап не открывается без действия; изменяющие операции по-прежнему защищены и вызывают его повторно.
- Удалён ненужный `data-user-key` из Blade-root.
- **Браузерная регрессия Chromium:** 320/440/768/1440 PASS. Смоделировано наследование старого `sessionStorage`, затем последовательность `/account/` → закрыть → другая GET-страница (без автоматического показа) → `/account/` → закрыть → reload → отдельная вкладка `/account/`. Во всех нужных состояниях попап открыт. Vite build и `node --check` PASS.
- Commit, push, PR, merge, deploy не выполнялись. Ожидается визуальная приёмка.

## Уточнение приёмки 2026-10-09 — автопоказ внутри кабинета

- По замечанию пользователя попап **автоматически открывается при каждой новой загрузке GET-страницы внутри `/account` и `/account/*`**, если сервер всё ещё требует завершить регистрацию. Предыдущее ограничение только маршрутом `/account` отменено для страниц кабинета; вне кабинета обычные GET-страницы не блокируются и не вызывают автопоказ.
- `/account/privacy/distribution` является исключением: полноценная отдельная форма остаётся fallback без самоперекрытия тем же диалогом, включая случай flash `onboarding_required`.
- Закрытие попапа действует только в текущем документе; новый переход снова предлагает завершить регистрацию. Запись приватности и повтор защищённых мутаций допускаются лишь после серверного подтверждения по прежнему контракту.
- PHPUnit проверяет автопоказ на обзорной странице, profile/wallet/roles/notifications/settings, отсутствие автопоказа на самостоятельной странице приватности и на публичных страницах. На визуальной приёмке; без commit/push/PR/merge/deploy.

- Финальный прогон приёмочных исправлений 019/021: 25 PHPUnit / 194 assertions PASS (включая форсированный flash на отдельной privacy-странице), Pint/Blade/JS/Vite/`git diff --check` PASS.
