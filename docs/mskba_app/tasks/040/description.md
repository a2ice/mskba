# 040 — Техдолг: шорткоды сущностей в сообщениях

**Статус:** запланировано, код и миграции не создаются.

## Цель

Пользователь может сослаться в сообщении на **доступную ему сущность** MSKBA: игру, тренировку, мероприятие, команду, площадку и т. д. Не загружать файлы и не сериализовать HTML в сообщения. Визуально — компактная карточка сущности внутри привычного сообщения; в поле composer — селектор с поиском и вставкой шорткода.

## Предварительный контракт для согласования

- Предлагаемый формат: `[mskba:game:123]`, `[mskba:event:124]`, `[mskba:place:456]`, `[mskba:team:789]`. Точный синтаксис и множество типов **согласовать при реализации**, не считать их уже утверждёнными API.
- Хранить исходный текст, а не подготовленный HTML. Парсер распознаёт только allowlist типов, экранирует текст, не исполняет произвольные HTML/URL/скрипты, неизвестные токены остаются текстом.
- **ACL в двух местах**: пользователь вправе приложить сущность в момент вставки, и каждый получатель/участник переписки должен иметь право читать её в момент открытия сообщения. При изменении видимости показывать безопасную заглушку без названия, превью, фотографий и других закрытых метаданных.
- Не делать N+1: собрать `{type, id}` по странице сообщений (включая lazy cursor по 10), получить типизированные данные пакетами (например, сервисы/query/EXISTS), кэшировать лишь с учётом области видимости и инвалидации.
- Обязательно предусмотреть удалённую/скрытую сущность, устаревший ID, тип с приватным доступом, изменённые права участника, отсутствие адресата, мобильные и Telegram Mini App, авторизацию WebSocket (не передавать закрытые карточки прямо в event payload).
- Составить независимый контракт сериализации и тесты на XSS, ACL, смену приватности, конкурирующую отправку и производительность. Не связывать модель ссылок только с личным direct-чатом: тот же renderer должен работать в тредах заявок/поддержки и контекстных чатах.

## Не входит в задачу 039

На текущем этапе не добавлять кнопку скрепки, autocomplete сущностей, таблицу вложений, UI карточек и изменения схемы сообщений. Это план следующего этапа после приёмки тестового чёрного списка и определения правил контекстных чатов.
