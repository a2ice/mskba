# #1039 — Множественный выбор типов площадок

DEV ONLY. Замечание владельца при приёмке: нужны одновременно «Спортзал» и «Спорткомплекс», а также отсутствие ограничения по типу.

- Filament: штатный Select multiple с placeholder «Все типы»; очистка всех значений снимает условие. В обычном каталоге обеих тем: компактный раскрывающийся список чекбоксов, summary показывает выбранные названия или «Все типы». Отправка штатным GET, без JS выбор работает; мобильный badge считает группу как один фильтр. Сохраняются map, sort, page, fragment и legacy search. Пустой набор не равен обязательному выбору одного значения.
- Типы объединяются по OR, остальные фильтры пересекаются по AND. Сохраняется прежняя семантика: «Спортзал» = наличие подходящей indoor-зоны, «Уличная площадка» = outdoor-зоны, «Спорткомплекс» и остальные = тип паспорта площадки. Следовательно спорткомплекс может иметь и уличные зоны; выбор пары сам по себе не гарантирует indoor-only. При access/rental проверяется реальная подходящая зона, не дублируются карточки. Отдельный независимый фильтр indoor-only для произвольных паспортных типов не вводится этим PR.
- GET поддерживает старый type=sports_hall и массив type[]=sports_hall&type[]=sports_complex. Нормализация убирает дубликаты и сортирует набор; одиночный набор имеет прежнее представление и SHA-256 signature, пустой — отсутствие условия. Запрещены неизвестные значения и не-списки. Точное сопоставление, unique активных наборов, slug и приватность черновиков сохраняются.
- Аддитивная nullable JSON колонка type_choices для двух и более значений; прежняя type остаётся для одиночного. Без backfill, без потери текущих настроек. Rollback запрещён при наличии multi-type записей до явной конвертации, чтобы не расширять выдачу незаметно. Только штатная dev migration.
- Тесты: OR, отсутствие дублей, старый URL, пустой выбор, map/fragment, обе темы, сохранение и очистка в редакторе, unordered exact match и DB unique. Визуально проверить desktop/mobile в обеих темах, компактность dropdown, очистку выбора и мобильный счётчик. Не считать CI визуальной приёмкой.
- Не менять main, публичный feature gate, robots/sitemap, внешние сервисы и booking/payment.
