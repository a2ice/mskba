# Площадки: безопасный HTML в полном описании

Дата: 23 ноября 2026 года. Маршруты: `/venues/{venue}` и `/venues/{venue}/courts/{court}`; темы `mskba_app` и `mskba_dark`.

## Проблема

В форме Filament «Полное описание» сохраняет HTML, но публичный шаблон выводил его через экранирующее Blade-выражение `{{ }}` внутри `<p>`. Теги `<h3>`, `<h4>`, `<ul>` и `<li>` отображались пользователю буквальным текстом; `<p>`-обертка также некорректна для блочной HTML-разметки.

## Решение

- В обеих публичных темах полный текст выводится внутри `<div>` после очистки существующим `ContentBodySanitizer` (белый список HTML и безопасных атрибутов). Сырой HTML без санитайзера не публикуется.
- Сохраненные в базе данные не перезаписываются и миграция не нужна.
- Стили контента изолированы контейнером описания: заголовки, абзацы, списки, ссылки и переносы строк для обычного текста.
- Краткое описание и прочие поля не меняются.

## Проверка

- На странице площадки №11 HTML-заголовки, абзацы, списки и их элементы отображаются как разметка, а не как строки с тегами.
- На странице конкретного зала родительское описание отображается аналогично при отсутствии собственного переопределения.
- `<script>`, обработчики событий и небезопасные схемы ссылок не проходят санитайзер.
- Тест: `php artisan test --filter=VenueCourtDetailInheritanceTest`.

## Уточнение по пробелам (23 ноября 2026)

Исправлен дополнительный дефект: общий стиль `white-space: pre-line` сохранял переносы строк между HTML-блоками и визуально создавал большие интервалы между заголовками, абзацами и списками. Теперь для безопасного HTML с блочными элементами используется `white-space: normal`, а для описаний без блочных тегов с помощью CSS `:has()` включается `pre-line` (обычные текстовые переносы строк). Логика определения разметки в Blade отсутствует. Изменение сделано в обеих темах.
