# Cookie notice & optional analytics — 2026-11-14

## Задача

Фиксированное уведомление по образцу пользователя, но строго на токенах действующей темы MSKBA:
не создавать отдельный визуальный дизайн. Удерживать содержимое в общем `.container` проекта
(ширина 1280px на десктопе, текущие адаптивные поля; фоновая полоса — на всю ширину экрана).
В старых темах используется их штатная ширина `.inner`. Не перекрывать работу сайта
модальным backdrop; мобильные кнопки переносятся в колонку.

## Поведение

- Первое посещение: внутренняя аналитика MSKBA выключена, доступны явные «Только необходимые» и «Принять все». Яндекс Метрика независима.
- POST `/cookie-consent`: CSRF, валидация выбора `accepted/rejected`, журнал аудита и сохранение актуального состояния.
- **Авторизованный пользователь**: выбор хранится за канонической учётной записью в `user_cookie_consent_preferences`. Действует на новых сессиях и устройствах, пока версия уведомления не поменяется или пользователь не изменит выбор. Гостевой выбор на авторизованного пользователя не наследуется.
- **Гость**: выбор хранится 365 дней в зашифрованной сервером host-only cookie `mskba_guest_cookie_consent_v2` (Secure, HttpOnly, SameSite=Lax). Не зависит от Laravel-сессии. При истечении срока, удалении cookie или смене версии требуется новый выбор. Старые cookie и сессионные решения не переносятся.
- Аудит `cookie_consent_events` по-прежнему сохраняет visitor UUID, пользователя (если есть), решение, версию, время, IP и user-agent. Плановая очистка доказательств старше 13 месяцев **не удаляет актуальную настройку аккаунта**; при миграции старые решения авторизованных пользователей переносятся из журнала в постоянные настройки. Обновление версии повторно открывает баннер.
- Яндекс Метрика (JS и noscript) подключается независимо от выбора на production-хосте с настроенным ID. Внутренняя статистика fingerprint и долговременная история live-просмотров требуют явного согласия текущей версии.
- «Настройки cookie» в футере позволяет отменить разрешение или изменить отказ.
  Необязательная аналитика не влияет на авторизацию, бронирования и другие сервисные функции.
- Единые подключение и поведение для `mskba_app`, legacy `mskba_dark`,
  `mskba_streetball` и `blank`. Без JS обычный POST формы остаётся рабочим.

## Компактный баннер — 20.11.2026 (Task 340)

Общий CSS всех тем уменьшает вертикальные отступы (10 px desktop / 8 px mobile), заголовок, текст и кнопки (36 px минимальная высота), не меняя содержание, безопасную зону и контракт согласия. Непрозрачность 0.9 по умолчанию, 1 при наведении или фокусе внутри; анимация отключается при prefers-reduced-motion. Гость получает баннер до явного решения; внутренняя аналитика остаётся opt-in. Проверка: обе темы, desktop/mobile, клавиатурный фокус, сохранение обеих кнопок выбора и отсутствие аналитики до согласия.

## Постоянное гостевое согласие — 22.11.2026

- Согласие и отказ гостя сохраняются в отдельной защищённой cookie на 365 дней; новая сессия сама по себе не открывает баннер.
- Настройки аккаунта и гостевого браузера изолированы. При авторизации используется только настройка аккаунта; её изменение не меняет гостевую cookie.
- Старые cookie не считаются согласием. После обновления гостю нужно выбрать один раз заново. Журнал аудита и контроль версии сохраняются.

## Разделение внешней и внутренней аналитики — 22.11.2026

Внешний счётчик включён независимо от решения баннера на индексируемых production-хостах; dev сохраняет изоляцию. AJAX больше не вызывает API Метрики. Внутренние долговременные fingerprint/история просмотров требуют согласия новой версии. Авторизация, аудит действий и краткоживущая live-presence работают без него. Предыдущий выбор относился к внешней аналитике, поэтому для новой области нужен новый явный выбор и гостям, и аккаунтам. Правовое основание внешней аналитики подлежит отдельной проверке.
