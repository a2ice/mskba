# 025 — Аккаунт: роли в проекте (MSKBA App)

Дата: 2026-10-09. Ветка: feature/139. Статус: на визуальной приёмке, local-only.

## Цель

Реализовать рабочий экран /account/roles в теме mskba_app, вместо текущей страницы-заглушки: показать все семь ролей участия, их описания, текущие активные роли и позволить выбрать несколько ролей, отключить все или вновь активировать старые.

## Границы и бизнес-правила

- Использовать существующие AccountParticipationRolesController::index/update, UpdateAccountParticipationRolesRequest и UpdateUserParticipationRolesHandler, не дублировать business logic во Vue/JS или Blade.
- GET/PATCH должны сохранять прежний контракт: PATCH account.roles.update, CSRF, массив roles со значениями 0/1 для **всех** ролей (включая случай без выбранных), возврат на account.roles и status. После обновления sidebar «Мой MSKBA» отражает активные роли без дублей.
- Для действующего onboarding-guard не создавать обхода: GET доступен для изучения, изменения до завершения регистрации должны оставаться защищены.
- Системные роли и операционные permissions не меняются; отключение роли участия не удаляет пользователей/команды/историю и не отменяет предметные договоры.
- Legacy mskba_dark должен использовать прежний шаблон и handler, без визуального рефакторинга.
- Не добавлять ссылки на отсутствующую страницу role details в mskba_app, если маршруты/представления отсутствуют.
- Только текущие UI-примитивы дизайна: panel/card, switch-label (44×24), button primary, neutral/error/success, focus-visible; одноразовая композиция без нового глобального компонента.
- Обращение на «ты» (CaseRule18).

## Первичная сверка

Старая тема уже использует контроллер и handler, который за одну транзакцию активирует/деактивирует enum-роли и повторно использует прежние строки. AccountMenu новой темы строит «Мой MSKBA» из активных UserParticipationRole: при PATCH→redirect обновлённое меню отразит выбор. Новая страница остаётся presentation layer.


## Изменённое согласованное поведение (дополнение пользователя)

- Общего блока сохранения и кнопки «Сохранить роли» нет. Одна роль = одно изменение via AJAX. При клике карточка показывает загрузку и временно недоступна, после ответа сервера загрузка снимается.
- Уточнено 2026-10-09: после сохранения input блокируется на 5 секунд, рядом со switch идёт обратный отсчёт. Клики и запросы во время блокировки невозможны, отложенного сохранения нет; серверный per-user/per-role throttle остаётся защитой от обхода. Разные роли доступны независимо.
- При ошибке switch откатывается к последнему подтверждённому значению, пользователь видит ошибку, карточка вновь доступна.
- Для активных ролей под описанием — ссылка «Параметры», отдельно от label переключателя, ведёт на account.participation-role/{role}. В новой теме нужен маршрутный экран (ранее отсутствовал): пока правдивая информация о роли и указание, что редактирование её параметров будет реализовано отдельно.
- Серверный handler для отдельной роли расширяется переиспользованием транзакционной синхронизации; legacy массовый PATCH остаётся прежним.
- Группа «Мой MSKBA» после подтверждения обновляется из серверной разметки без полной перезагрузки кабинета.

## Визуальная регрессия: возврат фирменного switch и масштаб шестерёнки (2026-10-09)

- На скриншоте пользователь выявил, что после переноса иконки параметров тумблеры превратились в стандартные квадратные checkbox. Причина: интерактивный input больше не имел предка с классом switch-label; CSS из принятой дизайн-системы действует по селектору .switch-label input. Исправление: класс switch-label возвращён на контейнер app-roles__control (без вложенной ссылки в label), margin input обнулён. Новый тумблер не рисовался: повторно используется старый примитив.
- Шестерёнка уменьшена с 20 до 14px (атрибуты SVG и специфичный CSS для защиты от глобального размера SVG). Область клика 44x44px сохранена.
- Браузерная проверка Chrome с реальными CSS: appearance=none, checked #ff7900, unchecked #1d2023, псевдоэлемент ползунка присутствует, радиус 999px, input 44x24px. Шестерёнка вычисляется 14px, hit area 44px, включая mobile. Добавлена регрессионная feature-проверка наличия switch-label у всех семи ролей.
- Пятисекундный cooldown, серверное сохранение одной роли, aria-label, роль-параметры и layout карточек не изменялись. Локальная визуальная приёмка ожидается.

## Финальное решение по sidebar (2026-10-10)

Сохранена общая условная группа **«Мой MSKBA»** только для дедуплицированных функциональных разделов. Рядом, на **верхнем уровне** sidebar, для каждой активной роли появляется отдельная ссылка **«Игрок»**, **«Тренер»** и т. д. — она ведёт на экран параметров соответствующей роли (`account.participation-role/{role}`), как шестерёнка на карточке роли. Внутри «Мой MSKBA» ссылок на параметры больше нет. При отключении роли её ссылка исчезает, а sidebar автоматически обновляется существующим JS. Подробнее: Task 022, финально согласованное UI-правило.
