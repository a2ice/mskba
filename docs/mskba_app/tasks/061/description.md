# 061 — Контракты площадок: специализация и шаблоны permissions

## Цель и критерии приёмки
В `/account/contracts/venues` заменить «Специализация / тип площадки» на «Специализация»; выбирать специализации самой договорной связи, НЕ тип площадки. Начальные: администратор, менеджер, организатор, другое; проектные enum/preset permissions привязать к access level с корректным mapping существующих договоров. Пресет задаёт начальные permissions, выдающий/редактирующий может убрать или добавить только разрешённые права и сохраняет snapshot. Фильтрация по специализации должна использовать контракт, без утечки чужих membership. Продумать миграцию старых значений и сохранить owner/admin/manager capabilities.

## Технические границы
Сверить существующие venue contract membership, enum и шаблоны; ACL/делегирование не расширять автоматически. Требуются backend+frontend и тесты.

## Процесс
CI (PHP, JavaScript, сборка frontend, PostgreSQL 16/17) → PR/merge в `dev` → проверка развёртывания → визуальная приёмка владельца. `main` не затрагиваем. Следующий этап выполняется после приёмки текущего.

## Статус
Зарегистрирована, ожидает приёмки предшествующих задач.
