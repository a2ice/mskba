# 061 — Контракты площадок: специализация и шаблоны permissions

## Цель и критерии приёмки
В `/account/contracts/venues` заменить «Специализация / тип площадки» на «Специализация»; выбирать специализации самой договорной связи, НЕ тип площадки. Начальные специализации: **администратор, менеджер, организатор, промо, агент, другое**; проектные enum/preset permissions привязать к access level с корректным mapping существующих договоров. Пресет задаёт начальные permissions, выдающий/редактирующий может убрать или добавить только разрешённые права и сохраняет snapshot. Фильтрация по специализации должна использовать контракт, без утечки чужих membership. Продумать миграцию старых значений и сохранить owner/admin/manager capabilities.

## Дополнение от 29.10.2026

- Добавить две отдельные специализации договорной связи: **«Промо»** и **«Агент»**; они доступны в форме создания/редактирования контракта и фильтре по специализации наравне с существующими.
- Для новых специализаций предусмотреть собственные preset permissions на основе уже существующего каталога прав. **Не назначать автоматически расширенные полномочия**: итоговый snapshot формируется только из разрешённых выдающему прав. Семантику и конкретные права пресетов сверить с текущей моделью ACL на этапе реализации.
- Существующие контракты, роли и права не изменять только из-за добавления специализаций; неизвестные/устаревшие значения обрабатывать совместимо.

## Технические границы
Сверить существующие venue contract membership, enum и шаблоны; ACL/делегирование не расширять автоматически. Требуются backend+frontend и тесты.
