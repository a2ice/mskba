# 048 — Попап просмотра подписки и восстановление отменённых

**Дата:** 26.10.2026. **Основание:** визуальная приёмка MSKBA App 047. Выполнение: отдельная ветка → PR → полный CI → dev.

## Интерфейс

- Диалог **«Посмотреть»** в «Моих подписках» приведён к общей модальной дизайн-системе MSKBA. Ширина до 640 px, шапка с нейтральным заголовком, подписью раздела и статусом; секция «Параметры подписки» с двухколоночными строками; отделённый footer и компактные кнопки. На мобильных строка становится вертикальной, прокручивается только содержимое.
- В списке у `expired` и `cancelled`: **«Посмотреть»**, **«Восстановить подписку»**; кнопка восстановления есть также в попапе просмотра. У активных и приостановленных действия прежние, у завершённых доступен просмотр.
- При восстановлении ошибка показывается локально в карточке/диалоге, не заменяет весь список. Успех обновляет список, применённый фильтр и счётчик страниц, закрывает окно просмотра.
- Восстановление разовой подписки с утратившими актуальность датами открывает специализированный редактор для выбора новой даты. Нельзя активировать её кнопкой без проверки дат.

## Сервер

- `PATCH /account/play-intents/{id}/restore` принимает и **истёкшие активные**, и **отменённые** записи. Только владелец. Статус становится `active`, срок пересчитывается от текущего момента на 30 дней (`flexible`) или 90 дней (`regular`), в **той же записи**, без потери id, настроек, уведомлений, публичности, idempotency key.
- Однократные `once` нуждаются в новой дате через редактирование; `completed` не восстанавливаются. Блокировка строки и повторная проверка статуса исключают двойное продление.

## Проверки

- Feature tests: cancelled -> active с сохранением ID и параметров, запрет чужому владельцу, невозможность повтора/восстановления completed, once отменённый требует новой даты; существующие expired тесты.
- UI: в обеих точках «Восстановить подписку»; корректная разметка попапа, адаптивность desktop/mobile, никакой утечки полей.
- Только CI + PostgreSQL migration → merge в `dev` → подтверждённый deploy_dev. Production не меняем.
