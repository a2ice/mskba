# Расписание по залам и сценарий выбора аренды/избранного — 18.11.2026 (задача 331)

## Сценарий

- На общей странице площадки единая карточка «Расписание» делится на секции с названиями каждого зала/корта. Каждая секция содержит собственные 9 дней, часы, исключения и процент занятости с собственной интеграцией. На странице отдельного зала остаётся только его расписание.
- Нажатие дня передаёт идентификатор зала в штатный попап бронирования; внутри него дни и шкалы занятости переключаются в контекст того же зала, не смешивая данные соседних залов. Финальная доступность и стоимость приходят из существующего API.
- Шаг «Отличный выбор!» и шаг «Площадка в избранном» — native dialog в top layer по центру viewport. Header остаётся виден; тело прокручивается при раскрытии блока. На экранах меньшей высоты кнопки подтверждения остаются доступны.
- В подтверждении избранного нижняя вторичная кнопка «Назад» (без стрелки) заменяет «Отмена», возвращает на первый экран выбора аренды/избранного, не закрывая сценарий. Кнопки «Назад» в заголовке нет; крестик по-прежнему закрывает попап. Текст подтверждения при добавлении: «Добавь площадку в избранное, чтобы вернуться к ней позже.»
- Гостю перед подтверждением избранного показываем штатный диалог входа/регистрации. После inline-входа или возврата на страницу после регистрации восстанавливаем именно шаг подтверждения. Избранное **не добавляется** без нажатия финальной кнопки.

## Критерии

1. Два зала с разными часами/занятостью не смешиваются, включая обновление процентной шкалы после ответа API.
2. Открытие расписания из секции сохраняет зал; открытие со страницы зала показывает только его даты.
3. Попап не вылезает за край экрана при раскрытии блока; scroll внутри тела.
4. Гость → вход → возврат в подтверждение; отмена входа не сохраняет данные.
5. Проверки feature, JS, сборка и green CI перед merge в main.

## Hotfix 332 — восстановление сетки дней (18.11.2026)

После добавления `.app-venue-schedule__court` общая родительская секция
`.app-venue-block` с `align-items:flex-start` перестала растягивать
новый промежуточный контейнер по горизонтали. Поэтому существующая сетка
`grid-template-columns:repeat(auto-fit,minmax(145px,1fr))` получила ширину
одной карточки и все дни выстроились вертикально даже на desktop.

**Контракт:** каждый непосредственный `.app-venue-schedule__court` внутри
`.app-venue-block` должен иметь `align-self:stretch;width:100%;min-width:0`.
Внутри него остаётся прежний адаптивный grid: несколько карточек в ряд
на desktop, автоматический перенос на узких экранах. Изменять часы,
занятость и серверное расписание ради этой CSS-правки не требуется.

## Hotfix 333 — компактные карточки дат (18.11.2026)

Публичная плашка каждого дня показывает **только общий диапазон** от первого начала
работы до последнего окончания (`07:00–00:00`), даже если внутри дня есть
несколько рабочих интервалов и перерывы. Не выводим отдельные интервалы
в этой плашке и убираем подписи `Исключение: выходной` / `Исключение: изменённые часы`.
Если в этот день нет часов, сохраняем обычную подпись `Не работает`.

Исключения и перерывы **остаются в модели и API** и учитываются при выдаче
фактически свободных слотов в раскрывающемся диалоге бронирования. Ширина
и адаптивная сетка дат не меняются. Регрессионный feature-тест проверяет
день с двумя интервалами и отсутствие технических подписей.
