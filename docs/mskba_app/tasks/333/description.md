# Task 333 — Удаление аккаунта в настройках

## UI и принятый стандарт
- Кнопка «Удалить аккаунт» находится в последнем блоке страницы «Настройки», а не в профиле.
- В теме `mskba_app` используются стандартная карточка `panel app-settings-panel`, кнопка `button danger` и фирменный `dialog.mskba-modal` с шапкой, телом и подвалом.
- Диалог открывается через native `showModal()` в top layer, центрируется средствами общих стилей, не перекрывается sticky header, закрывается через «Отмена», крестик, backdrop и Escape.
- Запрос физически не может отправиться до подтверждения: кнопка в обычной форме имеет `type=button`; после «Да, удалить аккаунт» отправляется стандартная CSRF-защищённая DELETE-форма.
- Нет фокуса на статических заголовках или декоративных текстах: начальный focus направлен на интерактивную кнопку «Отмена».
- Кнопки используют существующий дизайн и мобильные адаптивные стили.
- На legacy `mskba_dark` также есть отдельный нативный диалог подтверждения на странице настроек; старый browser confirm убран из профиля.

## Сценарии проверки
1. Нажать «Удалить аккаунт», увидеть фирменное подтверждение и предупреждение о последствиях.
2. «Отмена», Escape, крестик и клик по подложке ничего не удаляют.
3. Подтверждение выполняет soft delete и перенаправляет гостя на главную.
4. На публичном сайте профиль пользователя после удаления недоступен.
5. Повторное нажатие не создаёт двойную отправку; в нативном диалоге кнопка подтверждения блокируется при отправке.
