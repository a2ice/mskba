## Цель

Первый функциональный экран ролевой навигации 022: роль игрока/тренера открывает «Мои команды» даже без членства. Действующие участники видят свои команды, статусы, приглашения и фильтры. Новые участники видят две временные кнопки с модалкой-заглушкой до решения по последнему шагу регистрации.

## Границы

- Переиспользовать AccountTeamsController (status, condition, created_only) и TeamController index/show (q, member_count, sport_type, hiring); не дублировать бизнес-правила.

- UI: принятые primitives panel, button, input/form, адаптивность. Старую тему и права доступа не менять.
- Тексты на «ты». Без локального коммита и операций с origin до отдельной команды.

2. «Приглашения в команду»: только ожидающие входящие приглашения, отдельно от принятых членств. Принять/отклонить через существующий обработчик teams.invitations.respond. Empty: «Новых приглашений нет».
3. «Заявки в команду»: отдельные собственные исходящие TeamJoinRequest по canonical identityIds. Все статусы pending/accepted/rejected/blocked, отдельная пагинация, ссылка на команду и ответ команды при наличии. Empty: «У тебя пока нет заявок на вступление в команды». Не показывать чужие заявки. История принятых заявок остаётся отдельной от членства в первой панели.

Изменения относятся только к новой теме и app-ветви AccountTeamsController; старый кабинет сохраняет поведение. UI использует общие panel/button/modal классы. Реальные экраны поиска/создания команды в проекте не удалены, но именно эти две кнопки к ним временно не ведут.

## Tooltip в предупреждении о регистрации (2026-10-09)

По уточнению приёмки добавлена иконка ? рядом с текстом «Для продолжения необходимо завершить регистрацию». Текст подсказки зависит от инициирующего действия:

- find: «Всего один простой шаг и мы вернем тебя к поиску команды».
- create: «Всего один простой шаг и мы вернем тебя к созданию команды».

Подсказка — внутри native dialog, доступна по hover, focus и touch/click, имеет role=tooltip, aria-describedby и aria-expanded. Esc закрывает только подсказку, закрытие диалога сбрасывает подсказку и возвращает фокус. Кнопки footer имеют 12px gap, заголовок предупреждения зависит от действия. Продолжение после регистрации остаётся неисполняющей бизнес-операций заглушкой.

Проверено в headless Chrome на Blade/JS/CSS fixture для find и create: корректный текст, фокус, tap, Esc, закрытие и focus return PASS. Ожидается визуальная приёмка на localhost.

## Исправление наложения подсказки (2026-10-09)

По визуальному замечанию пользователя подсказка больше не участвует в потоке документа и не меняет высоту модального окна. В CSS app-team-gate-tooltip использует position:absolute; её DOM-узел вынесен из .mskba-modal__body (прокручиваемое содержимое), оставаясь дочерним элементом native dialog. JS размещает подсказку над знаком ? и ограничивает координаты размерами модалки, обновляя положение при resize/scroll. Оформление соответствует образцу wizard-required-label из принятого UI-гайдлайна.

Chrome DOM-fixture с реальными Blade/JS/CSS на desktop и узком окне: до/после показа высота dialog, верхняя граница текста и кнопки не меняются; tooltip выше знака ?, внутри границ диалога. Варианты поиска и создания, focus и Escape — PASS. Далее — визуальная проверка на localhost. Без коммита, push, merge и deploy.
