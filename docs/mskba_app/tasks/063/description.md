# MSKBA App 063 — способы пополнения баланса

**Issue:** #519. **Основание:** приёмка 058, 30.10.2026.

## Сценарий

Вместо плоского информационного окна на /account/participation/player:
- вводная фраза и переход в кошелёк с балансом и историей;
- вкладки «За выполнение заданий», «Пополнение баланса», «Перевод от друга»;
- задания в режиме аккордеона, первая карточка открыта, при переключении другие закрываются; суммы и условия из активных Rewards;
- «Добавить площадку» — форма общая с /venues/create, геолокация/обратный адрес/метро/проверка дублей из существующего кода, базовые поля + необязательные характеристики и фото, серверное сохранение, затем управление;
- «Пригласить друга» — рабочая /r/{username} только для confirmed, копирование и системный Share/mailto;
- «Пополнение баланса» не подключено: никаких фиктивных платежей;
- «Перевод от друга» — поиск только по DISCOVERABILITY, PROFILE, CONFIRMED и новой настройке WALLET_TRANSFER_REQUESTS.

## Права и финансы

Новая настройка включена по умолчанию, её можно отключить в настройках. На сервере проверяется доступность адресата при получении подсказок и при фактическом POST. Запрос лишь создаёт финансовое уведомление, не списывает бонусы, с rate limit 1 запрос конкретному адресату в час плюс 5/мин общим throttle. Получатель переводит бонусы добровольно через прежний кошелёк/сервис.

## Площадки

В форме обязательны название, тип и подтверждённый адрес. Дополнительные: описание, фото, кол-во зон (1), кол-во колец (2), покрытие и платность. Зоны сохраняются в транзакции вместе с площадкой. Фотографии — отдельным существующим галерейным сервисом после создания; неудача фото не провоцирует повтор создания площадки. Модерация, выдача Rewards, anti-duplicate и разрешения остаются прежними.

## Проверки

Feature tests: privacy default/opt-out/прямой POST, уведомление без wallet-ledger, throttling, светлая тема и shared venue form. PR -> green CI/PostgreSQL -> merge dev -> автоматический deploy -> ручная приёмка. Main/prod не менять.


## Ревизия интерфейса от 30.10.2026 — приёмка

- Верхние три способа — не tablist, а такие же раскрывающиеся плашки, как задания: первое открыто, остальные закрыты; переключение закрывает другие, включая управление с клавиатуры через native details/summary.
- Задания вложены в первый раздел, открыто первое, остальные свёрнуты. В заголовках только название задания, без бонусной суммы.
- В открытом задании описание заменено на семантический список ключ/значение: «Вознаграждение: N баллов» и «Условие: ...»; сумма и условие получаются из действующей версии Rewards. Никаких «100,00 ₽ бонусами» в UI.
- Бэкэнд кошелька, финансовые расчёты, условия модерации и кнопки действий неизменны.


### Финальная защита реферальной ссылки — 30.10.2026

Подтверждённый пользователь, у которого пока нет `username`, не должен приводить к ошибке генерации `/r/{username}` при открытии попапа. Для такого пользователя показываем инструкцию и переход в профиль для установки логина. Только подтверждённым пользователям с валидным непустым логином выдаём копируемую ссылку; соответствующий регрессионный Feature test обязателен.


## Приёмка 30.10.2026 — финальная доводка внешнего вида

- Верхние три «За выполнение заданий», «Пополнение баланса», «Перевод от друга» изначально закрыты; вместо стрелки у каждой плашки фирменная оранжевая ссылка «подробнее», при открытии меняется на «свернуть». Остаётся нативный details/summary и взаимоисключающее раскрытие.

- Под заголовком «Генерация аватара» — короткий тизер предстоящих функций (командные фото, хайлайты игр, примерка и заказ кастомной формы), с честным разграничением текущего и будущего.
- В подписи к силуэту порядок данных в одной строке: «Пол → Рост → Вес»; переход к редактированию пола сохранён.
- Sticky-предпросмотр: вычислять top через CSS из уже поддерживаемого глобального --app-sticky-offset и измеряемой высоты панели вкладок + 15px. Не брать top из transient getBoundingClientRect().bottom при восстановлении скролла; синхронизировать на pageshow, load, resize и изменении размера вкладок.
