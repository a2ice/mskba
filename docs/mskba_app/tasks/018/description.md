# 018 — Адаптивная плотность UI на маленьких смартфонах

**Дата:** 2026-10-09 · **Ветка:** feature/139 · **Статус:** Запланировано, ожидает согласования подхода.

## Контекст
На смартфонах с маленькой шириной компоненты и интервалы MSKBA App слишком крупные. Пользователь предложил уменьшать их примерно до 90%, но выразил сомнения в `zoom: .9` на body.

## Предложение на согласование
- [ ] Сначала проверить гайдлайн, токены и реальные страницы на ширинах 320/360/375/390/440, при увеличенном тексте ОС и мобильной клавиатуре. Выполнить замеры вертикального расхода места и фактического размера touch targets.
- [ ] Не использовать `zoom` или `transform:scale` для body: они масштабируют всю типографику, усложняют координаты, sticky/fixed, переполнение и доступность.
- [ ] Определить управляемую компактность на узких breakpoints через общие design tokens и `clamp()/calc()`: вертикальные промежутки, padding секций/карточек, gap, размеры крупных заголовков и декоративных элементов. Возможный CSS-токен `--ui-density` без принудительного умножения всех размеров.
- [ ] Сохранить доступный размер текста, кликабельность минимум около 44 CSS px для основных controls, ясные поля формы. Проверить с OS font scale и prefers-reduced-motion.
- [ ] Согласовать конкретные масштабируемые токены и примеры на скриншотах. После этого обновить гайдлайн/каталог и компоненты единой правкой, а не случайными локальными @media.
