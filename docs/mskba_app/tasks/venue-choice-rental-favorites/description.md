# MSKBA App — Выбор аренды конкретного зала или избранного (задача 330)

Дата: 18.11.2026. Целевая среда: production через feature branch → PR в main → зелёный CI → проверенный deploy.

## Продуктовая постановка

На странице площадки единый CTA «Хочу здесь играть» открывает краткий диалог со скрытыми разделами: аренда площадки или избранное.

- Аренда: показать шаги выбора зала, даты, реальных слотов, последующей авторизации и штатного подтверждения заявки; на общей странице с несколькими залами не подставлять первый зал молча.
- Избранное: компактное подтверждение через существующий Favorites API без создания PlayIntent или бронирования; активное избранное авторизованного игрока учитывается в прямой аудитории.
- Условия похожих площадок, регулярность и формат игры — только в «Моих подписках». Логика сопоставления matched-группы не меняется.
- Существующие активные прямые подписки сохраняются в аудитории для обратной совместимости; один канонический пользователь — одна карточка.

## Сверка с UI Kit и гайдлайном

Используются уже существующие `app-venue-overlay`, `app-venue-overlay__header`, `field-group`, `select-control`, `button primary/secondary` и темы `--surface`, `--line`, `--accent`; новый независимый модальный движок/система уведомлений не вводятся. Окна — native `dialog.showModal()` в верхнем слое, без фиксированных позиционных координат; закрытие по Escape, кнопке и backdrop. Focus outline — только на интерактивных элементах. Для выбора раскрывающегося сценария — семантические `details/summary`, без подсветки статичного текста. Узкие экраны — одна колонка, размеры ограничены `100vw - 24px` и `dvh`.

Используем штатные семантические селекты и иконку из Tabler theme symbol (`#chevron-down`) вместо нового иконного набора. Для сообщений — общий `mskba:action-toast` и доступная текстовая ошибка в диалоге. Публикация игровой информации/аватара по факту избранного запрещена; данные берутся из защищённой существующей модели и действующих разрешений. Проверяем визуальную согласованность в UI Kit и desktop/mobile после production-деплоя.

## Техническая приёмка

- Страница одной площадки с одним залом и отдельная страница зала: зал выбран, дата вызывает штатное расписание с его `venue_court_id`.
- Общая страница двух залов: открытие дня без выбора вызывает выбор зала; данные часов и занятости другого зала не представлены как текущие.
- Эндпоинт расписания проверяет принадлежность `venue_court_id` к площадке; существующий quote и booking остаются серверно авторитетными.
- Избранное гость/авторизованный, повторный клик, удаление/возврат, счётчики, единый toast, прямой интерес с дедупликацией.
- CI, PHPUnit + Node tests, production build. Подтвердить реальный prod-деплой; не объявлять merge равным готовности релиза.
