# Задача 310 — эффективные условия залов в поиске, картах и Telegram Mini App

## Контекст
Каталог /venues уже проверяет эффективные условия зала (task 306, PR #627). Главная карта, JSON поиск и Telegram Mini App раньше ориентировались на один inherited флаг Venue.

## Backend
- VenueSearchCache индексирует court_access, используя единую службу VenueCourtDiscoveryAccess (без повторных правил на клиенте).
- Подгрузка залов и активных BookingPolicy пакетная, без N+1.
- Комбинация фильтров requires_payment и requires_booking_approval должна выполняться для одного и того же зала, а не разных залов площадки.
- При фильтре возвращается URL подходящего зала. Без фильтра URL общей площадки. API дополнительно сообщает venue_url, matched_court, court_access, has_free_court, has_paid_court, has_approval_court и has_free_access (свободный проход без бронирования/подтверждения).
- Legacy поля requires_payment и requires_booking_approval для совместимости остаются, но смешанная платность выражается nullable/новыми флагами, а не вводящей в заблуждение «Бесплатно».
- Изменение и удаление зала или BookingPolicy сбрасывает версию поискового индекса (PR #631).

## UI Kit
- Главная карта показывает независимо наличие бесплатных и платных залов, наличие подтверждения и ссылку на совпавший зал при фильтрации.
- Telegram Mini App показывает те же характеристики, не делает вывод «Бесплатно» по общему Venue.requires_payment.
- Используем текущие DOM classes/popups/components и safe HTML escaping, без новых декоративных UI элементов, стилей и extra hints.
- Следовать docs/specification/ui-design-system.md.

## Тесты
- Школа №1794: уличный корт бесплатный без предварительной записи, школьный зал платный с подтверждением.
- Фильтр бесплатно возвращает URL уличного корта, платно / подтверждение — школьного зала.
- Одновременно платно + без подтверждения не должно находить школу, если платный зал требует подтверждения.
- API /venues/search, /home/venue-radius-search, поиск в TMA; закешированные данные обновляются после редактирования зала.
- Проверить PG16/17, Vite, desktop/mobile и ручной smoke test DEV. Main и production до приёмки не менять.
