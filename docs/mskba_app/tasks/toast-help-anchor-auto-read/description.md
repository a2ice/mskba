# Тосты над FAQ и автоматическое прочтение — 26.11.2026

По прямому запросу владельца. DEV ONLY. Локальная UX-корректировка существующих компонентов MSKBA App, обе appearance modes; старый самостоятельный mskba_dark без FAQ launcher не меняем. Контракт: [UI design system](../../../specification/ui-design-system.md), [универсальный notification popover](../../../specification/universal-notification-popover.md).

- Общая CSS-геометрия launcher и toast region: нижний край первого тоста на 10px выше верхнего края кнопки «?». Правый край совпадает, desktop/tablet/mobile и safe-area используют один набор custom properties. Стек растёт вверх, новые live и action тосты prepend, вытеснение нижнего незакреплённого не подтверждает чтение. Максимальная высота учитывает экран и safe-area. Локальная область action toast в открытом dialog сохраняет свой inset.
- Убраны отдельные кнопки прочтения компактного и раскрытого тоста. Крестик permanent notice подтверждает один ID существующим PATCH с CSRF; только успех удаляет тост и обновляет authoritative unread count, failure показывает ошибку без уменьшения. Открытие деталей подтверждает после отображения, conversation после успешной загрузки истории; нет подтверждения при недоступном контексте. Общий helper дедуплицирует одновременные запросы; уже прочитанное повторно не PATCH. Сворачивание возвращает исходный тост, закрытие освобождает очередь. Обычный CTA переход подтверждает конкретное уведомление перед навигацией, модифицированные клики не перехватываются.
- Полная переписка/системные уведомления ЛК используют действующие visibility-aware read endpoints. Ephemeral action toasts не persistent, не уменьшают unread, не отправляют PATCH; автоудаление и вытеснение не подтверждают прочтение. Отказ от старой session-dismissed семантики означает, что прежде скрытые, но не прочитанные сообщения снова доступны.
- Тесты существующей очереди, PATCH, отказа, ссылки, открытия, pin/read, дедупликации. CI и визуальная проверка после dev deploy: desktop/mobile/TMA, light/dark appearance, 1–3 тоста, новые вверх, точный отступ от FAQ, закрытие, раскрытие и сворачивание, ЛК/счётчик, отказ HTTP, эфемерные уведомления. Проверить отдельно standalone privacy toast при одновременном уведомлении. Бизнес-сценарии, API, БД, main не меняются.
