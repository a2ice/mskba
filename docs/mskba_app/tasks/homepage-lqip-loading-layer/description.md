# Главная: loading layer закрывается после первого отображения LQIP

## Проблема

На `dev.mskba.ru` первоначальный HTML после внедрения cache-first LQIP содержит оригиналы в `img src` и CSS. Браузер начинает их загрузку до `window.load`, поэтому loading layer ждёт тяжёлые исходники и остаётся слишком долго.

## Требуемая логика

- Первая загрузка: для имеющихся LQIP запрашиваются только миниатюры (в том числе для `picture/source` и фоновых изображений Page Builder). Доступные встроенные LQIP для критической сцены отображаются непосредственно из HTML.
- Закрытие loading layer и готовность первой отрисовки не зависят от полной загрузки оригиналов. Первичный `load` браузера завершается после миниатюр и остальных обязательных ресурсов страницы. Сама анимация loading layer остаётся управляемой опубликованным JS Page Builder.
- После `load` — асинхронный запрос оригиналов и замена только после успешной загрузки/декодирования; при ошибке LQIP не исчезает.
- Для фоновых CSS картинок сохраняются авторские координаты, слои, градиенты и другие параметры.
- Нет LQIP — оригинальная загрузка без вмешательства; ленивые изображения сохраняют отложенную загрузку. Важна совместимость с мобильными `picture/source`.
- Не менять опубликованные HTML/CSS/JS в Filament, UI-гайдлайн, production или ветку `main`. Изменения только в исходниках рендерера и runtime в Git, с проверками тестами и зелёным CI.

## Приёмка

1. С пустым кешем сеть на первой фазе показывает запросы `/lqip`, полноразмерные URL загружаются после закрытия loading layer.
2. Визуальные слои и фоновые изображения сохраняют геометрию без прыжков и белых кадров.
3. С медленным оригиналом loading layer не висит до его загрузки; миниатюра остаётся.
4. При ошибке оригинала сохраняется миниатюра.
5. Проверить на десктопе и мобильном, с обычным и холодным кешем.
