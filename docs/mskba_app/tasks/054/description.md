# 054 — Физические параметры: телосложение, обувь, кнопки

## Цель и критерии приёмки
Убрать «Стройность» (сохранённое значение не терять и не использовать как дополнительный интерактивный ввод); телосложение: худощавое, нормальное (default), упитанное и остальные существующие доступные варианты по согласованному порядку; убрать опцию «Не указано». Обновить enum/валидацию/модель/пользовательские значения с совместимостью старых данных. «Обувь» → «Кроссовки», добавить основные цвета, «Сохранить физические данные» → «Применить».

## Технические границы
Сверить влияние телосложения на 2D prompt и legacy profile, миграцию не создавать без необходимости.

## Процесс
CI (PHP, JavaScript, сборка frontend, PostgreSQL 16/17) → PR/merge в `dev` → проверка развёртывания → визуальная приёмка владельца. `main` не затрагиваем. Следующий этап выполняется после приёмки текущего.

## Статус
Принято пользователем 29.10.2026 после исправления HTTP 500; PR #500 и hotfix #504, CI и развёртывание миграции в `dev` подтверждены.

## Обратная совместимость и проверка

- Порядок селекта: Худощавое, Нормальное, Упитанное, Атлетичное, Мускулистое, Коренастое; без «Не указано». Старые null отображаются как нормальное, при сохранении физических данных нормализуются в normal. **Для уже развёрнутой PostgreSQL базы требуется schema migration**, расширяющая ранее созданный `player_profiles_body_type_check`; данные пользователей не переписывать.
- Legacy large остаётся в enum, отображается «Упитанное» и в AI описывается как fuller build.
- character.adiposity сохраняется в истории, но не влияет на UI, предпросмотр или генерацию.
- Цвета кроссовок сохраняются под прежним ключом character.shoes; список опций и валидация едины.
- Визуальная приёмка: пустой/старый профиль, смена телосложения, выбранный цвет, «Применить», повторная загрузка страницы, сохранение данных игры.

## Исправление приёмки 29.10.2026 — HTTP 500 на «Применить»

- В старой базе PostgreSQL CHECK-ограничение на `player_profiles.body_type` было создано исходной миграцией до появления `normal`; код и свежие CI-базы уже знают `normal`, но прежнее ограничение не изменялось.
- Добавлена отдельная миграция `2026_10_29_120000_extend_player_body_type_normal_constraint.php`: PostgreSQL CHECK пересоздаётся со всеми enum-значениями; для MySQL расширяется ENUM. Исходная миграция не переписывается, profile data не обновляются. Откат запрещён, пока в БД реально есть профили с `normal`, чтобы избежать потери данных.
- Регрессия: POST формы `section=physical` с ростом/весом, `body_type=normal`, формой и кроссовками; PostgreSQL тест воспроизводит старый CHECK, применяет миграцию и сохраняет профиль.
- Исходный статус HTTP 500 зафиксирован по пользовательскому скриншоту; исходные серверные логи недоступны. Это первичная причина, выведенная из схемы и логики записи, проверяется после деплоя.
