# 337 — Event-first воронка площадки и мероприятий

**Согласование:** 19.11.2026. Полное бизнес-ТЗ, состояния, ограничения и production-checklist: [docs/tasks/337/description.md](../../../../tasks/337/description.md).

## UI contract

- Тип мероприятия «Игра» не требует вложенной Game. Чекбокс «Создать игру внутри мероприятия» включён по умолчанию; при снятии создаётся только Event, игру можно добавить позднее. Полную ревизию Game провести отдельно.

- Hero площадки: только «Хочу здесь играть» и «В избранное»; галерея mouse drag, touch swipe, клавиатура, кликабельные превью.
- «Хочу здесь играть» — единый многошаговый попап: список ближайших публичных мероприятий (empty-state, кнопка создать всегда), подробный экран мероприятия, участники/аватары/организатор, действия «Пойду», «Подумаю», «Не пойду», системная лента и сообщения.
- «В избранное» — немедленное добавление + информационный попап; при удалении только фирменный подтверждающий попап. Смена текста на «В избранном», состояния синхронизируются.
- Трёхшаговый мастер создания в обеих темах: тип/автозаголовок/площадка/параметры → необязательное расписание, выбор нескольких пожеланий → подтверждение. Отдельные режимы «варианты одного мероприятия» / «несколько самостоятельных мероприятий». До авторизации пользователь не теряет форму; инфопопап перед auth.
- Чётко отделяем предзаявку от бронирования: UI не пишет «забронировано», не скрывает занятые слоты, показывает неполученное подтверждение. Прямая аренда — из расписания.
- UX-инварианты: backdrop закрывается только после pointerdown+pointerup на backdrop; Escape допускается; клавиша Enter валидирует поле и переводит фокус; инлайн ошибки, сброс при input; несохранённые данные и текущий шаг сохраняем на странице. Ссылки и кнопки не перегружают экран. Обязательна проверка мобильного экрана.

**Согласование в логике создания не означает подтверждение арендного слота.** Уведомления по PlayIntent остаются обязательной частью релиза.


## Визуальная приёмка площадок — корректировки 19.11.2026 (PR #856)

Эталон: `docs/specification/ui-design-system.md` (Modal 1.1 и drag handle); существующие `.mskba-modal`, `.icon-button`, `.app-venue-overlay`, `modal-dragging.js`, `css/modal.css`. Новых независимых модальных систем и нестандартных скелетонов не вводить.

- Попап аренды: единый крестик 44×44 и центрированная иконка захвата; поля и кнопка разделены отступом. При ровно одном доступном зале сразу открывать штатный календарь, при нескольких — оставлять выбор зала; API бронирования без изменений.
- Загрузка календаря: показывать существующий скелетон UI Kit (класс `.skeleton` и те же дизайн-токены), `aria-busy` на области слотов, саму декоративную заглушку скрывать от ассистивных технологий. Ошибку отображать текстом, без зависшего скелетона.
- Избранное: заголовок успеха «Площадка теперь в избранном», краткий текст; при удалении короткий вопрос и одна кнопка «Убрать», закрытие крестиком/Escape. Стандартный drag handle и close.
- «Хочу здесь играть»: без eyebrow, вступления и заголовка «Текущие мероприятия»; оставить пустое состояние или карточки и кнопку «Создать мероприятие». Детальный экран карточки/RSVP сохраняет существующее поведение.
- Оба оформления (mskba_app и mskba_dark) сохраняют корректную поверхность/фон; общая библиотека popup drag применяется без собственного контроллера. После CI требуется ручная мобильная приёмка.


## Повторная приёмка заголовков, контента и форм (19.11.2026)

Эталон: [MSKBA UI Design System](../../../specification/ui-design-system.md), секции Modal 1.1, Native Select, Form Controls, и реальный UI Kit `resources/views/design-themes/ui-kit.blade.php`.

- **«Хочу здесь играть»**: в модальном окне только заголовок, список карточек предстоящих мероприятий **или** текст «На этой площадке пока нет предстоящих мероприятий.», и закреплённая нижняя кнопка «Создать мероприятие». Ни eyebrow, ни вводного абзаца, ни подзаголовка «Текущие мероприятия», ни второго встроенного экрана RSVP/обсуждений. Карточка открывает каноническую страницу мероприятия; вся логика участников/стены остаётся там.
- **Добавление в избранное**: заголовок «Площадка теперь в избранном»; текст «Добавь площадку в избранное, чтобы вернуться к ней позже.»; единственное действие «Понятно». Удаление: заголовок «Убрать из избранного», один вопрос «Вы уверены, что хотите убрать площадку из избранного?» и одна кнопка «Убрать»; отмена через крестик/Escape.
- **Аренда**: при ровно одном зале нет отдельного шага выбора — сразу существующее расписание; при нескольких — корректный стандартный `.field-group` с семантическим `label`, native `select`, оболочкой `.select-control` и фирменным Tabler `#chevron-down` (20 px). Валидация обязательного выбора: `aria-invalid`, текст ошибки. Между селектом и кнопкой достаточно места.
- **Визард создания мероприятия** и диалог авторизации: единая оболочка `.mskba-modal`, `header/body/footer`, стандартная 44×44 кнопка закрытия с Tabler glyph, одна иконка перетаскивания, центрирование и не более 90dvh. Body — единственная прокручиваемая часть, footer не исчезает при скролле. Поля и **все шесть native select** соответствуют 48 px/12 px, шрифт 16/24, стрелка `#chevron-down`; не возвращать 43 px/8 px и системную стрелку без правильного контрола.
- **Обе темы** используют общую бизнес-логику; тон и оформление тем остаются своими. Перетаскивание управляется `modal-dragging.js`, без второго движка; закрытие кликом по фону только при pointerdown+pointerup на фоне.
- **Тесты**: проверка rendered Blade, контента, native-селектов и аренды одного/нескольких залов. PHPUnit/Node/CI не заменяет визуальную проверку на опубликованном сайте.
