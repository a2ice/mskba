# 015 — UX завершения регистрации: две группы, onboarding shell, напоминание

**Дата:** 2026-10-09 · **Задача:** #139 · **Ветка:** feature/139 · **Статус:** Принято пользователем 2026-10-09; локальный коммит разрешён. Публикация отдельно.

## Запрос

- На странице обязательной первичной настройки не показывать sidebar аккаунта; контент использует всю ширину standard inner.container. Обычные account-страницы сохраняют sidebar.
- Пока onboarding не завершён: аватар/иконка аккаунта в header получает заметную, но доступную shake-анимацию; рядом с контентом — явное предупреждение и toast с информацией «Остался последний шаг регистрации».
- Вместо бессистемных 20 переключателей — два главных смысловых блока:
  1. **Видимость профиля:** главный чекбокс, при включении раскрываются аватар, контакты, пол, возраст и другие реально доступные параметры; дочерние настройки никогда не могут сделать закрытый профиль публичным.
  2. **Видимость в поиске и взаимодействия:** главный чекбокс поиска, затем кто может писать сообщения и приглашать в группы. Ролевые действия (приглашение игрока в команду, тренера в секцию и т.п.) проектируются только с проверкой backend ACL.
- Не запрашивать общее согласие на публичное распространение, если пользователь всё оставил закрытым. Никаких включённых по умолчанию публичных данных.

## Ограничения

- Повторно использовать компоненты из UI-гайдлайна (panel, switch, notice, toast, badge, button); не вводить новый многоразовый компонент без согласования.
- Не выдавать права selected_users за «Моим связям». Не обещать переключатели «кто может приглашать в команду/кто может писать», если нет сохранения и фактической проверки при выполнении действия.
- Дополнительные категории пол/возраст требуют проверки существующего публичного выдающего слоя; если он не защищён, не делать псевдо-переключатели, а описать зависимость.
- Общее правило страницы приватности: иерархия разрешений, скрытые неактивные дочерние элементы не могут остаться публичными. Сервер проверяет зависимости, не доверяет только JS.
- Согласие по отдельному юридическому документу сохраняется через старый транзакционный механизм; контроллер/валидация совместимы с историческими флоу.

## Реализация и проверка (2026-10-09)

- На обязательном шаге регистрации не рендерится sidebar, а обычные страницы аккаунта сохраняют общий layout. Контент занимает единый standard container секции.
- Header: account avatar потряхивается по циклу 4,6 секунды, пока не завершён onboarding; ссылка ведёт на настройку приватности. Включён prefers-reduced-motion: reduce. На странице отображаются постоянное уведомление и одноразовый toast из дизайн-системы.
- Две основные группы с раскрытием при включённом главном переключателе: профиль (контакты, аватар, пол, возраст, дополнительные настройки игрока) и поиск (кому разрешены сообщения и групповые приглашения). Для двух select применён штатный .select-control.
- Сервер проверяет иерархию: закрытый профиль запрещает публикацию дочерних данных даже при подмене POST; закрытая страница игрока запрещает публикацию её спортивных подпунктов. Отключённый поиск принудительно закрывает сообщения и приглашения.
- Поиск, сообщения и групповые приглашения сохраняются транзакционно вместе с выбором профиля; приглашения уже используют действующие проверки доступа. Для пола и возраста введены отдельные закрытые по умолчанию разрешения и фильтр публичной проекции; дата рождения никогда не выводится.
- Не реализовывали несуществующий ACL «Моим связям», отдельные роли приглашений и систему личных сообщений. Поле будущих сообщений можно сохранить, но применять его пока негде — это отдельный этап.
- PHPUnit: **85 тестов / 574 утверждения PASS**. Историческую privacy-миграцию не изменяли (проверка её фиксированных 23 типов актуализирована).
- Chromium: **320, 390, 440, 768, 1024, 1440 px PASS**. Отсутствие overflow, динамические вложения, toast, header shaking в состоянии незавершённости.
- Blade и Vite сборка PASS. Laravel Pint исправил 3 style issues, окончательная проверка стиля и ссылок выполняется отдельно.
- **Не выполняли commit, push, PR, merge или deploy**. Визуальная приёмка на localhost пользователем ещё требуется.

## Уточнения при приёмке 2026-10-09

- Настройка поиска зависит от видимости профиля. Закрытый профиль выключает и блокирует поиск, скрывает связанные селекты. Включение профиля автоматически предлагает включённые поиск и аватар; пользователь может затем отключить их вручную. Открытие страницы с ранее сохранёнными настройками ничего самопроизвольно не включает.
- При выключении профиля сбрасываются поиск, аватар и прочие вложенные публичные опции, а сообщения/приглашения получают nobody. Повторное включение предлагает поиск и аватар on, но не возвращает снятые разрешения. При ручном выключении поиска его дочерние селекты сбрасываются к nobody.
- Блок игрока переименован в «Видимость игрока», текст подсказки «Показывать вашу страницу игрока». Сам блок раскрывается и сворачивается своим переключателем, а не визуальной бледностью вложенных полей. Скрытые детальные разрешения выключаются и не могут обойти сервер.
- Серверная валидация ограничивает разрешения поиска видимостью профиля; дополнительно UserPrivacyAccessService и SearchDiscoverableUsers не допускают обнаружения закрытого профиля, включая поиск по прямому ID.
- Chromium: 320, 390, 440, 768, 1024, 1440 px PASS для всех переходов/обратных переключений, восстановления уже сохранённых настроек и отсутствия overflow. Адресные PHPUnit: 21 тест/129 утверждений плюс проверка поиска по ID, 10 тестов/60 утверждений PASS. Blade, Vite и Pint PASS.
- Изменения только локальные, без коммита, push и merge. Задача ожидает визуальной приёмки.
