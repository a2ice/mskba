# 002 — Header и адаптивная навигация

**Статус:** На проверке · **Дата обновления:** 2026-10-08

## Цель

Создать первый реальный partial новой темы: desktop-header из принятого гайдлайна с функциональными разделами действующего MSKBA, а также доступную мобильную навигацию.

## Реализовано

- `resources/themes/mskba_app/views/partials/header.blade.php` подключён к `views/layouts/app.blade.php`.
- Оформление отделено в `css/header.css`; логотип/цвета/геометрия из эталона 002-03.
- Меню и видимость пунктов через существующий Laravel `MenuResolver::resolve('main')`/`MainMenu`; активные разделы и вложенные пункты.
- `js/header.js` закрывает раскрытые меню по клику вне header и Escape; без зависимостей старой темы.
- Гостям видна кнопка входа через существующий route `login`; пользователям — профиль и ссылка на уведомления.
- Для ширины от `1280px` расстояние от логотипа до меню дополнительно увеличено на **12 px**.

## Проверено

- Рендер главной с новым header: HTTP 200; ссылки без пустых href, Vite CSS и логотип: HTTP 200.
- После финальной CSS-правки Vite production build успешно выполнен в отдельную временную директорию; `node --check` для header JS прошёл.
- Получены скриншоты пользователя для desktop, iPhone 16 Pro Max (440), iPad mini (768), iPad Pro 13 (1032 и 1376); открытое mobile menu на `/events` показывает активный пункт и подразделы.
- Отзыв пользователя: «выглядит очень хорошо»; замечание по desktop отступу +10–15 px устранено локально.

## Требует проверки

- Повторный desktop скриншот после +12 px; отсутствие тесноты на границе breakpoint.
- Клавиатурная навигация, Escape/focus, console/network, состояние авторизованного пользователя, реальные мобильные устройства.
- Поведение на `360×800` и `390×844`, zoom 200%, длинные подписи и состояние раскрытых desktop меню по [протоколу #139](../../../tasks/139/visual-review.md).
- Вопрос полноценной страницы авторизации в новом дизайне решается отдельно; пока link `/login` может показывать fallback.

## Критерий завершения

Пользователь подтверждает повторную визуальную приёмку header после увеличения отступа; затем вносятся финальные отметки и (после разрешения) отдельный коммит. Это **не** означает завершения всей задачи #139.
