# MSKBA App — Task 302: экраны условий аренды, залов и расчёта

## Причина
На staging `APP_THEME=mskba_app`, но после первого PR #613 страницы `venues.booking-policy`, `venues.courts`, `venues.rental-quote` существовали только в `mskba_dark` и в активной теме отсутствовали. Калькулятор и миграции уже доставлены, однако посетитель видел заглушку недостающего шаблона. Исправление — отдельный UI-only PR для активной темы.

## Эталон UI Kit до кода
- `docs/specification/ui-design-system.md` и Filament → Дизайн → Темы оформления → UI Kit.
- Готовые общие компоненты `.panel`, `.button.primary/.secondary`, `.field-group`, `.badge`, `.check-label` (инпут 20×20, зона клика >=44px), `app-account-overview__intro` и `theme::layouts.account`.
- Никаких собственных цветов/шрифтов, локальных inline-стилей, eyebrow и несогласованных модальных окон. Страничный CSS `venue-rental-pricing.css` задаёт только сетки, расстояния и адаптивную компоновку, использует существующие CSS-токены.
- Основные формы завернуты в обычные панели. Цены по датам — одна общая partial для Venue и VenueCourt. Действия на маленьких экранах не перекрываются, таблицы скроллятся внутри своей области.

## Маршруты и состав
1. `/account/venues/{id}/booking-policy`: версия политики, значения для всех залов и календарные overrides площадки.
2. `/account/venues/{identifier}/courts`: настройки отдельных залов, наследование, weekly + calendar overrides, обновление/создание зала в пределах выданных rights.
3. `/venues/{id}/rental`: расчёт аренды с текущим залом; поля длительности и шага обновляются при переключении зала.
4. Контроллеры, модели, права, сценарий quote и история бронирования не дублируются в теме. В теме только представление.

## Корректировка от 06.11.2026 — только ручная синхронизация

- **Автоматическая синхронизация не реализована и не вызывается**: нет Scheduler/Job/Observer/Listener. В БД зарезервирован `venue_courts.auto_sync_enabled=false`, но редактировать этот флаг в Filament нельзя. Настройка остаётся выключенной до отдельного решения.
- Сохранены штатное наследование для залов без индивидуального расписания и запрет открывать зал, если вся площадка закрыта. Наследование не копирует записи в БД. Ручная синхронизация, напротив, создаёт собственный снимок расписания/цен зала.
- Filament → Площадки → редактирование → «Игровые зоны / залы»: кнопка **«Синхронизировать»** у зала, кнопка **«Синхронизировать все залы»** над таблицей, обязательное подтверждение замены выбранных данных.
- Режимы: **день**, **период (7 дней включительно по умолчанию, максимум 90 дней)** и **полная синхронизация** регулярной недели и всех родительских исключений.
- **«Включить цены» включено по умолчанию** и может быть выключено. Период/день обновляет календарные цены только выбранных дат (создаёт ценовой снимок по шагу конкретного зала); цены других дат, недельные и базовые цены зала не трогает. Полная синхронизация с включёнными ценами заменяет базовые, недельные и календарные цены зала. Если цены не включены, ни одна ценовая запись не меняется.
- Настройки у каждого зала: `sync_include_prices_default=true`, `sync_period_days=7`. Автоматическая синхронизация в Filament отображается **отключённой**.
- Сервис `SyncVenueCourtSchedule` выполняет операции в транзакции, сверяет принадлежность залов площадке и совместимость шагов, не меняет бронирования, заявки, игры, мероприятия, флаги платности и другие контрактные права. В системном логе фиксируются параметры ручного запуска.
- Для дня/периода при первом синхронизировании зала копируется регулярная неделя как исходная опора: другие даты не закрываются, а дальнейшие изменения родительской недели не перезаписывают индивидуальный снимок зала. При существующем индивидуальном расписании недели оно сохраняется.
- Полная синхронизация — **замена**, а не объединение. Родительские ограничения закрытия/сокращённого времени сохраняют приоритет для безопасности, даже если в зале уже имеется копия.
- Проверить: отсутствие любых изменений до запуска, один день, диапазон 7 дней, полная, с ценами и без, повторный идемпотентный запуск, чужие залы/права, rollback при ошибке одного зала; затем ручная визуальная приёмка Filament desktop/mobile на dev.


## Исправление приёмки — Filament «Редактировать зал» (скриншот 06.11.2026)

### Причина
В \`CourtsRelationManager::form()\` использовался внешний \`Grid::make(2)\` с четырьмя \`Section\`, каждая внутри — \`columns(2)\`. Поэтому модальное окно раскрывалось широко, но сами формы занимали две чрезвычайно узкие колонки и вызывали наложение текста/переключателей. Дополнительно одни и те же поля \`operational_status\`, \`requires_payment\`, \`requires_booking\`, \`requires_booking_approval\`, \`rental_enabled\`, цены находились и в «Игровой зоне», и в «Наследуемых условиях» — дублированная конфигурация.
Форму нельзя считать принятой при таком отображении.

### UI-контракт для Filament 5
- Без локального CSS: использовать штатные \`Tabs\`, \`Section\`, \`TextInput\`, \`Select\`, \`Toggle\`, \`CheckboxList\`.
- Один полный tabbed editor, без внешней двухколоночной сетки вокруг секций; \`columnSpanFull()\`, поля до 2 колонок только при ширине \`md+\`, одна колонка на mobile.
- Вкладки: «Игровая зона» (идентификация, оснащение и допустимые области), «Доступ и бронирование», «Цены и ограничения» (включая overrides длительности/шага), «Синхронизация» (автоматическая выключена, параметры ручного запуска), «Фотографии».
- Поле одного имени существует только в одной секции; для \`null\` наследования в селектах используется «Наследовать от площадки», для цены \`0\` означает осознанное бесплатное значение. Все предыдущие поля и действия сохранены.
- Переименование generic-заголовка \`Изменить venue court\` в «Редактировать: название зала».
- Оба модальных окна имеют 6xl, sticky header/footer; мобильная вкладочная навигация стандартного Filament.
