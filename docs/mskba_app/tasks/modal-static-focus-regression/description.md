# Фокус только на интерактивных элементах в попапах — 17 ноября 2026

## Причина повторной регрессии

Общие CSS-правила фокуса и общий drag-контроллер уже не делают статические заголовки фокусируемыми. Однако несколько отдельных JS/Vue-сценариев `showModal()` всё ещё **программно вызывали `.focus()` на `h2[tabindex="-1"]`**, в том числе мобильный попап входа. Это даёт прямоугольную рамку вокруг текста в Safari.

## Исправлено

- [x] `AuthDialog.vue`: при открытии и переключении режима фокус на кнопке закрытия, не на заголовке, без автооткрытия клавиатуры.
- [x] `PlayIntentDialog.vue` (поиск игры, подписки, избранное): статический `h2` не получает фокус, фокусируется кнопка закрытия.
- [x] Приватность/онбординг: фокус на закрытии; ошибка с `role="alert"` больше не становится программным фокусом.
- [x] Контекстные диалоги (FAQ и заглушка): фокус на закрытии, а не заголовке.
- [x] Диалог документа о согласии на распространение: фокус на закрытии, не на `h2`.
- [x] Мастерская формы: убран `tabindex="-1"` с информационного заголовка.
- [x] JS-регрессия в `modal-dragging.test.mjs` запрещает возврат фокуса на такие заголовки.
- [x] Сохранены существующий модальный focus trap, доступность ссылок/кнопок, восстановление фокуса при закрытии и поведение iOS без автоматического поднятия клавиатуры.

## Граница

Не подавляем `:focus-visible` на интерактивных элементах и не заменяем корректный фокус глобальным `outline:none`. Production не затрагивается. Слияние строго после зелёного CI.
