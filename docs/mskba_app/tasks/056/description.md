# 056 — Библиотека аватаров и ростовая шкала 225 см

## Цель и критерии приёмки
Ниже Пол/Рост/Вес добавить «Аватаров: N», четыре превью в области ширины карточки и горизонтальный скролл. Клик на превью выбирает текущий просмотр; сохранять primary только предусмотренным API. Шкала 0–225 см с отметками через 50 см и динамической оранжевой риской роста с белой подписью, синхронизация с ползунком; корректная высота изображения.

## Технические границы
Использовать авторизованную историю генераций, не раскрывать чужие ссылки; пустое состояние. Проверить 225 см, мобильную область.

## Процесс
CI (PHP, JavaScript, сборка frontend, PostgreSQL 16/17) → PR/merge в `dev` → проверка развёртывания → визуальная приёмка владельца. `main` не затрагиваем. Следующий этап выполняется после приёмки текущего.

## Статус
Принято пользователем 29.10.2026 после PR #505/#506/#507, зелёного CI и успешной публикации на `dev`.

## Реализация 29.10.2026

- Под блоком роста/веса/пола в карточке персонажа добавлены «Аватаров: N», горизонтальная лента из четырёх видимых превью с прокруткой, пустое состояние и адаптивность. Счётчик учитывает только завершённые изображения с доступной ссылкой.
- Источник данных — существующая защищённая операция `generation_history`; она не меняет основной аватар и возвращает только связанные с пользователем генерации. При загрузке сначала показывается основной (или последний завершённый), клик по превью меняет **только текущий предпросмотр**.
- Кнопка «Сделать основным» показывается только для выбранного неосновного изображения. Только её нажатие вызывает авторизованную `generation_primary`; после ответа API обновляются статус и бейдж. Во время запроса повторные клики заблокированы.
- Шкала калибрована от 0 до 225 см с отметками 0/50/100/150/200 и верхней границей 225 см; оранжевая риска с белым значением и высота персонажа рассчитываются в одних координатах с ползунком. **Ограничение роста игрока 150–220 см не изменено** в рамках 056.
- При завершении генерации библиотека перечитывается; изображение недоступного чужого пользователя не должно присутствовать в истории. Проведены проверки backend/API и UI-контракта.
- Приёмка: пустая лента, 1/4/5+ изображений, выбор одного превью без изменения primary, отдельное подтверждение основного, прокрутка и мобильный viewport, рост 150/185/220 см и синхронизация шкалы/риски, сохранение после перезагрузки.

## Дополнения по визуальной приёмке 29.10.2026

- Если в библиотеке ещё **нет готовых аватаров**, не показывать заголовок `Аватаров: 0` и пустую горизонтальную ленту. Оставить только сообщение `Сгенерированных аватаров пока нет.`. В состоянии загрузки заголовок тоже скрыт; при наличии ≥1 завершённого аватара показываются счётчик и превью.
- Заголовок страницы роли `Роль: Игрок` заменить на `Игрок` только для роли Player; остальные роли без изменений.
- Ростовая риска: по умолчанию тонкая оранжевая горизонтальная линия; при hover появляется компактный оранжевый бейдж **по ширине значения**, в начале линии у шкалы роста. При фокусе ползунка показать значение и без hover (клавиатура/сенсорный экран); после blur снова оставить линию. Сохранить синхронизацию высоты и числа, поддержку reduced motion.
- После PR проверяются нулевой список, появление 1+ изображений, отсутствие мигания счётчика 0, вид и позиция метки 185 см, управление мышью и клавиатурой, корректность заголовка.

## Замечания повторной приёмки — масштаб фигуры и перетаскивание шкалы (29.10.2026)

- На скриншотах рост **196 см** и **220 см** показывал почти одинаковую высоту персонажа, хотя линия ростовой отметки перемещалась правильно. Причина: `max-width:95%` вместе с flex shrink ограничивали размер PNG по ширине, и он не мог дальше расти по высоте. Убрать ширинный cap и не сжимать flex-элемент; сохранить высоту в единой шкале `cm / 225`, привязку ног к 0 см, пропорции изображения и изменение ширины тела по параметрам.
- Сделать горизонтальную оранжевую линию толщиной **1px**.
- Добавить возможность **перетаскивать саму оранжевую линию вверх/вниз мышью или пальцем**. Пересчитывать координату указателя относительно шкалы 0–225 см, округлять до целых сантиметров и ограничивать разрешённым диапазоном **150–220 см**. Изменять native `input[type=range]` и посылать `input` event, чтобы обновлялись ползунок, его числовая подпись, линия, метрики и масштаб фигуры единой логикой.
- Во время перетаскивания показывать компактную подсказку со значением, продолжать движение даже за пределами узкой полосы (pointer capture), на `pointerup`, `pointercancel` и потере захвата возвращать обычное состояние. На сенсорных экранах захват полосы не должен прокручивать страницу. Клавиатурное управление родным ползунком не менять.
- Приёмка: 150 → 185 → 196 → 220 см должны иметь возрастающую *видимую* высоту фигуры; при 220 верх должен достигать соответствующей отметки шкалы, а не останавливаться у 200. Проверить drag мышью и touch, границы 150/220, смену значений при обычном ползунке и без сохранения до нажатия «Применить».
- Задача остаётся на повторной визуальной приёмке после зелёного CI и деплоя на `dev`. `main` без изменений.
