# MSKBA Backoffice — 065: собственная запись superadmin

## Причина
Каталог Filament /backoffice/backoffice-users исторически исключал все записи системной роли superadmin, а проверка mayManage запрещала редактировать собственную запись.

## Решение
- Подтверждённый, не заблокированный и не удалённый superadmin видит себя в списке наравне с пользователями нижних ролей. Чужие superadmin и SYSTEM не становятся доступными для делегирования.
- На странице своей записи разрешено редактировать персональные данные и роли участия через существующие проверяемые сервисы с аудитом изменений.
- Системная роль, права, а также собственный статус superadmin недоступны для изменения.
- Три группы глобальных прав в интерфейсе отмечены по умолчанию и заблокированы; кнопка сохранения прав скрыта. Сервер отклоняет изменение прав для superadmin независимо от UI.
- Проверка эффективных прав учитывает все права системной роли superadmin и игнорирует исторические явные запреты, но блокировка аккаунта сохраняет приоритет.

## Критерии приёмки
1. Superadmin видит и может открыть свою запись в /backoffice/backoffice-users.
2. Superadmin сохраняет свои персональные данные (с основанием, аудитом), а роли участия редактирует через существующий UI.
3. Свои системные права показаны включёнными, блокированы к изменению. Нет кнопки сохранения прав; поддельный POST/Livewire вызов отклонён.
4. Собственный статус и системную роль менять нельзя.
5. Другие superadmin и SYSTEM по-прежнему не доступны через список и редактор.
6. Администраторы ниже superadmin не получают право редактировать себя.
7. Полный CI, merge в dev и подтверждённый SSH-деплой до приёмки.
