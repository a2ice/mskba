# 044 — Карточка и список заинтересованных игроков: компактный итог и скрытые аватары

**Контекст:** уточнение визуальной приёмки задачи [286](../../../tasks/286/subscriptions-20261026.md), 2026-10-26. Статус: в реализации / проверка CI → dev.

## Запрос и точное поведение

1. В попапе «Площадкой интересуются» итог: крупное число по центру, строкой ниже правильная форма слова **игрок / игрока / игроков**. Убрать «N напрямую · N по условиям» из верхнего блока.
2. В списке попапа скрывать секции с нулевым количеством, включая заголовок и пустое состояние. Ненулевые группы «Подписаны на эту площадку» / «Подходят по условиям» и их счётчики сохраняются.
3. В обезличенном по аватару/характеристикам профиле **показывать логин** (или безопасное «Игрок», если логин пуст), не выводить «Скрытый профиль» и «Без данных профиля». Фотография и спортивные характеристики остаются скрытыми. Из-за смены правила откорректировать согласие: логин показывается независимо от выбора публикации аватара/характеристик.
4. У скрытого фото показывать стандартную иконку пользователя **Tabler Icons Outline**, использовать существующий `#user` из `resources/themes/mskba_app/views/partials/icons.blade.php`. Заменить прежнюю точку и в карточке, и в попапе.
5. На компактной карточке площадки: аватары + одна строка «N игроков» + «Посмотреть всех», без разбивки по группам.
6. Рамка аватара `#f7f8fa` для различимости светлых фотографий в карточке и попапе.

## Граница и эталон

- Уникальные пользователи, логика direct/matched, совпадения, счётчики и подписка не меняются.
- Только тема `mskba_app`; другие системы «интересов» не затрагиваются.
- Паттерн: [UI design system](../../../specification/ui-design-system.md) — Tabler Icons Outline 3.46.0, общие аватары, токены типографики и отступов, modal через native `dialog`; существующие `app-venue-interest-summary__avatar`, `app-venue-interests-dialog__group`, без новых общих компонентов.
- Модель `VenueSubscriptionAudience` сохраняет `public=false`, `avatar=null`, пустые `positions`, `experience_years=null`; только `name` раскрывает username.
- Тексты публичности в wizard должны быть однозначными относительно видимости username.

## Критерии приёмки

- Для 0/1/2/5/11/21/22 и т. д. корректное склонение в попапе и карточке.
- При 2 direct, 0 matched попап показывает только 1 группу, нет «Пока нет игроков».
- Для скрытого профиля HTML содержит логин, icon `#user`, не содержит avatar URL, позиций и игрового опыта.
- При 1 direct + 1 matched обе группы видны, каждый пользователь учитывается только один раз.
- Нет разбиения групп на карточке, рамка `#f7f8fa`.
- PHP feature tests + frontend CI проходят; затем PR merge в `dev`, публикация dev по штатному workflow.
