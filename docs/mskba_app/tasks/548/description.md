# 548 — UI Kit 1.0: лиги, сезоны, баннеры

Продолжение задач #541 и #544 после успешного деплоя на `dev`. Это косметическая корректировка уже реализованных сценариев; новый визуальный контракт не вводится.

## Эталон
- `docs/specification/ui-design-system.md`: **«Пространство и композиция»**, **«Адаптивный layout»**, **«Компоненты и состояния»**.
- Интерактивный эталон: Filament → Дизайн → Темы оформления → UI Kit / Гайдлайн.
- Реальные компоненты `mskba_app`: `.panel`, `.button.primary|secondary|danger`, `.badge`, `.app-team-field`, стандартный `.mskba-modal`, SVG-спрайт Tabler `#ball`.

## Изменения
- Расстояния между независимыми плашками не меньше 20px (24px для крупных секций) без дублирования margin в строках.
- В строках элементов — `align-items:center`, осмысленный `gap:12/16px`, текстовый узел `min-width:0`; touch targets от 44px.
- На страницах лиг и сезонов кнопка «Изменить баннер» живёт внутри шапки, выровнена вертикально относительно названия и логотипа; на mobile переносится в свою строку.
- Настройки лиги и сезонов: навигация — отдельная плашка `.panel`, с активным пунктом и гарантированным вертикальным промежутком до редактора.
- Универсальный редактор: общие цвета/радиусы/кнопки; отдельные текущая обложка, загрузка и предпросмотр; сдвиг изображения мышью, пальцем или стрелками; масштаб; восстановление текущего кадрирования при открытии; `Drag & Drop`; подтверждение удаления штатным `<dialog class=mskba-modal>`.
- Дизайн-копирайт: без терминов «оригинал», «медиаколлекция», «WebP-производная», «API» в заголовках/описаниях. Форматы и лимит упомянуты только в подсказке перед выбором изображения (требование контракта Upload).
- Используются существующие компоненты, нового семейства UI Kit нет; потому новая ревизия дизайн-гайдлайна не требуется.

## Проверки
- HTTP страниц лиг и сезонов, наличие CTA только для владельца, активный пункт навигации, отдельно от аватара/лого.
- Контракт markup компонента и сохранённого кадрирования, штатный modal delete.
- CI → merge только при зелёном CI → dev deploy; production не затрагивать.
- **Визуальная приёмка владельцем обязательна** на desktop 1440/1024 и mobile 390/360/320, включая активные/hover/focus/disabled, межкарточные отступы и выравнивание.
