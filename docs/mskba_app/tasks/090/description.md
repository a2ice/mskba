# 090 — Единые чаты заявок: мобильная вёрстка и контекстные действия

Дата: 17.11.2026. Этап 1: заявки на вступление в команду; отдельный этап — бронирования.

## UX и гайдлайн

- Существующие app-message-workspace, компактная панель шапки, скроллируемая панель истории и общий app-messages__compose — единые для direct/support/profile/team/booking.
- Мобильная шапка: отдельная кнопка-стрелка возврата, отдельно иконка типа заявки, название и статус с переносом слов. Участники в отдельной адаптивной раскрывающейся панели, без наложения на заголовок.
- Поле ввода и кнопка «Отправить» имеют одну внешнюю рамку; кнопка внутри панели с отступом 5px снизу и справа. Без рамок на статических лейблах и тексте. Меню «Действия» использует существующий app-context-actions.
- Менеджер с правом MANAGE_JOIN_REQUESTS видит только действия, допустимые статусом: pending/awaiting_response → принять/отклонить/заблокировать; blocked → разблокировать. Для отказа и блокировки требуется причина. Заявитель не видит управленческих кнопок.
- Используется нативное dialog для подтверждения и причины; состояния и действия обновляются через сервер, окончательная проверка прав всегда на сервере.

## Техническая реализация

- AccountConversationsController отдаёт единое представление team thread и защищённое state-представление с актуальными действиями; доменные сообщения и уведомления не дублируются.
- Новый account-team-request-chat.js обновляет контекст по получении уведомления и по резервному опросу, сохраняя черновик при сбое.
- Общие partials team-request-actions и team-request-timeline для первого рендера и refresh; CSS-правки в account-messages.css, без новых глобальных focus-состояний.

## Приёмка

- Ширины 320/375/390/430/768/1024/1440/1920px, длинные названия, раскрытие меню вверх, мобильные клавиатуры.
- Роли кандидат/менеджер/посторонний, статусы pending/awaiting_response/accepted/rejected/blocked, динамические кнопки и серверные запреты.
- PHP feature tests, Blade, Vite, CI; публикация production только после проверки dev.
