# 045 — Управление игровыми подписками и карточка игрока

**Связь:** [286](../../../tasks/286/subscriptions-20261026.md), [044](../044/description.md). Уточнение приёмки от 26.10.2026. Статус: реализация в feature-ветке, CI → dev.

## Требования
- На странице Venue вместо «Отменить подписку» показывать «Вы подписаны» в hero, боковой CTA и попапе игроков; кнопки ведут в `route('play-intents.mine')`. Отменять можно только в кабинете.
- В AccountMenu темы mskba_app видимый всем авторизованным раздел **«Мои подписки»** (без обязательной роли PLAYER); прежний «Хочу играть» убрать из ролевого меню «Участие» и сделать действием открытия формы в самих «Моих подписках».
- В списке «Площадкой интересуются» для текущего канонического User показывать «Это вы», а также **его собственные аватар и игровые поля даже когда `show_on_venue=false`**. Для других по скрытой подписке по-прежнему лишь username + иконка #user; без сведений о профильных навыках.
- У публичных игроков добавить «Подробнее». В попапе поверх текущего через второй native <dialog> показываются только проецируемые сервером игровые поля: позиции, опыт, рост/вес/телосложение, самооценка навыков. Текущий пользователь может открыть собственную карточку независимо от флага публичности.
- Скрытых пользователей другим просматривающим кнопку «Подробнее» не показывать, не вставлять чувствительные данные даже в HTML/template/JSON. Для владельца данные доступны только в его HTTP-контексте.
- Сохранить прежние уникальные direct/matched счётчики и предыдущий вид компактной карточки.
- Модалка поверх списка ESC/close → возврат к списку без потери scroll, фокус и мобильное окно; применяются штатный Tabler и CSS-токены из [UI design system](../../../specification/ui-design-system.md).

## Проверка
PHP feature: AccountMenu без роли/с PLAYER; Venue show 2 CTA → route('play-intents.mine'); private self vs чужой vs guest; доступные подробности только public+own; сквозная проверка кнопки и шаблона. CI PHP/JS/build + RBAC migration → merge dev и штатный deploy, без production.
