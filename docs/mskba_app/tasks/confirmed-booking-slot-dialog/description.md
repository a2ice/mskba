# Переход в подтверждённую заявку из занятого слота

## Контекст

В новой теме `mskba_app` на странице площадки в диалоге конкретного занятого слота («Занятое время») заказчик и ответственный со стороны площадки должны легко найти исходную заявку и переписку. Источник данных — серверная проекция `PublicVenueDaySchedule`, а не DOM или параметры URL.

## UI

- Для конечного заказчика подтверждённой брони показывать «Перейти в заявку», открывая в новой вкладке, сохраняя страницу расписания.
- Для `superadmin` и представителя, **фактически подтвердившего** эту бронь, дополнительно выводить «Заказчик: <логин>».
- Если событие прикреплено к брони, ссылка на заявку не подменяет информацию о публичном мероприятии.
- Для участника с переходом в заявку не показывать бессмысленное сообщение «Действия недоступны», если иного доступного действия нет.
- Использовать уже существующую тему, классы кнопок и диалог, без нового оформления или избыточных фокусных рамок.

## Разграничение и регрессия

- Переход и логин появляются только для статуса `confirmed`, только если у брони существует `public_id` и конечный заказчик.
- Суперадмин должен иметь действующий системный доступ; подтверждавший представитель — действующее разрешение `CONFIRM_BOOKING_REQUESTS` для конкретной площадки/зала плюс исторический факт подтверждения этой брони.
- Наблюдатели, представители другой площадки и люди без полномочий не получают логин, публичный ID заявки или URL. Отдельные внешние busy-слоты также не раскрывают владельца.
- Страница заявки и её переписка независимо повторно проверяют доступ на backend.
- Регрессионный feature-тест проверяет владельца, супер-администратора, подтверждавшего, постороннего сотрудника, гостя, отзыв права и неподтверждённую бронь.
