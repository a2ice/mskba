# Контекстный FAQ по типам страниц — MSKBA App (24.11.2026)

## Область
Единственный целевой UI — `mskba_app`. Светлая и тёмная темы влияют только на оформление. Все 89 типов страниц описаны в `config/faq-page-types.php`, а не привязаны к каждой модели/ID. Страница зала/зоны оставлена в каталоге без отдельного URL: на текущем этапе она использует страницу площадки, отдельный контекст появится позже.

## UX
На всех страницах основной и Inertia-оболочки доступна плавающая кнопка `?` в правом нижнем углу (на мобильном — выше нижней навигации). При нажатии открывается существующий единый `dialog` с вкладками:
1. **Что это за страница** — краткий текст;
2. **Возможности** — список;
3. **Связанные материалы** — ссылки на другие FAQ.

Пункт «Перейти ко всем вопросам FAQ» открывает прежний каталог без нового окна. Декларативные кнопки из Page Builder по-прежнему открывают обычный выбор разделов/статей. Уведомления и тосты в `mskba_app` закреплены у верхнего края, чтобы не закрывать плавающую кнопку.

## Данные
`PageFaqContentSeeder` создаёт **по одной редактируемой FAQ-статье на тип**:
- `system_key = faq.page.<key>`;
- `short_description` — вкладка «Что это за страница»;
- `full_description` — два секционных `<h2>` («Возможности» и «Связанные материалы») с HTML-списками;
- `alias = faq-page-<key-with-hyphens>`;
- тип `FAQ`, без публикации в новостях и Telegram.

После первичной публикации текст доступен через существующий редактор **Filament → Контент → Материалы и FAQ**. Seeder использует `firstOrCreate`: не перезаписывает ручные правки и не восстанавливает удалённые статьи. Не переименовывать указанные два заголовка `<h2>` до появления отдельной модели табов: JavaScript использует их для раскладки на вкладки.

`GET /faq/help-content?page_key=venues.detail` отдаёт `page_help` только для опубликованной статьи из белого списка, HTML обрабатывается штатным `ContentBodyRenderer`. Контекстные материалы не попадают в список общих разделов FAQ, но доступны по прямому URL и в связи между статьями.

Production workflow очищает прежний config cache и запускает только `PageFaqContentSeeder` после миграций. Повторный запуск безопасен.

## Проверка
- Главная: кнопка `?`, три вкладки и переход в полный FAQ.
- `/venues`, `/venues/{alias}`, `/venues/create`: разные тексты, один тип на все экземпляры площадок.
- `/events`, `/teams`, `/account/contacts`: тематические тексты.
- Редактор Filament: изменения описания отражаются в попапе, повторное заполнение не перезаписывает их.
- Перевод статьи в черновик: вместо устаревшего текста показывается исходный FAQ-каталог.
- Мобильный экран: кнопка поверх контента, но не поверх навигации, тосты сверху.
- Светлый и тёмный режим: одинаковые тексты, разные цвета дизайна.
- Неактивные / будущие маршруты остаются в справочнике, но не показываются как работающие страницы.
- Тесты: `tests/Feature/PageContextFaqTest.php`, полный CI + сборка Vite.

## За пределами MVP
Wiki и AI-ассистент; аналитика вопросов сотрудников и партнёров; UI управления структурой отдельных табов; контекст конкретных залов и зон.
