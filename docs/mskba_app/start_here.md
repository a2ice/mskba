## Цель и границы

Постепенно создать самостоятельную `mskba_app` с единым визуальным языком и рабочими сценариями поверх существующего Laravel. Новые экраны планируются на Vue 3 + Inertia; серверная оболочка и первый header пока реализованы на Blade. Не дублировать предметные сервисы, правила доступа, авторизацию или API без необходимости. Существующая `mskba_dark` остаётся рабочей темой production.

## Рабочий процесс

- Перед началом: прочитать этот файл → `progress.md` → нужную задачу из `tasks.md` → связанные правила и исходники. Проверить ветку и `git status`.
- **Каждая новая самостоятельная правка начинается с отдельной задачи**: добавить следующий номер в [локальный реестр](tasks.md), создать `tasks/NNN/description.md` с целью, критериями и статусом, только затем менять код или документацию. Исправления и проверки *той же* задачи отражать в её карточке; не плодить дубликаты для одного приёмочного цикла.
- **Local-only:** до отдельной явной команды пользователя не выполнять `push`, force-push, открытие PR, merge, deploy и иные действия, публикующие работу по `mskba_app`/#139. Локальные коммиты допустимы, если согласованы; фраза «коммитим» не разрешает push. Подробнее: [задача 007](tasks/007/description.md) и [CaseRule13–14](../specification/agent-rules.md).
- Перед разработкой: указать цель, ограничения, текущий экран, зависимость, критерии приёмки и запросить решение, если оно неоднозначно.
- **Обязательное правило всех модальных окон:** top layer через `showModal()` выше любого CSS `z-index`, центрирование desktop/mobile, не более **90vh/90dvh**, header/footer неподвижны, прокручивается только body с тематическим `.mskba-scroll`; общий CSS `mskba_app/css/modal.css`. Подробности: [Modal 1.1](../specification/ui-design-system.md#актуализация-2026-10-08-modal-11--согласованное-общее-правило), [задача 011](tasks/011/description.md).
- **Обязательная проверка UI до реализации:** для каждого элемента сначала найти утверждённый паттерн в [гайдлайне](../specification/ui-design-system.md), [каталоге](../../resources/themes/mskba_app/catalog/README.md), CSS-токенах и уже готовых компонентах. Если есть — **строго переиспользовать его**, включая оформление, иконку, состояния, responsive и доступность, без локального «похожего» варианта.
- **Новый многократно используемый UI:** прежде чем добавлять в страницу, представить назначение, контракт, варианты и состояния на согласование. После **явного одобрения** оформить дополнение к гайдлайну с ревизией, добавить образец в каталог и общий компонент; только затем внедрять в продуктовые экраны. Для одноразовой композиции разрешены исключительно утверждённые примитивы и токены. Полный порядок — [CaseRule15](../specification/agent-rules.md#caserule15---сверять-ui-с-гайдлайном-до-реализации-mskba-app) и [задача 009](tasks/009/description.md).
- Во время работы: соблюдать контракт принятой дизайн-системы; не создавать разрозненные варианты. Переиспользовать реальные данные и меню проекта.
- Перед сдачей: **указать для изменённых элементов ссылки на разделы гайдлайна/компоненты каталога или на согласованное расширение**; проверить сборку/рендер, desktop/mobile, состояние гостя/пользователя, меню, ссылки, accessibility, а также console/network там, где доступен браузер. Несовпадение с эталоном без согласования блокирует приёмку. Фиксировать **непроверенное** отдельно от пройденного.
- После: обновить описание задачи, [прогресс](progress.md), при необходимости [основную задачу #139](../tasks/139/description.md), техническую/продуктовую документацию. Для визуальной приёмки использовать протокол #139.
- Коммиты — локально в рамках согласованного процесса. Push, PR, merge и deploy по `mskba_app`/#139 запрещены без отдельной явной команды пользователя; записи этого раздела не означают принятие или публикацию.

## Локальные точки входа

- Web: `http://localhost:8000`, только при локальной конфигурации `APP_THEME=mskba_app`. Кнопка «Войти» открывает Vue-попап (локальная задача 008).
- Inertia integration preview: `http://localhost:8000/ui-preview` (локальная задача 003; при старой теме возвращает 404). Путь `/app` зарезервирован Nginx для WebSocket.
- Каталог принятого эталона: `resources/themes/mskba_app/catalog/` (см. [инструкцию](../../resources/themes/mskba_app/catalog/README.md)); локальный адрес зависит от поднятого сервера.
- Vite: `make vite` при уже работающем Docker или `make dev` для полного старта.

## Правило статусов

«Запланировано» → «В работе» → «На проверке» → «Принято». Для каждого принятия фиксируется основание и дата; отсутствие проверки не заменяется отметкой «готово». Общий статус #139 закрывается только по правилам `docs/tasks.md` после merge в `main`.
