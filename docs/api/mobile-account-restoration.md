# Восстановление удалённого аккаунта — REST API v1

Самостоятельное восстановление использует подтверждение владения ранее верифицированным email. Авторизация Bearer **не нужна**: токены были отозваны при удалении. Новые токены не выдаются при восстановлении.

1. POST https://mskba.ru/api/v1/account/restore/request
   JSON: {"contact":"user@example.com"}
   Ответ HTTP 200 (одинаковый для любого корректно оформленного email):
   {"message":"Если аккаунт доступен для восстановления, код отправлен на подтверждённый контакт."}

2. POST https://mskba.ru/api/v1/account/restore/confirm
   JSON: {"contact":"user@example.com","code":"123456"}
   Успех HTTP 200:
   {"restored":true,"message":"Аккаунт восстановлен. Теперь войдите заново."}

Ошибки:
- 422: ошибка валидации / неверный, использованный, заблокированный либо просроченный код / восстановление недоступно (один общий ответ);
- 429: лимит частоты (5 запросов в минуту на выдачу, 10 в минуту на проверку) плюс внутренний лимит не более 3 писем в час на контакт;
- 500: непредвиденная ошибка сервера (временный сбой).

Код состоит из 6 цифр, действует 10 минут, допускает до 5 неверных попыток. Повторная выдача ограничена одной в минуту.

Восстанавливается исходный пользователь с тем же ID и историей; canonical identity и aliases восстанавливаются вместе. Восстановление доступно только при **самостоятельном** удалении и наличии ранее подтверждённого email. Административное удаление и блокировка не отменяются.

После успешного подтверждения приложение должно показать форму входа; новый Bearer-токен выдаёт обычный POST /api/v1/auth/login. Использовать устаревший токен после восстановления нельзя.

Если у пользователя был подтверждён только Telegram/телефон, в этой версии доступно административное восстановление; канал OTP для этих контактов требует отдельной реализации доставки.
