# AGENTS.md

Краткая входная инструкция для AI-агентов. Подробные правила проекта живут в документации, этот файл только направляет, что читать и какие ограничения соблюдать в первую очередь.

## С чего начать

1. Работай из корня репозитория: `/Users/dmitrylosev/Projects/mskbanew/site`.
2. Перед изменениями проверь текущую ветку и статус git.
3. Если работа относится к задаче из `docs/tasks.md`, следуй процессу из `docs/specification/protsess-raboty-s-zadachami.md`.
4. Перед планированием или реализацией изучи релевантные разделы:
   - `docs/project.md` - продуктовая картина, пользователи, сценарии, бизнес-процессы.
   - `docs/specification.md` - техническая картина, архитектура, workflow, проверки.
5. Если в этих документах есть ссылки на раскрытия, изучи релевантные раскрытия тоже.

## Главные документы

- `docs/tasks.md` - общий список задач.
- `docs/tasks/{NNN}` - рабочие материалы конкретной задачи.
- `docs/project.md` - продуктовая документация для менеджеров, команды и пользователей.
- `docs/project/{alias}.md` - раскрытия продуктовых тем.
- `docs/specification.md` - техническая документация для разработчиков и AI-агентов.
- `docs/specification/{alias}.md` - раскрытия технических тем.

## Обязательные правила

- Не дублируй подробные технические правила в `AGENTS.md`; обновляй `docs/specification.md` или его раскрытия.
- Не дублируй подробные продуктовые описания в `AGENTS.md`; обновляй `docs/project.md` или его раскрытия.
- Любое важное изменение продукта, архитектуры, процесса или правил разработки должно сопровождаться актуализацией документации.
- Поддерживай оглавления и ссылки в `docs/project.md` и `docs/specification.md`.
- Не откатывай чужие незакоммиченные изменения. Если они мешают задаче, сначала разберись, как с ними совместиться.
- Не трогай `.env`, `vendor/`, `node_modules/`, `storage/framework/*`, `storage/logs/*` и сгенерированные build-артефакты без явной необходимости.

## Быстрые команды

Подробности смотри в `docs/specification.md` и `Makefile`.

```bash
make up
make down
make test
make clear
make artisan CMD='route:list'
make npm CMD='run build'
```

Локально, если зависимости установлены:

```bash
composer test
npm run build
```

## Когда сомневаешься

- Сначала ищи ответ в `docs/project.md` и `docs/specification.md`.
- Если документация противоречит коду, проверь актуальное поведение в коде и обнови документацию вместе с изменением.
- Если решение влияет на пользователей, фиксируй его в продуктовой документации.
- Если решение влияет на разработку или архитектуру, фиксируй его в технической документации.
