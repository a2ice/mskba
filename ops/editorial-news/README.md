# Editorial news API bridge

Production-only reviewed publishing requests. No token or password may be committed. Create GitHub environment editorial-production, restrict deployment to main, add environment secret MSKBA_EDITORIAL_NEWS_TOKEN from Filament with write/publish/social scopes. The superadmin may revoke the token in Filament. Rotate before expiry; this does not renew VK authorization.

A reviewed request JSON in requests/ may omit the cover for any channel. When provided, a cover in covers/ (JPEG/PNG/WebP <=5 MiB) is validated and uploaded; otherwise Telegram and VK publish text with the material link. A photo publication never silently falls back to text. Site-only publication skips the social destination registry and sends no social payload. Fields: alias, title, summary, content (Markdown), cover (optional repo-relative path), telegram_chat_titles (explicit exact titles, matched case-insensitively, unique), vk_group_id (exact configured group ID or null), optional resume_existing_draft (only true after admin verifies draft), optional allow_vk_wait (explicitly defer the full VK photo post until authorization is restored). A merge to main changing exactly one request triggers the bridge, or an authorized operator can manually run it with that reviewed path. No public request is included in this infrastructure PR. No real sends from dev. If VK or a Telegram destination is unavailable, preflight fails rather than silently changing recipients. With explicit allow_vk_wait, site/Telegram may publish while VK awaits authorization; awaiting_auth is not delivery success. Never auto-retry ambiguous external writes. Check API/Filament before resuming a draft; an existing published alias is read-only and reported, not re-sent. Success means the API returned a site URL and each selected external post ID, not independent visual acceptance.
