# Identity

Модуль ограниченного контекста для пользователей, аутентификации, профиля и ролей.

## Ответственность

- Регистрация, вход и выход пользователя.
- Создание аккаунта через `CreateUserAccountHandler`.
- Базовый профиль пользователя в таблице `profiles`.
- Системные роли и роли участия.
- Browser fingerprints для security-, аналитических и device-сценариев; fingerprint не предоставляет права на сущности.
- Actor attribution: централизованный субъект действия для гостя, пользователя и системы.
- Предметные профили участия пользователя, например `PlayerProfile`.
- Проверки пользователя перед отображением страниц личного кабинета.
- Персональные операционные права, не связанные с системной ролью.
- Настройки приватности и единая проверка доступа к пользовательским данным.

## Структура

- `Domain`: бизнес-модели, enum, события, исключения, value object.
- `Application`: use case, DTO и application-сервисы.
- `Infrastructure`: ACL, интеграции, service provider, factory.
- `Presentation`: HTTP-контроллеры, request-классы, resource-классы.
- `Tests`: feature- и unit-тесты модуля.

## Actor attribution

Новые сущности проекта не должны хранить автора действия через отдельные пары `created_by_user_id` + `created_by_fingerprint_id`.

Канонический подход:

- получить текущий actor через `CurrentActorResolver`;
- передать `?Actor` в use case;
- сохранить `created_by_actor_id` в доменной сущности.

Подробнее: `docs/architecture/actors.md`.

## Операционные права

Поддерживаемые права перечислены в `UserOperationalPermissionEnum`.
`UserOperationalPermissionChecker` читает персональный snapshot из
`user_operational_permissions`. Отсутствующая строка означает, что право
разрешено: благодаря этому новые permissions безопасно включаются по умолчанию
без массового обновления всех пользователей.

Подтверждённый пользователь уровня `admin+` может менять snapshot только для
пользователя с более низкой системной ролью. Изменения выполняются
транзакционно, блокируют целевого пользователя и аудитируются.

## Приватность

Пользователь независимо настраивает общую видимость, доступ к контактам,
сообщениям и приглашениям в группы. Для каждого правила доступны все,
выбранные пользователи или никто. Отсутствующая запись использует безопасное
значение по умолчанию, а прикладные сценарии проверяют доступ через
`UserPrivacyAccessService`.

Технические правила: `docs/specification/identity-privacy.md`.
